핵심 3요소와 동작 구조

하네스 구성 요소는 많지만, 강사는 이 세 가지만 갖춰도 멀티 에이전트 협업이 잘 일어난다고 보고 여기에 집중합니다 — 에이전트 · 스킬 · 오케스트레이터.

1) 에이전트 — 자연어 문서

에이전트는 코드가 아니라 자연어로 작성된 문서입니다. 다음을 담습니다.

  • 역할과 원칙
  • 입력 프로토콜 · 출력 프로토콜(결과를 어떤 포맷으로 낼지)
  • 협업 — 다른 에이전트와 무엇을 주고받을지
  • 재호출·에러 발생 시 행동

2) 스킬 — 반복 작업의 표준화

스킬은 name + description 에, 정해진 프로세스·지식·체크리스트를 자유롭게 담은 것입니다.

  • 프로세스가 정해져 있어 일관성이 유지됩니다.
  • 작은 스킬들을 조합해 더 큰 시스템을 구성할 수 있습니다.
  • 표준화 덕분에 반복 작업이 빨라집니다.

스킬 설계 요령: 반복 작업을 찾아 → 단일 책임으로 분리 → 입력/출력 정의 → 예외 처리 → 에이전트에 연결.

3) 오케스트레이터 — 마이크로매니징하지 않는 PM

전체 워크플로우가 잘 수행되는지 책임지는 PM 입니다. 망하는 PM처럼 세세하게 간섭하지 않고, "워크플로우를 잘 수행하고 있는가" 정도만 체크합니다.
