Knowledge Map — AI

このページは AI World の下の講義・学習の文書の全体を AI が読んで作った構造的な知識のインデックス（knowledge-index.json）を総合した知識の地図です。文書ごとの要約 · 中心の概念 · 関連する文書を集め、何がどこにあり互いにどうつながっているかを示します。各文書の下にある“関連する文書”の推薦も同じインデックスから出ており、この関連は Knowledge Graph で 3 種類の 3D と 6 種類の 2D の表現として見られます。

ウィキの知識は World → Domain → System → Document の 4 階層で構成されます — World は最上位の知識の世界（AI · DOUZONE）、Domain は知識の領域、System は具体的な体系・主題（下の表のグループ）、Document は個別の文書です。この地図はそのうち AI World を扱い、業務の知識は Douzone Knowledge Map が同じ構造で集計します。

ふたつの World — 学習の知識（AI）と業務の知識（DOUZONE）が、同じインデックスの上でつながります。
三つの筋に分かれますが、上の共有の概念が筋を横切って文書を密につなぎます。

System の詳細 — 何が入っていて、どの順に読むか

知識体系 — このウィキ自身の説明書（6 編）

このウィキの知識がどう積み上がり、つながり、読まれるのかを実際のデータで解説する自己記述の System です。知識はどう積み上がるのか（4 階層・登録のパイプライン・三つの目印） → 文書はどうつながるのか（概念のキュレーション・idf のエッジ・方向のある型つきの関係） → グラフを読む 9 つの眼（ビューごとの問い・ハブ・ブリッジ） → AI はこのウィキをどう読むのか（機械が読める層） → ウィキのエンジンのプラグイン化（wiki-plugin） → ウィキはどう自分を守るのか（ゲート・自動化）の順に読めば、この地図のページのすべての数値がどこから来るのかが分かります。

Introduction — Claude Code の第一歩（6 編）

Claude Code とは何で、どう始めるのかを扱う入口の System です。Welcome で道具の正体を、インストールと開始でインストールと認証を、日々の利用でスラッシュコマンド・CLAUDE.md・プランモードを身につけます。続いて拡張の三つの軸 — Skills、MCP Servers、Hooks — を紹介します。この System の概念（インストール・スラッシュコマンド・CLAUDE.md）は Tutorial や OMC の System へそのままつながります。

Tutorial（入門） — 基礎の講義の実習（12 編）

Claude Code の基礎の講義を文書にした System で、講義の概要と目標が入口です。Claude Code とは → ターミナルの基礎 → CLAUDE.md の指針で基礎を固めたあと、調査・ファイル・ウェブサイト・デザインシステムの抽出・Hugging Face の論文の整理といった実戦の例を経て、スキルをつくる・プラグイン・エージェントをつくるへ広げ、使用量と文脈の管理・役に立つ機能で締めます。

Skill — スキルの深掘り（12 編）

“スキルはなぜ、どう動くのか”を原理から掘る System です。概要とコーディングエージェントの誕生で背景をつかみ、スキルとは・長所・コンテキストウィンドウと道具・段階的な読み込みで中心の原理を、SKILL.md の構造・例のスキル・インストールと利用・セキュリティ上の注意・スキルをつくるで実務を扱います。エンジニアリングの階層と Q&Aが MCP やハーネスとの関係を整理し、自動化の筋へ橋を架けます。

Second Brain — 知識の管理の 5 段階（9 編）

個人と組織の知識の管理をレベル 1（正確に見つける）からレベル 5（自律のブレイン OS）までの段階のモデルで説明する System です。セカンドブレインとはから始め、入口の文書 5 段階をひと目でで全体の絵をつかみ、レベル 1〜レベル 5を順に読みます。何を入れ、何を置くかと 自分のレベル探し・チームへの拡張が実際に当てはめる判断を助けます。LLM Wiki の System が、このモデルのレベル 2 を実装する実体です。

LLM Wiki — Obsidian をもとにした知識のボールト（11 編）

Obsidian のボールトで LLM に優しいウィキを運用する方法論の System です。概要のあと、入口の文書 ボールトの体系で構造をつかみ、知識のキャプチャ・ノートのメタデータ・連結と参照・ウィキのカード・システムのファイルと rulesで運用の規則を学びます。オンボーディングの実習・Ingest・Query・Lint・ウェブクリッパーと Query の実戦が実習の軸で、活用と哲学が締めです。

Harness エンジニアリング — エージェントのチームの方法論（12 編）

AI World でいちばん多くつながるハブ（構成と効果、11 回）を抱える System です。概要 → ハーネスエンジニアリングとは → 構成と効果で概念をつかみ、メタなハーネスのスキルのインストール・ハーネスを実行する・生成された結果のレビューで実習します。厨房のたとえ・エージェントのチームと文脈・中心の 3 要素が働きの原理を、活用の事例・ハーネス 100・道具の拡張が応用を扱います。

Harness プラグイン — ERP の実戦のハーネス（10 編）

ハーネスの方法論を ERP のカスタマイズの実務に当てはめたプラグインの System です。紹介・中心の概念・インストールのあと、最初の実行（営業・受注）ですぐ実習します。動く構造と 6 段階・エージェントとスキルの設計・検証・品質と _workspaceが内部の構造を、シナリオの掲示板・ハーネス 100・性能・コマンドが活用を扱います。Harness エンジニアリングの System の理論が、ここで業務のドメインと出会います。

OMC プラグイン — 実行のモードと自律の実行（13 編）

oh-my-claudecode のプラグインの使い方の System で、編数がいちばん多いのです（13 編）。紹介・中心の用語のあと、ハブの文書 インストールと インストールの診断で環境を作り、実行のモード（autopilot・ralph・ultrawork・team）・エージェントとスキル・Hook とメモリ・高度な道具で機能を身につけます。実戦のシナリオ・Windows の注意・費用と性能・コマンド集・クイックリファレンスが運用の編です。

おすすめの学習の経路

  • はじめてなら — Welcome → インストールと開始 → 日々の利用 → 基礎の講義（Tutorial の順に） → Skills。Claude Code を入れて日々の道具にする最短の経路です。
  • 知識の管理が目的なら — セカンドブレインとは → 5 段階をひと目でで自分のレベルを見つけ、レベル 2 が要るなら LLM Wiki の概要 → ボールトの体系へ降りて実際のボールトを作ります。
  • 自動化・マルチエージェントが目的なら — スキルの深掘りで原理を固めてから ハーネスエンジニアリングとは → 構成と効果 → 実行する、続いて実務への適用は Harness プラグインか OMC へ分かれます。
