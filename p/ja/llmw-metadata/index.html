ノートの構造 — メタデータと段階的な開示

ウィキのノートを開くとタイトル → メタデータ → 本文の順に並んでいます。たとえば本文が 38 行目から始まるなら、その前の37 行はすべてメタデータです。

YAML フロントマターが肝

Obsidian がマークダウンのエディタとして価値が高いのは、まさにこの YAML フロントマターのメタデータのフィールドです。Claude Code で学んだ段階的な開示（progressive disclosure）と同じ原理で動きます。

エージェントはメタデータ（フロントマター）を先に読み、必要なときだけ本文を開きます。
  • コンテキストウィンドウには制限があり（多くて 100 万トークン）、すべての内容を開いて見ることはできません。
  • だから重要な内容だけを簡潔に（concise）いちばん上（メタデータ）に入れておきます。
  • Claude Code のようなエージェントは、このメタデータを先に読みます。全体に比べれば氷山の一角ですが、この一角だけをざっと見て、何に関する内容かを素早くつかみます。

タイトル・説明をうまく書く（英語で）

スキルの description と同じく、ノートのタイトルと説明（description）のフィールドをうまく書くことが大切です。私たちは日本語話者ですが、人工知能は英語のほうが速く・うまく読むので、メタデータは英語で書くほうが有利です。

コンテキストの最適化 Obsidian の大きな長所は、ひとつのファイルにすべてを詰め込まず、「好みは 好み.md を見よ」「専門のペルソナはここを見よ」のように別ファイルの住所を書けることです。仕事のときに必要なファイルだけ開かせてコンテキストを最適化します。講師は Karpathy のアイデアを借りて、こうしたメタデータの作成を自動化するコマンド・スキルのセットを用意しています。
