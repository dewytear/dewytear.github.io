スキルの構造と動作原理

スキルの原理を理解するには、まずコンテキストウィンドウから知る必要があります。

コンテキストウィンドウ

コンテキストウィンドウとは、LLM へ入力される入力の大きさです。（出力がまた入力へ入って続いていく構造なので、出力も含まれます。）ここには利用者の質問だけでなく、次のすべてが収まります。

  • 基本の情報（あなたは誰で、今日は何日で、何をして何をしてはいけないか）
  • 指示文 · few-shot の例 · 出力の形式 · 文脈 · メモリ
  • ツールの定義 · チャットの履歴（長くなるほど積み増される）

昔の LLM はコンテキストが 2K〜8K（GPT-3 で約 2K、GPT-4 の初期で 8K）しかありませんでしたが、いま Claude Code で使うモデルは基本 200K、一部のモデル（Sonnet 4.6・Opus 4.6 以降など）は1M（100 万）トークンまで受けとります。ただし、大きければよいというものでもありません。コンテキストが埋まりはじめると LLM が不安定になり、仕事をしたがらなくなったり、おかしなところで終わらせたりします。

clear · compact — 机の片づけ Claude Code の /clear・/compact は、いまのコンテキストを減らしたり空にしたりして新しい作業に備えるコマンドです。机が散らかったまま仕事をするのと、すっかり片づけてから始めることの違いだと考えてください。

ツールがコンテキストを食う

スキルも結局はツールの一種です。ところがツールをひとつ開いてみると、関数・引数・使う時点・単位などが書かれた複雑な JSON のスペックです。これがひとつひとつけっこう大きいので、ツールが数個を超えただけでコンテキストが破裂しそうになります。MCP やコネクタをいくつもつないでいると「これ以上つなげません」と出るのは、これが理由です。

トランクのたとえ ツールは自動車のトランクのようなものです。大きさに限りがあるので、キャンプ道具を全部は入れられません。選択肢はふたつ — もっと大きなトランクを買うか、荷物をできるかぎり減らすか。コーディングエージェントは後者を選び、ツールを六つに減らして実行環境を一緒に渡すやり方で問題を解きました。そしてその上にスキルが登場したのです。

段階的な読み込み（スキルの中心原理）

スキルのいちばん中心にある原理は段階的な読み込み（progressive disclosure）です。スキル全体をコンテキストに載せるのではなく、メタデータだけを先に載せておいて、必要なときに残りを取り出します。

図書館の本の表紙のたとえ

コンテキストに入るのは、登録されたスキルのメタデータ（名前 + 説明、3〜4 行、スキルあたり約 100 トークン）だけです。図書館に本がずらりと並んでいて、私たちは本の表紙（タイトル・簡単な説明）だけを眺め、必要になったら取り出して読むのと同じです。メタデータがとても小さいので、100 個以上入れてもコンテキストをほとんど食いません。（JSON のツールはスキーマ全体が先にコンテキストを占め、数が増えるほど負担が大きくなるのと対照的です — だから Claude Code は MCP ツールのスキーマも遅延ロードします）

3 段階の読み込み

上へ行くほどつねに、下へ行くほど必要なときだけ — 読み込む時点が段階ごとに遅くなります。
レベル内容読み込む時点
1メタデータ（SKILL.md の名前・description）つねに読み込む（スキルあたり約 100 トークン）
2指示（SKILL.md の本文、マークダウンの使い方）そのスキルが呼ばれたとき
3リソース · スクリプト · テンプレート（同梱ファイル）必要なときだけ（スクリプトは読み込まずに実行するだけ）

同梱ファイルは必須ではありません。言葉（マークダウン）だけで足りるならファイルなしでもよく、実行するスクリプトやテンプレートが要るなら含めます。ファイルがあるほど、より決定論的な結果が得られます。ちなみに公式のガイドは SKILL.md の本文を5K トークン未満に保ち、長い内容は同梱ファイルへ分けることを勧めています。

マニュアルのたとえ（組み立て製品・マトリックスのヘリ） 通販で組み立て製品を買うと、マニュアルを見ずに完成写真だけ見て組み立て、ネジが余った瞬間にマニュアルを取り出します。スキルの指示も発動したときにちょうど取り出して読み、ふだんは取り出しません。映画マトリックスで、ヘリの前でマニュアルを一瞬でロードして操縦する場面と同じ感覚です。
確認のコツ Claude Code で /context と打つと、システムプロンプト・カスタムツール・スキルなどがそれぞれ何 % を占めているかが見えます。積んだスキルが多くてもトークンをほとんど使っていないことを確認できます。

SKILL.md の構造とディスクリプション

スキルのフォルダの中心は SKILL.md のファイルで、そのほかに reference・examples・scripts といった同梱ファイルが一緒にあります。

フロントマター（メタデータ）

ひとつのファイルの中で、フロントマターはつねに、本文は呼ばれたときに読み込まれます。

SKILL.md のいちばん上には YAML のフロントマターがあります。たとえば PDF のスキルなら:

# SKILL.md のフロントマター (つねに読み込まれる部分)
name: pdf
description: PDF のテキスト/表の抽出、結合、分割などに使うツールキット

最初に読み込まれるときはこのフロントマターだけが載り、実際の説明書（本文）は呼ばれたときに読み込まれます。

ディスクリプションの書き方が大事

スキルは /スキル名 で明示的に呼び出すこともできますし、「PDF からテキストを抽出してみて」のように言えばフロントマターを根拠に自動で発動することもあります。だから description をうまく書く必要があります。

  • 呼び出されない場合 — 例: PDF の編集機能があるのに description に「読むのに使う」としか書いていないと、編集を頼んでも呼び出されないことがある。
  • 不要に呼び出される場合 — PDF と関係ないのに急に発動してしまう。

だから、ちゃんと呼び出されるか、むだに発動しないかをテストしてみて、自分で作るときは description を念入りに書くべきです。

指示の中でファイルを参照する

本文（マークダウン）の指示の中には、「こういうときはこのファイルを見よ」のように別のファイルを参照するよう書いておけます。これは先に見た JSON のツールのスペックと違い、人に教えるように自然言語で「コマンドの実行のしかた」くらいを書くものです。

なぜ read と実行だけで動くのか コーディングエージェントはファイルの読み・書き・編集・検索のツールを標準で備えていて、ファイルシステムを自由に扱えます。だから指示に「このファイルを読め」とあるだけで、エージェントが自分で読み込みます。スキルの内容とコーディングエージェントのツールがどう相互作用しながら読むのかを想像しながら見ると、理解しやすくなります。

例のスキルを眺める

概念をつかんだので、実際のスキルの集まりを見てみます。始めるときは、こうした例をいくつか開いてみるのがおすすめです。

Anthropic の標準スキル

Anthropic が公式に作った標準のスキルが GitHub に公開されています。フォルダごとコピーしてノート PC の Claude Code に入れると、読み込み時に各 SKILL.md の YAML フロントマターだけを先に読み、必要なときに本文を読み込みます。

科学エージェントのスキル集（約 140 個）

科学研究向けのスキルを集めたコレクションもあります。約 140 個の科学関連のスキルが入っていて、その分野の研究者が「うちの分野でよく使うスクリプトがここにある」と言うほどです。

  • Biopython などのバイオ関連、データセットのダウンロードのスキル（どこからどう取るかまで）。
  • Scientific Writing — 学会ごとの論文の書式、図表の規定（解像度の下限、JPG 禁止・PNG など）まで収めて、きれいな論文／PDF を生成。

メタデータのおかげで複数のスキルを同時に読み込んで融合的な研究ができます。例:「バイオのデータセットを機械学習で処理して」→ バイオを読み込み → データを読み込み → 学習 → 論文の執筆・投稿まで続きます。量子・深層学習のハイブリッドな処理も、ある程度は可能です。

韓国向けのスキル集

「韓国人による、韓国人のための」スキル集もあります。日常でいちいち面倒だったことを、Claude Code（およびアプリ）からそのまま処理します。

  • SRT・KTX の予約、自然休養林の空室の照会、Kakao マップ
  • ソウルの地下鉄の到着情報、遺失物の照会、ニュース・天気、漢江の水位
  • 韓国の法令の検索、登記簿謄本、HWP 文書の閲覧、宅配の追跡、グルメなど
そのあいだの空白 とても科学的なスキルと、とても日常的なスキルのあいだの広い空白を、あなたの業務のスキルで十分に埋められます。

原理をつかんだら、あとは手を動かすだけです — 導入・セキュリティ・作成の章で実際にインストールして使い、セキュリティの注意点を押さえ、スキルを作るところまで進みます。
