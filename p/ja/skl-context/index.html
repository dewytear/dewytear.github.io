コンテキストウィンドウとツールの問題

スキルの原理を理解するには、まずコンテキストウィンドウから知る必要があります。

コンテキストウィンドウ

コンテキストウィンドウとは、LLM へ入力される入力の大きさです。（出力がまた入力へ入って続いていく構造なので、出力も含まれます。）ここには利用者の質問だけでなく、次のすべてが収まります。

  • 基本の情報（あなたは誰で、今日は何日で、何をして何をしてはいけないか）
  • 指示文 · few-shot の例 · 出力の形式 · 文脈 · メモリ
  • ツールの定義 · チャットの履歴（長くなるほど積み増される）

昔の LLM はコンテキストが 2K〜8K（GPT-3 で約 2K、GPT-4 の初期で 8K）しかありませんでしたが、いま Claude Code で使うモデルは基本 200K、一部のモデル（Sonnet 4.6・Opus 4.6 以降など）は1M（100 万）トークンまで受けとります。ただし、大きければよいというものでもありません。コンテキストが埋まりはじめると LLM が不安定になり、仕事をしたがらなくなったり、おかしなところで終わらせたりします。

clear · compact — 机の片づけ Claude Code の /clear・/compact は、いまのコンテキストを減らしたり空にしたりして新しい作業に備えるコマンドです。机が散らかったまま仕事をするのと、すっかり片づけてから始めることの違いだと考えてください。

ツールがコンテキストを食う

スキルも結局はツールの一種です。ところがツールをひとつ開いてみると、関数・引数・使う時点・単位などが書かれた複雑な JSON のスペックです。これがひとつひとつけっこう大きいので、ツールが数個を超えただけでコンテキストが破裂しそうになります。MCP やコネクタをいくつもつないでいると「これ以上つなげません」と出るのは、これが理由です。

トランクのたとえ ツールは自動車のトランクのようなものです。大きさに限りがあるので、キャンプ道具を全部は入れられません。選択肢はふたつ — もっと大きなトランクを買うか、荷物をできるかぎり減らすか。コーディングエージェントは後者を選び、ツールを六つに減らして実行環境を一緒に渡すやり方で問題を解きました。そしてその上にスキルが登場したのです。
