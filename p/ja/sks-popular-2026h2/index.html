2026年下半期の人気スキル — インストール数上位7つと使い方

三行まとめ

  • 2026年10月22日時点で skills.sh の累計インストール1位は find-skills(約398万)だ。公式の Claude プラグインディレクトリでは frontend-design(約113万)と Superpowers(約101万)が1・2位だ。
  • 上位は大きく五種類に分かれる。スキルを探すスキル、計画を問い詰めるスキル、ブラウザや動画のような手足を与えるスキル、好みとルールを植えるスキル、開発方法論をまるごと束ねたスキルだ。
  • インストール数は品質の点数ではない。計数器ごとに数える単位が違い、skills.sh はリポジトリ単位で数えるので、スキルの多いリポジトリが一度に何行も占める。

スキルは、エージェントが必要なときに読み込むマークダウン一枚(SKILL.md)とそのフォルダだ。冒頭のフロントマターの description が、いつこのスキルを取り出すかを決める。詳しい仕組みはスキルとはと構造と動作にある。本記事は2026年下半期に最も多くインストールされたスキルを選び、それぞれの元の SKILL.md を直接読んで、何をするのか、どう使うのか、どこで役に立つのかを整理する。

順位はどこで数えるのか

「最も人気のあるスキル」を一つの数字で言うのは難しい。スキルを数える場所がいくつもあり、単位もばらばらだからだ。同じ frontend-design でも、どこで数えるかで数字が変わる。

skills.sh は Vercel が運営するスキルのディレクトリで、npx skills コマンドでインストールされた回数を数える。ここに注意点がある。インストールをリポジトリ単位で数えるため、一つのリポジトリにスキルが複数あると、一緒にインストールされたスキルが並んで上位に来る。下の上位10のうち5行が mattpocock/skills、2行が heygen-com/hyperframes から来ているのもそのためだ。複数の順位をまとめて毎日公開するオープンデータ(LinklyAI best-skills、CC BY 4.0)が、この限界を自ら書いている。

1. find-skills — スキルを探すスキル

何をするか。ユーザーが「X はどうやるの?」「X をするスキルはある?」のように尋ねると、このスキルが目を覚ます。エージェントはまず skills.sh の順位表に実績のあるスキルがあるかを見て、なければ npx skills find で検索する。すぐには勧めず、三つを確かめる。インストール数が1,000以上か、出どころが信頼できるか(vercel-labs・anthropics・microsoft のような公式の出どころ)、元のリポジトリの GitHub スターが100を超えるかだ。通ったものだけを、名前・用途・インストール数・インストールコマンドと一緒に示し、ユーザーが望めばインストールまで行う。

npx skills add vercel-labs/skills --skill find-skills   # インストール
# その後の会話で
「PR レビューを手伝うスキルはある?」 → npx skills find pr review
                                  → 候補を検証 → インストールコマンドを提示
npx skills add <owner/repo@skill> -g -y                 # ユーザー単位でインストール

どこで役に立つか。スキルの生態系の入口の役目だ。1位の理由もここにある。初めてスキルを入れる人がまず入れ、その後のスキルはこのスキルを通って入ってくる。検証の基準をスキルの中に書いておいた点も目を引く。ただしその基準もインストール数とスター数なので、本記事の結論どおり、数字を超える判断は人がする。

2. grill-me — 計画をとことん問い詰めるインタビュー

何をするか。grill-me の SKILL.md は7行だ。本文は「grilling スキルを呼べ」の一行だけで、実際のルールは同じリポジトリの grilling スキルにある。フロントマターの disable-model-invocation: true は、モデルが勝手に取り出さず、ユーザーが /grill-me で呼んだときだけ使えという意味だ。小さなスキルが別のスキルを呼ぶ構成で、スキルが「マークダウン一枚でできた再利用の単位」だということが実際にどう使われるかをよく示している。

grilling は計画を決定の木として見る。一つの決定には、その決定にぶら下がる次の決定が枝のようにつく。エージェントは、前提の決定がもう決まっていて今聞ける質問(フロンティア)を一つのラウンドでまとめて聞く。質問ごとに番号をつけて推奨の答えを添え、「yes」とだけ答えれば推奨を受け入れるように文を組む。

npx skills add mattpocock/skills --skill grill-me
# または Claude Code プラグインとしてリポジトリ全体を
claude plugin install mattpocock-skills@claude-plugins-official

/grill-me   ← 計画や設計を貼りつけて呼ぶ
❓ Q1 - 保存場所: …   ➡️ 推奨の答え
❓ Q2 - 失敗時の動作: … ➡️ 推奨の答え
(答えると次のラウンドへ)

どこで役に立つか。コードを書く前に、計画に隠れた前提をあぶり出すのに使う。事実の確認はエージェントがサブエージェントで自分で調べ、ユーザーには決定だけを聞く。質問がむやみに増えない理由だ。一緒に上位にいる grill-with-docs(約121万)は、同じインタビューをしながら domain-modeling スキルで用語集(GLOSSARY.md)と決定の記録(ADR)をその場で書く。ADR は三つの条件がすべてそろうときだけ提案する。取り消しにくく、文脈なしでは驚かれ、実際の代替案の中から選んだ決定のときだ。直近7日のソーシャルでの言及数1位も grill-me だった。

3. agent-browser — エージェントにブラウザを

何をするか。Rust で作ったブラウザ自動化の CLI だ。Chrome DevTools プロトコルで Chrome を直接動かし、Playwright や Puppeteer に頼らない。要はページを HTML のまま読まないことにある。アクセシビリティツリーを撮ったスナップショットで、ボタンや入力欄ごとに @e1、@e2 のような短い参照をつけ、エージェントはその参照でクリックし入力する。元の文書は、こうすると HTML の代わりに200〜400トークンだけ読めばよいと説明する。SKILL.md 自体は案内板で、実際の使い方はインストールされたバージョンから agent-browser skills get core で読み込む。だから説明書が古びない。

npm i -g agent-browser && agent-browser install   # CLI と Chrome
npx skills add vercel-labs/agent-browser           # スキル

agent-browser open https://example.com
agent-browser snapshot -i          # 操作できる要素だけ
agent-browser click @e3
agent-browser skills get electron  # Slack・VS Code など Electron アプリ用のサブスキル

どこで役に立つか。Web アプリのテスト、フォーム入力、画面キャプチャ、データ抽出のように、エージェントが実際の Web ページを扱う仕事だ。サブスキルで Electron アプリ(VS Code・Slack・Figma)、探索型の QA、サイトのリクエストを録画して API クライアントを作る仕事、クラウドブラウザまで広がる。公式ディレクトリ6位の Playwright MCP と仕事が重なる。違いは MCP ツールの代わりに短い CLI コマンドで動く点で、Playwright 側の文書もコーディングエージェントには CLI とスキルの組み合わせのほうがトークンが少なくて済むと書いている。

4. hyperframes — HTML で動画を作る

何をするか。HeyGen が公開したオープンソースのフレームワークで、HTML・CSS で組んだ場面を動画にレンダーする。止めたタイムラインを1フレームずつ進めて撮るので、同じファイルはいつレンダーしても同じ動画になる。index.html が動画全体を、compositions/ 以下のファイルが場面一つずつを受け持つ。スキルはこのレンダーの規則と作業の順序、動画の種類ごとに必要なもの(音・字幕・画面比)を収めている。Web サイトを題材にするときは、サイトをそのままキャプチャして素材にする。

npx hyperframes skills update        # コアのスキル一式(エージェント向け推奨)
npx skills add heygen-com/hyperframes   # または選んでインストール

npx hyperframes init my-video
npx hyperframes capture https://example.com --json   # サイトを素材に
npx hyperframes check --json                         # 規則違反の検査
npx hyperframes render --quality looks --output out.mp4

どこで役に立つか。製品紹介の動画、説明動画、グラフのアニメーション、縦型クリップのように、何度も直す動画だ。動画編集ソフトではなくコードなので、エージェントが直して再レンダーしやすい。直近7日の成長率1位(+13.3%)で、リポジトリのスキル七つがそろって上位40に入った。

5. frontend-design — ありきたりな AI デザインを避ける方法

何をするか。Anthropic が作ったデザイン判断のスキルだ。エージェントに「どの顧客にも他と取り違えられない個性を与えるデザインスタジオの責任者」という役を与える。まずこの画面が何についてのものか、誰が見るのか、何をすべきかを決め、その題材の世界(業種・素材・使う言葉)から色と書体を選ばせる。そして生成されたページによくある跡を具体的に禁じる。見出しの一語だけを強調する、ラベルをすべて大文字にする、順序のない内容に01・02・03の番号をつける、すべての区画に同じフェードインを入れる、といったものだ。作業の順序は計画、依頼との照合、制作、自己批評だ。

/plugin install frontend-design@claude-plugins-official
# または
npx skills add anthropics/skills --skill frontend-design

「近所のパン屋の予約ページを作って」   ← UI の作業なら自分で目を覚ます

どこで役に立つか。ランディングページ、ダッシュボード、アプリ画面のように、UI を一から作る仕事だ。公式ディレクトリのインストール1位(1,134,112)で、総合点でも3位だった。同じオープンデータの直近7日の成長順位に、UI の好みを扱う別のスキル(ui-taste)が2位で入っているのを見ると、「AI が作った跡が出る画面」はいま多くの人が抱えている問題だ。

6. Superpowers — 開発方法論をまるごと

何をするか。スキル15個を束ねた開発方法論だ。入口の using-superpowers が会話を始めるたびに目を覚まし、「スキルが当てはまる可能性が1%でもあれば必ず先に呼べ」と念を押す。その後、下の七段階のスキルが順に自動で発動する。計画は熱意はあるが文脈のない新人エンジニアでもたどれるほど細かく刻み(作業あたり2〜5分)、実装は失敗するテストを先に書く TDD で行う。

/plugin install superpowers@claude-plugins-official

「ToDo アプリに繰り返し予定の機能を入れたい」
→ brainstorming が先に目を覚まし、目的を聞いて設計を短く区切って見せる
→ 承認すると作業場所・計画・実装・レビューが順に進む

どこで役に立つか。エージェントに数時間の仕事を任せるときだ。元の説明によれば、計画を承認するとエージェントが計画から外れずに二時間ほど一人で働くことはよくある。公式ディレクトリのインストール2位(1,009,371)で、Claude Code のほか Codex・Cursor・Gemini CLI など多くのハーネス向けのインストール方法も出している。逆に短い質問でもブレインストーミングから始まるので、軽い作業が多い人には重く感じられるかもしれない。

7. vercel-react-best-practices — 70のルールを優先順位で

何をするか。Vercel のエンジニアリングがまとめた React・Next.js の性能ルール70個を8つの範疇に分け、影響度の順に並べた。最上位はリクエストが順番待ちになる滝(waterfall)をなくすことと、バンドルサイズを減らすこと(どちらも CRITICAL)で、サーバー側の性能、クライアントのデータ取得、再レンダーの順に下がる。エージェントは React のコードを書いたりレビューしたりするとき、この順に見る。同じリポジトリの web-design-guidelines(総合9位)は、レビューのたびに最新の指針を URL から取り直し、ファイル:行 の形式で違反を書く。

npx skills add vercel-labs/agent-skills --skill vercel-react-best-practices
npx skills add vercel-labs/agent-skills --skill web-design-guidelines -a claude-code

「このページはなぜ遅い?」 ← React・Next.js の作業なら自分で目を覚ます
「UI をレビューして」     ← web-design-guidelines

どこで役に立つか。チームのコードのルールを文書ではなくエージェントに直接植える方法の手本だ。ルールが優先順位と接頭辞(async-、bundle-)で整理されているので、社内ルールのスキルを作るときにそのまま倣う価値がある。

選ぶときに見ること

  • インストール数は人気の数字だ。同じ計数器の中だけで比べ、リポジトリ単位で一緒に数える効果を差し引く。総合点も公式の出どころかどうかを信頼の点に使うだけで、まだセキュリティ検査はしていないとデータの提供者が明かしている。
  • スキルはエージェントの権限で動く。インストールの前に SKILL.md と付属のスクリプトを読む。何を実行し、どこへつなぐのかを確かめる方法は導入・セキュリティ・作成にまとめた。
  • 自動で発動するかを見る。frontend-design・Superpowers のように自分で目を覚ますスキルは便利だが、望まないときにも割り込む。grill-me のように disable-model-invocation で直接呼んだときだけ使うようにしたスキルもある。
  • プラグインの順位は別にある。公式ディレクトリ上位のプラグインとその構成は2026年下半期の人気プラグインにまとめた。

事実確認ノート

skills.sh のインストール数と総合点(Worth-Installing Score)・直近7日の成長率・ソーシャルでの言及順位は、LinklyAI のオープンデータ best-skills(CC BY 4.0)の 2026-10-22(UTC)スナップショットの CSV を直接取得して移した。リポジトリ単位の集計の限界と点数の構成(人気0.30・成長0.15・評判0.20・保守0.15・信頼0.20、セキュリティ検査なし)は同じリポジトリの方法論の文書による。skills.sh のサイトは本記事を書いた環境から開けず、元のサイトの数値と直接照合はできなかった。公式 Claude プラグインディレクトリのインストール数(frontend-design 1,134,112・Superpowers 1,009,371)は 2026-10-23(KST)の claude.com/plugins ページのデータから読んだ。各スキルの動作・コマンド・ルールは、該当する GitHub リポジトリ(vercel-labs/skills、mattpocock/skills、vercel-labs/agent-browser、heygen-com/hyperframes、anthropics/skills、obra/superpowers、vercel-labs/agent-skills)を取得し、SKILL.md と README の原文を直接読んで整理した。「200〜400トークン」と「二時間ほど一人で働く」はそれぞれ元の文書自身の説明だ。カード画像は原文のフロントマターを変えずにこのウィキがレンダーしたもので(長い説明は…で省略)、ロゴ・アイコンと録画の例は各リポジトリにコミットされたファイルをライセンスに従って載せた。リポジトリ作者の個人名は書かず、リポジトリ名で示した。
