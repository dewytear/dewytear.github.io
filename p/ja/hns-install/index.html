実行する — 導入・実行・レビュー

ハーネスを毎回手で組む（エージェントやスキルをいちいち用意する）のは面倒です。そこで講師は目標を渡すだけでハーネスを代わりに組んでくれる「メタハーネス」スキルを開発して GitHub に公開し、多くの使用レポートとスターを集めました。今日の実習は、このスキルを入れるところから始めます。

方法 1 — コマンド 2 行

# 1) ハーネスのマーケットプレイスを追加
/plugin marketplace add lev-factory/harness
# 2) ハーネスプラグインをインストール
/plugin install harness

方法 2 — /plugin の UI

  1. /plugin と入力 → 方向キーの右で移動して Marketplace タブを選ぶ。
  2. Add Marketplace で lev-factory/harness を入力 → Enter（GitHub からダウンロード）。
  3. プラグインのインストール画面で Enter → User スコープで入れると、どのプロジェクトでも使えます。

インストール後 — リロードして確認

インストールが終わると「リロードせよ」という案内が出ます。/reload（プラグインのリロード）のあと /harness が出れば、正常にインストールされています。

/reload
# 下が補完・実行できればインストール成功
/harness
マーケットプレイスのパスを確認 マーケットプレイスのハンドル（lev-factory/harness）は発表で言及された値を写したものなので、実際に入れるときは講師の GitHub（例:「ハーネス 100」で検索）で正確なリポジトリのパスを確認してください。プラグインのインストールがうまくいかないときは、UI の方法とコマンドの方法を交互に試します。

ハーネスを実行する（実習）

意図を渡すだけでチームが組まれ、人がレビュー・承認したあとの実行は手を離れます。

入れた /harness で実際に仕事をさせてみます。核心的な違いは「意図だけを渡す」という点です。

「作成して」ではなく「作成したいと思っています」

ふつう AI には「レポートを作成して」と指示します。しかしハーネスには意図だけを言います。すると、その意図を解決してくれるエージェントチームを組んでくれます。

/harness 2026 年の国家科学技術の全分野にわたる戦略技術の予算配分と、
ポスト PBS への対応戦略について調査し、レポートを作成したいと思っています。
  • /harness と入力して Tab で補完したあと、依頼を続けて書きます。
  • 実行するとドメイン分析 → チーム編成が進みます。
  • 途中で「ハーネスをフル構築 / ハーネスだけ構築」のような選択を尋ねてきます。
  • 自分のデータがあれば一緒に渡して尋ねられます。（例: 1000 ページを超える PDF の分析もきちんと処理）

構成の完了 → レビュー → 実行

ハーネスの構成が完了すると、いったん止まります。作られたエージェントたちをレビューし、問題がなければ実行します。

# レビューのあと、そのまま進行の指示
進めて

この瞬間、作業は人の手を離れ、エージェントチームがリサーチ → レポート作成 → QA をオーケストレーターの立てた順序どおりに最後まで進めます。

並列でいくつもの作業

  • ひとつの作業を回しておいて、別のターミナル窓を開いてまた別の仕事をさせられます。（例:「KOSPI は 1 万まで行けるか？」の調査）
  • 実務の開発者の席では、こうしてターミナルがいくつも開いていて、別々の仕事を同時にしています。
  • Shift + 方向キーで、いまスポーンされているエージェントが何をしているかを見られます。（色の付いたエージェントが作業中）
何に使うのか データ分析、リサーチ、レポート作成、シミュレーションなど — 何であれ意図を渡せば、その仕事をするエージェントチームを組んでくれます。

生成結果のレビュー — エージェント・スキル・オーケストレーター

オーケストレーターがエージェントたちを整え、スキルが注入され、成果物は _workspace に集まります。

ハーネスが組まれると何が作られるのかを見ていきます。Claude Code はエージェントやスキルなどを.claude フォルダの下に生成します。

作られたエージェント（例）

「国家 R&D 予算・ポスト PBS」という課題では、こんなチームが組まれました。

  • R&D 予算の定量分析担当 — 予算の配分・調整案を省庁・事業・年度の単位に分解し、政府／出資機関の比率の変化を追跡。
  • 政府出資機関のガバナンス・財政の専門家 — PBS から任務中心型の体制への転換戦略を導く。
  • 国家 R&D 政策のリサーチャー — 予算・政策文書・報道資料・NIS/NSTC の議題などを一次情報から調査。
  • レポート執筆エージェント — 前段の成果物を集めてレポートに書き上げる。
  • QA レビュアー — 単なる誤字脱字ではなく主張と出典の整合、数値の一貫性、提言の論理のつながりを突き合わせて確認。

注入されるスキル

エージェントだけでは足りないので、専門化したスキルを作って注入します。例: 予算の定量分析の手法（標準の様式・計算のルール・チェックリスト）、政策レポートの引用検証（検証の軸・優先順位）、政府向け政策レポートの書式（目次）。

オーケストレーター（つねに 1 つ）

エージェントたちが横道へそれないように整える PM の役割です。細かい作業をのぞき込むことはせず、「エージェントたちがうまく働いているか」だけを見ます。Phase 0 から各段階に必要なエージェントが何かまで、ワークフローが事前に計画されています。（Claude Code のプランモードに近い感覚）

レビューと実行の準備

  • レビューの工程は必須です。「エージェントをもっと追加」「意図と合わないので修正」「ハーネスを直して」のようにフィードバックすれば、エージェント／スキルが新しく生まれたり補強されたりします。
  • エージェントが動的にロードされない問題があります。/agents に見えないときは /exit してから入り直すとロードされます。
_workspace フォルダ ハーネスで実行すると _workspace フォルダができて、エージェントたちが作った中間の成果物が集まります — 一次リサーチ、予算分析、QA レポート（クリティカル・メジャー・マイナーの各課題）と修正案、限界事項、そして根拠となる出典まで。出典ベースなのでハルシネーションが大きく減ります。

回してみたら、今度は中を覗く番です — 動作原理の章が厨房のたとえから始めて、エージェントチームと中核の三要素の構造を解きます。
