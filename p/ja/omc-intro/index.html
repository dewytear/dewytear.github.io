OMC — 紹介とインストール

oh-my-claudecode（以下 OMC）は、Claude Code に自律実行・マルチエージェント協業・自動検証の機能を足してくれるプラグインです。

OMC は Claude Code に自律実行・マルチエージェント・自動検証をコマンド一行で足します。

三つの概念

  • Claude Code とは — ターミナルや IDE から Claude にコーディングの作業を任せる CLI ツールです。ファイルを読んで修正し、コマンドを実行して開発を助けます。
  • プラグインとは — Claude Code に新しい機能を足す拡張パックです。いちど入れれば専用のコマンドと動作が追加されます。
  • OMC が足すもの — 「最後まで自分で実装」「複数の作業者で分担」「作業後の自動検証」といった高度な進め方を、コマンド一行で使えるようにしてくれます。

この文書は、ローカル環境に実際にインストールして一部を検証し、公式ドキュメント・リリースノート・プラグインの文書と突き合わせて作成した要約です。Windows PowerShell、WSL2、macOS、Linux によって一部のコマンドと動作が変わりうるので、環境に依存する項目は分けて表示しました。基準のバージョンは v4.15.2（2026-07-05 時点で確認）です。リリースが月に 3〜5 回と多めなので、細かい動作は読んでいる時点の最新のリリースノートと違うことがあります。

用語のポイント

OMC の文書には次の用語がよく出てきます。先に理解しておくと、以降の内容がぐっと読みやすくなります。

  • スラッシュコマンド — Claude Code の入力欄で / から始める特別なコマンドです。普通の会話ではなく、決められた機能をすぐ実行します。例: /plugin install ...
  • ネームスペース — コマンドの前にプラグイン名が付く形式です。ほかのプラグインと名前がぶつからないようにしてくれます。例: /oh-my-claudecode:autopilot
  • エージェント（Agent） — 特定の役割を負った AI の作業者です。探索・実装・検証のように役割が分かれているので、大きな作業を分担させられます。例: explore、executor、qa-tester
  • スキル（Skill） — ひとつの作業をこなす機能の単位です。自律実行やくり返し実行といった動作がスキルとして提供されます。例: autopilot、ralph、skillify
  • Hook（フック） — 決められた時点（例: ファイル修正の前後）に自動で割り込んで実行される動作です。キーワードの検知や完了の検証などに使われます。例: PreToolUse、PostToolUse
  • プロジェクトメモリ — AI がプロジェクトの構造を覚えていられるように整理しておいた文書です。毎回ゼロから探索するコストを減らします。例: deepinit、AGENTS.md

インストール

インストールの経路は三つに分かれます。一般の利用者はプラグインのマーケットプレイス方式を優先すれば大丈夫です。

「どう入れる?」からマーケットプレイス（推奨）・--local・npm CLI の三つに分かれます。

1）推奨 — プラグインのマーケットプレイス

Claude Code の中でマーケットプレイスを追加してから OMC プラグインを入れます。入力欄で下の 2 行を順に実行します。2 行をまとめて貼り付けると失敗するので、必ず 1 行ずつ実行してください（公式 README に明記）。

# ステップ 1: プラグインのリポジトリ（マーケットプレイス）を登録
/plugin marketplace add https://github.com/Yeachan-Heo/oh-my-claudecode
# ステップ 2: 登録したリポジトリから OMC プラグインをインストール
/plugin install oh-my-claudecode

2）プロジェクトの設定（--local を推奨）

インストール後はプロジェクト単位の設定をおすすめします。--local を付ければ既存のグローバルな CLAUDE.md を上書きしないので安全です。

# いまのプロジェクトにだけ OMC の設定を適用 — グローバル設定はそのまま保存
/oh-my-claudecode:omc-setup --local

グローバルな設定がどうしても必要なときだけ下のコマンドを使います。ただし、既存の ~/.claude/CLAUDE.md に影響が出ないかを先に確認してください。

# すべてのプロジェクトに共通で適用 — 既存のグローバル CLAUDE.md への影響を要確認
/oh-my-claudecode:omc-setup
会社の開発 PC・共用プロジェクトでの推奨 グローバルな設定よりプロジェクトローカルの設定（--local）を優先することをおすすめします。プロジェクトごとにルールが違うとき、グローバルな CLAUDE.md が混ざるのを防げます。

3）npm でのインストール — CLI/runtime 用途の公式な別経路

一般の利用者は上のプラグイン方式で十分ですが、npm でのインストールも公式に対応した別の経路です。ただし用途が違います。プラグインのインストールは Claude Code のセッション内でスラッシュコマンド（/autopilot など）を使うためのもので、npm のインストールはターミナルで omc CLI のコマンド（omc doctor、omc team、omc ask など）を使うためのものです。

# ターミナル CLI(omc コマンド)が必要なときだけ — npm のパッケージ名は oh-my-claude-sisyphus
npm i -g oh-my-claude-sisyphus@latest

注意すべきなのはnpm のパッケージ名がリポジトリ名と違うことです。プロジェクトのブランドは oh-my-claudecode ですが、npm に公開されたパッケージ名は oh-my-claude-sisyphus です。インストールすると oh-my-claudecode と omc のふたつのコマンドが一緒に登録されます。インストール中に deprecated prebuild-install の警告が見えることがありますが、上位の依存に由来する既知の警告で、インストールの失敗を意味しません。curl スクリプトによるインストールは公式ドキュメントにないので使いません。

インストール・アップデート プラグイン方式を使う場合、インストールとアップデートは Claude Code のプラグイン管理の機能で処理します。マーケットプレイスの自動更新がオフなら、/plugin marketplace update omc でまず最新版に同期してから、/oh-my-claudecode:omc-setup をもう一度実行して最新の設定を適用してください。

インストールの診断

インストール後に問題が起きたら、まず診断のコマンドで状態を確認します。

プラグインの環境では下のコマンドを優先して使います。

# インストール・設定の状態を点検し、問題を知らせてくれる（問題解決の第一歩）
/oh-my-claudecode:omc-doctor

CLI ランタイムの経路を別に使っている場合は、次の診断もできます。

# CLI ランタイムの経路で診断
omc doctor
# プラグインのインストール先を直接指定して診断
omc doctor --plugin-dir /path/to/oh-my-claudecode

インストールと診断まで済んだら本題です — 実行モードで OMC の中核であるモード体系を身につけ、エージェント・スキルと Hook・メモリへ進んでください。
