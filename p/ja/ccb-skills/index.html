拡張 — スキル・プラグイン・エージェント

スキルは、一度以上くり返す作業を保存しておいて再利用しつづけるための機能の単位です。さきほど作ったデザインシステムをスキルにすれば、以後いくつものサイトを同じデザインで簡単に量産できます。

@（アットマーク）— ファイル・フォルダの参照

既存のファイルを参考にして作業させたいときは @ を入力します。@ を打つとファイル選択の一覧が出るので、目当てのファイルを選んで Tab で確定します。

# デザインシステムのファイルを参照してスキルにする
@design-system_new.html このデザインシステムを "my-design" スキルにして。

@ のあとのファイル／フォルダは「この内容を参考にして作業する」という意味です。ファイルだけでなくフォルダも指定できます。

権限の確認

作業中に特定のフォルダへ何かをしようとするとき、権限をたずねる選択肢が出ます。

  • 1 番 — 今回だけ許可。
  • 2 番 — 同じ作業はもう聞かない。

スキルが保存される場所

  • プロジェクト専用 — プロジェクト配下の .claude/skills/ に生成（そのプロジェクトだけ）。
  • グローバル — ユーザーフォルダ配下の ~/.claude/skills/（Windows は Users\ユーザー\.claude\skills）。どのフォルダで実行しても使えます。

スキルができると ~/.claude/skills/my-design/ の下にその内容（例: Apple トーンのホワイトなデザインシステム）が記録されます。

スキルでもう一度サイトを作る

@papers_new.md この論文の内容をもとに、my-design スキルを使って
同じデザインで論文紹介のウェブサイトを作って。

こうすると、さきほど作った Mythos のサイトと同じデザインの論文紹介サイトができあがります。

もっと多くのスキル スキルの作り方はだいたい同じです。たとえば OpenAI の GPT Image 2 の開発者ドキュメントの URL を渡して「この内容で GPT イメージのスキルにして」と言えば、インフォグラフィック生成のスキルになります。HWP のように公式にない形式も、自分でスキルにして再利用できます。

プラグイン・マーケットプレイス

複数のスキルをまとめてプラグインの形で配布できます。論文はたいてい PDF なので、PDF をうまく読むスキルの入った公式のドキュメントスキル（document-skills）プラグインを入れてみます。

1）マーケットプレイスの追加

Claude Code で /plugin と入力して Enter を押すと、プラグインの画面が出ます。矢印キーでマーケットプレイスを選び → Add Marketplace で Anthropic 公式のマーケットプレイスを追加します。

# GitHub への接続が塞がれていたり UI が難しいときは、コマンドで直接実行
/plugin marketplace add anthropics/skills

2）document-skills のインストール

追加したマーケットプレイス（Anthropic 公式）にはプラグインがいくつかありますが、そのうち document-skills だけを入れます。一覧で Space で選び、Enter でインストールします。コマンドでもできます。

/plugin install document-skills

このスキルは PDF・PPT（pptx）・エクセルといった文書を Claude Code で読めるようにしてくれます。

3）再起動して確認

インストール後にうまく反映されないときは、/exit で Claude Code を出てから再起動します。そのうえで /pdf または /pptx と入力してコマンドが出ればインストール成功です。出なければマーケットプレイスの追加とインストールをやり直します。

インストールで詰まったとき（GitHub のエラーなど） Google で 「anthropic skills github」と検索して公式リポジトリに入ると、README の途中にインストールのコマンドがあります。plugin marketplace add ... の一行と plugin install document-skills の一行をそれぞれコピーして Claude Code に貼り付けて実行すれば大丈夫です。

エージェント（Agent）を作る

エージェントは特定の役割を負った専門の作業者です。スキルを作るのと同じくらい簡単です — アイデアさえあれば、あとは AI が書いてくれます。ここでは論文分析エージェントを作って、ダウンロードした PDF を分析します。

1）PDF を用意

# 論文の詳細ページの URL を渡して
https://arxiv.org/abs/....  この論文の PDF ファイルをダウンロードして。

Claude Code が arXiv から PDF リンクを見つけて、いまのフォルダに落とします。（PDF の読み取りは、さきほど入れた document-skills が担当します。）

2）エージェントの生成

このプロジェクト限定で作るなら、.claude/ の下に作るよう指定します。

.claude の下に、論文を分析するエージェントを追加して。

生成されたエージェントには、次のようなメタ情報が入ります。

  • 名前・説明（description） — このエージェントが何をするのか。
  • 使えるツールの権限 — ファイルの読み取り、Bash コマンドの実行など。
  • モデルの指定 — エージェントごとに使うモデルを選ぶ（例: いちばん良い opus）。
  • ペルソナ・原則 — 例:「学術論文の分析の専門家」「5 分で要点をつかめるレポートを生成」。

分析のやり方（要旨中心／限界点中心／検証を強めるなど）は、追加の依頼で高度化できます。

3）一覧の確認・実行

エージェントは作った直後にすぐ読み込まれないことがあります。/agents でいまのフォルダで使えるエージェントを確認し、見えなければ /exit して再起動します。

# PDF を参照に付けて、作ったエージェントで分析
@paper.pdf  paper-analyzer エージェントを使ってこの論文を分析して。

4）並列分析 — Claude Code の真価

ひとつのオーケストレーターが複数のエージェントを並列に立ち上げ、同時に分析してから取りまとめます。

リンクが分かっている残りの論文も一度に分析できます。

残りの論文も分析してファイルに保存して。

Claude Code はエージェントを複数、並列にスポーンして（例: 12 本の論文を 5〜6 個のエージェントで）同時に分析します。これはウェブのチャットではできないことです。分析の結果は、さきほど作った論文紹介サイトの詳細ページにしてつなぐこともできます。

エージェントを使うもうひとつの理由 — コンテキストの節約 エージェントはメインのセッションとは別のコンテキストウィンドウを使います。重い分析はエージェントに任せて結果だけ受け取れば、メインセッションのコンテキストをほとんど使わずに済み、品質を長く保てます。（次の文書を参照）

作れるものはひと通り作ったので、残るのは長く使う方法です — 運用の章で使用量・コンテキスト・セッション管理と締めのコツを整理します。
