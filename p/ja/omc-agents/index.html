エージェント・スキルと Hook・メモリ

OMC の核心は委任（delegation）です。メインの Claude が指揮者の役割を負い、役割の決まった専門のエージェントたちへ作業を分けて任せます。各エージェントは作業の難しさに合うモデルへ自動で割り当てられ（設計・分析には高性能なモデル、単純な参照には軽量なモデル）、ひとりで全部こなすより正確で速くなります。

エージェントは役割に応じて大きく四つのグループに分かれます。以下はグループごとの主なエージェントと、それぞれがやることです。

メインの Claude が指揮者として、役割の決まった専門エージェントのグループへ作業を分けて任せます。

探索・分析

  • explore — コードベースをざっと見て、作業に関係するファイルと構造を見つけ出します。
  • analyst — コードや要件を分析して、要点と論点を整理します。
  • architect — 全体の構造と設計の方向を定め、結果が設計に合っているかを検証します。
  • planner — 作業を実行できる段階に分けて計画を立てます。
  • critic — 計画や結果を批判的に見直し、抜けと危険を探します。
  • tracer — バグや障害の原因を、コードの流れをたどって追跡します。

実装・修正

  • executor — 計画に従って実際のコードを書き、直します。作業の難しさに応じて軽量・標準・高性能の段階に分かれます。
  • debugger — バグの原因を見つけて直します。
  • code-simplifier — 複雑に絡んだコードを、より単純で読みやすく整えます（リファクタリング）。

検証・品質

  • qa-tester — 機能が意図どおりに動くかテストし、完了の根拠を集めます。
  • test-engineer — 自動テストのコードを書き、構成します。
  • code-reviewer — コードの品質とスタイルを見ます。
  • security-reviewer — セキュリティの脆弱性を点検します。

文書・デザイン・データ

  • writer — 文書と説明の文章を書きます。
  • document-specialist — 外部のライブラリ・API のドキュメントを探して確認し、整理します。
  • designer — 画面の UI/UX のデザインを扱います。
  • vision — 画面のキャプチャや図のような画像を分析します。
  • scientist — データを分析します。
  • git-master — ブランチ・コミット・マージなど Git の作業を処理します。
ひと言でいうと 自分でエージェントを選ぶ必要はありません。autopilot のようなモードが作業の意図をつかんで必要なエージェントを勝手に配置するので、たいていは「何をするか」だけ言えば大丈夫です。

skillify — くり返し作業をスキルにする

/oh-my-claudecode:skillify は、ひとつのセッションで効果的だった作業のパターンを、再利用できるスキルとして抜き出すコマンドです。よくくり返す流れをいちど整理しておけば、次の作業ですぐ呼び出して使えます。かつての名称である learner は deprecated（サポート終了予定）の互換エイリアスなので、新しい文書・教育では skillify を使ってください。

# セッションで効果的だったパターンを再利用スキルとして抽出
/oh-my-claudecode:skillify

Hook・メモリ

OMC は Claude Code の Hook イベントを活かして、キーワードの検知、スキルの注入、状態の復元、完了の検証を処理します。最新の Reference では Hook イベントはさらに細分化されています。

知っておくこと

  • autopilot・ralph・ultrawork・ultraqa は Hook ではなくスキルです。keyword-detector がこれらを有効にし、persistent-mode の Hook が継続実行を助けます。
  • Hook を全部オフにするには DISABLE_OMC、特定の Hook だけ外すには OMC_SKIP_HOOKS を使います。
  • Windows の Native Hook は v4.14.4 以降に改善され、そのまま使えます。tmux が必要な一部の機能も、現行の公式 README では psmux（ネイティブ Windows 向けの tmux 互換ツール）を使えば WSL なしで動き、WSL2 は代替の経路です。
# OMC のすべての Hook を一度に無効化
export DISABLE_OMC=1
# 指定した Hook だけ除外（残りは正常に動作）
export OMC_SKIP_HOOKS=PreToolUse,PostToolUse

Hook が走るタイミング

Hook は Claude Code の特定のイベントごとに自動で割り込んで実行される動作です。OMC はこれを通じてコンテキストを注入し、スキルを自動でオンにします。主なタイミングは四つです。

セッションが始まるとき、プロンプトを出すとき、ツールの直前・直後ごとに Hook が自動で割り込みます。
  • SessionStart — セッションが始まるとき。OMC の初期化、notepad・project-memory の読み込み、直前の実行モードの状態の復元。
  • UserPromptSubmit — プロンプトを送るとき。マジックキーワードの検知、ふさわしいスキルの自動接続、コンテキストの注入。
  • PreToolUse — ツールを使う直前。並列で読むことを勧めるヒント、関連ファイルの事前読み込みの提案。
  • PostToolUse — ツールを使った直後。結果の検証、次の手の提案、エラーを検知したときの自動修正の提案。

会話中に見えるメッセージの読み方

作業中に system-reminder の形のメッセージが見えることがあります。慌てず、下のように理解すれば大丈夫です。

メッセージ意味
hook success: Success正常に動いているという表示です。そのまま進めて大丈夫です。
hook additional context: ...役に立つヒントです。参考にして取り入れるとよいです。
[MAGIC KEYWORD: ralph detected]そのモード（ここでは ralph）が自動でオンになったという知らせです。
The boulder never stops rollingralph・ultrawork が実行しつづけているという表示です。

メモリとプロジェクトの文書化

OMC は作業の文脈をセッションをまたいでも保つために、三つの仕組みを用意しています。それぞれ保存の場所と役割が違います。

  • deepinit — コードベース全体をざっと見て、ディレクトリごとに AGENTS.md の文書を作ってくれます。各フォルダが何を収めているのか、ファイルどうしの関係、作業時の注意点、依存関係を整理しておくので、AI が毎回ゼロから構造を探索しなくて済みます。大規模なプロジェクトの事前整理に役立ちます。
  • notepad — .omc/notepad.md に保存される作業メモです。会話が長くなって文脈が整理（圧縮）されても生き残ります。絶対に失ってはいけない情報（priority）、いま進行中の作業の状態（working）、手で記録するメモ（manual）の三段階に分かれ、古い項目の整理は notepad_prune のツールで処理します。
  • project memory — .omc/project-memory.json に保存され、プロジェクトの技術スタック・コーディング規約・アーキテクチャの指針を覚えます。既定値は omc-setup で設定します。
# コードベースを分析してディレクトリごとに AGENTS.md を生成（[path] を省くと現在のパス）
/oh-my-claudecode:deepinit [path]

構成要素を押さえたら、実戦での組み合わせは高度な活用の章で — ツール・シナリオ別ワークフロー・Windows の注意点を見ます。
