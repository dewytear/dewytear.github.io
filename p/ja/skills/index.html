拡張機能 — Skills · MCP · Hooks

Claude Code は素のままでも十分に働きますが、チームとプロジェクトに合わせて育てはじめた瞬間から本領が出ます。拡張の通り道は三つ。繰り返すノウハウをパッケージにまとめるスキル、外部システムへ手を伸ばす MCP サーバー、決まった時点で必ず実行されるフック — 三つは性格が違うので互いの代わりにはならず、組み合わせたときにいちばん噛み合います。

Skills — 再利用できる能力

スキル（Skill）は、特定の作業のための専門知識とワークフローを Claude Code に与える、再利用可能なパッケージ形式の能力です。指示文（必要ならスクリプトやリソースまで）をひとまとめにしておくと、依頼がそのスキルの用途に合ったときに Claude が必要な分だけ読み込んで使います。 スキルは通常のスラッシュコマンドと同じく / のあとにスキル名を打って直接呼び出せますし、Claude Code が作業を見分けて関連スキルを自動的に発動することもあります。スキルにできることの例:

  • 現在の diff に対する構造化されたコードレビューの実行
  • 複数の情報源をあたる深いリサーチと、出典つきレポートの作成
  • フック・キーバインド・設定の設計と構成
  • 一貫したデザインシステムに従うデータ可視化の作成
細かなノウハウが毎回打つメッセージではなくスキルの中に住むので、プロンプトは短くなり、結果は一貫します。Claude Code に標準搭載されたスキルを使うことも、プラグインとして入れることも、自分でつくることもできます。

MCP サーバー — 外の世界とつながる

MCP（Model Context Protocol）は、AI アシスタントを外部のツールやデータソースとつなぐための開かれた標準です。Claude Code に MCP サーバーをつなぐと、ローカルファイルの外にまで手が届くようになります — データベース、イシュートラッカー、クラウドサービス、ブラウザなど。 MCP サーバーが接続されると、そのサーバーのツールが組み込みツールとまったく同じように Claude Code から使えるようになります。たとえば適切なサーバーが構成されていれば、Claude は:

  • GitHub のイシューや PR を読み、作成できます。
  • データベースや社内 API に問い合わせできます。
  • メール・カレンダー・ドキュメントを検索できます。
  • ヘッドレスブラウザを操作してウェブページをテストできます。
サーバーの管理は claude mcp コマンド（add、list、remove）か設定ファイルで行います。各サーバーは自分が公開するツールを宣言し、Claude Code はルールに触れる操作だけを止めます — 2026年8月14日からauto モードが既定値になり、毎回許可を求める代わりに、あらかじめ書いた拒否ルールと安全チェックが判断を担います（尋ねない既定値）。外部システムに触れる範囲は、そのルールと設定で握ります。

Hooks — 毎回実行される自動化

フック（Hook）は、Claude Code がライフサイクルの特定の時点ごとに自動で実行する、ユーザー定義のシェルコマンドです。ルールを強制し、動作を決定論的に自動化できます — ハーネスが直接実行するので、Claude が覚えていたときだけでなく毎回実行されます。 フックは settings.json で設定し、次のようなイベントに結びつきます:

  • PreToolUse — ツール実行の直前（例: 保護対象ファイルの変更をブロック）
  • PostToolUse — ツール実行の直後（例: 直前に直したファイルを自動フォーマット・リント）
  • SessionStart — セッションが始まるとき（例: テストが走るように依存関係をインストール）
  • Stop — Claude が応答を終えたとき（例: 通知の送信）
代表的な使い道は、修正のたびにフォーマッターを走らせる、コミット前にテストスイートを実行する、機微なパスを保護する、長い作業が終わったらデスクトップ通知を送る、などです。フックは結局ただのシェルコマンドなので、プロジェクトがすでに使っているどんなツールとも Claude Code をつなげられます。 スキルができることを、MCP が届く先を広げるなら、フックは守られるルールをつくります。三つをどう組み合わせるかは、Claude Code チュートリアルで手を動かしながら身につけられます。
