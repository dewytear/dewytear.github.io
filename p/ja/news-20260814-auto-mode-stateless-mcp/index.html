尋ねない既定値 — autoモードとMCPのステートレス化

今日（8月14日）から、Claude Code の新しいセッションは auto モードで始まります。毎回「このコマンドを実行しますか」と尋ねていた許可プロンプトが、既定の動きから外れました。その二週間前、エージェントがツールをつなぐ標準である MCP は、セッションという概念そのものをプロトコルから取り除きました。片方は人のクリックを、もう片方は接続の記憶を外したわけですが、空いた場所を埋めたのはどちらもあらかじめ書いておいたルールです。この記事では二つの変更の中身を整理し、なぜこれが一つの話なのかを見ます。

記事情報（出典） · 対象: Anthropic の auto モード既定化の告知（2026-08-08 発表 · 08-14 適用） · MCP 2026-07-28 仕様のリリース候補
· 整理: 公式発表・仕様文書 + 複数報道の突き合わせ（2026-08-14）— 文末に出典一覧とファクトチェックのメモ

三行まとめ

  • Claude Code の Pro・Max・Team の新規セッションが auto モードを既定値として使います。取り消せない操作、破壊的な操作、作業環境の外に向かう操作だけを止め、残りは尋ねずに進みます。
  • 根拠として出された数字が痛いところを突きます。Anthropic の調査で利用者は許可プロンプトの 97% を承認しており、実験でこっそり混ぜた危険なコマンドを 人は 13.6% しか拒否できませんでした。同じコマンドを auto モードの分類器は 89% 阻止しました。承認ボタンはすでに安全装置として働いていなかった、という話です。
  • MCP は initialize ハンドシェイクと Mcp-Session-Id を削除しました。プロトコルのバージョンとクライアントの能力は、これからは毎リクエストの _meta に載って運ばれます。どのリクエストもどのサーバーインスタンスが受けてよくなった一方、双方向で互換が切れる変更なので、既存のサーバーには作り直しが要ります。

承認ループはすでに壊れていた

変更そのものより、変更を正当化するために公開された数字のほうが目を引きます。Anthropic が明かした利用実態はこうです。

  • 利用者は許可プロンプトの 97% を承認します。同社はこれを判断ではなく反射的なクリックと読みました。
  • CLI のアクティブ利用者の 49.5% が Bash の許可ルールを自分で作っており、62% は bypassPermissions や「次から尋ねない」を使ったことがあります。対話セッションの 4分の1 は、最初から bypass の状態で始まります。

そこで実験をしました。有料で募った専門テスター 1,053人 をテスト用のコーディング環境に入れ、セッションの途中でありふれた許可プロンプトを一つ、誰が見ても危険なコマンドにすり替えます。承認してもコマンドが実際に走ることはなく、記録したのは参加者が気づいて拒否したかどうかだけです。結果は 143人、13.6%。六人のうち五人は危険なコマンドをそのまま通しました。

同じコマンドを auto モードの分類器にかけると、1,053件のうち937件、89% が止まりました。裏返せば 116件、およそ11% は通ったということで、この数字を見出しにして「11%も見逃すのに既定値にするのか」と指摘した報道もあります。指摘そのものは妥当です。ただ、比較の相手が無欠の人間ではなく 13.6% の人間だという点が、この判断の論拠になっています。

では何が守るのか — クリックの代わりにルール

許可プロンプトを外した場所には、三つの層が入りました。

  • ハードデナイ（hard deny） — 文脈を問わず無条件に止めるルールです。データを外に持ち出す操作が代表例で、秘密情報と公開データを区別して判定します。利用者や企業の管理者が範囲を追加できます。
  • 操作の直前の状態確認 — git reset --hard のような破壊的コマンドの前には、git の状態とリポジトリが公開かどうかをまず見ます。同じコマンドでも、コミットしていない変更が溜まっていれば判断が変わります。
  • プロンプトインジェクションの検査 — ファイルやウェブから読み込んだ内容に「これからはこうしろ」といった指示が紛れていないか、ツールの結果をプローブが走査します。さらに別の分類器が、やろうとしている操作が利用者の意図と合っているかを見ます。

いまも人に上がってくるものはあります。取り消せない、破壊的、あるいは Claude が動いている環境の外に向かう操作です。このとき Claude はまず安全な迂回路を探し、見つからなければそこで許可を求めます。逆に、既存の許可ルールのうち広すぎるもの、たとえば制限のない python・node の実行などは auto モードでは無視されます。そうしたルールが生きていると、何でも分類器を迂回して実行できてしまうからです。

ゲートが消えたのではない。その場のクリックから、先に書いておいたルールへ移った。

攻撃側の評価も一緒に出ています。独立評価機関の Trajectory Labs が 72通りの間接プロンプトインジェクションのシナリオを各10回、モデルあたり720回 試み、auto モードで動かした Fable 5・Opus 5・Sonnet 5 では 成功した攻撃が一つもなかったと報告しました。社内運用で実際に止まった例としては、ネットワーク外へのデータ流出、破壊的な大量操作、権限昇格の三件が公開され、いずれも Claude が自分で安全な経路を見つけるか、利用者に確認を取っています。

同じ週、MCPはセッションを捨てた

MCP（Model Context Protocol）は、エージェントが外部のツールやデータにつながる方法を定めた標準です。この wiki の MCP 講義が扱っているその規約で、2026-07-28 のリリース候補は公開以来もっとも大きな改訂です。核心は一文で足ります — プロトコルの層から状態をなくした。

  • ハンドシェイクの削除 — 接続を開くときに一度だけやり取りしていた initialize/initialized がなくなりました。プロトコルのバージョン・クライアント情報・クライアントの能力は、すべてのリクエストの _meta に載ります。サーバーの能力を先に知りたいときは、新設の server/discover で必要なときに取得します。
  • セッション識別子の削除 — Mcp-Session-Id ヘッダーと、それに付いていたプロトコル水準のセッションが一緒に消えました。二つが消えたことで、どのリクエストもどのサーバーインスタンスに届いてかまいません。台数を増やすために必要だった固定ルーティングや共有セッションストアが、規約の水準では要らなくなります。
  • 状態が要るなら表に出して渡す — 呼び出しをまたいで続く状態は、サーバーが発行したハンドルを普通のツール引数としてやり取りします。隠れていた状態が引数に上がってきた形です。
  • 薄いコア + 拡張 — 残りはリクエストごとに交渉する任意の拡張に回りました。いまの公式拡張は Tasks・MCP Apps・企業向け管理型の認可の三つで、認可まわりは OAuth の取り違え攻撃に弱かった部分が手直しされています。
接続が持っていた記憶がリクエストの中に降りてきた。代わりに一回ごとが重くなる。

反応は割れました。「結局 REST を作り直しただけではないか」という側と、そもそも標準を一つに揃えたこと自体が要点だったという側です。前者の冷めた見方には実務上の利点が付いてきます — ロードバランサー、API ゲートウェイ、段階的な展開など、REST 向けにすでに用意した仕組みをそのまま使えます。代償ははっきりしています。この変更は双方向でワイヤ互換が壊れるので、既存のサーバーはバージョンを上げるだけでは済まず、実際に直さなければなりません。認証や再開の問題を自前の拡張で解決済みのチームなら、より良い規約でもそれを外すのに時間がかかります。

なぜこれが一つの話なのか

二つの変更は別々の会社の、別々の層で起きましたが、外したものは同じです。実行時に握られていた固定点です。auto モードが外したのは、その都度人が文脈を見て下していた判定であり、MCP が外したのは、接続が勝手に抱えていた記憶です。どちらも、あるうちは楽でも回数が増えるほど高くつく種類でした。人の承認はエージェントが一日に何百回も動いた瞬間に反射的なクリックになり、セッションはサーバーを何台かに増やした瞬間に固定ルーティングという荷物になります。

代わりに入ったものも性格が同じです。ハードデナイのルールは「何を絶対にしないか」を、事が起きる前に書いておいた文書です。_meta は逆の向きで、毎回のリクエストが自分は誰で何ができるかを載せて運ぶほうです。先に書いておくか、毎回持って行くか — どちらにせよ判定の根拠が、その場の人と接続から宣言されたルールとデータへ移りました。

実務でこれが何を意味するかは、かなり具体的です。CLAUDE.md と設定ファイルの拒否ルールが、これまでは好みに近かったとすれば、これからは実際に執行される方針になります。広く開けておいた許可ルールは便利さではなく無視の対象になり、狭く書いた拒否ルールは人が席を外している間も働き続けます。この wiki が 「ハーネスでは足りない」でまとめた結論と同じ向きです — ハーネスの値打ちは指示の厚みではなく、検証と境界がどれだけ明確かにあります。

もちろんこの方向には値が付きます。先に書いておいたルールは、書いた分だけ守ります。89% という数字がその限界で、残りの 11% はルールになかった形の危険でした。セッションをなくした MCP も状態をなくしたのではなく、表に出して引数へ移したので、そのハンドルを誰が発行していつ失効させるのかが新しい宿題になります。隠れていた問題が見える場所に出てきた、というほうが正確です。

この wiki で直したところ

この変更で古くなった記述が二か所あり、あわせて直しました。

  • ツールの拡張と締めくくりの Q&A で、オートモードを「権限を毎回たずねないのでより自律的に動く」とだけ説明していました。既定値になったことと、ハードデナイ・インジェクション検査を書き足しました。
  • MCP 講義の最後の一文「Claude Code は使用の前に許可を求めます」は、8月14日から事実と合いません。ルールに触れる操作だけを止める、という形に直しました。
