動作の構造と 6 ステップ

進めて を押したあと、ハーネスの内部で何が起きているのかをのぞいてみます。大きくは6 ステップでチームを組み、そのあと運用のループを回します。

プラグインの 6 ステップ — チームを作る過程

ここまでが「チーム作り」。⑥ の検証を通れば、実際の作業（運用のループ）が始まります。

運用のループ — チームの働き方

チームができると、オーケストレーターが下のループを回します。核心は「分けて並列にやり、テストで検証し、間違っていればやり直す」です。

  1. 分解 — 目標を作業の単位に切り分けます。例: 影響範囲の分析・保留ロジック・通知・回帰テスト
  2. 分担 & 並列実行 — 各エージェントが同時に担当の作業を進めます。
  3. 検証 — QA が結果を突き合わせて確認（標準機能の回帰、数値の整合性）。
  4. フィードバックのループ — 問題があれば担当のエージェントへ戻してやり直し。通るまでくり返します。

エージェントチーム vs 隔離サブエージェント

Claude Code の標準のサブエージェントは互いに隔離されていて会話できません。エージェントチームは互いに通信します — たとえば開発のエージェントが「標準ソースの情報が足りない」と気づけば、分析のエージェントを呼び起こして追加の調査をさせられます。

実験機能 — オンにする方法 エージェントチームは実験機能です。~/.claude/settings.json の環境変数でオンにします: 
"env": {
  "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
}
動的ロードに失敗すると隔離サブエージェントとして立ち上がるバグがあるので、エージェントが見えないときは /exit してから入り直し、/agents で確認してください。
ファイルはどこにできるのか 生成されたエージェント・スキルの定義はプロジェクトの .claude の下に残るので、Git でチームと共有できます。ただしプラグイン自体はマシンごとに個別インストールが必要です。構成の変更履歴は CLAUDE.md に記録されます。チーム設計そのものをさらに深く扱うエージェント・スキルの設計へ続きます。
