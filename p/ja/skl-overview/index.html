スキルとは — 背景と強み

この資料は「スキル深掘り / キム・テイン」の講義を、順に段落ごとに整理したものです。スキルは使い方そのものなら 5 分で足りるほど簡単です。だからこの講義は、使い方よりもスキルという発想と、それを動かしている哲学・アイデアに集中します。

くり返すノウハウをスキルとして一度まとめておけば、新しい作業・別のプロジェクト・チームがそのまま再利用します。
なぜ深く学ぶのか スキルをきちんと理解すると、これからの業務や生成 AI の組み込みにおいて単なる技術ではなく生態系の全体をつかむのに大いに役立ちます。続くハーネスも見方によってはメタなスキルの一種なので、スキルの概念をつかんでおくと、その内容もずっと見通しやすくなります。

スキルの背景 — コーディングエージェントの誕生

スキルは、ある日突然「じゃーん」と出てきた技術ではありません。コーディングエージェントという土台の上に自然と現れました。その文脈を知ってはじめて、スキルがなぜそういう動き方をするのかが分かります。

エージェントの種類

段階が上がるほど自分でやる範囲が広がります — コーディングエージェントの上で、スキルが可能になります。
  • チャットエージェント — 私たちがふだん使う対話型。
  • ツール呼び出しエージェント — MCP・API をつないで Gmail の確認、予定の登録といった外部の作業をこなす。
  • コーディングエージェント — ツール呼び出しよりもう一段上。Claude Code がこれにあたります。

「ツールは簡素に、残りは LLM に」

はじめは、ツールを精巧にたくさん作ればエージェントがうまく動くだろうと期待しましたが、どれだけよく作っても望むかたちにならないという限界にぶつかりました。そこで発想を変えました。

  • ツールはごく基礎的なものだけ渡す — ファイルの読み・書き・編集・検索、そしてコマンドの実行くらい（およそ六つ）。
  • 残りは LLM が自分でやるようにする。
  • そのためには実行環境とファイルシステムが要る → サンドボックス + 簡素なツール。

こうして生まれたのがコーディングエージェントです。キャンプにあらゆる道具を積んでいく代わりに、ハンマーのような基礎の道具だけ持っていって現地で作って使うやり方に近いものです。

Claude Code がフォルダを咥えて始まる理由 Claude Code が特定のフォルダの中で実行されるのは、まさにこれが理由です。ファイルを読み書きし、こちらのコマンドを実行するには自分の OS とファイルシステムが必要なので、自分のコンピュータ（ローカル）で動きます。スキルは、このコーディングエージェントの上でだけ可能な機能です。

スキルとは何か

Claude のスキルは特定の仕事のやり方を教えるために作った、再利用できる作業のパッケージです。個人の能力を伸ばすのではなく、組織の中で誰が使っても同じ品質の結果が出るように — つまり個人技ではなく組織の知識にすることが核心です。

なぜ組織にとって大事なのか

  • ひとりがスキルを作って全体に配れば、みんなが同じスキルで一貫した品質の結果を出せます。
  • エージェントのガバナンス、組織のポリシー、業務の流れと密接につながります。
  • スキルは自分たちで作れなければなりません。社内の業務は社内でしか分からないので、外で作られたものをそのまま持ってきて使うのは難しいのです。自前で作って高度化していく生態系が整ってはじめて、コーディングエージェントを自由に使えます。

実体はただのフォルダ

スキルの中にはインストラクション（指示）・スクリプト・リソースの入ったフォルダがあります。コンピュータの目で見ればただのファイルとフォルダ、圧縮ファイルひとつです。大それた実行ファイルがあるわけではなくスクリプトとリソースだけですが、これを必要な瞬間に動的に読み込むという点が大きな意味を持ちます。

Claude に渡す「業務のオンボーディング文書」

スキルは、あなたが使う Claude に手渡す業務のオンボーディング文書のようなものです。

  • この業務はいつやるべきか
  • どんな順序で処理すべきか
  • どんな基準で結果を判断するか
  • 私たちの品質の基準は何か

こうしたことを教えて自分の好みに合わせて作らせるのが、スキルの始まりです。私たちはみな汎用のエージェントを使っていますが、それを自分の業務に合った専門のエージェントに変えるには、スキルが欠かせません。

スキルの強み

ふつう、ある製品の特徴とは、別々に作られたいくつもの機能の並びです。ところがスキルの強みは「スキル」という発想ひとつからすべて派生します。だから概念を理解すれば、特徴は自然につながって見えてきます。

強み意味
再利用できるいちど作れば、共有せず自分だけで何度も使うだけでも生産性が大きく上がる。
反復業務のパッケージ化いつも同じようにやる仕事をスキルにして、毎回らくに、一貫して処理する。
段階的な読み込み必要なときだけ読み込んでコンテキストの無駄を減らす（中心の原理 — 次の章）。
スクリプト・リソースを同梱検証済みの既存スクリプトをそのままかぶせ、確率的な結果を決定論的にする。
複合のワークフロー複数のスキルを同時に読み込んで組み合わせ（融合）できる。
プラットフォーム互換Claude AI・API・Code・Cowork で使える（環境と権限は少しずつ違う）。Codex・Antigravity でも一部使える。
専門性・組織知のパッケージ化トーン&マナー、レビューのチェックリスト、品質の基準などをスキルに収めて標準化する。

検証済みのスクリプトをそのまま

「AI が書いたものはそのつど違うので使えない」「ハルシネーションがある」という問題を、スキルは自分が渡したスクリプトの中で実行される決定論的な結果に変えてくれます。何年も使ってきた検証済みのスクリプト（例: 各分野の伝統的な分析スクリプト）をスキルとしてかぶせれば、幻覚なしに安定して活用できます。

組織にもたらす価値 自分たちの機関から出る成果物を決められた品質の基準に合わせて作れる、という点が大きな意味を持ちます。ドメインの専門性と組織の知識をスキルとしてパッケージしておけば、誰が作っても「ひとりが書いたように」一貫した結果が出ます。
