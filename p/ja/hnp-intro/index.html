Harness プラグイン — 紹介・概念・インストール

ハーネス（Harness）プラグインは、「目標（意図）を渡すだけで、複数の AI がチームを組んで自律的に長く働ける場を整えてくれる」Claude Code のプラグインです。プロンプトをひとつずつ投げる代わりに、「何がほしいのか」だけを言えば、プラグインがエージェントチーム・スキル・オーケストレーターを代わりに組み立てて実行します。

一枚で見る全体像

ハーネスプラグインがやることは、つまるところ下の流れです。人はいちばん前（意図）といちばん後ろ（検討・意思決定）にだけ関わり、真ん中のくり返し作業は AI のチームが引き受けます。

人は前（意図）と後ろ（検討）だけ、真ん中のくり返し作業は AI のチームが引き受けます。

なぜ「ハーネス」なのか — プロンプトからハーネスへ

AI を扱うやり方は、下のように発展してきました。ハーネスはモデルひとつではなく「モデルを取り囲む環境全体」を設計する段階です。同じモデルでも、どんな場（ハーネス）に載せるかで成果物の品質は大きく変わります。

段階核心たとえ
プロンプトエンジニアリング問いをうまく投げるひと言をうまく言う
コンテキストエンジニアリング必要な資料・文脈をうまく入れる資料を手に握らせる
ハーネスエンジニアリングAI が働くシステム全体を設計馬に馬具（ハーネス）を着けて長く走らせる

ERP のカスタマイズになぜ向くのか

顧客ごとのカスタマイズ業務は、ふつういくつもの段階が順番につながります — 要件（CR）の分析 → 標準ソース・影響範囲の把握 → 設計 → 開発 → 回帰検証。これはひとりで順にやると時間がかかるが、役割を分けて並列にやるとずっと速い典型的な仕事です。ハーネスはこの段階をそれぞれ担当のエージェントに任せ、オーケストレーターが整えます。

  • 標準の毀損を最小化 — 「このカスタムが標準パッケージのどこに影響するか」を分析エージェントが先に押さえます。
  • 回帰検証の自動化 — 開発のあと、QA エージェントが標準の機能が壊れていないかを突き合わせて確認します。
  • 成果物の標準化 — 仕様・影響範囲・テスト・移行ガイドが _workspace にまとめて残ります。

※ 具体的な例（営業・受注の与信限度のカスタム）ははじめてのハーネス実行で段階を追って試します。

核心の概念をやさしく

ハーネスは五つの要素からできています。難しく感じますが、会社で働くチームにそのまま対応します — PM ひとり、担当者が複数、それぞれのマニュアル、検収、そして共有の作業フォルダ。

名前の由来 — 馬車の馬具 「ハーネス（harness）」はもともと馬に着ける馬具を意味します。馬（＝AI モデル）がどれだけ優れていても、どう繋いで操るかによって、よく走りもすれば空回りもします。ハーネスエンジニアリングとは、まさにその「操るための場」を設計する仕事です。

構成図 — 要素はどう噛み合うのか

オーケストレーターがチームを整え、すべての成果物は共有の _workspace に残ります。

五つの要素

  • エージェント（Agent） — 特定の役割を負った AI の作業者。コードではなく自然言語で書いた「職務記述書」です（役割・原則・入出力・協業の方法・エラー時のふるまい）。例:「営業の標準ソース分析担当」
  • スキル（Skill） — くり返し作業を収めたマニュアル。名前 + 説明 + 手順・チェックリストでできています。例:「与信限度の検証手順」スキル
  • オーケストレーター（Orchestrator） — チームを整える PM。つねにひとりで、始める前に作業の順序（ワークフロー）をあらかじめ計画します。（Claude Code のプランモードに似ています）
  • 評価・テスト — 結果を信頼できるものにする検収。誤字脱字ではなく主張と根拠の整合、数値の一貫性、標準機能の回帰を突き合わせて確認します。
  • アーティファクト・メモリ — 実行時にできる共有の作業フォルダ _workspace。中間の成果物と根拠の出典が一緒に残るので、あとから「なぜこうしたのか」を追え、ハルシネーション（もっともらしい嘘）も減ります。

会社のチームにたとえると

ハーネスの要素会社でのたとえERP カスタムの例
オーケストレーターPM / チームリーダーCR の処理順を組むリーダー
エージェント担当の実務者標準ソース分析担当・開発者・回帰 QA
スキル業務マニュアル「影響範囲の分析手順」「回帰テストのチェックリスト」
評価・テスト検収の担当標準機能の破損・数値の整合性の確認
アーティファクト・メモリ共有ドライブ_workspace: 仕様・影響範囲・テスト・移行ガイド
最小の構成は 3 つ はじめはエージェント・スキル・オーケストレーターの三つだけ理解すれば十分です。評価・テストとアーティファクト・メモリは、ハーネスプラグインが勝手に付けてくれます。次の文書でインストールして、実際に実行してみます。

インストールと準備

ハーネスは Claude Code のプラグインとして配布されています。マーケットプレイスを一度登録してインストールすれば、/harness コマンドが使えるようになります。

先に必要なもの Claude Code が入っている必要があります（はじめに を参照）。ターミナルで作業するプロジェクトのフォルダへ移動し、claude を実行した状態で下のスラッシュコマンドを入力します。

インストールの 3 ステップ

方法 1 — コマンド 2 行（おすすめ）

# 1) ハーネスのマーケットプレイスを追加
/plugin marketplace add lev-factory/harness
# 2) ハーネスプラグインをインストール
/plugin install harness

インストールの画面が出たら User スコープで入れます（自分のアカウント全体で使える）。特定のプロジェクトだけで使いたいときはプロジェクトスコープを選びます。

方法 2 — /plugin の画面から

  1. /plugin と入力 → 方向キーの右で Marketplace タブへ移動。
  2. Add Marketplace に lev-factory/harness を入力 → Enter。
  3. 一覧から harness を選択 → インストール画面で Enter → User スコープで導入。

インストール後 — リロードして確認

# プラグインを現在のセッションに反映
/reload
# 下が補完・実行できればインストール成功
/harness

/harness と入力して補完が出れば準備完了です。ここからはじめてのハーネス実行へ進みます。

注意 — マーケットプレイスのアドレスを確認 上の lev-factory/harness は講義で言及された例の値です。実際に入れるときは配布者の GitHub リポジトリのパスを確認して入れてください（検索語:「ハーネス 100」）。インストールできないときはコマンドの方法 ↔ /plugin 画面の方法を交互に試してみてください。
社内環境でのコツ 社内ネットワークやプロキシの環境では GitHub へのアクセスが制限されることがあります。マーケットプレイスの追加が失敗したら、ネットワーク／プロキシのポリシーと Git のアクセス権限をまず確認してください。プラグインはマシンごとに個別インストールが必要です（エージェントの定義は Git で共有できますが、プラグイン自体は各自でインストール）。

概念とインストールが済んだら、すぐ回してみます — 最初の実行と動作構造で、営業・受注カスタマイズのハーネスを実際に作ります。
