dews-sourcegraph — 社内コード検索を Claude に任せるスキル

社内に SourceGraph を置いて使っている組織なら、こういう場面によく出会います。いま作っている機能と同じ類のものが会社のどこかにもうあるはずなのに、自分のローカルにはそのリポジトリがありません。ウェブ UI を開いて検索し、結果を目で追ってから Claude にもう一度説明しなおす往復が生まれます。dews-sourcegraph はその往復をなくします — Claude が社内インスタンスへ直接問い合わせて repo │ ファイル:行 │ スニペット を受け取り、その根拠をそのまま引用して実装を続けます。

つまずくのは認証です。非公開のインスタンスは匿名アクセスが 401 で閉じられているので、ふつうのウェブ取得ツールでは何ひとつ読めません。そこでこのスキルは、ブラウザのフォームログインを一度だけ自動で済ませ、得たセッションをキャッシュして使い回します。人が開発者ツールを開いてクッキーをコピーする手順はありません。

入手 dews-sourcegraph-skill.zip（15KB）— スキル本体 · 実行ツール · 認証情報のテンプレート · インストール README。 インスタンスのアドレスとアカウントは入っていません。各自が自分の環境の値を埋めて使います。

認証が流れる仕組み

図 1. セッションが生きていれば ② を飛ばす — ブラウザが立ち上がるのは最初の一度と、セッションが切れたときだけ

ブラウザの自動化は playwright-core が正式にインストールされた Edge や Chrome を直接動かします。ダウンロードしてくるキャッシュブラウザを使わない理由は、現場の環境にあります — セキュリティエージェントが ms-playwright キャッシュの実行ファイルをブロックする社内 PC があり、そういう環境ではキャッシュブラウザが空のページさえ出せないまま止まります。システムのブラウザは同じ条件で問題なく動きます。探索の順番は SG_CHROMIUM_PATH 環境変数 → システムの Edge/Chrome → キャッシュブラウザです。

インストール

ツールのパスがプロジェクトルートからの相対なので、Claude Code を開くプロジェクトルートで展開します。

自分のプロジェクト/
├── .claude/
│   ├── skills/dews-sourcegraph/SKILL.md      # スキル本体
│   └── tools/sourcegraph-search.mjs …        # 実行ツール + package.json
└── SourceGraph.md                            # 認証情報(自分で作成)

zip の .claude フォルダをプロジェクトルートへマージし、SourceGraph.md.example を SourceGraph.md にコピーして三行を埋めます。

URL:https://<sourcegraph-ホスト>/
ID:(アカウント ID)
PW:(パスワード)

別の場所に置きたいときは SG_CRED_FILE 環境変数でパスを指定します。あとは依存をインストールして Claude Code を再起動すれば、スキルの一覧に載ります。

cd .claude/tools
npm install
二つだけは必ず守ってください ① SourceGraph.md と .claude/tmp/ はコミットしません — アカウントとセッションのクッキーがリポジトリへ漏れます。.gitignore に二行を足してください。
② ログインに失敗したら再試行しません — パスワードのログインを続けて失敗するとアカウントが一時的にロックされます。ツールが出すサーバーのメッセージ(User or password was incorrect / locked out)を読んで原因を直したうえで、一度だけやり直します。

使い方

Claude に「ソースグラフで ○○ を探して」と言うか、/dews-sourcegraph で直接呼びます。ターミナルからそのまま実行することもできます。

node --no-warnings .claude/tools/sourcegraph-search.mjs --query "myFunction file:\.java$ count:30" --max 20

クエリは Sourcegraph 標準の文法をそのまま使います。

フィルタ例意味
(本文)myFunctionコードの中身を検索
repo:repo:my-serviceリポジトリ名のパターン限定
file:file:\.java$ファイルパスの正規表現
type:type:pathファイル名だけ照合(中身は無視)
count:count:allサーバー側の件数上限
- 除外-file:bin/ビルド成果物のノイズを除く

正規表現が必要なら --pattern regexp を付けます。結果が 0 件のときはたいてい語彙がずれているので、フィルタを外して広く投げ、言い方を直してから絞りなおすほうが速いです。

ローカルを先に探させる理由

スキルの文書にはローカル優先をルールとして書き込んであります。全社の検索がいつも良い答えをくれるわけではないからです。同じ機能でも組織ごとに慣習が違い、自分のリポジトリの既存コードと食い違うパターンを引いてくれば、レビューで戻ってきます。そこで発動の条件を三つに絞りました — ローカルに同じ類の先例がないとき、派生版しかなく原本がどのリポジトリなのか確かめたいとき、共通ライブラリの内部実装や呼び出し元を見たいとき。

引用の形も決めてあります。検索で得た根拠は [SG {repo}/{ファイル}:{行} → 再現するパターン] として残し、ローカルの先例の ファイル:行 という根拠と同じ格で扱います。原文の全体が必要なら、そのリポジトリがローカルにあるかを先に確かめ、なければクローンするかどうかをユーザーに尋ねます。検索と抜粋までがこのスキルの境界です。

配布の範囲 公開している zip は特定の組織の情報を含まない一般化版です — インスタンスのアドレス · アカウント · 組織固有の検索例は各自の環境で埋めて使います。 検索の結果はその組織のコードなので、外部のサービスへ持ち出さないという条項もスキルの文書に入れてあります。
