あらすじで映画を探す — Neo4jサンドボックスで作る初めてのベクトルリトリーバー

前編が地図を広げる文章だったなら、今回は靴ひもを結ぶ文章です。何もインストールせず、ブラウザでグラフDBを一台借り、映画のあらすじを数値に変えて植え込み、「こんな話の映画ない?」と尋ねると似た映画を返してくる検索機を、最後まで作り切ります。

目標は一文に収まります。あらすじを投げると、あらすじが似ている映画が返ってくる検索機。大げさに聞こえますが部品は三つだけで、どれも名前が物々しいわりに、やることは素朴です。

  • 埋め込み(エンベディング) — 文章を意味を担う数値の並び(ベクトル)に変えること。意味が近い文章ほど、数値も近くに寄ります。この変換をするのが埋め込みモデルで、ここではOpenAIのものを使います。
  • ベクトルインデックス — その数値を速く探せるように付けておく索引。辞書の小口にある「あかさたな」の切り込みを指で押さえれば目当てのページが開くように、索引があれば「近いベクトル」を総当たりせずに見つけられます。
  • リトリーバー — 質問を受け取り、埋め込み、索引から近いものを選んで結果を返す検索機そのものです。
今日の五歩。最後の一歩で「あらすじ → 似た映画」が実際に動きます。

一歩目 — グラフDBを借りる

グラフDBを触るのに何かをインストールする必要はありません。Neo4jがサンドボックスという無料のクラウドインスタンスを貸してくれます — Pythonノートブックをブラウザでそのまま回すGoogle Colabと同じ感覚で、ブラウザにグラフDBが一台現れます。ログインしてプロジェクトを選ぶ画面が出たらRecommendationsを選びます。映画推薦研究で広く使われるMovieLens系の映画推薦データが、あらかじめ積み込まれたプロジェクトです。

開いてみると、前編で絵として眺めていたものが実物として立っています。ノードは五種類 — 映画(Movie)、ジャンル(Genre)、俳優(Actor)、監督(Director)、ユーザー(User)。映画ノードを一つクリックすると、タイトル(title)、上映時間、そしてあらすじ(plot)といったプロパティがずらりとぶら下がっています。カンフー・パンダ3のノードにはジャック・ブラックがACTED_INの矢印でつながり、あるユーザーがRATEDの矢印でつながっている — そしてその矢印の中に、評価4点と残した時刻がプロパティとして入っています。関係そのものがデータを持つ。前編で語っていたプロパティグラフの性質を、ここで初めて自分の目で確かめることになります。

Recommendationsデータの骨組み。RATEDの矢印は評価と時刻を自分の中に持っています — プロパティグラフでは関係もデータを持つのです。

二歩目 — Cypherでご近所散歩

本格的な工事の前に、Cypher(グラフ問い合わせ言語 — 前編参照)を数行、データへの挨拶がわりに。骨組みは三語だけです。MATCHで探したい関係の形を描き、RETURNで何を返してほしいかを書き、LIMITで件数を切ります。

// 誰がどの映画を評価したか — 25件だけ眺める
MATCH (u:User)-[r:RATED]->(m:Movie) RETURN u, r, m LIMIT 25

// トム・ハンクス出演作のタイトルとあらすじ — グラフではなく表で返ってくる
MATCH (a:Actor {name: 'Tom Hanks'})-[:ACTED_IN]->(m:Movie)
RETURN m.title, m.plot LIMIT 10

最初の問い合わせは画面にグラフとして描かれ、二つ目のようにノードではなくプロパティだけを返すと表になって戻ってきます。同じデータを絵でも表でも受け取れる — それが確かめられたら、散歩はもう十分です。

三歩目 — あらすじを数値に変えて植え戻す

いよいよ中心工程です。PythonからNeo4jドライバーでサンドボックスに接続し(接続コードはサンドボックスの画面のConnect via driversにそのまま出ているので、コピーして貼るだけです)、映画ノードのplotテキストを一つずつ取り出して埋め込みモデルに通し、返ってきたベクトルをそのノードの新しいプロパティとして植え戻します。全部回すと時間がかかるので、実習らしく100本だけに切ります。

# あらすじのある映画100本 → 埋め込み → plotEmbedding として保存
movies = tx.run("""
    MATCH (m:Movie) WHERE m.plot IS NOT NULL
    RETURN m.title AS title, m.plot AS plot LIMIT 100""")
for row in movies:
    vec = generate_embedding(row["plot"])   # OpenAI 埋め込みを呼ぶ
    tx.run("""
        MATCH (m:Movie {title: $title})
        SET m.plotEmbedding = $vec""", title=row["title"], vec=vec)

数十秒後、サンドボックスで適当な映画をもう一度クリックすると、plotの隣にplotEmbeddingというプロパティが生まれ、1,536個の実数がぎっしり詰まっています。人の目にはノイズですが、この数値たちの距離こそが、物語の似ている度合いです。デモで使われたのはOpenAIのtext-embedding-ada-002(出力1,536次元)ですが、いま新しく始めるなら同じ席の後継モデル(text-embedding-3系)を使うのがよいでしょう — 手順は完全に同じです。

四歩目 — 索引を付ける

ベクトルを植えたら、次は探す速さの番です。100本なら総当たりでも構いませんが、数十万本になると、問い合わせのたびに全部を測り直すのは無駄です。そこでベクトルインデックスを作ります — 辞書の小口の切り込みのように、近いベクトルへの近道をあらかじめ掘っておくのです。Cypher一文で済みます。

// Movie ノードの plotEmbedding にベクトルインデックスを作成
CREATE VECTOR INDEX moviePlots
FOR (m:Movie) ON m.plotEmbedding
OPTIONS {indexConfig: {
  `vector.dimensions`: 1536,          // 埋め込みモデルの次元と一致させる
  `vector.similarity_function`: 'cosine'
}}

オプション二行の言っていることは単純です。この索引が扱うベクトルは1,536次元で、「近い」の基準はコサイン類似度(ベクトル同士の角度で似ている度合いを測る関数)だということ。次元数は埋め込みモデルの出力と必ず合わせます — ここがずれると、索引はベクトルを受け付けてくれません。

五歩目 — リトリーバーを組み立てて、尋ねる

部品が揃いました。接続(ドライバー)、索引(インデックス)、変換器(エンベダー)。この三つを、前編で紹介したneo4j-graphragパッケージのVectorRetrieverに渡せば検索機の完成です。四つ目の引数で「結果としてどのプロパティだけを返すか」を決められます。

from neo4j_graphrag.retrievers import VectorRetriever

retriever = VectorRetriever(
    driver,                                # ① どのDBで
    index_name="moviePlots",               # ② どの索引で
    embedder=embedder,                     # ③ 質問をどうベクトルにするか
    return_properties=["title", "plot"],   # ④ 何を返すか
)
result = retriever.search(query_text="おもちゃがこっそり動き出す話", top_k=3)

いよいよ本当に尋ねます。トイ・ストーリーのあらすじを短く要約して投げると、1位でトイ・ストーリーが返ってきます — タイトルとあらすじ、そしてコサイン類似度のスコアまで一緒に。銃撃事件を扱った映画を描写して投げれば、まさにその題材の映画が0.93ほどのスコアで浮かび上がります。注目すべきは、質問の中で映画のタイトルを一度も口にしていないこと。言葉が重なったからではなく、物語が似ていたから見つかった — ここがキーワード検索とベクトル検索の分かれ道です。

ここからもう一歩

今日作ったのは純粋なベクトル検索機です。グラフの力はまだ半分も使っていません — 見つけた映画ノードからACTED_INをたどって俳優へ、IN_GENREをたどってジャンルへ、RATEDをたどって好みの近いユーザーへ歩き出した瞬間から、GraphRAGの本編が始まります。それでも順序はこちらが正しいのです。ベクトルですくい、グラフで歩く — 今日完成させたリトリーバーは、その最初の動詞です。検索が物語を見分けたのは、あらすじを丁寧に植えておいたからです。このウィキが文書ごとに概念と関係を機械が読める形で持たせているのも、同じ理由からです。

ファクトチェックノート 実習の手順と実行結果(埋め込み100本、トイ・ストーリー検索1位、銃撃題材の質問での類似度約0.93)は外部のデモを再構成したもので、このウィキが同一環境を再実行したわけではない。コードと文法は一次資料で照合した — neo4j-graphrag-python ドキュメントのVectorRetriever(driver・index_name・embedder・return_properties、searchのquery_text・top_k)、Neo4jのCREATE VECTOR INDEX文法(vector.dimensions・vector.similarity_function)、Neo4jサンドボックスのRecommendations(MovieLens系)データセット。デモ当時のパッケージ名はneo4j-genaiで、現在はneo4j-graphragに改名されている。text-embedding-ada-002はレガシーモデルで、新規構築にはtext-embedding-3系が推奨される。埋め込み空間の図は概念模式図であり、実測座標ではない。
