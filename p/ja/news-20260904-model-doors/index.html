モデルに扉がついた — 誰が使うのか、どう呼ぶのか

三行まとめ

  • Fable 5.1 と Mythos 5.1 は能力が同じ一つのモデルである。Fable 5.1 は誰でも API で使えるが、Mythos 5.1 は Project Glasswing の参加者にだけ開かれる。
  • 値段が下がったのはキャッシュ読み取りの一行だけだ — 100万トークンあたり $1 から $0.25 へ。基本の入力・出力単価は Fable 5 のままである。
  • 同じリリースが呼び方を三か所変えた。ツール呼び出しを強制できず、以前のモデルはこのモデルの推論を読めず、対話履歴を書き換えるとその後の推論が無効になる。
  • 3週間後、同じ規則が Opus 5.5 に来た（9月22日）。特殊なモデルの条件だったものが、既定で受け取るモデルの条件になり、値下げはキャッシュではなく基本単価で起きた。

同じモデル、二つの名前

9月1日に出た Fable 5.1 と Mythos 5.1 は能力も仕様も価格もすべて同じだ。 分かれるのは誰が使えるかだけである。Fable 5.1 は Claude API と AWS・グーグルクラウド・マイクロソフト Foundry ですべての顧客に開かれ、Mythos 5.1 は Project Glasswing（サイバーセキュリティや生命科学のように賭け金の大きい分野のソフトウェアを守ろうという Anthropic のプログラム）の承認顧客にだけ提供される。同じ能力を二つの名前で出しながら、片方にだけ扉をつけた形だ。

仕様はコンテキスト100万トークン、出力は最大12.8万トークンで、コンテキストの全域に同じトークン単価が適用される。適応的思考は常に入っていて切れず、深さは effort で調節する。両モデルには30日のデータ保持がつくため、個別の承認なしにはデータ無保持（zero data retention）の条件では使えない。

もう一つ分かれる点がある。後述する履歴編集の検査を Mythos 5.1 は走らせない。 同じモデルでもかかる条件が違うということなので、二つの名前を行き来するコードを書くなら覚えておく価値がある。

値段はキャッシュで下がった

表を見ると下がったのは一マスだけだ。基本入力は100万トークンあたり $10、出力 $50、5分キャッシュ書き込み $12.50、1時間キャッシュ書き込み $20 と Fable 5 のままで、キャッシュ読み取りだけが $1 から $0.25 に変わった。比で見ると基本入力価格の 0.1 倍だったものが 0.025 倍になった — ほかの Claude モデルはいまも 0.1 倍である。キャッシュできる最小の長さ512トークンも据え置きだ。

一マスが全体の費用を揺らすのは、エージェントの働き方に理由がある。長いセッションは毎ターン、冒頭（システムプロンプト・ツール定義・それまでの対話）をまるごと読み直す。その冒頭がキャッシュに載っていれば請求されるものの大半はキャッシュ読み取りで、だからこの一行が4分の1になると全体が目に見えて下がる。公開時の報道が伝えた「一般的な作業で25%、エージェント色の濃い作業で最大45%の削減」は、すべてこの一行から出た数字だ。

モデルそのものは、長いセッションのエージェント的コーディング、文書・表計算・スライドの作業、多段階の調査、図表が詰まった PDF の読み取り、100万トークン全域をつなぐ長文推論、ブラウザやデスクトップの操作で Fable 5 より優れているとされる。effort を高くするほど差が開くという但し書きもついた。ただし価格表が示すとおり、この改善は値上げではなくキャッシュの値引きという形で来た。 大半の作業はいまも Opus 5 から始め、Opus 5 を高い effort で回しても足りないときに Fable 5.1 へ移れというのが公式の案内である。

呼び方が三か所変わった

価格だけを見てモデル名を差し替えると、三か所で引っかかる。

第一に、ツール呼び出しを強制できない。 tool_choice に any や特定のツール名を入れて「このターンでは必ずこのツールを呼べ」と釘を刺すやり方が 400 エラーを返す。理由は文書に書かれている — このモデルは思考が常に入っており、ツール呼び出しを強制するとその思考を飛ばして、検討すべき中身をツールの引数の中に書き込んでしまう。引数の質が落ちるのである。代わりに tool_choice は auto のままにしてツール定義に strict: true をつけスキーマを強制するか、プロンプトに「こういうときはこのツールを使え」と書けばよい。

第二に、思考ブロック（モデルが答えを出す前に回した推論を収めて履歴に残す断片）に向きができた。Fable 5.1 は Opus 5・Fable 5 をはじめとする以前のモデルの思考ブロックを読むが、それらのモデルは Fable 5.1 のものを読めない。ルータがモデルを切り替えたり拒否のフォールバックで古いモデルに下りたりすると、API は読めないブロックをあらかじめ取り除いて要求を通す。取り除かれたトークンは請求されないが、そのモデルは推論なしで一から計画を立て直す。 ベータヘッダをつけなければ、この除去は何の表示もなく静かに起きる。

第三の変更がいちばん多くのコードに触れる。Fable 5.1 の思考ブロックは、その前にあったシステムプロンプト・ツール一覧・対話履歴に対してのみ有効だ。 前のターンを書き換える・並べ替える・消すこと、毎回の要求で前のターンに注意書きを挿し込んで次の要求で外すこと、同じ対話の中で system や tools を作り直すこと — いずれもその後の思考ブロックを無効にする。逆に、先頭から思考ブロックをまとめて取り除くこと、サーバ側の圧縮やコンテキスト編集、cache_control の印を動かすこと、要求のあいだで effort を変えることは無効にしない。

この検査が既定で入るのは 2026年8月31日以降に作った API アカウントだけである。それ以前のアカウントはずれを記録するだけで通す。そして履歴を代わりに管理してくれる道具 — Claude Code・claude.ai・Managed Agents・Agent SDK — を使っていれば、すでに守られている。自分で messages 配列を組み立てるコード、とりわけ要約で履歴をたたむ圧縮をクライアント側で回すエージェントのフレームワークが引っかかる。自作の道具を他人に配っているならさらに用心がいる — 開発者のアカウントはたいてい古い側で検査が切れており、新しいアカウントで使う利用者のほうが先にぶつかるからだ。

確かめ方

自分のコードが履歴を書き換えるかどうかは、推し量らずに測ればよい。thinking-binding-controls-2026-08-01 のベータヘッダをつけ prefix_mismatch_behavior を "drop_block" にすると、検査が切れているアカウントでも検査が入り、応答に input_transformations の配列が載ってくる。複数ターンのセッションを一度回してこの配列を記録してみるとよい。毎ターン空なら履歴は無傷で、prefix_binding_mismatch が出ればそのブロックの前で何かが変わっている。モデルを乗り換えたあとに出る model_binding_mismatch は不具合ではなく想定どおりの動きだ。

本番で何を選ぶかは設計しだいである。履歴が変わること自体が不具合なら既定の "error" のままにして失敗させ、圧縮のようにわざと履歴をたたむ設計なら "drop_block" にして該当ブロックだけ落とす。どちらにせよ 400 の件数か input_transformations の項目を見張ることは併せて要る。

移行のついでに見ておくものがいくつかある。同じリリースには、対話の途中で effort を変えるベータ、一ターンだけ生きて消えるシステムメッセージのベータ、ツール呼び出しの合間の進行状況をテキストで受け取る display: "updates" のベータが入った。既定の挙動も少し変わり、以前は複数のツールをまとめて呼んでいた場面で一ターンに一つずつ呼ぶことが増えた。答えの質が落ちるわけではないが、往復が増えてトークンと時間を余分に使う。

9月22日 — 例外が既定になった

この記事を書いてから3週間後、Opus 5.5 が出た（9月22日）。仕様は Fable 5.1 と同じくコンテキスト100万・出力12.8万で、適応的思考が常に入っている点も同じだ。違うのは値段である。Fable 5.1 は基本単価をそのままにキャッシュ読み取りの一行だけを削ったが、Opus 5.5 は基本単価そのものが下がった。

エラーになる箇所は四つで、そのうち三つは上で見たものと同じだ — 思考を切れない、ツール呼び出しを強制できない、思考ブロックがモデルと履歴に縛られる。新しいのは四つ目だけである。Claude API と Google Cloud では旧来のコンピュータ使用ツール（computer_20251124）が400を返すので、computer_toolset_20260801 ツールセットへ移す必要がある。Amazon Bedrock では旧ツールがそのまま動くため、プラットフォームごとに答えが違う。

リクエストを失敗させない変更の二つのほうが、むしろ危ないかもしれない。一つは既定の effort が high から medium に下がったことだ。モデル名だけ差し替えて effort を書かなければ、以前より考えないモデルを受け取ることになる。エラーも警告も出ない。同じ effort 値でもこのモデルはターンあたり多く考える傾向なので、値をそのまま移すのも正しくない — 公式の案内は測り直せというものだ。

もう一つはツール呼び出しのあいだに書かれる短いメモが text ではなく思考ブロックで返ることである。既定の設定ではそのブロックの文字が空なので、進捗を利用者に流して見せていた画面がツール呼び出しのあいだ静かになる。エラーが出ないので気づきにくく、display の値を変えて初めて文字が戻る。

思考ブロックの向きは、もはや地図が要るほど分かれた。Opus 5.5 は Opus 5 とそれ以前の Opus・Sonnet・Haiku のブロックを読むが、Fable・Mythos のものは読めない。逆に Fable 5.1 と Mythos 5.1 は Opus 5.5 のブロックを読む（Claude API の場合）。つまり Opus 5 → Opus 5.5 → Fable 5.1 と上がる道では推論がつながり、それ以外の移動では切れる。履歴編集の検査が2026年8月31日以降のアカウントで既定で入る点も同じだ。

この変化が重要なのは、規則が変わったからではなく規則の置かれた場所が変わったからである。9月初めにはこれらの条件が高価な特殊モデルと扉の向こうのモデルにだけ付いていたので、移るか移らないかを選ぶ問題だった。同じ日に出た Claude Code 2.1.280 は Opus 5.5 を既定の Opus モデルに入れ、Pro・Team Standard プランの既定モデルを Sonnet から Opus に変えた。選ばなくても受け取るモデルが、これらの条件を帯びているということだ。

なぜ一つの流れなのか

安くなったという知らせと壊れるという知らせは別々に回ったが、二つの文が求めているものは同じだ — 冒頭には触れず、後ろに足していけ。 キャッシュが温かいまま保たれる条件と、思考ブロックが生きている条件が同じ条件だからである。公式文書も、履歴に足していくだけのパターンを説明したうえで「これらのパターンはプロンプトキャッシュも温かく保つ」と付け加えている。キャッシュ読み取りの値下げはその規律への褒美であり、履歴編集の検査は破ったときの罰だ。褒美だけを見て移ると罰のほうで引っかかる。

Opus 5.5 はその褒美と罰を一歩先へ進めた。褒美はキャッシュの一行から基本単価まで広がり、罰は特殊モデルを選んだ人ではなく既定を受け取った人にもかかる。規律を守るかどうかが選択だった区間が終わったわけだ。

判定を誰に任せるのかで見た流れは、判定を機械の側へ寄せる向きだった。Mythos 5.1 の配り方はその反対側の事例である — 同じ能力を前にして、人が組織を確かめてから扉を開ける。 自動化がどこまで行けるかを、能力ではなく被害の大きさが決めるという側に近い。

尋ねない既定値が扱った無状態への転換も、ここで再び顔を出す。セッションという器をなくすと、状態をどこに置くかという問いが残る。思考ブロックごとに、どのモデルがどの履歴の上で作ったのかを刻んでおくやり方は、その場所に置かれた一つの答えだ。接続を開いたままにする代わりに、断片ごとに自分がどこから来たかを持たせるのである。

事実確認ノート

価格表（基本入力 $10・出力 $50・キャッシュ読み取り $0.25・キャッシュ倍率 0.025）、仕様（コンテキスト100万・出力12.8万・30日保持）、三つの破壊的変更とその理由、prefix_mismatch_behavior・input_transformations・8月31日のアカウント条件、Mythos 5.1 が履歴検査を走らせない点と Project Glasswing 限定の提供は、すべて公式のリリース文書と移行ガイドに従った。公開時の報道が併せて伝えた「Terminal-Bench-Science の点数が2倍」「エージェント的コーディングが30%以上向上」といった倍率は公式文書の性能記述に入っていないため、この記事では使わなかった — 当該評価はモデルごとの標準誤差が ±3.5〜4.5 ポイントとされ、一度の比較で倍率を語りにくい。削減幅の25%・45%は Anthropic 発表によるもので、キャッシュ読み取りの比重が小さいワークロードではそこまで下がらない。Opus 5.5 の部分（公開日、単価 $4・$20、キャッシュ読み取り $0.20 と5%の倍率、既定の effort medium、仕様100万・12.8万、四つの破壊的変更と思考ブロックの向き、コンピュータ使用ツールセットのプラットフォーム差）は公式のリリース文書とモデルページに従い、既定モデルの変更は Claude Code 2.1.280 の changelog で確認した。一部の報道が伝えた「運用費40%削減」はこの記事では使わなかった — 公式単価では $5→$4、$25→$20 でトークンあたり20%の値下げであり、40%は既定の effort が下がってトークンを使わなくなる効果まで含めた作業あたりの推定と見られるが、その倍率は公式文書にない。
