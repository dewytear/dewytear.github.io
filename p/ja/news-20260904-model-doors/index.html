モデルに扉がついた — 誰が使うのか、どう呼ぶのか

三行まとめ

  • グーグルは同じモデルを二つの扉に分けて出した。一般版の Gemini 3.8 Flash は誰でも使えるが、脆弱性の発見と修正に特化した 3.8 Flash Cyber は審査を通った防御側にだけ開かれる。
  • Anthropic は Fable 5.1 で呼び出し方に条件をつけた。ツール呼び出しを強制できなくなり、対話履歴を巻き戻して書き換えるとその後の推論が無効になる。
  • 片方は人を審査し、もう片方は要求を審査するが、防いでいるものは同じだ — 能力がそれを生んだ条件から切り離されることである。

同じモデル、二つの扉

9月2日、グーグルが Gemini 3.8 Flash を公開した。安価な段に属しながらコーディングとツール利用が大きく伸び、Terminal-Bench 2.1 で 90.8% を記録した（直前の 3.7 Flash は 81.6%）。価格は100万トークンあたり入力 $0.75・出力 $3.75 のままだ。

同じ日に並んで出た 3.8 Flash Cyber こそがこの知らせの本体である。セキュリティ作業に合わせた版で、C・C++ コードの脆弱性を探す CyberGym（業界で広く使われる脆弱性発見の評価）で 86.2% を取った。修正側の CWE-Bench では 47.2% で、はるかに大きい競合モデルと事実上並ぶ値をずっと安く出している。グーグル自身の試験では20のプログラミング言語にわたって発見成功率が70%を超え、Chrome のセキュリティチームは、はるかに大きい商用モデルより正確な修正を2.6倍多く受け取ったと述べた。

ところがこの版は API には載らない。Fairwind という別のプログラムを通してのみ開かれ、申請者は組織が何であるか、防御上の目的が何か、どんな安全装置を備えているかを説明しなければならない。対象は政府機関・重要インフラ事業者・ソフトウェアの保守者で、通過が保証されるわけでもない。脆弱性をうまく見つける能力とうまく突く能力は同じ能力なので、配布を開けば防御側と攻撃側に同時に開くことになる。グーグルはその対称性を、価格でも性能でもなく身元の審査で断ち切った。

呼び出しに条件がついた

一日早い9月1日に出た Fable 5.1 は反対側である。誰でも API で使えて価格もトークナイザもそのままだが、呼び方が三か所変わった。

第一に、ツール呼び出しを強制できない。 これまでは tool_choice に any や特定のツール名を入れて「このターンでは必ずこのツールを呼べ」と釘を刺せた。Fable 5.1 はそうした要求に 400 エラーを返す。代わりに対話の途中で role: "system" のメッセージを足してツールを指名し、ツール定義に strict: true をつけて引数がスキーマに合うようにする。強制から指示へ変わったわけだ。

第二に、思考ブロック（モデルが答えを出す前に回した推論を収めて履歴に残す断片）に向きができた。Fable 5.1 は Opus 5・Fable 5 をはじめとする以前のモデルの思考ブロックを読むが、それらのモデルは Fable 5.1 のものを読めない。ルータがモデルを切り替えたりフォールバックで古いモデルに下りたりすると、API は読めないブロックをあらかじめ取り除いて要求を通す。取り除かれた分のトークンは請求されないが、そのモデルは推論なしで一から計画を立て直す — 切り替え直後の一ターンで費用と待ち時間が上がる。

第三の変更がいちばん多くのコードに触れる。Fable 5.1 の思考ブロックは、その前にあったシステムプロンプト・ツール一覧・対話履歴に対してのみ有効だ。 前のターンを書き換えたり、ツール配列を作り直したり、クライアント側で履歴を圧縮したうえで古い思考ブロックをそのまま送り返すと 400 エラーになる。この検査が既定で入るのは 2026年8月31日以降に作った API アカウントだけである。それ以前のアカウントはずれを記録するだけで通すが、Anthropic は今後のモデルではすべてのアカウントに適用する計画だと述べている。

この第三の条件が他人事でない場合ははっきりしている。Claude Code・claude.ai・Agent SDK のように履歴を代わりに管理してくれる道具を使っていれば、すでに守られている。 自分で messages 配列を組み立てるコード、とりわけ要約で履歴をたたむ圧縮を入れているエージェントのフレームワークが引っかかる。自作の道具を他人に配っているならさらに用心がいる — 開発者の API アカウントはたいてい古い側で検査が切れており、新しいアカウントで使う利用者のほうが先にぶつかるからだ。

確かめ方

自分のコードが履歴を書き換えるかどうかは、推し量らずに測ればよい。thinking-binding-controls-2026-08-01 のベータヘッダをつけ prefix_mismatch_behavior を "drop_block" にすると、検査が切れているアカウントでも検査が入り、応答に input_transformations の配列が載ってくる。複数ターンのセッションを一度回してこの配列を記録してみるとよい。毎ターン空なら履歴は無傷で、prefix_binding_mismatch が出ればそのブロックの前で何かが変わっている。モデルを乗り換えたあとに出る model_binding_mismatch は不具合ではなく想定どおりの動きだ。

本番で何を選ぶかは設計しだいである。履歴が変わること自体が不具合なら既定の "error" のままにして失敗させ、圧縮のようにわざと履歴をたたむ設計なら "drop_block" にして該当ブロックだけ落とす。どちらにせよ 400 の件数か input_transformations の項目を見張ることは併せて要る。

なぜ一つの流れなのか

二つの知らせは形がまるで違う。片方はセキュリティモデルの配布方針で、もう片方は API 仕様の変更だ。それでも両方とも能力を、それが生まれた条件につなぎ止める仕掛けである。Fairwind は脆弱性を見つける能力がそれを使う資格から切り離されないようにつなぎ止め、思考ブロックの結び付けは推論がそれを生んだ文脈から切り離されないようにつなぎ止める。文脈をすげ替えたうえで古い推論をその上に載せることが、静かに通らなくなった。

判定を誰に任せるのかで見た流れは、判定を機械の側へ寄せる向きだった。Fairwind はその反対側の事例である — 人が書類を読み、組織を確かめてから扉を開ける。自動化がどこまで行けるかを、能力ではなく被害の大きさが決めるという側に近い。

尋ねない既定値が扱った無状態への転換も、ここで再び顔を出す。セッションという器をなくすと、状態をどこに置くかという問いが残る。思考ブロックに署名をつけて前の履歴に結び付けるやり方は、その場所に置かれた一つの答えだ。接続を開いたままにする代わりに、断片ごとに自分がどこから来たかを持たせるのである。

事実確認ノート

Fable 5.1 の三つの変更と prefix_mismatch_behavior・input_transformations・8月31日のアカウント条件は公式の移行ガイドに従った。Gemini 3.8 Flash Cyber の数値は、CyberGym の 86.2% が C・C++ を対象とする公開評価であるのに対し「20言語で70%以上」はグーグル自身の試験で、互いに別の測定である。両者を一つの指標のように移した整理があったため、ここでは分けて記した（SC Media・VentureBeat）。Fairwind の対象と審査項目は TechTimes・CybersecurityNews で照合した。CWE-Bench・CyberGym の点数はいずれもグーグル発表によるもので、独立に再現された値ではない。
