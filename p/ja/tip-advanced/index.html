21. ワークツリーでセッションを並列に回す

同じプロジェクトで二つのセッションが同時にファイルを直すと — 片方はログイン機能、片方はグラフィックのロジック — 同じファイルに触れた瞬間に衝突します。ワークツリー（worktree）は git が提供する独立した作業コピーで、リポジトリの履歴は共有しつつファイルは別々に持ちます。セッションごとに自分のワークツリーで働けば絶対に重ならず、終わったら git のマージで合わせます。

講座では git worktree コマンドを直接打つ方法を紹介していますが、いまは Claude Code が寿命管理までやってくれます — claude --worktree（-w）で始めれば作成・命名・後片付けが自動で、デスクトップアプリは新しいセッションごとに勝手にワークツリーを作ります。.env のような git が追跡しないファイルはコピーに存在しないので、自動で持ち込みたければプロジェクトのルートに .worktreeinclude ファイルを置きます。

コピーが物理的に分かれているから、衝突はそもそも起きない — 管理するのは合わせる瞬間だけ。

公式ドキュメント: Run parallel sessions with worktrees

22. MCP サーバーの代わりに API を直接呼ぶ

MCP（Model Context Protocol）は外部ツールをつなぐ標準ですが、サーバーをつなぐとそのツール定義の一式がコンテキストに載る費用があります。要る機能が一つ二つなら、その API エンドポイントを直接呼ばせるほうがトークンもコンテキストも安い。ツールをほぼ全部使うなら MCP、一つ二つなら直接呼ぶ — この区別がこのコツの全部です。なお、いまはツール検索（Tool Search）が標準で入り、必要なツール定義だけをその都度読み込むのでこの費用は大きく減りましたが、「使う分だけ載せる」という原則そのものは変わらず有効です。

公式ドキュメント: Connect Claude Code to tools via MCP — この wiki の MCP 紹介も参考に。MCP 仕様そのものの大改訂は尋ねない既定値で扱いました。

23. /loop で予約作業を仕掛ける

/loop 5分ごとにデプロイの状態を確認してのように繰り返し作業を仕掛けておくと、セッションが生きている間、Claude が定期的に自分で確認します。デプロイの監視、定期点検、「8時にうちの Slack を確認して」のような時刻指定も可能。人が見張らなくていい監視系の仕事を丸ごと渡せるので、使い道は広いです。

24. スマホから遠隔で操縦する

ターミナルでclaude remote-controlを実行するとリンクが一つ出ます。それをスマホで開くと — コードはあなたのローカルマシンでそのまま動いたまま — 操作だけがスマホに移ります。地下鉄で進み具合を確かめて次の指示を出す、という使い方です。覚えておく条件は一つ、ローカルマシンが点いていること — 操縦する相手はそのマシンだからです。長い作業が終わったときや承認が要るときはスマホに通知も来ます。

公式ドキュメント: Remote Control — continue local sessions from your phone

25. データベースに自然言語で聞く

PostgreSQL・Supabase など主要なデータベースは MCP サーバーで Claude Code とつながります。つないでおけば「先週の登録者のうち離脱した人の共通点は？」のような質問を SQL なしの自然言語で投げられます — スキーマの探索、集計、条件検索まで、Claude がデータアナリストのように処理します。どのデータベースを使っていても、まず「この DB をつないで」と聞くのがいちばん速い始め方です。

26. 深く考えさせるときは ultrathink

ターミナルでプロンプトに ultrathink を添えると（入力欄が虹色になれば適用済み）、Claude が思考（thinking）の予算を最大まで使ってから答えます。そのぶんトークンを多く燃やすので日常使いには向かず — プロンプトをいくら変えてもよい答えが出ない難問や、構造設計の判断のような場面に取っておく切り札です。

公式ドキュメント: Model configuration — effort。執筆時点では思考の深さを effort 設定でも調節できます。

27. 権限を編集して安全に自律走行させる

settings.json でコマンドごとに無条件で許可／必ず確認を決められます。全部を自動承認すると、rm（ファイル削除）や git push --force（衝突を無視する強制プッシュ）のような危険なコマンドまで通り得るので、「こういう危険なコマンドは私に聞くようにして」と頼んで拒否ルールを作らせておきましょう。2026年8月14日から既定値になった auto モードでは、このルールの重みがさらに増しました — 狭く書いた拒否ルールは席を外している間も働き続け、広すぎる許可ルールはむしろ無視されます。ルールが実際に執行される方針になったわけです。

公式ドキュメント: Permissions — 背景は尋ねない既定値の記事を。

28. エージェントチーム — 互いに会話するエージェントたち

サブエージェントと混同しやすいのですが、構造が違います。サブエージェントは並列で働くものの互いに会話せず、メインに報告するだけ。エージェントチームは独立したセッション同士が会話し、作業リストを共有して仕事を分け合います — 各メンバーとあなたが個別に話すこともできます。企画・マーケティング・デザインのエージェントを置いて互いに相談させながら働かせる絵なら、サブエージェントではなくエージェントチームです。トークンは余計にかかりますが、メンバー同士が互いの結果に反論し補い合うべき課題では、成果がはっきり違います。

報告の構造が違えば使い道も違う — 独立した調査はサブエージェント、協業の課題はエージェントチーム。

公式ドキュメント: Orchestrate teams of Claude Code sessions — 執筆時点では実験的な機能で、環境変数 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 で有効化します。方法論が気になるなら、この wiki のハーネスエンジニアリング講義がエージェントチームの運用を12編で扱っています。

むすび

28のコツは三つの原則に縮みます。コンテキストは予算（初級）— 節約し、分割し、見えるようにする。繰り返しは仕組みへ（中級）— うまくいったプロンプトはスキルと CLAUDE.md に固める。並列は隔離から（上級）— ワークツリーと権限ルールを先に置いてから自律を広げる。道具は変わり続けますが、この三つは長持ちするはずです。
