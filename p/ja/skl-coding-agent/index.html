スキルの背景 — コーディングエージェントの誕生

スキルは、ある日突然「じゃーん」と出てきた技術ではありません。コーディングエージェントという土台の上に自然と現れました。その文脈を知ってはじめて、スキルがなぜそういう動き方をするのかが分かります。

エージェントの種類

段階が上がるほど自分でやる範囲が広がります — コーディングエージェントの上で、スキルが可能になります。
  • チャットエージェント — 私たちがふだん使う対話型。
  • ツール呼び出しエージェント — MCP・API をつないで Gmail の確認、予定の登録といった外部の作業をこなす。
  • コーディングエージェント — ツール呼び出しよりもう一段上。Claude Code がこれにあたります。

「ツールは簡素に、残りは LLM に」

はじめは、ツールを精巧にたくさん作ればエージェントがうまく動くだろうと期待しましたが、どれだけよく作っても望むかたちにならないという限界にぶつかりました。そこで発想を変えました。

  • ツールはごく基礎的なものだけ渡す — ファイルの読み・書き・編集・検索、そしてコマンドの実行くらい（およそ六つ）。
  • 残りは LLM が自分でやるようにする。
  • そのためには実行環境とファイルシステムが要る → サンドボックス + 簡素なツール。

こうして生まれたのがコーディングエージェントです。キャンプにあらゆる道具を積んでいく代わりに、ハンマーのような基礎の道具だけ持っていって現地で作って使うやり方に近いものです。

Claude Code がフォルダを咥えて始まる理由 Claude Code が特定のフォルダの中で実行されるのは、まさにこれが理由です。ファイルを読み書きし、こちらのコマンドを実行するには自分の OS とファイルシステムが必要なので、自分のコンピュータ（ローカル）で動きます。スキルは、このコーディングエージェントの上でだけ可能な機能です。
