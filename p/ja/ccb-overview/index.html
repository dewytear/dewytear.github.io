基礎 — 概要・ターミナル・CLAUDE.md

この資料は「Claude Code 基礎 / ファン・ミンホ」の実習講義を映像の順に整理したものです。開発者ではない方にとってターミナルは不慣れな環境ですが、たったひとつの山 — 「フォルダを作り、その場所で claude を実行すること」さえ越えれば、そこから先は AI がほとんどの仕事を代わりにやってくれます。今日の目標はターミナルと仲よくなることです。

この講義でできるようになること

  • ターミナルでフォルダを作り、Claude Code を実行する。
  • CLAUDE.md で自分だけの作業方針を与える。
  • ウェブ調査 → ファイル保存 → ウェブサイト生成までを一度に任せる。
  • 繰り返し作業をスキル（Skill）に、専門的な作業をエージェント（Agent）にして再利用する。
  • プラグインを入れて PDF・PPT・エクセルの文書を扱う。
  • 使用量・コンテキスト・セッションを管理して品質とコストを調節する。

もう一歩 — ハーネス（Harness）

数行のプロンプトで、チーム編成から執筆・挿絵・変換・ウェブサイトまで約 1 時間で仕上がります。

基礎の山を越えると、その次にハーネス（Harness）が待っています。ハーネスを使えば、数行のプロンプトだけで 200〜300 ページを超える本を一冊つくり出せます。講義で見せられた例はこう動きます。

  • 本を書くエージェントを複数（例: 5 つ）作る。
  • リサーチのエージェントが本の素材を用意する。
  • エージェントたちが並列で執筆し、完了を報告する。
  • 必要な挿絵の画像まで生成し、正確な位置に挿入する。
  • 成果物をマークダウン・PDF に変換し、ページをめくって見るウェブサイトまで作る。 — 所要は合計およそ 1 時間。

つまり「Claude Code を始める人のための自分だけの本」も自分で作れます。ハーネス自体はこのあと別のセッションで扱います。

Claude Code とは何か

Claude Code は自分のローカル環境（自分の PC）で動く AI エージェントだと考えてください。ウェブのチャットと違い、自分のコンピュータのファイルを直接読んで修正し、コマンドを実行して仕事を片づけます。作業はプロジェクトごとにフォルダをひとつ作り、そのフォルダの中で進めます。Windows では通常 PowerShell のターミナルで実行します。

既存のサービスとの違い

形態特徴自由度
ウェブブラウザ（Claude・ChatGPT・Gemini）ブラウザ内の制約された環境で AI を使う。ファイルをいちいちアップロードする必要があるもっとも制限的
Claude デスクトップアプリローカルで動くが、ターミナルに比べると制約がある中間
Claude Code（ターミナル）実行したフォルダのファイルに直接アクセス。思いどおりに自由に作業できるもっとも自由

ターミナル環境に少し慣れるだけで、普段 AI チャットを使うようにずっと自由に使えるようになります。

実演 — 議事録 3 つをひとつのレポートに

ファイル一覧を教えなくても、自分で探索・読み込み・分析してレポートを作ります。

議事録ファイル 3 つが入ったフォルダで Claude Code を実行し、こう頼みます。

この議事録 3 つをまとめて 1 つのレポートに要約して。日本語で。

ここで肝心なのはどんなファイルがあるかを教えていないという点です。ウェブのチャットならファイルを自分でアップロードする必要がありますが、Claude Code は

  • いまのフォルダにどんなファイルがあるかをまず探索（search）し、
  • そのファイルを一つずつ読み込み、
  • 内容を分析したうえで結果（レポート）を作ってくれます。

つまり「実行した場所のフォルダ」がそのまま作業空間になり、その中のファイルを自分で扱います。

覚えておくこと Claude Code は claude を実行したそのフォルダ全体にアクセスします。だからプロジェクトごとにフォルダを分け、作業するフォルダの中で実行する習慣が大切です。

ターミナルの基本コマンド

ターミナルに不慣れでも大丈夫です。私たちの目標は「新しいフォルダを作り、その場所へ行って claude を実行」するところまでです。その先は AI が全部やってくれます。Windows は PowerShell を起動すると、たいていユーザーフォルダから始まります。

四つだけ覚えてください

コマンド意味やること
pwdprint working directoryいま自分がどのフォルダにいるかを表示
cd <フォルダ>change directory別のフォルダへ移動（例: cd Downloads）
mkdir <名前>make directory新しいフォルダを作る（例: mkdir kist-test）
claude—いまのフォルダで Claude Code を実行

実習の手順

新しいフォルダを作り、その場所へ移動して claude を実行する — これが今日の関門です。
# 1. いまの位置を確認
pwd
# 2. ダウンロードフォルダへ移動
cd Downloads
# 3. 新しいフォルダを作る
mkdir kist-test
# 4. 作ったフォルダへ移動
cd kist-test
# 5. そのフォルダで Claude Code を実行
claude

こうして新しく作ったフォルダで claude を実行すると、これ以降 Claude Code はそのフォルダの中ですべての作業をするようになります。

今日の関門 「フォルダを作る → その場所へ移動 → claude を実行」 — ここまで越えれば、あとは AI の助けを借りられます。詰まったら遠慮なく助けを求めてください。

CLAUDE.md — 作業方針のファイル

Claude Code は、つねに参照するファイルとして CLAUDE.md というマークダウンファイルを使います。AI にどんな指示を出すときも、いつも一緒に含まれるファイルだと考えてください。だから長くなりすぎないように、大事な内容を明快に入れる必要があります。

四つのレイヤー

同じ CLAUDE.md でも置き場所によって適用範囲が変わり、下の階層ほど優先されます。

同じ CLAUDE.md でも、どこに置くかで適用範囲が変わります。

  • 会社（マネージド） — 会社の全メンバーに適用。
  • ユーザー全体 — 自分の PC でどのプロジェクトをしていても、つねに適用。
  • プロジェクト — そのプロジェクトでのみ適用（同僚と共有）。
  • プロジェクトローカル — プロジェクトの中だが共有しない、自分の PC だけのための方針。

実習 — 方針を作る

新しいフォルダで claude を実行したあと、こう頼んで CLAUDE.md を作ります。

このフォルダに CLAUDE.md ファイルを作って。
方針: 回答はつねに日本語で書き、
新しく作るファイル名にはつねに _new を付けて。

ファイルができると、その中にいま与えた方針（「日本語で書く」「新しいファイルに _new を付ける」）が記録されます。以降のすべての作業はこのフォルダ配下でつねにこの方針に従います。たとえば「簡単な詩をテキストファイルに保存して」と頼めば、結果は日本語で書かれ、ファイル名には _new が付きます。

何を入れるとよいか

  • 元のファイルを修正させないためのルール
  • コード（例: Python）を書くときに守るべきルール
  • 出力の形式・ファイルの保存方法
  • 書きものの文体・言語
コツ CLAUDE.md は AI に作らせてもよいし、自分で開いて直してもかまいません。Windows ではプロンプトの改行がうまくいかないことがありますが、改行なしでそのまま続けて書いても問題ありません。

ここまでが基礎です — フォルダを作り、起動し、指針を植えました。次の章実習では、ウェブ調査からデザインシステムの抽出、論文整理まで実際の作業をひと流れで回します。
