段階的な読み込み（スキルの中心原理）

スキルのいちばん中心にある原理は段階的な読み込み（progressive disclosure）です。スキル全体をコンテキストに載せるのではなく、メタデータだけを先に載せておいて、必要なときに残りを取り出します。

図書館の本の表紙のたとえ

コンテキストに入るのは、登録されたスキルのメタデータ（名前 + 説明、3〜4 行、スキルあたり約 100 トークン）だけです。図書館に本がずらりと並んでいて、私たちは本の表紙（タイトル・簡単な説明）だけを眺め、必要になったら取り出して読むのと同じです。メタデータがとても小さいので、100 個以上入れてもコンテキストをほとんど食いません。（JSON のツールはスキーマ全体が先にコンテキストを占め、数が増えるほど負担が大きくなるのと対照的です — だから Claude Code は MCP ツールのスキーマも遅延ロードします）

3 段階の読み込み

上へ行くほどつねに、下へ行くほど必要なときだけ — 読み込む時点が段階ごとに遅くなります。
レベル内容読み込む時点
1メタデータ（SKILL.md の名前・description）つねに読み込む（スキルあたり約 100 トークン）
2指示（SKILL.md の本文、マークダウンの使い方）そのスキルが呼ばれたとき
3リソース · スクリプト · テンプレート（同梱ファイル）必要なときだけ（スクリプトは読み込まずに実行するだけ）

同梱ファイルは必須ではありません。言葉（マークダウン）だけで足りるならファイルなしでもよく、実行するスクリプトやテンプレートが要るなら含めます。ファイルがあるほど、より決定論的な結果が得られます。ちなみに公式のガイドは SKILL.md の本文を5K トークン未満に保ち、長い内容は同梱ファイルへ分けることを勧めています。

マニュアルのたとえ（組み立て製品・マトリックスのヘリ） 通販で組み立て製品を買うと、マニュアルを見ずに完成写真だけ見て組み立て、ネジが余った瞬間にマニュアルを取り出します。スキルの指示も発動したときにちょうど取り出して読み、ふだんは取り出しません。映画マトリックスで、ヘリの前でマニュアルを一瞬でロードして操縦する場面と同じ感覚です。
確認のコツ Claude Code で /context と打つと、システムプロンプト・カスタムツール・スキルなどがそれぞれ何 % を占めているかが見えます。積んだスキルが多くてもトークンをほとんど使っていないことを確認できます。
