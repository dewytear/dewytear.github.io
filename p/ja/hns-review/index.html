生成結果のレビュー — エージェント・スキル・オーケストレーター

オーケストレーターがエージェントたちを整え、スキルが注入され、成果物は _workspace に集まります。

ハーネスが組まれると何が作られるのかを見ていきます。Claude Code はエージェントやスキルなどを.claude フォルダの下に生成します。

作られたエージェント（例）

「国家 R&D 予算・ポスト PBS」という課題では、こんなチームが組まれました。

  • R&D 予算の定量分析担当 — 予算の配分・調整案を省庁・事業・年度の単位に分解し、政府／出資機関の比率の変化を追跡。
  • 政府出資機関のガバナンス・財政の専門家 — PBS から任務中心型の体制への転換戦略を導く。
  • 国家 R&D 政策のリサーチャー — 予算・政策文書・報道資料・NIS/NSTC の議題などを一次情報から調査。
  • レポート執筆エージェント — 前段の成果物を集めてレポートに書き上げる。
  • QA レビュアー — 単なる誤字脱字ではなく主張と出典の整合、数値の一貫性、提言の論理のつながりを突き合わせて確認。

注入されるスキル

エージェントだけでは足りないので、専門化したスキルを作って注入します。例: 予算の定量分析の手法（標準の様式・計算のルール・チェックリスト）、政策レポートの引用検証（検証の軸・優先順位）、政府向け政策レポートの書式（目次）。

オーケストレーター（つねに 1 つ）

エージェントたちが横道へそれないように整える PM の役割です。細かい作業をのぞき込むことはせず、「エージェントたちがうまく働いているか」だけを見ます。Phase 0 から各段階に必要なエージェントが何かまで、ワークフローが事前に計画されています。（Claude Code のプランモードに近い感覚）

レビューと実行の準備

  • レビューの工程は必須です。「エージェントをもっと追加」「意図と合わないので修正」「ハーネスを直して」のようにフィードバックすれば、エージェント／スキルが新しく生まれたり補強されたりします。
  • エージェントが動的にロードされない問題があります。/agents に見えないときは /exit してから入り直すとロードされます。
_workspace フォルダ ハーネスで実行すると _workspace フォルダができて、エージェントたちが作った中間の成果物が集まります — 一次リサーチ、予算分析、QA レポート（クリティカル・メジャー・マイナーの各課題）と修正案、限界事項、そして根拠となる出典まで。出典ベースなのでハルシネーションが大きく減ります。
