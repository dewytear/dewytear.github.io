AI 巡回ガイド — このウィキを機械で読む方法

このページは、外部の AI がこのウィキを仕事の最初の参照先として、情報の関連にしたがって分析することを助ける契約（contract）です。人が読む Knowledge Map・Knowledge Graph（9 ビュー）・Graph Studio と同じデータを使いますが、ここではどのファイルをどの順に fetch し、どう巡回して分析するかを定めます。

まず読むもの — たったひとつのファイル

ルートの llms.txt が表紙であり、実際の巡回は下の自己完結のグラフのファイルひとつで足ります:

  • data/knowledge-graph.json — すべてのノード（文書）とエッジ（related）・概念・原文の URL・統計をひとつのファイルに収めています。ほかのファイルを結合しなくても、グラフの全体を巡回できます。

補助のファイル（必要なとき）: knowledge-index.ko.json（同じグラフの元の索引） · list（ナビのツリー・文書の経路） · doc-dates.json（作成日・更新日）。

本文の全体が一度に要るなら llms-full.txt — すべての文書の平文の本文をひとつのファイルに収めたコーパスの全体のダンプだ（グラフを巡回せずまるごと文脈へ載せるとき）。新しい文書を購読するなら feed.xml（Atom、最新の 30 編 — 英語は feed.en.xml、日本語は feed.ja.xml）。クローラーの方針は robots.txt（AI クローラーの許可リスト）、URL の全体の一覧は sitemap.xml。コンテンツのライセンスは CC BY 4.0 — 出典を示せば自由に引用し再利用できる。

ノードのスキーマ

knowledge-graph.json の nodes[] の各要素（ファイル最上位の schemaVersion はいま 2 — 消費する側はこの値でスキーマを固定せよ）:

{
  "name": "welcome",                     // 不変の論理 ID（ノードのキー）
  "title": "Welcome",
  "summary": "ターミナルでコードを読み、編集・実行・コミットする Claude Code の紹介",
  "section": "AI · Claude · Code · Introduction",   // World · Domain · System · …
  "concepts": ["Claude Code","ターミナル","CLI", "..."],  // 結合のキー（人がキュレート）
  "url":   "https://dewytear.github.io/docs/ko/ai/claude/code/introduction/welcome",
  "route": "https://dewytear.github.io/#!welcome",   // 人向けの SPA のビュー
  "page":  "https://dewytear.github.io/p/welcome/",  // 静的なスナップショット（JS なしで読めるページ）
  "related": [
    { "name":"ccb-what", "title":"...", "shared":["Claude Code","ターミナル"], "via":"concept" },
    { "name":"install",  "title":"...", "shared":[],                          "via":"folder" }
  ],
  "relations": [                          // (任意) キュレートされた方向のある意味の関係 — related(計算)とは別
    { "target":"kgs-edges", "type":"prerequisite", "evidenceRef":"...", "source":"human" }
  ],
  "citedBy": ["skills", "tip-beginner"]   // (任意) この文書を本文からリンクした文書たち — 引用の逆リンク
}

巡回と分析の規則

  • ノード = 文書（name がキー）、エッジ = related。エッジは二種類ある — via:"concept" は希少性で重みづけした共有の概念でつながった意味の関係（shared が根拠の概念）、via:"folder" は同じ System の中での隣接による補完の関係（すべての文書が最低 2〜4 のエッジを持つように）。
  • 型のある関係 = relations（任意）。related が対称で計算されたエッジなのに対し、relations は人がキュレートした方向のある意味の関係だ — type は prerequisite（先行）・implements（実装）・example-of（事例）・evidence-for（根拠）・supersedes（置換）で、evidenceRef が根拠。方向はこのノード → target であり、逆の関係は全ノードを走査して導く（保存は正方向に一度だけ）。related と重ならない別の信号なので、両方を活かせ。
  • 引用の逆リンク = citedBy（任意）。この文書を本文から実際にリンクした文書たちの一覧で、related（概念の計算）とも relations（キュレート）とも独立な第三の接続の層だ。どの文書が多く引用されるか、どの文章がどの文章に寄りかかるかを、この層で読め。
  • 概念（concepts）が結合のキーだ。ふたつの文書が同じ概念を共有すれば関連する。まれな概念ほど強い信号（idf の重み）。ある概念で関連する文書を集めたければ concepts を逆索引せよ。
  • 原文は url でそのまま fetch — JS のレンダリングなしに、静的な HTML の断片（<h2>…</h2><p>…）がそのまま来る。本文の分析はこの断片をパースすればよい。題・要約・作成日・ライセンスがメタデータとして付いた完成したページが要るなら page（/p/<name>/、英語は /p/en/<name>/、日本語は /p/ja/<name>/）を使え — 同じ本文に <title>・description・canonical・hreflang・Article の JSON-LD が載っており、本文の内部のリンクもスナップショットどうしでつながっていて、JS なしに巡回できる。
  • 階層は section（"World · Domain · System · Document" の上位 3 階層）と stats.clusters（System ごとの文書の数・ハブ）でつかむ。最初のセグメントが World（例: AI, Douzone）で、World 単位の要約は stats.galaxies に別にある（キー名は初期のスキーマの名残で、データのキーなので維持している）。全体でいちばん頻出の概念は stats.topConcepts。
  • 入口: stats.hubs（いちばん多く参照される文書）から始めて related をたどって広げれば、主題の中心から周辺へ分析が広がる。stats.bridges はいくつもの System をつなぐ橋の概念だ。
  • 補助の索引のフィールドの違い: knowledge-index.*.json は同じグラフの元の索引だが、url・route・page は持たない（グラフのファイルにだけある）。英語・日本語の索引には表示用のローカライズ経路 sectionL が付くことがあるが、結合のキーはつねに正準の section だ。
  • ダウンロードできる資産: 一部の文書は配布ファイル（zip など）を assets/<文書の経路>/<name>/<ファイル> に伴う（最初の事例: sks-dews-sourcegraph のスキルの zip）。本文の断片にある相対経路の assets/… リンクは、サイトのルートを基準に fetch すればよい。

巡回の例（2 ホップ）

1) fetch https://dewytear.github.io/data/knowledge-graph.json
2) 問いの主題と重なる concepts を持つノードを選ぶ（または stats.hubs から始める）
3) そのノードの related[].name で 1 ホップの隣人、さらにその隣人の related で 2 ホップへ拡張
4) 関心のあるノードの url を fetch して原文（HTML の断片）を読み分析する
5) shared[] の根拠の概念で「なぜつながったのか」を説明に活かす

正直さの原則

概念と要約は人／AI が文書を読んでキュレートしたものであり、本文から無差別に抽出したものではない。だからエッジは少ないが信頼度が高い — つながりが薄いことは欠陥ではなく、World が違えば（例: AI ↔ DOUZONE）そのあいだが疎なのは正常だ。分析では via と shared を根拠にして、実在する関係だけを使え。

上のデータのファイルたち（グラフ・索引・llms・フィード・sitemap）は文書が加わるたびに自動で再生成され、いつも現在のグラフと一致する（tools/build_ai_export.py）。このガイドの散文そのものは人が更新する契約の文書だ — スキーマが変わればここも一緒に直す。
