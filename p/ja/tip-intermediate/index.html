中級 — セッションを仕組みに変える11の方法

初級編が一つのセッションをきれいに回す習慣だったのに対し、中級は繰り返すものを仕組みへ移す話です。並列で調べさせ、うまくいったプロンプトをスキルに固め、CLAUDE.md をルーターとして使う — 公開講座のコツ10〜20番を公式ドキュメントと突き合わせて整理しました。

10. サブエージェントを並列で回す

サブエージェントとは、メインセッションが部下のように立ち上げる別のエージェントです。それぞれが自分専用のコンテキストウィンドウを持ち、要約だけをメインに報告するので、調査や検証のような読む量が多い仕事に特に向きます — 読んだ分がメインのコンテキストを燃やしません。「参考資料を10件以上、並列のサブエージェントで調べて」と頼めば、複数のエージェントが同時に別々の角度から調べ、メインが総合します。並列なので時間も節約できます。

サブエージェントが燃やすのは自分のコンテキスト — メインは要約だけ受け取って軽いまま。

公式ドキュメント: Run agents in parallel · Create custom subagents。サブエージェント同士は会話しません — 会話が要るなら上級編のエージェントチームです。

11. 自分だけのスキルを作る

スキルは .claude/skills/ フォルダに置く再利用プロンプトのファイルです。毎回コピペしていた長い指示を一度定義しておけば、説明文（description）に合う依頼が来たとき Claude が自分で取り出して使い、スラッシュで直接呼ぶこともできます。何度も同じことを頼んでいるなら、それがスキルを作る合図です。作り方は簡単 — 「いまやったのをスキルにして」と言えば Claude が作ってくれます。予測できる結果を得るためのこうした装置を総称してハーネス（harness）と呼びますが、スキルはその代表例です。

この wiki のスキル講義が原理からセキュリティまで12編で扱っています。公式ドキュメント: Skills

12. サブエージェントには安いモデルを

検索してテキストを読んでくる仕事に最上位モデルは無駄です。任せるときに「サブエージェントは Haiku で回して」と明示すればよく、カスタムのサブエージェント定義なら model: haiku フィールドで固定もできます。収集は速くて安いモデルに、総合や設計判断は高いモデルに — この分業がトークンを大きく節約します。

モデル別の単価: 公式 Pricing 文書 — 執筆時点で Haiku 4.5 は入力 $1／出力 $5（百万トークンあたり）と、最上位モデルの数分の一です。

13. セッションが終わったら CLAUDE.md を更新 — ただし150〜200行の上限で

このセッションで新しい慣習ができたり、やり方が変わったりしたら、CLAUDE.md に反映しておきましょう。しなければ、次のセッションの Claude はその変化を知りません。ただし CLAUDE.md は毎セッション無条件に読まれるファイルなので、長くなるほど開始時のコンテキストを食います — 更新を頼むとき「150〜200行の上限で」と添えれば、Claude がうまく圧縮します。公式ドキュメントも「会議の合間にざっと読めなければ長すぎる」と勧めています。

公式ドキュメント: Memory — CLAUDE.md

14. CLAUDE.md をルーターとして使う

13番の上限と「たくさん情報を渡したい」という欲を両立させる方法です。内容そのものを CLAUDE.md に入れる代わりに、「こういう用があればこのファイルを読め」という案内だけを入れます。例:「コード構造が知りたければ docs/architecture.md を読め」。必要なときだけそのファイルを読みに行くので、文脈は伝えつつ常時のコンテキストは節約できる賢い構造になります。これも「この案内を CLAUDE.md にルーターとして足して」と頼めば済みます。

15. おかしいと思ったら、終わるのを待たずに切る

進行中に方向が違うと見えたらすぐ止めましょう（Esc）。そして「意図はこうだったのに、なぜそうしたの？」と聞けば Claude が自分の意図を説明します。そこで方向を直してから続きをやらせればいい。終わるまで待ってから直すのは時間とトークンの無駄なうえ、間違った結果がコンテキストに残って以後の判断まで汚します。停止ボタンを怖がる理由はありません。

16. 突き返す — そして当たったら記録する

最初の成果物が気に入らないのに直し方を言葉にできないときは、抽象的でいいから突き返しましょう — 「もっと上質に」「完成度を上げて」「まったく別の観点でやり直して」。最初の試みが外れたという文脈を Claude が持った状態なので、二度目の的中率はずっと上がります。たいていの人は一度で諦めますが、二、三度突き返すと驚くことが多い。そして望んだ結果が出た瞬間が記録の瞬間です — 「これいいね、スキルにして」「CLAUDE.md に反映して」。記録しなければ、次も同じ道をもう一度歩くことになります。

17. /rewind で時間を巻き戻す

途中の結果が間違ったとき、「元に戻して」と言葉で頼むと、戻す過程でまた誤りが入り得ます。代わりに /rewind を — チェックポイントの一覧から時点を選べば、それ以降のファイル修正が丸ごと巻き戻ります。コードと会話のどちらを戻すかも選べます。

公式ドキュメント: Checkpointing — セッション中の修正は自動でチェックポイントとして積まれます。

18. フックで通知を受ける

フック（hook）は、Claude Code の特定の時点 — 作業完了、承認待ちなど — で自動実行されるコマンドです。「セッションの作業が終わるたびに音で知らせるフックを設定して」と頼めば、Claude が設定ファイルに書いてくれます。セッション一つなら要りませんが、複数のプロジェクトとセッションを並列で回し始めると、どこで何が終わったかを教えてくれるこの装置が必須になります。手軽な方法としては preferredNotifChannel を terminal_bell にする手もあります。

公式ドキュメント: Automate actions with hooks — この wiki の Hooks 紹介も参考に。

19. Claude には目がある — 画像を渡す

エラーメッセージ、気に入ったウェブサイト、UI の画面 — 言葉で説明しにくいものはスクリーンショットを撮ってそのまま貼りましょう。ターミナルもデスクトップアプリも、画像のドラッグや貼り付けを受け付け、Claude が読んで理解します。エラー画面を撮って投げるほうが、エラー文を手で書き写すより速くて正確です。

20. スクリーンショットからテンプレートを作る

19番の応用です。参考にしたいデザイン — カードニュースのレイアウト、色使いのよいページ — を撮って渡し、「この画像を参考にテンプレートを作って」と明示しましょう。要は丸写しではなく、色とレイアウトの構造を抜き出して再利用できる型にすることです。
