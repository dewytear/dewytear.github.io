中級 — セッションを仕組みに変える11の方法

初級編が一つのセッションをきれいに回す習慣だったのに対して、中級は繰り返すものを仕組みへ移す話です。並列で調べさせ、うまくいったプロンプトをスキルに固め、CLAUDE.md をルーターとして使う — シリーズのコツ10〜20番を公式ドキュメントと突き合わせて整理しました。

文書情報（出典） · 根拠: Claude Code 公式ドキュメント（2026-08-14 時点）

10. サブエージェントを並列で回す

サブエージェントは、メインセッションが部下のように立ち上げる別のエージェントです。それぞれが自分専用のコンテキストウィンドウを持って要約だけをメインに報告するので、調査や検証みたいに読む量が多い仕事にぴったり — 向こうが読んだ分はメインのコンテキストを燃やしません。並列だから時間も節約できます。

ビューティーブランドの Instagram マーケティングで何がいちばん大事か
調べたい。サブエージェントを並列で回して参考資料を10件以上集めて —
成功事例、失敗事例、最近のアルゴリズム変化をそれぞれ別のエージェントが
担当して、最後にあなたが共通点をまとめて。
サブエージェントが燃やすのは自分のコンテキスト — メインは要約だけ受け取って軽いまま。

実はこの wiki も同じパターンで動いています。ニュース記事を一本載せる前の複数報道のクロス検証 — 同じ出来事を扱う複数の出典を同時に読んで、数値や日付が合うか突き合わせる仕事 — がまさにこれです（各記事の末尾のファクトチェックのメモがその成果物）。百編を超える文書を総ざらいする文体の全数監査みたいな、読む量が山ほどある仕事も同じ — 読むのはサブエージェントが分担して、メインは要約を受けて判定だけ。

公式ドキュメント: Run agents in parallel · Create custom subagents。サブエージェント同士は会話しません — 会話が要るなら上級編のエージェントチームです。

11. 自分だけのスキルを作る

スキルは .claude/skills/ フォルダに置く再利用プロンプトのファイルです。毎回コピペしていた長い指示を一度定義しておけば、説明文（description）に合う依頼が来たとき Claude が自分で取り出して使うし、スラッシュで直接呼ぶこともできます。何度も同じことを頼んでいる？ それがスキルを作る合図です。作り方も簡単 — 「いまやったのをスキルにして」の一言で Claude が作ってくれます。こうした、予測できる結果を得るための装置を総称してハーネス（harness）と呼びますが、スキルはその代表選手です。

この wiki のスキル講義が原理からセキュリティまで3章で扱っています。公式ドキュメント: Skills

12. サブエージェントには安いモデルを

検索してテキストを読んでくる仕事に最上位モデルはもったいない。任せるときに「サブエージェントは Haiku で回して」と一言添えるだけでOKです — カスタム定義なら model: haiku フィールドで固定もできます。収集は速くて安いモデルに、総合や設計判断は高いモデルに — この分業がトークンを大きく節約します。

モデル別の単価: 公式 Pricing 文書 — 執筆時点で Haiku 4.5 は入力 $1／出力 $5（百万トークンあたり）と、最上位モデルの数分の一です。

13. セッションが終わったら CLAUDE.md を更新 — ただし150〜200行の上限で

このセッションで新しい慣習ができたり、やり方が変わったりしたら、CLAUDE.md に反映しておきましょう。しないと、次のセッションの Claude はその変化を知りません — 文脈がないんですから。ただし注意がひとつ。CLAUDE.md は毎セッション無条件に読まれるファイルなので、長くなるほど開始時のコンテキストを食います。更新を頼むときは「150〜200行の上限で」を必ず添えてください — Claude が上手に圧縮してくれます。公式ドキュメントも「会議の合間にざっと読めなければ長すぎ」と言っています。

公式ドキュメント: Memory — CLAUDE.md

14. CLAUDE.md をルーターとして使う

13番の上限と「たくさん情報を渡したい」という欲、両方を叶える方法があります。内容そのものを CLAUDE.md に入れる代わりに、「こういう用があればこのファイルを読め」という案内だけを入れるんです。必要なときだけそのファイルを読みに行くので、文脈は全部伝わるのに常時のコンテキストは節約できる、賢い構造になります。

docs/architecture.md にこのプロジェクトのコード構造をまとめてある。
コード構造が知りたい命令やセッションがあればこのファイルを読むよう、
CLAUDE.md にルーターとして足して。CLAUDE.md 本体には一行だけ残して。

15. おかしいと思ったら、終わるのを待たずに切る

進行中に方向が違うと見えたら、すぐ止めましょう（Esc）。停止ボタンを怖がる理由はひとつもありません。切ってから「意図はこうだったのに、なぜそうしたの？」と聞けば Claude が自分の考えを説明してくれるので、そこで方向を直して続きをやらせればいい。終わるまで待ってから直すのは時間とトークンの無駄なうえ、間違った結果がコンテキストに残って以後の判断まで汚します。

16. 突き返す — そして当たったら記録する

最初の成果物が気に入らないけど、直し方を言葉にできない？ 抽象的でいいから突き返してください。最初の試みが外れたという文脈が向こうにある状態なので、二度目の的中率はぐっと上がります。たいていの人は一度で「できないのかな」と諦めますが、二、三度突き返すと驚くことが多いんです。そして望んだ結果が出た瞬間が、記録の瞬間 — ここで素通りすると、次も同じ道を最初から歩くことになります。

# 気に入らないとき — 直し方が分からなくてもOK
いまいち。もっと上質に、完成度を一段上げてやり直して。
まったく別の観点の案もひとつ作ってみて。

# 当たったとき — ここで終わらせない
この結果すごくいい。いまの過程をスキルにして。
次に「カードニュース風で」と言ったらこれが出るように。

17. /rewind で時間を巻き戻す

途中の結果が間違ったとき、「元に戻して」と言葉で頼むと、戻す過程でまた誤りが入りかねません。代わりに /rewind を — チェックポイントの一覧から時点を選べば、それ以降のファイル修正が丸ごと巻き戻ります。コードと会話のどちらを戻すかも選べます。

公式ドキュメント: Checkpointing — セッション中の修正は自動でチェックポイントとして積まれます。

18. フックで通知を受ける

フック（hook）は、Claude Code の特定の時点 — 作業完了、承認待ちなど — で自動実行されるコマンドです。「セッションの作業が終わるたびに音で知らせるフックを設定して」と頼めば、Claude が設定ファイルに書いてくれます。セッション一つなら要らないんですが、プロジェクト複数にセッション10本と並列で回し始めると、どこで何が終わったかを教えてくれるこの装置が必須になります。いちばん手軽なのは preferredNotifChannel を terminal_bell にする方法。

公式ドキュメント: Automate actions with hooks — この wiki の 基礎講義の拡張編（Hooks の節）もどうぞ。

19. Claude には目がある — 画像を渡す

エラーメッセージ、気に入ったウェブサイト、UI の画面 — 言葉で説明しにくいものはスクリーンショットを撮ってそのまま貼りましょう。ターミナルもデスクトップアプリも、画像のドラッグや貼り付けを受け付けて、Claude が読んで理解します。エラー画面を撮って投げるほうが、エラー文を手で書き写すより速くて正確です。

20. スクリーンショットからテンプレートを作る

19番の応用です。参考にしたいデザイン — カードニュースのレイアウト、色使いのいいページ — を撮って渡して、「この画像を参考にテンプレートを作って」と明示しましょう。ポイントは丸写しじゃなく、色とレイアウトの構造を抜き出して再利用できる型にすることです。
