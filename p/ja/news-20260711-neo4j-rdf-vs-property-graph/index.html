RDF かプロパティグラフか — 知識グラフのためのふたつのモデル（Neo4j）

Neo4j の主席科学者 ジム・ウェバー（Jim Webber）の記事 “RDF vs. property graphs: Choosing the right approach for implementing a knowledge graph”（2024-06-04）を整理した文書です。生成 AI で知識グラフの需要がふたたび高まるなか、知識グラフを実際に実装するときにぶつかる根本の選択 — 1990 年代のセマンティックウェブから来た RDF（トリプル）か、現代のグラフデータベースのプロパティグラフか — を、著者の論旨のとおりに比べます。このウィキのオラクルのオントロジー・プロパティグラフがオラクル（SQL/PGQ）の視点だとすれば、この記事はNeo4j・セマンティックウェブの視点から同じ問いを見ます。

なぜいま知識グラフなのか

生成 AI の市場が急増し（オライリーの集計で前年比 3,600%）、知識グラフの需要がよみがえりました。知識グラフは高度につながった異質なデータに強く、LLM を事実に接地（grounding）させるのによく合います。data.world・Microsoft の独立した研究も RAG に知識グラフを使う利点を挙げました。ところが知識グラフを構築・運用するには数多くの設計の決定がついて回り、その最初の分かれ道が RDF かプロパティグラフか、です。

知識グラフとは — エンティティ · 関係 · 組織の原理

知識グラフはつながったエンティティを保存・組織し理解するための意味論的に豊かなデータモデルです。三つの要素からできています。

  • エンティティ（Entities） — 組織・ドメインのデータ。
  • 関係（Relationships） — エンティティが互いにどう相互作用・関連するか。データに文脈を与える。
  • 組織の原理（Organizing principle） — 中心となる概念についてのメタ情報。データと利用者のあいだの契約（メタのレイヤー）の役割。

要は組織の原理の複雑さを、仕事に合わせて選ぶことです。著者は、その幅が単純なラベル（ノードのラベル + 名前つきの関係） → 製品の階層（Product Line → Category → Product） → 完全なオントロジー（ビジネスの語彙の全体）まで広いと言います — 重いオントロジーがいつも正解なわけではありません。

知識グラフの“組織の原理”はスペクトラム — 単純なラベルから完全なオントロジーまで、必要なぶんだけ。

RDF — トリプルとセマンティックウェブ

RDF（Resource Description Framework）はウェブでのデータの交換のための W3C 標準です。基本の単位はトリプル — 主語（subject）・述語（predicate）・目的語（object）の三つからなる文であり、それぞれ URI で識別されます。主語はグラフの資源（ノード）、述語はエッジ（関係）、目的語はまた別のノードかリテラルの値です。

セマンティックウェブの夢、そしてトリプルストア RDF はセマンティックウェブとともに知られました — よく定義された意味を持つ機械可読なデータを公開のウェブに載せ、ソフトウェアのエージェントがウェブを巨大な分散データ構造のように扱えるようにしよう、という夢。メタデータ（オントロジー）と問い合わせ言語（SPARQL）を組み合わせて、ウェブのデータから知識を推論するという構想でした。この夢は実現されず、その技術はローカルの DB に適用された“トリプルストア”へ流れていきます。当時は SQL が支配的で押されていましたが、グラフ DB の台頭とともにトリプルストアが“グラフ DB の一種”として再マーケティングされます。オントロジーの規則に従ってトリプルの上で推論する SPARQL が、その問い合わせ言語です。

RDF の実務上の限界

RDF は DB のシステムを念頭に設計されたわけではなく、実装が厄介です。著者が挙げる要点:

  • 同じ型の固有の関係を区別できない — ふたつのノードが同じ型の関係で何度つながっても、RDF ではトリプル一つに潰れます。表現力が制限されます。
  • 関係が一級市民ではない — 関係がトリプルの中に隠れているので、関係に属性をつけたり、同じ型の多重の関係を表したりするには新しいノードとトリプルをさらに作らなければなりません（リレーショナル DB の結合テーブルと同じ迂回）。例: ソーシャルネットワークで互いにフォローする多重の関係を保存しようとすると、トリプルが増え続けます。モデルが冗長で複雑になり、保守が煩わしくなります。
  • SPARQL は終了が保証されない — オントロジーがデータを“賢く”しますが、問い合わせが終わるという保証がなく、利用者がいつまでも答えを待つことがありえます。

オントロジー主導のやり方そのものの現実的な負担も三つあります。

負担内容
スキルの壁標準のオントロジーを作る専門性の習得に時間と労力がかかり、特殊性が高くて組織の中で移転（transfer）しにくい。
資源の集約オントロジーの構築は長くかかり、完成しないと配備できないので、ビジネスの価値までの時間が大きく遅れる。
現実との遅れビジネスはオントロジーの更新より速く動くので、オントロジーが常に後れる → 知識グラフが“過去のビジネス”を映す。

それでも RDF が合う場所はあります — 互いによく理解されたふたつのローカルなドメインのあいだの情報の交換のための橋としてのオントロジー。そして著者は付け加えます: オントロジーは結局グラフなので、セマンティックウェブのスタックの外でも使えます。

プロパティグラフ — 描いたとおりに保存する

プロパティグラフは情報をノード・関係・属性で組織します。

  • ノード（Node） — 一つ以上のラベルで役割を示し、任意の属性（key-value）を持つ。
  • 関係（Relationship） — ふたつのノードのあいだの方向のある名前つきのつながり。つねに方向・型・始点のノード・終点のノードを持ち、ノードと同じく属性を持てる。方向があっても両方向に効率よく探索できる。
  • 属性（Property） — ノードと関係の両方につく key-value。

設計の原則は論理モデルとできるだけ似た形で保存すること — ホワイトボードに描いた絵そのままです。Neo4j のようなネイティブなプロパティグラフでは物理の保存モデルが論理モデルと同型（isomorphic）です: “描いたとおりに保存する（what you draw is what you store）”。問い合わせ言語はプロパティグラフの ISO 標準 GQL で、いちばん広く使われている実装が Cypher です。Cypher・GQL は SPARQL とは違い推論ではなくパターンマッチングに集中する宣言型なので、たいていグラフの大きさに比例する時間で問い合わせが終わります。

同じ“関係に属性”を、プロパティグラフは関係に一度で載せ、RDF は関係が一級ではないので新しいノード・トリプルを足して表す。

プロパティグラフの長所

プロパティグラフはデータの交換のフォーマットではなく、アプリケーション・分析のための DB のモデルとして設計されました。RDF とは違い多対多・同じ型の多重の関係を手軽に扱え、あらかじめ決められた構造に閉じ込められないので、知識グラフを少しずつ育てていけます。著者が挙げた長所は四つ:

長所内容
単純さ（Simplicity）素早く立てて使う — 初心者も熟練者も低い複雑さ。
詳しさ（Detailed）ノードと関係の両方にデータを持たせ、エンティティとつながりがビジネスを正確に映す。
相互運用（Interoperable）Neo4j は RDF を消費・生成して既存のトリプルストアと連携し、リレーショナル・ドキュメント DB など現代のシステムとも統合。
標準への準拠（Standards）ISO GQL で、リレーショナル DB が ISO SQL で得ていたのと同じ信頼をグラフでも。

事例 — プロパティグラフの成果

  • NASA — 1950 年代の末からのプロジェクトのデータが組織のサイロに埋もれていたが、DB をプロパティグラフに移して数百万件の歴史の文書を収めた。エンジニアが過去のプロジェクトから傾向と教訓を見つけ、災害を予防する — “火星ミッション”の準備で数百万ドルと数年の R&D を節約。
  • Basecamp Research — Neo4j で地球の生物多様性の世界最大の知識グラフを構築。生物・化学・環境のデータをつないで知られたタンパク質を 50% 拡張し、50 億以上の生物学的な関係を記録 — タンパク質の設計・生成 AI の優れた資源。
  • Novo Nordisk — Neo4j をもとにした知識グラフで StudyBuilder を動かし、臨床データの収集・報告を簡素化。CDISC・SNOMED・UCUM など絡み合ったデータ標準を渡り歩きながら、縦断の一貫性・規制の順守・自動化・再利用を確保（オープンソースで公開）。

結論 — 基本はプロパティグラフ、必要なときに RDF の組織の原理を載せる

モデルの選択は状況に左右されますが、自由に選べるならたいてい単純さと機敏さのゆえにプロパティグラフを採ります — 道具・文献・教育・人材・ISO 標準の生態系も広いのです。グラフはセマンティックウェブの時代のあと大きく進み、現代のベストプラクティスはふたつの学派の両方から採ります。著者の勧めははっきりしています:

著者の勧め 既定はプロパティグラフに置き、システムが必要とするときに RDF の世界の組織の原理（タクソノミー・オントロジー）をレイヤーとして載せよ — 技術的な前提条件としてではなく。
二者択一ではない — プロパティグラフを基本に、RDF の組織の原理は必要なときに載せるレイヤーとして。

まとめ — 三つの文で

  • 知識グラフはエンティティ・関係・組織の原理からなり、組織の原理の複雑さは仕事に合わせて選ぶ。
  • RDF は標準・相互運用・既製のオントロジー・セマンティックなデータに強いが、関係が一級ではなく（多重の関係・関係の属性にトリプルとノードが増える）、SPARQL の終了の保証やオントロジーの維持費の負担がある。
  • 著者の勧めはプロパティグラフを基本に使い、必要なときに RDF のタクソノミー・オントロジーを組織の原理のレイヤーとして載せること — 前提条件としてではなく。
