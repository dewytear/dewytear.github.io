レベル 2 · 主題でまとめる（LLM ウィキ + メモリ）

ファイルが積み上がると主題ごとに編んでおきたくなります。そこで登場するのが LLM ウィキです。この段階の問いは「この主題に関するものを全部集めて」。レベル 1 の上にインデックスとつながりを載せる、と考えれば大丈夫です。

すでに扱った主題とのつながり このウィキにはKarpathy（カルパシー）流の LLM ウィキを詳しく扱った LLM Wiki のセットがすでにあります。レベル 2 はまさにその世界です — ここではセカンドブレインの観点から要点だけを押さえます。

ウィキは「インデックスをたどって降りながら読む」

ウィキの強みはインデックス（索引）です。AI がウィキに入ってくると、「この人がエージェンティックなワークフローを尋ねたのでここから始める → 関連する WAT フレームワークへ降りて → 必要なら CLAUDE.md のシステムプロンプトまで」というふうに道（trail）をたどってページをまるごと読みます。

YouTube の字幕や議事録を「ウィキに入れて」と頼めば、AI が概念・比較・出典・技法に自動で分類して、こうした構造を作ってくれます。

メモリ — AI が自分で書くファイル

レベル 2 で新しく加わる軸がメモリです。Claude Code の自動メモリをオンにすると、AI が memory.md を自分で更新します。気にかけなくても文脈が積み上がります。

# 自動メモリのオン/オフを確認
/memory
# auto-memory on / off の状態が見えるので、off ならオンにすればよい

道具に依存しない — Claude Code でも Codex でも

セカンドブレインはただのファイルとフォルダなので、特定の道具に縛られません。ただしファイル名の慣例は道具ごとに違います。

道具方針のファイルメモリ
Claude CodeCLAUDE.mdmemory.md を自動更新
Codex などAGENTS.md（内容は同じものをコピー）「メモリは memory.md を見よ」とルーティング

※ CLAUDE.md をコピーして AGENTS.md として置けば、ふたつの道具が同じブレインを共有します。結局はどこを見よと案内する（ルーティングする）かの問題です。

ウィキのリンク = 知識グラフ？ 違います ウィキのリンクは「関連項目（See also）・バックリンク」に近いものです。「これはこれを裏づける / これはあれの競合だ」のような関係の意味までは持ちません。似た効果は出ますが、本当の関係ベースはレベル 4 — 知識グラフです。
Obsidian は必須ではない 華やかなグラフビューで知られる Obsidian は、結局マークダウンを可視化してくれるレイヤーにすぎません。視覚的に見るのが助けになるなら使い、そうでなければなくてもかまいません — 大事なのは自分のシステムがそれを見つけて取り出してくれるかです。次はレベル 3 — 意味で探す。
