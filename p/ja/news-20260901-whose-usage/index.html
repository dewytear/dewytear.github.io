私の上限を使っているのは誰か — Claude の使用量をめぐる三つの場面

三行要約

  • マルウェアが利用者の PC からログインセッションを盗み、他人のアカウントで Claude を使って上限を消費した事例が確認された。Anthropic は該当アカウントを強制ログアウトし、保存された支払い方法を削除し、不正と確認された請求を返金した。
  • 9月14日には Claude Code の週次上限が変わる。一時的に上乗せされていた 50% 増量が恒久的な 25% 増量に置き換わり、いま手元にある上限を基準にすると実質は減少だ。
  • 同じ時期、ハーネスは逆に動いた。/usage に支出上限のバーとセッション別のプロンプトキャッシュ行が付き、モデルが切り替わる瞬間を挟むフックが入った。

盗まれたセッションで他人のアカウントを使う

ログインの確認が済むと、サイトはブラウザにセッションクッキー（ログイン状態を証明し続ける小さな印）を発行する。それ以降はこの印がそのまま身元になる。インフォスティーラー（感染した端末から保存済みの資格情報やクッキーを抜き取るマルウェア）が持ち去るのは、まさにこの印だ。攻撃者がそれを再生すると、サーバーはすでにログインを終えた利用者として扱う。

二要素認証があってもこの経路は塞がらない。二要素認証が守るのはログインする瞬間であり、盗まれたのはその瞬間を通過したあとの印だからだ。兆候は静かだ。使っていないのに使用上限が満たされては減っていたなら、この事例を疑う価値がある。

Anthropic の対応は三つだ。該当アカウントを強制ログアウトして盗まれたセッションを無効にし、保存された支払い方法を削除してそれ以上請求されないようにし、不正と確認された請求を返金した。支払い方法が消えているので、更新や追加購入には再登録が要る。名指しされたマルウェアは Windows の Vidar・LummaC2・StealC・RedLine・Acreed と、少数の Mac で見つかった Atomic Stealer だ。

ここで見落としやすい点がある。ログアウトは盗まれたセッションを断つだけで、マルウェアを消さない。感染が残っていれば、次にログインした瞬間に新しい印がまた漏れる。支払い方法の再登録は、感染を取り除いたあとにするべきだ。

9月14日、週次上限が実質下がる

Claude Code の週次使用上限に一時的に上乗せされていた 50% 増量が、9月14日に恒久的な 25% 増量へ変わる。一時措置を恒久化するという側から見れば増える話だが、いま手元にある上限を基準にすれば減る話で、おおむね17% ほど減る。

同じ変更の書かれ方が割れるのはこのためだ。基準線を元の上限に取れば +25%、いまの一時的な上限に取れば -17% になる。どちらも誤りではないが、来週実際に何が変わるかを語るのは後者の数字だ。

ハーネスが使った分を出し始めた

8月28日の Claude Code 2.1.251 は、使用量が見える面を広げた。/usage に支出上限のバーが付いて残りが目盛りで読め、セッション別のプロンプトキャッシュ行ができてキャッシュがどれだけ効いたかがセッション単位で見える。フォアグラウンドのサブエージェントのツール呼び出しは、リモートコントロールのクライアントへ実時間で中継される。

同じリリースに PreModelSwitch・PostModelSwitch フック（決まった時点で利用者の指定した処理を差し込む拡張点）が入った。モデルが切り替わる瞬間を前後から挟めるということだ。モデルごとに単価が違うので、この地点はそのまま費用が分かれる地点でもある。

なぜ一つの流れなのか

三つの知らせは同じメーターを別の角度から触る。一つ目は誰がそれを使っているか、二つ目はどれだけ残っているか、三つ目は何がそれを見せるかだ。使用量をアカウントに付随する副次的な数字と見れば三つは無関係に見えるが、毎日ハーネスを立ち上げて働く側からは一つの問題になる。

判定を誰に任せるのかが扱った資格情報の委任は、承認画面で見える問題だった。今回のセッション奪取は、同じ委任が承認画面より一段下で崩れた場合だ。押して許可した覚えがないのにすでに許可されたものとして処理されたのだから、設計すべきだったのは承認ボタンではなく、その下で身元を証明する物のほうだった。

事実検証ノート

セッション奪取（強制ログアウト・支払い方法の削除・返金、マルウェアの一覧、ログアウトが感染を消さないという但し書き）は BleepingComputer・SecurityWeek・Help Net Security・Security Affairs で相互確認した。9月14日の週次上限の変更（一時 50% → 恒久 25%、実質およそ 17% 減）は使用上限の変更年表に基づき、同じ変更が +25% とも -17% とも書かれる — 基準線を元の上限に取るか現在の一時的な上限に取るかの違いなので、本文にその割れを併記した。Claude Code 2.1.251 の項目（モデル切り替えフック、支出上限のバー、セッション別プロンプトキャッシュ行、サブエージェントのツール呼び出し中継）は公式チェンジログに従った。なお同時期に「9月1日に Claude Sonnet 5 が値上げ」という整理が出回ったが、公式の価格ドキュメントは導入価格の据え置きと値上げ不実施を明記している。この記事は公式ドキュメントに従った。
