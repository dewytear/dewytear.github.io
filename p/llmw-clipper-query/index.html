웹 클리퍼와 인박스, Query 실전

웹 기사를 클리퍼로 인박스에 모아 /inbox로 분류하고, 인제스트한 뒤 /query로 꺼내 씁니다.

Obsidian 웹 클리퍼

크롬 확장 Obsidian Web Clipper 로 웹 아티클을 클리핑해 볼트의 인박스에 넣습니다. 강사는 캡처 규칙(JSON 템플릿)을 위키 볼트에 넣어 두었습니다.

  • 설정 → 일반 옵션의 볼트 저장소에 볼트명들을 등록하면 어느 볼트로 보낼지 지정할 수 있습니다.
  • 템플릿(JSON)을 임포트하고, Web Article 템플릿을 맨 위로 올립니다(먼저 발동). x.com·youtube 등 주소에 따라 트리거되는 템플릿도 있습니다.
  • 캡처하면 미리 지정한 0.2 inbox/article 같은 폴더에 저장됩니다.

인박스 스킬 — 모아서 분석

/inbox        # 인박스에 모아둔 자료를 분석·주제별로 묶어 제안

여러 개를 미리 모아 두고 /inbox 를 돌리면, "5개 중 3개는 같은 결이니 같이 인제스트할까?" 처럼 주제별로 나눠 제안합니다.

토큰 팁 — 원본 스크래핑

인제스트할 때 링크만 주면 AI가 원본을 긁어서 시작해야 해 토큰이 더 듭니다. 웹 클리퍼로 미리 스크래핑해 원본을 확보한 뒤 시작하면 토큰을 아낍니다.

Query 실전

/query LLM 위키 볼트의 학술적 가치를 정리해줘.
나중에 레퍼런스 매니저로 서지정보를 인용할 거야.

위키 볼트에서 부족하면 메인 볼트까지 검색해 가져오게 되어 있고, 내가 어떻게 질문했는지도 함께 기록됩니다. 결과에는 답변뿐 아니라 Obsidian 메타데이터를 어떻게 설계하면 좋은지(author·created·source·category 등) 까지 추천해 줍니다.

논문은 통째로 넣지 말 것 논문 원문을 전부 인제스트하기보다, 초록(abstract) 정도로 기본 개념만 알게 하고 원문의 위치를 남기는 것이 좋습니다. 중요 키페이퍼만 풀로 읽히고, 내 코멘터리·실험 맥락을 함께 넣으면 더 유용합니다.
