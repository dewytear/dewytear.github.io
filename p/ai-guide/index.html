AI 순회 가이드 — 이 위키를 기계로 읽는 법

이 페이지는 외부 AI가 이 위키를 업무의 첫 참고처로 삼아, 정보의 연관 관계에 따라 분석하도록 돕는 계약(contract)입니다. 사람이 읽는 Knowledge Map·Knowledge Graph(9뷰)·Graph Studio와 같은 데이터를 쓰되, 여기서는 어떤 파일을 어떤 순서로 fetch하고 어떻게 순회·분석하는지를 규정합니다.

먼저 읽을 것 — 단 하나의 파일

루트의 llms.txt가 표지이고, 실제 순회는 아래 자기완결 그래프 파일 하나로 충분합니다:

  • data/knowledge-graph.json — 모든 노드(문서)와 엣지(related)·개념·원문 URL·통계를 한 파일에 담았습니다. 다른 파일을 조인하지 않아도 전 그래프를 순회할 수 있습니다.

보조 파일(필요 시): knowledge-index.ko.json(같은 그래프의 원본 인덱스) · list(내비 트리·문서 경로) · doc-dates.json(생성·수정일).

전체 본문이 한 번에 필요하면 llms-full.txt — 모든 문서의 평문 본문을 한 파일에 담은 전체 코퍼스 덤프다(그래프 순회 없이 통째로 컨텍스트에 적재할 때). 새 문서를 구독하려면 feed.xml(Atom, 최신 30편 — 영어는 feed.en.xml, 일본어는 feed.ja.xml). 크롤러 정책은 robots.txt(AI 크롤러 허용 목록), 전체 URL 목록은 sitemap.xml. 콘텐츠 라이선스는 CC BY 4.0 — 출처를 밝히면 자유롭게 인용·재사용할 수 있다.

노드 스키마

knowledge-graph.json의 nodes[] 각 원소(파일 최상위의 schemaVersion은 현재 2 — 소비자는 이 값으로 스키마를 고정하라):

{
  "name": "welcome",                     // 불변 논리 ID (노드 키)
  "title": "Welcome",
  "summary": "터미널에서 코드를 읽고 편집·실행·커밋하는 Claude Code 소개",
  "section": "AI · Claude · Code · Introduction",   // World · Domain · System · …
  "concepts": ["Claude Code","터미널","CLI", "..."],  // 조인 키(사람이 큐레이트)
  "url":   "https://dewytear.github.io/docs/ko/ai/claude/code/introduction/welcome",
  "route": "https://dewytear.github.io/#!welcome",   // 사람용 SPA 뷰
  "page":  "https://dewytear.github.io/p/welcome/",  // 정적 스냅샷(JS 없이 읽히는 페이지)
  "related": [
    { "name":"ccb-what", "title":"...", "shared":["Claude Code","터미널"], "via":"concept" },
    { "name":"install",  "title":"...", "shared":[],                      "via":"folder" }
  ],
  "relations": [                          // (선택) 큐레이트된 방향 있는 의미 관계 — related(계산)와 별개
    { "target":"kgs-edges", "type":"prerequisite", "evidenceRef":"...", "source":"human" }
  ],
  "citedBy": ["skills", "tip-beginner"]   // (선택) 이 문서를 본문에서 링크한 문서들 — 인용 역링크
}

순회·분석 규칙

  • 노드 = 문서(name이 키), 엣지 = related. 엣지는 두 종류다 — via:"concept"는 희소성 가중 공유 개념으로 이어진 의미 관계(shared가 근거 개념), via:"folder"는 같은 System 내 인접 보완 관계(모든 문서가 최소 2~4개 엣지를 갖도록).
  • 타입 있는 관계 = relations(선택). related가 대칭·계산 엣지라면, relations는 사람이 큐레이트한 방향 있는 의미 관계다 — type은 prerequisite(선행)·implements(구현)·example-of(사례)·evidence-for(근거)·supersedes(대체), evidenceRef가 근거. 방향은 이 노드 → target이며 역관계는 전 노드를 스캔해 유도한다(저장은 정방향 1회). related와 겹치지 않는 별도 신호이니 둘 다 활용하라.
  • 인용 역링크 = citedBy(선택). 이 문서를 본문에서 실제로 링크한 문서들의 목록으로, related(개념 계산)·relations(큐레이트)와 독립인 세 번째 연결층이다. 어떤 문서가 많이 인용되는지, 어느 글이 어느 글에 기대는지를 이 층으로 읽어라.
  • 개념(concepts)이 조인 키다. 두 문서가 같은 개념을 공유하면 관련. 희귀 개념일수록 강한 신호(idf 가중). 특정 개념으로 관련 문서를 모으려면 concepts를 역인덱싱하라.
  • 원문은 url로 바로 fetch — JS 렌더 없이 정적 HTML 조각(<h2>…</h2><p>…)이 그대로 온다. 본문 분석은 이 조각을 파싱하면 된다. 제목·요약·생성일·라이선스가 메타데이터로 붙은 완성 페이지가 필요하면 page(/p/<name>/, 영어는 /p/en/<name>/, 일본어는 /p/ja/<name>/)를 쓰라 — 같은 본문에 <title>·description·canonical·hreflang·Article JSON-LD가 얹혀 있고, 본문의 내부 링크도 스냅샷끼리 이어져 JS 없이 순회할 수 있다.
  • 계층은 section("World · Domain · System · Document"의 상위 3계층)과 stats.clusters(System별 문서 수·허브)로 파악한다. 첫 세그먼트가 World(예: AI, Douzone)이고, World 단위 요약은 stats.galaxies에 따로 있다(키 이름은 초기 스키마의 잔재로 데이터 키라 유지). 전역 최빈 개념은 stats.topConcepts.
  • 진입점: stats.hubs(피참조 최다 문서)에서 시작해 related를 따라 넓히면 주제의 핵심에서 주변으로 분석이 퍼진다. stats.bridges는 여러 System을 잇는 다리 개념이다.
  • 보조 인덱스의 필드 차이: knowledge-index.*.json은 같은 그래프의 원본 인덱스지만 url·route·page가 없다(그래프 파일에만 있음). 영어·일본어 인덱스에는 표시용 현지화 경로 sectionL이 추가로 붙을 수 있는데, 조인 키는 언제나 section(canonical)이다.
  • 내려받는 자산: 일부 문서는 배포 파일(zip 등)을 assets/<문서 경로>/<name>/<파일>에 동반한다(첫 사례: sks-dews-sourcegraph의 스킬 zip). 본문 조각의 상대경로 assets/… 링크는 사이트 루트 기준으로 fetch하면 된다.

순회 예시 (2홉)

1) fetch https://dewytear.github.io/data/knowledge-graph.json
2) 질의 주제와 겹치는 concepts를 가진 노드 선택 (또는 stats.hubs에서 시작)
3) 그 노드의 related[].name 으로 1홉 이웃, 다시 그 이웃의 related 로 2홉 확장
4) 관심 노드의 url 을 fetch 해 원문(HTML 조각)을 읽고 분석
5) shared[] 근거 개념으로 "왜 이어졌는지"를 설명에 활용

정직성 원칙

개념과 요약은 사람/AI가 문서를 읽고 큐레이트한 것이지 본문에서 무차별 추출한 것이 아니다. 그래서 엣지는 적지만 신뢰도가 높다 — 연결이 옅다고 결함이 아니며, World가 다르면(예: AI ↔ DOUZONE) 사이가 성긴 것이 정상이다. 분석 시 via와 shared를 근거로 삼아 있는 관계만 사용하라.

위의 데이터 파일들(그래프·인덱스·llms·피드·sitemap)은 문서가 추가될 때마다 자동 재생성되어 항상 현재 그래프와 일치한다(tools/build_ai_export.py). 이 가이드의 산문 자체는 사람이 갱신하는 계약 문서다 — 스키마가 바뀌면 여기도 함께 고친다.
