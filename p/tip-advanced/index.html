고급 — 병렬·자율·예약의 8가지

마지막 편은 Claude Code를 여러 개, 오래, 손을 떼고 굴리는 이야기입니다. 세션끼리 파일을 두고 충돌하지 않게 하는 워크트리부터, 예약 작업, 폰 원격 조종, 그리고 서로 대화하는 에이전트 팀까지 — 공개 강좌의 팁 21~28번을 공식 문서와 대조해 정리했습니다.

문서 정보 (출처) · 뼈대: 공개 강좌 영상 — Claude Code 꿀팁 28가지의 고급 편(21~28)
· 검증·보강: Claude Code 공식 문서 대조 (2026-08-14 기준) — 실험 기능은 버전에 따라 달라질 수 있습니다

21. 워크트리로 세션을 병렬로 돌린다

같은 프로젝트에서 세션 두 개가 동시에 파일을 고치면 — 하나는 로그인 기능, 하나는 그래픽 로직 — 같은 파일을 건드리는 순간 충돌합니다. 워크트리(worktree)는 git이 제공하는 독립된 작업 사본으로, 저장소 이력은 공유하되 파일은 따로 갖습니다. 세션마다 자기 워크트리에서 일하면 서로 절대 겹치지 않고, 끝나면 git 머지로 합칩니다.

강좌는 git worktree 명령을 직접 치는 방법을 소개하지만, 지금은 Claude Code가 수명 관리까지 해 줍니다 — claude --worktree(-w)로 시작하면 워크트리 생성·이름·정리가 자동이고, 데스크톱 앱은 새 세션마다 알아서 워크트리를 만듭니다. .env처럼 git이 추적하지 않는 파일은 사본에 없으므로, 자동 복사가 필요하면 프로젝트 루트에 .worktreeinclude 파일을 두면 됩니다.

사본이 물리적으로 나뉘어 있으니 충돌 자체가 일어나지 않는다 — 합치는 시점만 관리하면 된다.

공식 문서: Run parallel sessions with worktrees

22. MCP 서버 대신 API를 직접 부른다

MCP(Model Context Protocol)는 외부 도구를 붙이는 표준인데, 서버를 연결하면 그 서버의 도구 정의 전체가 컨텍스트에 실리는 비용이 있습니다. 필요한 기능이 한둘뿐이라면 해당 API 엔드포인트를 직접 호출하게 하는 편이 토큰·컨텍스트 모두 쌉니다. 도구 전부를 쓸 거면 MCP, 한두 개만 쓸 거면 직접 호출 — 이 구분이 핵심입니다. 참고로 지금은 도구 검색(Tool Search)이 기본 제공되어 필요한 도구 정의만 그때그때 불러오는 식으로 이 비용이 크게 줄었지만, "쓰는 만큼만 싣는다"는 원칙 자체는 그대로 유효합니다.

공식 문서: Connect Claude Code to tools via MCP — 이 위키의 MCP 소개도 참고. MCP 스펙 자체의 큰 개정은 묻지 않는 기본값에서 다뤘습니다.

23. /loop로 예약 작업을 건다

/loop 5분마다 배포 상태를 확인해 줘처럼 반복 작업을 걸어 두면 세션이 살아 있는 동안 Claude가 주기적으로 알아서 확인합니다. 배포 감시, 정기 점검, "8시에 슬랙 확인" 같은 시간 지정도 됩니다. 사람이 지켜보지 않아도 되는 감시성 업무를 통째로 넘길 수 있어 활용 폭이 넓습니다.

24. 폰에서 원격으로 조종한다

터미널에서 claude remote-control을 실행하면 링크가 하나 나옵니다. 그 링크를 폰에서 열면 — 코드는 여러분의 로컬 머신에서 그대로 돌고 — 조작만 폰에서 하게 됩니다. 지하철에서 진행 상황을 확인하고 다음 지시를 내리는 식입니다. 로컬 머신이 켜져 있어야 한다는 조건만 기억하면 됩니다. 긴 작업이 끝나거나 승인이 필요할 때 폰으로 알림도 옵니다.

공식 문서: Remote Control — continue local sessions from your phone

25. 데이터베이스에 자연어로 물어본다

PostgreSQL·Supabase 등 주요 데이터베이스는 MCP 서버로 Claude Code와 연동됩니다. 연결해 두면 "지난주 가입자 중 이탈한 사람들의 공통점이 뭐야?" 같은 질문을 SQL 없이 자연어로 던질 수 있습니다 — 스키마 탐색, 집계, 조건 검색까지 Claude가 데이터 분석가처럼 처리합니다. 쓰는 데이터베이스가 무엇이든 일단 "이 DB 연결해 줘"라고 물어보는 것이 가장 빠른 시작입니다.

26. 깊게 생각시킬 땐 ultrathink

터미널에서 프롬프트에 ultrathink를 함께 쓰면(입력창이 무지개색으로 바뀌면 적용된 것) Claude가 생각(thinking) 예산을 최대치로 쓰고 답합니다. 그만큼 토큰을 많이 태우므로 아무 데나 쓸 것은 아니고 — 프롬프트를 아무리 바꿔도 좋은 답이 안 나오는 어려운 문제, 구조 설계 판단 같은 곳에 아껴 쓰는 카드입니다.

공식 문서: Model configuration — effort. 집필 시점 기준 생각 깊이는 effort 설정으로도 조절할 수 있습니다.

27. 권한을 편집해 안전하게 자율 주행한다

settings.json에서 명령별로 무조건 허용 / 무조건 확인을 정할 수 있습니다. 전부 자동 승인하면 rm(파일 삭제)이나 git push --force(충돌 무시 강제 푸시)처럼 위험한 명령까지 통과할 수 있으니, "이런 위험한 명령은 나한테 물어보게 해 줘"라고 시켜 거부 규칙을 만들어 두세요. 2026년 8월 14일부터 기본값이 된 auto 모드에서는 이 규칙이 특히 중요합니다 — 좁게 적은 거부 규칙은 사람이 자리를 비운 사이에도 일하고, 너무 넓게 열어 둔 허용 규칙은 오히려 무시됩니다. 규칙이 곧 실제로 집행되는 정책이 된 셈입니다.

공식 문서: Permissions — 배경은 묻지 않는 기본값 기사 참고.

28. 에이전트 팀 — 서로 대화하는 에이전트들

서브에이전트와 헷갈리기 쉬운데 구조가 다릅니다. 서브에이전트는 병렬로 일하되 서로 대화하지 않고 메인에게 보고만 합니다. 에이전트 팀은 독립된 세션들이 서로 대화하고, 작업 목록을 공유하며 일을 나눠 갖습니다 — 각 팀원과 여러분이 개별 대화도 할 수 있습니다. 기획자·마케터·디자이너 에이전트를 두고 서로 소통시키며 일을 시키는 그림이라면 서브에이전트가 아니라 에이전트 팀입니다. 토큰은 더 들지만, 팀원끼리 서로의 결과를 반박·보완해야 하는 과제에서 확실히 성과가 다릅니다.

보고 구조가 다르면 쓰임도 다르다 — 독립 조사엔 서브에이전트, 협업 과제엔 에이전트 팀.

공식 문서: Orchestrate teams of Claude Code sessions — 집필 시점 기준 실험 기능이라 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 환경 변수로 켜야 합니다. 방법론이 궁금하면 이 위키의 하네스 엔지니어링 강의가 에이전트 팀 운영을 12편으로 다룹니다.

마치며

28가지를 관통하는 원칙은 셋으로 줄어듭니다. 컨텍스트는 예산이다(초급) — 아끼고, 쪼개고, 시각화하라. 반복은 시스템으로(중급) — 잘 나온 프롬프트는 스킬과 CLAUDE.md에 굳혀라. 병렬은 격리부터(고급) — 워크트리와 권한 규칙을 먼저 두고 자율을 늘려라. 도구는 계속 바뀌지만 이 세 원칙은 오래갈 것입니다.
