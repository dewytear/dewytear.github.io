Harness 플러그인 — 소개·개념·설치

하네스(Harness) 플러그인은 "목표(의도)만 주면, 여러 AI가 팀을 이뤄 스스로 오래 일하도록 판을 깔아 주는" Claude Code 플러그인입니다. 내가 프롬프트를 하나하나 던지는 대신, "무엇을 원하는지"만 말하면 플러그인이 에이전트 팀 · 스킬 · 오케스트레이터를 대신 구성해 실행합니다.

한 장으로 보는 큰 그림

하네스 플러그인이 하는 일은 결국 아래 흐름입니다. 사람은 맨 앞(의도)과 맨 뒤(검토·의사결정)에만 개입하고, 가운데의 반복 작업은 AI 팀이 맡습니다.

사람은 앞(의도)과 뒤(검토)만, 가운데 반복 작업은 AI 팀이 맡습니다.

왜 "하네스"인가 — 프롬프트에서 하네스로

AI를 다루는 방식은 아래처럼 발전해 왔습니다. 하네스는 모델 하나가 아니라 "모델을 둘러싼 환경 전체"를 설계하는 단계입니다. 같은 모델이라도 어떤 판(하네스)에 올려놓느냐에 따라 결과물의 품질이 크게 달라집니다.

단계핵심비유
프롬프트 엔지니어링질문을 잘 던지기말 한마디 잘하기
컨텍스트 엔지니어링필요한 자료·맥락을 잘 넣기자료를 손에 쥐여 주기
하네스 엔지니어링AI가 일하는 시스템 전체를 설계말(馬)에 마구(하네스)를 채워 오래 잘 달리게

ERP 커스터마이징에 왜 잘 맞나

고객사 커스터마이징 업무는 보통 여러 단계가 순서대로 이어집니다 — 요구사항(CR) 분석 → 표준 소스·영향도 파악 → 설계 → 개발 → 회귀 검증. 이건 혼자 순서대로 하면 오래 걸리지만, 역할을 나눠 병렬로 하면 훨씬 빠른 대표적인 일입니다. 하네스는 이 단계들을 각각 담당 에이전트에게 맡기고 오케스트레이터가 조율합니다.

  • 표준 훼손 최소화 — "이 커스텀이 표준 패키지의 어디에 영향 주는지"를 분석 에이전트가 먼저 짚어 줍니다.
  • 회귀 검증 자동화 — 개발 후 QA 에이전트가 표준 기능이 깨지지 않았는지 교차 확인합니다.
  • 산출물 표준화 — 명세·영향도·테스트·이관 가이드가 _workspace에 함께 남습니다.

※ 구체 예제(영업·수주 여신한도 커스텀)는 첫 하네스 실행에서 단계별로 따라 해 봅니다.

핵심 개념 쉽게

하네스는 다섯 가지 요소로 이뤄집니다. 어렵게 느껴지지만, 회사에서 일하는 팀에 그대로 대응됩니다 — PM 한 명, 담당자 여러 명, 각자의 매뉴얼, 검수, 그리고 공용 작업 폴더.

이름의 유래 — 마차의 마구(馬具) "하네스(harness)"는 원래 말에 채우는 마구를 뜻합니다. 말(=AI 모델)이 아무리 좋아도 어떻게 매어 부리느냐에 따라 잘 달리기도, 헛돌기도 합니다. 하네스 엔지니어링은 바로 그 "부리는 판"을 설계하는 일입니다.

구성도 — 요소들이 어떻게 맞물리나

오케스트레이터가 팀을 조율하고, 모든 산출물은 공용 _workspace에 남습니다.

다섯 가지 요소

  • 에이전트(Agent) — 특정 역할을 맡은 AI 작업자. 코드가 아니라 자연어로 쓴 "직무기술서"입니다(역할·원칙·입출력·협업 방법·에러 시 행동). 예: "영업 표준소스 분석가"
  • 스킬(Skill) — 반복 작업을 담은 매뉴얼. 이름 + 설명 + 절차·체크리스트로 이뤄집니다. 예: "여신한도 검증 절차" 스킬
  • 오케스트레이터(Orchestrator) — 팀을 조율하는 PM. 항상 한 명이며, 시작 전에 작업 순서(워크플로우)를 미리 계획합니다. (Claude Code의 플랜 모드와 비슷)
  • 평가 · 테스트 — 결과를 믿을 수 있게 하는 검수. 오탈자가 아니라 주장–근거 정합성, 수치 일관성, 표준 기능 회귀를 교차 확인합니다.
  • 아티팩트 · 메모리 — 실행 시 만들어지는 공용 작업 폴더 _workspace. 중간 산출물과 근거 출처가 함께 남아, 나중에 "왜 이렇게 했는지" 추적할 수 있고 할루시네이션(그럴듯한 거짓)도 줄어듭니다.

설치와 준비

하네스는 Claude Code 플러그인 형태로 배포됩니다. 마켓플레이스를 한 번 등록하고 설치하면 /harness 명령을 쓸 수 있습니다.

먼저 필요한 것 Claude Code가 설치되어 있어야 합니다(시작하기 참고). 터미널에서 작업할 프로젝트 폴더로 이동해 claude 를 실행한 상태에서 아래 슬래시 명령을 입력합니다.

설치 3단계

방법 1 — 명령어 두 줄 (권장)

# 1) 하네스 마켓플레이스 추가
/plugin marketplace add lev-factory/harness
# 2) 하네스 플러그인 설치
/plugin install harness

설치 화면이 뜨면 User 스코프로 설치합니다(내 계정 전체에서 사용). 특정 프로젝트에서만 쓰려면 프로젝트 스코프를 선택합니다.

방법 2 — /plugin 화면에서

  1. /plugin 입력 → 방향키 오른쪽으로 Marketplace 탭 이동.
  2. Add Marketplace 에 lev-factory/harness 입력 → Enter.
  3. 목록에서 harness 선택 → 설치 화면에서 Enter → User 스코프로 설치.

설치 후 — 리로드하고 확인

# 플러그인을 현재 세션에 반영
/reload
# 아래가 자동완성/실행되면 설치 성공
/harness

/harness 를 입력했을 때 자동완성이 뜨면 준비 완료입니다. 이제 첫 하네스 실행으로 넘어갑니다.

주의 — 마켓플레이스 주소 확인 위의 lev-factory/harness 는 강의에서 언급된 예시 값입니다. 실제 설치 시에는 배포자의 GitHub 저장소 경로를 확인해서 넣으세요(검색어: "하네스 100"). 설치가 안 되면 명령어 방식 ↔ /plugin 화면 방식을 번갈아 시도해 보세요.
사내 환경 팁 사내망·프록시 환경에서는 GitHub 접근이 제한될 수 있습니다. 마켓플레이스 추가가 실패하면 네트워크/프록시 정책과 Git 접근 권한을 먼저 확인하세요. 플러그인은 머신마다 각각 설치해야 합니다(에이전트 정의는 Git으로 공유 가능하지만, 플러그인 자체는 개인 설치).

개념과 설치가 끝났으니 바로 돌려 봅니다 — 첫 실행과 동작 구조에서 영업·수주 커스터마이징 하네스를 실제로 만듭니다.
