Harness 플러그인 — 소개

하네스(Harness) 플러그인은 "목표(의도)만 주면, 여러 AI가 팀을 이뤄 스스로 오래 일하도록 판을 깔아 주는" Claude Code 플러그인입니다. 내가 프롬프트를 하나하나 던지는 대신, "무엇을 원하는지"만 말하면 플러그인이 에이전트 팀 · 스킬 · 오케스트레이터를 대신 구성해 실행합니다.

한 장으로 보는 큰 그림

하네스 플러그인이 하는 일은 결국 아래 흐름입니다. 사람은 맨 앞(의도)과 맨 뒤(검토·의사결정)에만 개입하고, 가운데의 반복 작업은 AI 팀이 맡습니다.

왜 "하네스"인가 — 프롬프트에서 하네스로

AI를 다루는 방식은 아래처럼 발전해 왔습니다. 하네스는 모델 하나가 아니라 "모델을 둘러싼 환경 전체"를 설계하는 단계입니다. 같은 모델이라도 어떤 판(하네스)에 올려놓느냐에 따라 결과물의 품질이 크게 달라집니다.

단계핵심비유
프롬프트 엔지니어링질문을 잘 던지기말 한마디 잘하기
컨텍스트 엔지니어링필요한 자료·맥락을 잘 넣기자료를 손에 쥐여 주기
하네스 엔지니어링AI가 일하는 시스템 전체를 설계말(馬)에 마구(하네스)를 채워 오래 잘 달리게

ERP 커스터마이징에 왜 잘 맞나

고객사 커스터마이징 업무는 보통 여러 단계가 순서대로 이어집니다 — 요구사항(CR) 분석 → 표준 소스·영향도 파악 → 설계 → 개발 → 회귀 검증. 이건 혼자 순서대로 하면 오래 걸리지만, 역할을 나눠 병렬로 하면 훨씬 빠른 대표적인 일입니다. 하네스는 이 단계들을 각각 담당 에이전트에게 맡기고 오케스트레이터가 조율합니다.

  • 표준 훼손 최소화 — "이 커스텀이 표준 패키지의 어디에 영향 주는지"를 분석 에이전트가 먼저 짚어 줍니다.
  • 회귀 검증 자동화 — 개발 후 QA 에이전트가 표준 기능이 깨지지 않았는지 교차 확인합니다.
  • 산출물 표준화 — 명세·영향도·테스트·이관 가이드가 _workspace에 함께 남습니다.

※ 구체 예제(영업·수주 여신한도 커스텀)는 첫 하네스 실행에서 단계별로 따라 해 봅니다.
