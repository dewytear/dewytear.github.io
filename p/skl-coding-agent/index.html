스킬의 배경 — 코딩 에이전트의 탄생

스킬은 어느 날 갑자기 "짠" 하고 나온 기술이 아닙니다. 코딩 에이전트라는 토대 위에서 자연스럽게 등장했습니다. 그 맥락을 알아야 스킬이 왜 그런 방식으로 동작하는지 이해됩니다.

에이전트의 종류

단계가 올라갈수록 스스로 하는 범위가 넓어집니다 — 코딩 에이전트 위에서 스킬이 가능해집니다.
  • 채팅 에이전트 — 우리가 기본적으로 쓰는 대화형.
  • 도구 호출 에이전트 — MCP·API를 연결해 Gmail 확인, 일정 등록 같은 외부 작업 수행.
  • 코딩 에이전트 — 도구 호출보다 한 단계 위. Claude Code가 여기에 해당합니다.

"도구는 간단하게, 나머지는 LLM에게"

처음엔 도구를 정교하게 많이 만들면 에이전트가 잘 동작할 거라 기대했지만, 아무리 잘 만들어도 원하는 형태가 나오지 않는 한계에 부딪혔습니다. 그래서 발상을 바꿨습니다.

  • 도구는 아주 기초적인 것만 준다 — 파일 읽기·쓰기·편집·찾기, 그리고 명령 실행 정도(약 여섯 개).
  • 나머지는 LLM이 알아서 하도록 한다.
  • 그러려면 실행 환경과 파일 시스템이 필요하다 → 샌드박스 + 간단한 도구.

이렇게 탄생한 것이 코딩 에이전트입니다. 캠핑에 온갖 도구를 다 싣는 대신, 망치 같은 기초 도구만 들고 가 현장에서 만들어 쓰는 방식에 가깝습니다.

Claude Code가 폴더를 물고 시작하는 이유 Claude Code가 특정 폴더 안에서 실행되는 이유가 바로 이것입니다. 파일을 읽고 쓰고 내 명령을 실행하려면 내 OS와 파일 시스템이 필요하기 때문에, 내 컴퓨터(로컬)에서 동작합니다. 스킬은 이 코딩 에이전트 위에서만 가능한 기능입니다.
