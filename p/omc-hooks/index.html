Hook · 메모리

OMC는 Claude Code의 Hook 이벤트를 활용해 키워드 감지, 스킬 주입, 상태 복구, 완료 검증을 처리합니다. 최신 Reference 기준으로 Hook 이벤트는 더 세분화되어 있습니다.

알아둘 점

  • autopilot · ralph · ultrawork · ultraqa 는 Hook이 아니라 스킬입니다. keyword-detector가 이들을 활성화하고, persistent-mode Hook이 지속 실행을 보조합니다.
  • Hook을 전부 끄려면 DISABLE_OMC, 특정 Hook만 제외하려면 OMC_SKIP_HOOKS 를 사용합니다.
  • Windows Native Hook은 v4.14.4 이후 개선되어 그대로 사용할 수 있습니다. tmux가 필요한 일부 기능도 현행 공식 README 기준 psmux(네이티브 Windows용 tmux 호환 도구)를 쓰면 WSL 없이 동작하며, WSL2는 대안 경로입니다.
# OMC의 모든 Hook을 한 번에 비활성화
export DISABLE_OMC=1
# 지정한 Hook만 제외 (나머지는 정상 동작)
export OMC_SKIP_HOOKS=PreToolUse,PostToolUse

Hook이 실행되는 시점

Hook은 Claude Code의 특정 이벤트마다 자동으로 끼어들어 실행되는 동작입니다. OMC는 이를 통해 컨텍스트를 주입하고 스킬을 자동으로 켭니다. 주요 타이밍은 네 가지입니다.

세션이 시작되고 프롬프트를 낼 때, 도구 직전·직후마다 Hook이 자동으로 끼어듭니다.
  • SessionStart — 세션이 시작될 때. OMC 초기화, notepad·project-memory 로드, 직전 실행 모드 상태 복구.
  • UserPromptSubmit — 프롬프트를 보낼 때. 매직 키워드 감지, 알맞은 스킬 자동 연결, 컨텍스트 주입.
  • PreToolUse — 도구를 쓰기 직전. 병렬 읽기 권장 힌트, 관련 파일 사전 로드 제안.
  • PostToolUse — 도구를 쓴 직후. 결과 검증, 후속 조치 제안, 에러 감지 시 자동 수정 제안.

대화 중 보이는 메시지 해석

작업 중 system-reminder 형태의 메시지가 보일 수 있습니다. 당황하지 말고 아래처럼 이해하면 됩니다.

메시지의미
hook success: Success정상 작동 중이라는 표시입니다. 그대로 진행하면 됩니다.
hook additional context: ...유용한 힌트입니다. 참고해서 적용하면 좋습니다.
[MAGIC KEYWORD: ralph detected]해당 모드(여기선 ralph)가 자동으로 켜졌다는 알림입니다.
The boulder never stops rollingralph·ultrawork가 계속 실행 중이라는 표시입니다.

메모리와 프로젝트 문서화

OMC는 작업 맥락을 세션이 바뀌어도 유지하기 위해 세 가지 장치를 제공합니다. 각각 저장 위치와 역할이 다릅니다.

  • deepinit — 코드베이스 전체를 훑어 디렉토리마다 AGENTS.md 문서를 만들어 줍니다. 각 폴더가 무엇을 담는지, 파일 간 관계, 작업 시 주의점, 의존성을 정리해 두어, AI가 매번 처음부터 구조를 탐색하지 않아도 되게 합니다. 대규모 프로젝트의 사전 정리 작업에 유용합니다.
  • notepad — .omc/notepad.md 에 저장되는 작업 메모입니다. 대화가 길어져 맥락이 정리(압축)되어도 살아남습니다. 절대 잃으면 안 되는 정보(priority), 현재 진행 중인 작업 상태(working), 수동으로 기록하는 메모(manual)의 세 단계로 나뉘며, 오래된 항목 정리는 notepad_prune 도구로 처리합니다.
  • project memory — .omc/project-memory.json 에 저장되며, 프로젝트의 기술 스택·코딩 컨벤션·아키텍처 지침을 기억합니다. 기본값은 omc-setup 으로 설정합니다.
