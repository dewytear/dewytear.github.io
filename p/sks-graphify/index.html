graphify — 코드베이스를 지식 그래프로 바꿔 grep 대신 질의하게 하는 스킬

세 줄 요약

  • graphify는 /graphify . 한 줄로 폴더 안의 코드·문서·PDF·이미지·영상을 하나의 지식 그래프로 만들고, 그 뒤부터 에이전트가 파일을 통째로 읽는 대신 graphify query·path·explain으로 필요한 부분 그래프만 받아 보게 하는 스킬이다. 코드는 tree-sitter(구문 트리 파서)로 로컬에서 LLM 없이 파싱하고, 모든 연결선에 EXTRACTED·INFERRED·AMBIGUOUS 신뢰 꼬리표를 단다.
  • 2026년 4월 4일 PyPI 첫 공개 뒤 11월 23일 0.9.118까지 284번 릴리스됐고, Claude Code·Cursor·Codex·Gemini CLI 등 20여 어시스턴트를 지원한다. 저장소 스타는 집계 사이트마다 7.6만에서 15만으로 갈려 이 글은 "10만 전후"로만 적는다. 만든 회사는 Graphify Labs(Y Combinator S26), 라이선스는 Apache-2.0과 MIT 이중.
  • 공식 벤치마크는 LOCOMO 기억 검색에서 recall@10 0.497(mem0 0.048), 그래프 구축에 LLM 비용 0을 내세운다. 자주 인용되는 "토큰 71.5배 절감"은 52개 파일 코퍼스의 질의 한 번 기준이고, 실제 세션 단위 독립 측정에서는 7~8% 절감이나 품질 동률(44 대 45점)이 나왔다. 큰 저장소의 길 찾기·영향 분석에서 강하고, 작은 프로젝트와 집중 편집에서는 득이 적다.

코딩 에이전트가 낯선 저장소에서 하는 첫 일은 grep과 파일 읽기다. 질문이 "이 엔드포인트는 어디서 저장소까지 닿나"처럼 구조를 묻는 것이면, 파일을 하나씩 읽어 컨텍스트에 쌓는 방식은 토큰을 많이 쓰고 큰 그림을 놓친다. graphify는 그 자리에 그래프를 둔다. 한 번 만들어 두면 세션이 바뀌어도 남고, 질문마다 관련 노드 몇십 개만 돌려준다. 이 글은 공식 저장소(README·ARCHITECTURE·BENCHMARKS·skill.md)와 외부 검증 글을 바탕으로 동작 원리, 설치와 사용법, 벤치마크의 실제 의미, 한계와 보안을 정리한다. 이 위키도 문서 그래프 위에서 돌아가는 저장소라 마지막에 두 그래프를 나란히 놓았다.

1. 어떻게 만들어지나 — 세 번의 패스

공식 how-it-works 문서와 ARCHITECTURE.md의 파이프라인을 옮겼다. 1패스는 33개 언어를 tree-sitter 문법으로, 7개(Dart·Apex·COBOL·Razor·Blade·Pascal·Robot Framework)는 자체 추출기로 처리한다.

핵심은 "코드는 LLM에 보내지 않는다"는 원칙이다. 함수·클래스·import·호출 관계는 구문 트리에서 결정적으로 뽑히므로 같은 입력에 같은 그래프가 나오고, 비용이 0이며, 아무것도 밖으로 나가지 않는다. 문서와 이미지만 의미 추출을 위해 모델을 거치는데, Claude Code 안에서는 그 세션의 모델이 서브에이전트를 병렬로 띄워 처리하고, 터미널에서 graphify extract로 돌릴 때는 설정된 API 키(Gemini·Kimi·Claude·OpenAI·DeepSeek·Azure·Bedrock·Ollama 순으로 자동 감지)를 쓴다. 커뮤니티 검출은 Leiden 알고리즘(간선 밀도로 노드를 묶는 그래프 군집화)이고, 임베딩이나 벡터 저장소는 쓰지 않는다. 모델이 뽑은 semantically_similar_to 간선이 이미 그래프 안에 있어 그 구조 자체가 유사도 신호 노릇을 한다는 설명이다. 커뮤니티 이름은 LLM 없이 허브 노드 이름에서 짓는다.

2. 모든 선에 꼬리표 — 신뢰도 체계

how-it-works 문서의 규칙표. 스킬 파일의 "정직 규칙"은 간선을 지어내지 말고 모르면 AMBIGUOUS로 두라고 못 박는다. 같은 관계가 여러 곳에서 보이면 가장 높은 꼬리표 하나만 남기고 나머지는 also_seen에 기록한다.

이 꼬리표가 graphify를 "또 하나의 검색 인덱스"와 가르는 지점이다. graphify explain "APIRouter"를 치면 소스 위치, 커뮤니티, 차수와 함께 연결 47개가 [uses] [INFERRED], [imports] [EXTRACTED]처럼 꼬리표를 달고 나오고, graphify path "FastAPI" "ModelField"는 3홉 경로와 그 경로의 전체 신뢰도(가장 약한 홉)를 돌려준다. 저장소 BENCHMARKS.md는 FastAPI 프로덕션 패키지 안의 INFERRED 교차 파일 간선 12개를 손으로 전수 검사해 전부 맞았다고 적되, 날짜 박힌 1회 점검이지 상시 지표는 아니라고 밝힌다. 해결기는 "틀린 간선보다 없는 간선"을 택한다.

3. 설치와 사용법

Python 3.11.5~3.14와 uv(또는 pipx)가 있으면 두 줄이다. PyPI 패키지 이름이 graphifyy(y 두 개)인 점만 조심한다. 다른 graphify* 패키지는 무관하다.

uv tool install graphifyy      # CLI 설치 (pipx install graphifyy 도 가능)
graphify install               # Claude Code 기본. 스킬 + CLAUDE.md 블록 + PreToolUse 훅
graphify install --project     # 저장소 안 .claude/skills/graphify/ 에 설치 (git add 안내 출력)
graphify cursor install        # Cursor
graphify install --platform codex    # Codex ($graphify 로 호출)

그다음 어시스턴트 안에서 /graphify .를 친다. 스킬은 먼저 graphify-out/graph.json이 있는지 보고, 있으면 다시 만들지 않고 질의로 넘어간다(빠른 길). 없으면 파일 감지 → 추출 → 그래프 → 군집 → 이름 짓기 → 출력 순으로 진행하며 코퍼스 크기와 토큰 비용을 보고한다. 스킬 파일 자체가 "API 키를 절대 묻지 말고 키 없이 진행하라"고 적어 두어, 코드 저장소에서는 아무 설정 없이 끝난다.

스크립트에서 쓰기 좋게 종료 코드가 정해져 있다. 0은 답, 3은 이름이 여러 노드에 걸려 후보를 나열한 경우, 4는 노드 없음이다. 이름이 겹치면 추측하지 않고 거부하는 쪽이다. 프로젝트 설정은 스캔 루트의 .graphifyrc에 둔다. 확장자가 애매한 파일(.inc가 PHP인지 Pascal인지, .h가 C인지 C++인지)은 language.inc=php처럼 못 박아야 그래프가 엉성해지지 않는다.

4. 에이전트가 정말 그래프를 쓰게 만드는 장치

README의 "Make your assistant always use the graph" 절과 install.py의 훅 정의를 옮겼다. 훅 명령은 설치 시점의 절대 실행 경로를 박아 넣으므로 업그레이드 뒤엔 graphify install과 graphify hook install을 다시 돌린다.

그래프가 있어도 에이전트가 안 쓰면 소용없다. graphify가 이 문제를 다루는 방식이 다른 코드 인덱스 도구와 다른 점이다. graphify install은 스킬 파일만 두는 게 아니라 CLAUDE.md에 안내 블록을 쓰고, Claude Code의 PreToolUse 훅(도구 호출 직전에 끼어드는 훅)을 .claude/settings.json에 등록한다. 훅은 Read·Glob·Grep은 물론 Bash의 cat·head·tail·sed -n 같은 읽기 명령 앞에서도 발동해 "그래프를 먼저 보라"고 권한다. --strict(또는 GRAPHIFY_HOOK_STRICT=1)로 설치하면 세션의 첫 원본 읽기를 한 번 거부해 그래프로 돌려보내고, 최근 30분 안에 그래프 질의가 있었으면 그냥 통과시킨다. 거부는 세션당 한 번이라 에이전트가 영영 막히지는 않는다. 그래프가 오래됐으면(마지막 커밋 뒤 바뀜) 훅이 그 사실도 알린다.

5. 벤치마크 — 공식 수치와 바깥 측정

BENCHMARKS.md(2026-07-05 갱신)의 표. 모든 시스템을 같은 하네스에서 같은 모델(Kimi K2.6)·같은 예산으로 돌리고 심판을 2차 심판과 대조(일치 90.6%, 카파 0.81)했다고 밝힌다. supermemory의 recall은 자체 임베더를 쓰라는 제약 때문에 직접 비교가 어렵다는 각주가 붙어 있다. 코드 지능 항목은 n=6이라 표본이 작다.

벤치마크를 읽을 때 두 가지를 분리해야 한다. 첫째, 위 표는 graphify 자체 하네스의 결과다. 공정성 규칙(단일 모델, 공유 임베더, 지출 장부)을 공개하고 재현 명령을 적어 둔 점은 평가할 만하지만, 자사 측정이라는 사실은 남는다. 둘째, 가장 널리 퍼진 수치인 "토큰 71.5배 절감"은 벤치마크 표가 아니라 how-it-works 문서의 토큰 비교에서 왔다. 그 비교의 코퍼스는 Karpathy의 저장소 셋 + 논문 5편 + 이미지 4장(52개 파일)이고, 질의 한 번에 약 1,700토큰 대 원본 전체 약 123,000토큰이다. 같은 문서가 4개 파일에선 5.4배, 6개 파일 라이브러리에선 약 1배라고 적는다. 작은 코퍼스는 어차피 컨텍스트에 들어가니 압축이 아니라 구조 파악이 값어치라는 뜻이다.

공식 수치는 how-it-works 문서, 독립 측정은 검색으로 확인한 정리 글들(Zero-to-Hero 가이드가 인용한 Exchangepedia·Medium·KubeBlogs 값) 기준이다. 원문 다수가 이 글을 쓴 환경에서 열리지 않아 가이드의 인용을 그대로 옮겼다.

6. 장점과 한계

강한 곳약한 곳
큰 저장소에 처음 들어갈 때. 허브와 커뮤니티로 구조를 먼저 잡고, "이 엔드포인트에서 저장소까지"를 경로로 본다작은 프로젝트. 파일이 컨텍스트에 다 들어가면 질의 오버헤드가 오히려 토큰을 늘린다
영향 분석과 온보딩. 공유 컴포넌트의 호출자·의존을 한 번에 나열하고, # WHY: 주석과 ADR이 노드로 코드에 연결된다집중 편집. 파일 몇 개를 고치는 작업에서는 에이전트가 그냥 rg로 가는 편이 빠르고, 실제로 그렇게 한다
문서 많은 저장소. PDF·논문·영상까지 같은 그래프에 들어가 "코드와 설계 문서의 연결"이 보인다오래된 그래프. pull·merge는 훅이 안 잡아 graphify update .를 잊으면 틀린 지도를 들고 다닌다(새 디렉터리 미발견 #1837 등)
검증 가능성. 간선마다 꼬리표와 file:line이 붙어 답을 원본에 대조할 수 있다그래프 답은 "맥락이지 검증된 답이 아니다". INFERRED 간선은 틀릴 수 있고 테스트 코드의 동명 헬퍼가 소음을 만든다
비용. 코드 그래프는 무료·오프라인이고, 재실행은 해시로 건너뛴다의미 패스는 문서·이미지를 설정한 모델로 보낸다. Kimi를 고르면 Moonshot 서버로 간다. 로그 파일 ~/.cache/graphify-queries.log가 질문을 남긴다(끄기 가능)

보안 쪽에서는 2026년 11월 21일 0.9.115가 Windows에서 저장소 안 경로(.sh의 source \\host\share\x 같은 UNC 경로)가 스캔 루트 밖을 건드려 SMB 인증을 유발하던 문제를 고쳤다(GHSA-g6c9-j4vm-mwq4). 낯선 저장소를 그래프로 만드는 도구라 이런 종류의 입력 처리 문제가 생길 수 있다는 뜻이고, 최신판 유지가 답이다. 스킬 파일 자체도 스캔 경로를 셸에 치환하지 않고 따옴표 heredoc으로 넘겨 경로에 섞인 셸 코드가 실행되지 않게 짜여 있다. 공유 HTTP MCP 서버를 띄울 때는 --api-key를 두고, graphify-out/cache/·manifest.json·cost.json은 gitignore에 넣는다.

7. 이 위키의 그래프와 나란히 놓으면

이 위키는 문서 79편을 개념 공유·인용 역링크·선언된 타입 관계의 세 층으로 잇는 자체 지식 그래프를 갖고 있다(연결의 세 층). 재료가 다르다. 이 위키는 사람이 큐레이션한 개념과 본문 링크에서 간선을 만들고, graphify는 구문 트리에서 호출·import·상속을 기계로 뽑는다. 그런데 운영 원칙은 닮았다. 이 위키의 "본문에 실재하는 관계만"은 graphify의 "간선을 지어내지 말고 모르면 AMBIGUOUS"와 같은 자리에 있고, 둘 다 임베딩 없이 구조 자체로 이웃을 찾는다. 다른 점은 쓰임이다. 이 위키의 그래프는 사람과 AI가 문서를 돌아다니는 지도이고, graphify의 그래프는 에이전트가 코드를 읽기 전에 들르는 색인이다. 이 저장소의 app.js·tools/*.py에 graphify를 돌려 보면 문서 그래프 옆에 코드 그래프가 하나 더 생기는 셈인데, 지금은 문서 쪽 그래프만 있으니 다음 실험으로 남겨 둔다.
