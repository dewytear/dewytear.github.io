Windows 주의

Windows PowerShell 환경에서는 별도 주의가 필요합니다. 핵심은 tmux 의존 기능은 psmux로 해결(WSL 불필요), WSL2는 대안 경로라는 점입니다.

  • v4.14.4에서 Native Windows Hook manifest 관련 수정(sh 호출 제거)이 있었고, 이후 Native Windows Hook은 그대로 사용할 수 있습니다. 과거 문서의 "WSL2 권장" 안내는 구식으로, 현행 공식 README는 WSL2를 대안 경로로만 안내합니다.
  • tmux 가 필요한 기능(omc team CLI, 일부 외부 AI 워커 병렬 실행)은 Native Windows PowerShell만으로는 제약이 있을 수 있습니다. 공식 README는 Windows용 네이티브 tmux 호환 도구인 psmux(winget install psmux)를 제시하며, psmux 사용 시 WSL이 필요 없습니다.
  • 플러그인 설치·setup·doctor·세션 내 스킬 사용은 Native Windows에서 그대로 가능합니다. 문제가 반복되는 환경이라면 WSL2로 전환하는 대안 경로도 있습니다.
  • PowerShell에서 npm view·npm ping 이 정상이어도, Claude Code 플러그인 설치 흐름과 npm CLI 설치 흐름은 별개입니다.
사전 확인 사항 1. 실제 사용 환경이 Windows Native PowerShell인지 WSL2인지
2. OMC를 Claude Code 플러그인으로 쓸지, npm CLI/runtime으로 쓸지
3. /omc-teams 처럼 tmux가 필요한 멀티 AI 기능까지 사용할 계획인지
