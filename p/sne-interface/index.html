인터페이스 — 먼저 확정 요청 (최우선)

우선 요청 엔진 전체 구현에는 시간이 걸리므로, 인터페이스(주고받는 규격)를 엔진 본체보다 먼저 확정·제공해 주기를 요청한다. 그래야 AI 알림도 발송요청 발행·결과 수신 부분을 병행 구현할 수 있다.

진행 순서(제안)

  1. 선호안 제시 — AI 알림이 발송요청을 큐로 발행하고 엔진이 소비하는 방향을 선호한다.
  2. 방향 합의 — 이 방향 논의를 가장 높은 우선순위로 협의.
  3. 인터페이스 선확정 — 합의 즉시 인터페이스를 먼저 확정 → 병행 개발 착수.

필요한 인터페이스 (방향 · 주고받는 정보)

#인터페이스방향주고받는 정보(개념)
①발송요청 전달AI 알림 → 엔진요청 식별자, 회사, 발송 대상, 메시지 내용, 수신자 목록, 채널, 시점 유형·파라미터
②발송 시점 확정(조회·해석)엔진 → AI 알림 → 엔진타이밍 도래 시 "지금 발송할 최종 대상·내용"을 확정 요청 → 확정 결과 회신
③발송 결과·상태 회신엔진 → AI 알림요청 매핑, 채널별 성공/부분실패/실패, 실패 사유, 도달·읽음
④(선택) 현황·이력 연계협의현황 화면을 엔진이 제공 시 AI 알림 데이터와의 연계 방식

구체 필드·형식은 협의로 확정한다. 이 문서에서는 방향과 주고받는 정보의 종류까지만 제시한다.

규모 · SLA · 우선순위

규모·SLA(일/피크 발송 물량, "즉시" 허용 지연, 이력 보존 기간, 결과 회신 세분도)는 협의로 확정한다. 공수 산정에 필요한 최소 규모(자릿수)는 킥오프에서 함께 정한다.

우선순위(Phase)

Phase 1 · 필수

  • 알림·쪽지·메일 발송 + 멱등·전달 보장
  • 시점 4유형 타이밍 + 발송 시점 최신 확정
  • 주기 배치 수명주기 관리
  • 결과·상태 회신 + 발송 현황 화면
  • 인터페이스 선확정

이후 단계

  • 예약/회수 고급 기능, 카카오톡·대화 채널 확장
  • 읽음 확인, 고급 통계·분석

협의가 필요한 사항

  • 인터페이스 방향(선호안 → 빠른 확정)
  • "즉시" 발송의 실시간 기준(허용 지연)
  • 채널 확장 순서·우선순위
  • 도달·읽음 확인의 범위(어디까지 회신)
  • 발송 시점 대상 확정의 구체 연계 방식(확정 요청·응답)
  • 채널 인증 정보의 보유·관리 주체
  • 발송 규모·SLA 대략치(공수 산정용)

기대효과 · 일정

  • 전달 신뢰성 — 유실·중복 없는 발송, 도달 확인.
  • 확장성 — 대량·다채널·신규 채널 대응.
  • 운영성 — 현황·재처리로 운영 부담 감소.
  • 공용화 — 발송엔진을 공용 자산으로.
