실행하기 — 설치·실행·리뷰

하네스를 매번 손으로 구성(에이전트·스킬 등을 일일이 준비)하긴 번거롭습니다. 그래서 강사는 목표만 주면 하네스를 대신 구성해 주는 "메타 하네스" 스킬을 개발해 GitHub에 공개했고, 많은 사용 후기와 스타를 받았습니다. 오늘 실습은 이 스킬을 설치하는 것으로 시작합니다.

방법 1 — 명령 두 줄

# 1) 하네스 마켓플레이스 추가
/plugin marketplace add lev-factory/harness
# 2) 하네스 플러그인 설치
/plugin install harness

방법 2 — /plugin UI

  1. /plugin 입력 → 방향키 오른쪽으로 이동해 Marketplace 탭 선택.
  2. Add Marketplace 에서 lev-factory/harness 입력 → Enter (GitHub에서 다운로드).
  3. 플러그인 설치 화면에서 Enter → User 스코프로 설치하면 어떤 프로젝트에서든 사용 가능.

설치 후 — 리로드하고 확인

설치가 끝나면 "리로드하라"는 안내가 나옵니다. /reload(리로드 플러그인) 후 /harness 가 뜨면 정상 설치된 것입니다.

/reload
# 아래가 자동완성/실행 가능하면 설치 성공
/harness
마켓플레이스 경로 확인 마켓플레이스 핸들(lev-factory/harness)은 발표에서 언급된 값을 옮긴 것으로, 실제 설치 시에는 강사의 GitHub(예: "하네스 100" 검색)에서 정확한 저장소 경로를 확인하세요. 플러그인 설치가 잘 안 되면 UI 방식과 명령 방식을 번갈아 시도합니다.

하네스 실행하기 (실습)

의도만 전하면 팀이 꾸려지고, 사람이 리뷰·승인한 뒤 실행은 손을 떠납니다.

설치한 /harness 로 실제 일을 시켜 봅니다. 핵심 차이는 "의도만 전달" 한다는 점입니다.

"작성해줘"가 아니라 "작성하고자 합니다"

보통 AI에는 "보고서를 작성해줘"라고 지시합니다. 하지만 하네스에는 의도만 말합니다. 그러면 그 의도를 해결해 줄 에이전트 팀을 구성해 줍니다.

/harness 2026년 국가 과학기술 전 분야 전략기술 예산 배분 및
포스트 PBS 대응 전략에 대해 조사하고 보고서를 작성하고자 합니다.
  • /harness 입력 후 Tab 으로 자동완성한 뒤 요청을 이어 붙입니다.
  • 실행하면 도메인 분석 → 팀 구성을 진행합니다.
  • 중간에 "하네스 풀 구축 / 하네스만 구축" 같은 선택을 물어봅니다.
  • 내 데이터가 있으면 함께 주며 물어볼 수 있습니다. (예: 1000페이지 넘는 PDF 분석도 잘 처리)

구성 완료 → 리뷰 → 실행

하네스 구성이 완료되면 잠시 멈춥니다. 만들어진 에이전트들을 리뷰한 뒤, 문제없으면 실행합니다.

# 리뷰 후 그냥 진행 지시
진행시켜

이 순간 작업은 사람의 손을 떠나, 에이전트 팀이 리서치 → 보고서 작성 → QA를 오케스트레이터가 계획한 순서대로 끝까지 진행합니다.

병렬로 여러 작업

  • 한 작업을 돌려놓고 다른 터미널 창을 띄워 또 다른 일을 시킬 수 있습니다. (예: "코스피가 만까지 갈 수 있을까?" 조사)
  • 실무 개발자 자리에는 이렇게 터미널이 여러 개 떠서 서로 다른 일을 동시에 합니다.
  • Shift + 방향키 로 현재 스폰된 에이전트들이 무슨 일을 하는지 살펴볼 수 있습니다. (색이 들어간 에이전트가 작업 중)
무엇에 쓰나 데이터 분석, 리서치, 보고서 작성, 시뮬레이션 등 — 무엇이든 의도를 주면 그 일을 할 에이전트 팀을 구성해 줍니다.

생성 결과 리뷰 — 에이전트·스킬·오케스트레이터

오케스트레이터가 에이전트들을 조율하고, 스킬이 주입되며 산출물은 _workspace에 모입니다.

하네스가 구성되면 무엇이 만들어지는지 살펴봅니다. Claude Code는 에이전트·스킬 등을 .claude 폴더 하위에 생성합니다.

만들어진 에이전트 (예시)

"국가 R&D 예산·포스트 PBS" 과제에서는 이런 팀이 구성됐습니다.

  • R&D 예산 정량 분석가 — 예산 배분·조정안을 부처·사업·연도 단위로 분해, 정부/출연 비율 변화 추적.
  • 정부출연기관 거버넌스·재정 전문가 — PBS에서 임무중심형 체제로의 전환 전략 도출.
  • 국가 R&D 정책 리서처 — 예산·정책 문서·보도자료·NIS/NSTC 안건 등을 1차 출처에서 조사.
  • 보고서 작성 에이전트 — 앞선 산출물을 모아 보고서로 집필.
  • QA 리뷰어 — 단순 오탈자가 아니라 주장–출처 정합성, 수치 일관성, 권고 논리의 연결을 교차 확인.

주입되는 스킬

에이전트만으로는 부족해서, 전문화된 스킬을 만들어 주입합니다. 예: 예산 정량 분석법(표준 양식·계산 규칙·체크리스트), 정책 보고서 인용 검증(검증 축·우선순위), 정부 정책 보고서 작성 포맷(목차).

오케스트레이터 (항상 1개)

에이전트들이 딴 길로 새지 않게 조율하는 PM 역할입니다. 세부 작업을 들여다보진 않고, "에이전트들이 일을 잘하는가"만 봅니다. Phase 0부터 각 단계에 필요한 에이전트가 무엇인지 워크플로우가 사전 계획되어 있습니다. (Claude Code의 플랜 모드와 유사한 느낌)

리뷰와 실행 준비

  • 리뷰 과정은 필수입니다. "에이전트를 더 추가", "의도와 안 맞으니 수정", "하네스를 수정해줘" 처럼 피드백하면 에이전트/스킬이 새로 생기거나 보강됩니다.
  • 에이전트가 동적으로 로딩되지 않는 문제가 있습니다. /agents 에 안 보이면 /exit 후 다시 들어오면 로딩됩니다.
_workspace 폴더 하네스로 실행하면 _workspace 폴더가 생겨, 에이전트들이 만든 중간 산출물이 모입니다 — 1차 리서치, 예산 분석, QA 리포트(크리티컬·메이저·마이너 이슈)와 수정안, 한계 사항, 그리고 근거 출처까지. 출처 기반이라 할루시네이션이 크게 줄어듭니다.

돌려 봤으니 이제 속을 들여다볼 차례입니다 — 동작 원리 편이 주방 비유로 시작해 에이전트 팀과 핵심 3요소의 구조를 풉니다.
