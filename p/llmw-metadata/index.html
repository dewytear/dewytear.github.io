노트 구조 — 메타데이터와 점진적 공개

위키 노트를 열면 제목 → 메타데이터 → 본문 순으로 구성됩니다. 예컨대 본문이 38번째 줄부터 시작한다면, 앞의 37줄이 모두 메타데이터입니다.

YAML 프론트매터가 핵심

Obsidian이 마크다운 에디터로서 가치가 높은 지점이 바로 이 YAML 프론트매터 메타데이터 필드입니다. Claude Code에서 배운 점진적 공개(progressive disclosure) 와 같은 원리로 동작합니다.

에이전트는 메타데이터(프론트매터)를 먼저 읽고, 필요할 때만 본문을 엽니다.
  • 컨텍스트 윈도우는 제한(많아야 100만 토큰)되어 있어, 모든 내용을 다 열어 볼 수 없습니다.
  • 그래서 중요한 내용만 간결하게(concise) 맨 위(메타데이터)에 담아 둡니다.
  • Claude Code 같은 에이전트는 이 메타데이터를 먼저 읽습니다. 전체에 비하면 빙산의 일각이지만, 이 일각들만 훑어 무엇과 관련된 내용인지 빠르게 파악합니다.

제목·설명을 잘 쓰기 (영어로)

스킬의 description 처럼, 노트의 제목과 설명(description) 필드를 잘 쓰는 것이 중요합니다. 우리는 한국인이지만 인공지능은 영어를 더 빨리·잘 읽으므로 메타데이터는 영어로 쓰는 것이 유리합니다.

컨텍스트 최적화 Obsidian의 큰 장점은, 한 파일에 모든 내용을 담지 않고 "취향은 취향.md 를 보라", "전문 페르소나는 여기를 보라" 처럼 다른 파일의 주소를 명시할 수 있다는 점입니다. 일할 때 필요한 파일만 열어 보게 해 컨텍스트를 최적화합니다. 강사는 Karpathy의 아이디어를 빌려 이런 메타데이터 작성을 자동화하는 커맨드·스킬 세트를 만들어 두었습니다.
