영화 줄거리로 영화 찾기 — Neo4j 샌드박스에서 만드는 첫 벡터 리트리버

앞 편이 지도를 펼치는 글이었다면, 이번 편은 신발끈을 묶는 글입니다. 설치 없이 브라우저에서 그래프 DB를 하나 빌리고, 영화 줄거리를 숫자로 바꿔 넣고, “이런 이야기의 영화 없나?”라고 물으면 비슷한 영화를 찾아 주는 검색기를 끝까지 만들어 봅니다.

목표는 한 문장입니다. 줄거리를 던지면, 줄거리가 비슷한 영화를 돌려주는 검색기. 대단해 보이지만 부품은 세 개뿐이고, 셋 다 이름만 낯설지 하는 일은 소박합니다.

  • 임베딩 — 문장을 의미를 담은 숫자 목록(벡터)으로 바꾸는 일입니다. 뜻이 비슷한 문장일수록 숫자들도 가까워집니다. 이 변환을 해 주는 것이 임베딩 모델이고, 여기서는 OpenAI의 모델을 씁니다.
  • 벡터 인덱스 — 그 숫자들을 빨리 찾을 수 있게 달아 두는 색인입니다. 사전 옆면의 ㄱㄴㄷ 홈을 짚으면 바로 그 페이지가 펼쳐지듯, 인덱스가 있으면 “가까운 벡터”를 전수조사 없이 찾습니다.
  • 리트리버 — 질문을 받아 임베딩하고, 인덱스에서 가까운 것을 골라 결과로 돌려주는 검색기 그 자체입니다.
오늘의 다섯 걸음. 마지막 걸음에서 “줄거리 → 비슷한 영화”가 실제로 돌아갑니다.

첫걸음 — 그래프 DB를 빌린다

그래프 DB를 만져 보려고 뭘 설치할 필요는 없습니다. Neo4j가 샌드박스라는 무료 클라우드 인스턴스를 빌려줍니다 — 파이썬 노트북을 브라우저에서 바로 돌리는 구글 코랩과 같은 감각으로, 브라우저에서 바로 그래프 DB 한 대가 생깁니다. 로그인하고 프로젝트를 고르라는 화면이 나오면 Recommendations를 고릅니다. 영화 추천 연구에 널리 쓰이는 MovieLens 계열의 영화 추천 데이터가 미리 적재된 프로젝트입니다.

열어 보면 앞 편에서 그림으로만 보던 것이 실물로 서 있습니다. 노드는 다섯 종류 — 영화(Movie), 장르(Genre), 배우(Actor), 감독(Director), 사용자(User). 영화 노드 하나를 클릭하면 제목(title), 상영시간, 그리고 줄거리(plot) 같은 속성들이 줄줄이 달려 있습니다. 쿵푸팬더 3의 노드에는 잭 블랙이 ACTED_IN 화살표로 이어져 있고, 어느 사용자가 RATED 화살표로 이어져 있는데, 그 화살표 안에 평점 4점과 남긴 시각이 속성으로 들어 있습니다. 관계 자체가 데이터를 담는다 — 그래프 DB의 이 성질을 여기서 처음 눈으로 확인하게 됩니다.

Recommendations 데이터의 뼈대. RATED 화살표는 그 안에 평점과 시각을 담습니다 — 관계도 데이터를 갖는다는 것이 프로퍼티 그래프의 특징입니다.

두 걸음 — 사이퍼로 동네 산책

본격적인 공사 전에 사이퍼(그래프 질의 언어, 앞 편 참조) 몇 줄로 데이터와 인사를 해 둡니다. 골격은 셋뿐입니다. MATCH로 찾고 싶은 관계의 모양을 그리고, RETURN으로 무엇을 돌려받을지 적고, LIMIT으로 개수를 자릅니다.

// 어떤 사용자가 어떤 영화를 평가했나 — 25건만 구경
MATCH (u:User)-[r:RATED]->(m:Movie) RETURN u, r, m LIMIT 25

// 톰 행크스가 출연한 영화의 제목과 줄거리 — 그래프가 아니라 표로 돌아온다
MATCH (a:Actor {name: 'Tom Hanks'})-[:ACTED_IN]->(m:Movie)
RETURN m.title, m.plot LIMIT 10

첫 질의는 화면에 그래프로 그려지고, 두 번째처럼 노드가 아니라 속성만 돌려받으면 표로 돌아옵니다. 같은 데이터를 그림으로도 표로도 받아 볼 수 있다는 것, 여기까지 확인되면 산책은 충분합니다.

세 걸음 — 줄거리를 숫자로 바꿔 노드에 심는다

이제 핵심 공정입니다. 파이썬에서 Neo4j 드라이버로 샌드박스에 접속한 뒤(접속 코드는 샌드박스 화면의 Connect via drivers에 그대로 나와 있어 복사해 붙이면 됩니다), 영화 노드의 plot 텍스트를 하나씩 꺼내 임베딩 모델에 통과시키고, 나온 벡터를 그 노드의 새 속성으로 도로 심습니다. 전부 돌리면 오래 걸리니 실습답게 100편만 자릅니다.

# 줄거리가 있는 영화 100편 → 임베딩 → plotEmbedding 속성으로 저장
movies = tx.run("""
    MATCH (m:Movie) WHERE m.plot IS NOT NULL
    RETURN m.title AS title, m.plot AS plot LIMIT 100""")
for row in movies:
    vec = generate_embedding(row["plot"])   # OpenAI 임베딩 호출
    tx.run("""
        MATCH (m:Movie {title: $title})
        SET m.plotEmbedding = $vec""", title=row["title"], vec=vec)

몇십 초 뒤 샌드박스에서 아무 영화나 다시 클릭해 보면, plot 옆에 plotEmbedding이라는 속성이 새로 생겨 1,536개의 실수가 빼곡히 들어차 있습니다. 사람 눈에는 소음이지만, 이 숫자들의 거리가 곧 줄거리의 닮음입니다. 시연에 쓰인 모델은 OpenAI의 text-embedding-ada-002(출력 1,536차원)인데, 지금 새로 시작한다면 같은 자리의 후속 모델(text-embedding-3 계열)을 쓰는 편이 좋습니다 — 절차는 완전히 같습니다.

네 걸음 — 색인을 단다

벡터를 심었으니 찾는 속도를 챙길 차례입니다. 100편이야 전수조사해도 그만이지만, 수십만 편이 되면 질의마다 전부 재 보는 건 낭비입니다. 그래서 벡터 인덱스를 만듭니다 — 사전의 ㄱㄴㄷ 홈처럼, 가까운 벡터로 가는 지름길을 미리 파 두는 것입니다. 사이퍼 한 문장이면 됩니다.

// 영화 노드의 plotEmbedding 위에 벡터 인덱스 생성
CREATE VECTOR INDEX moviePlots
FOR (m:Movie) ON m.plotEmbedding
OPTIONS {indexConfig: {
  `vector.dimensions`: 1536,          // 임베딩 모델의 차원과 일치
  `vector.similarity_function`: 'cosine'
}}

옵션 두 줄이 하는 말은 단순합니다. 이 색인이 다룰 벡터는 1,536차원이고, ‘가깝다’의 기준은 코사인 유사도(벡터 사이의 각도로 닮음을 재는 함수)라는 것. 차원 수는 반드시 임베딩 모델의 출력과 맞춰야 합니다 — 여기서 어긋나면 인덱스가 벡터를 받아 주지 않습니다.

다섯 걸음 — 리트리버를 조립하고, 묻는다

부품이 다 모였습니다. 접속(드라이버), 색인(인덱스), 변환기(임베더). 이 셋을 앞 편에서 소개한 neo4j-graphrag 패키지의 VectorRetriever에 넘기면 검색기가 완성됩니다. 넷째 인자로 “결과로 어떤 속성만 돌려줄지”를 정할 수 있습니다.

from neo4j_graphrag.retrievers import VectorRetriever

retriever = VectorRetriever(
    driver,                                # ① 어느 DB에서
    index_name="moviePlots",               # ② 어느 색인으로
    embedder=embedder,                     # ③ 질문을 어떻게 벡터로
    return_properties=["title", "plot"],   # ④ 무엇을 돌려줄지
)
result = retriever.search(query_text="장난감들이 몰래 살아 움직이는 이야기", top_k=3)

이제 진짜 묻습니다. 토이 스토리의 줄거리를 짧게 요약해 질의로 던지면, 1등으로 토이 스토리가 돌아옵니다 — 제목과 줄거리, 그리고 코사인 유사도 점수까지 함께. 총기 사건을 다룬 영화를 묘사해 던지면 그런 소재의 영화가 0.93쯤의 점수로 올라옵니다. 질의에 영화 제목을 말한 적이 없다는 점이 포인트입니다. 단어가 겹쳐서가 아니라 이야기가 닮아서 찾아진 것 — 이것이 키워드 검색과 벡터 검색의 갈림길입니다.

여기서 한 발 더

오늘 만든 것은 순수한 벡터 검색기입니다. 아직 그래프의 힘은 절반도 쓰지 않았습니다 — 찾아낸 영화 노드에서 ACTED_IN을 타고 배우로, IN_GENRE를 타고 장르로, RATED를 타고 취향이 비슷한 사용자로 걸어 나가는 순간부터가 GraphRAG의 본편입니다. 그래도 순서는 이쪽이 맞습니다. 벡터로 건지고, 그래프로 걷는다 — 오늘 완성한 리트리버가 그 첫 동사입니다. 검색이 이야기를 알아본 것은 줄거리를 정성껏 심어 둔 덕입니다. 이 위키가 문서마다 개념과 관계를 기계가 읽을 수 있는 형태로 담아 두는 것도 같은 이유에서입니다.

사실검증 노트 실습 절차와 실행 결과(임베딩 100편, 토이 스토리 검색 1위, 총기 소재 질의의 0.93 유사도)는 제공받은 시연 녹취를 재구성한 것으로, 이 위키가 동일 환경을 재실행하지는 않았다. 코드와 문법은 공식 문서로 교차검증했다 — neo4j-graphrag-python 문서의 VectorRetriever(driver·index_name·embedder·return_properties, search의 query_text·top_k), Neo4j의 CREATE VECTOR INDEX 문법(vector.dimensions·vector.similarity_function), Neo4j 샌드박스의 Recommendations(MovieLens 계열) 예제 데이터셋. 시연 당시 패키지명은 neo4j-genai였으나 현재 neo4j-graphrag로 개명되었고, text-embedding-ada-002는 레거시 모델이라 신규 구축에는 text-embedding-3 계열이 권장된다. 임베딩 공간 그림은 개념 모식도이며 실측 좌표가 아니다.
