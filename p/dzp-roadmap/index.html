추진 로드맵 — 4 Phase와 1차 PoC

검증되지 않은 것을 조직에 도입하지 않는다. 사전 검증에서 시작해 팀 PoC, 센터 확대, 전사 확장의 순서로 단계를 밟는다.

4단계 추진

  • Phase 1 · Reference Wiki 엔진 이식 — 백지에서 시작하지 않는다: 회사 저장소에 wiki-plugin(v0.21.0)을 설치해 등재·인덱스·검증 체계를 그대로 부트스트랩하고(플러그인화의 wiki-init → add-doc → validate 스킬), Claude Code 연계로 SCM 도메인 지식을 수동 큐레이션하며 Knowledge Index 검색·HTML 축적·AI Curator Prototype을 검증한다. 첫 대상: OmniEsol ERP · SCM 도메인
  • Phase 2 · 회사 PoC (SCM구축개발1Unit) — 회사 Wiki Repository, GitLab Project Registry, Change Collector, SHA 증분 처리, AI Knowledge Curator, 확장 필드(identifiers·sources·trust) 도입, Read-Only Portal. 첫 Source: OmniEsol ERP SCM GitLab Repository
  • Phase 3 · SCM개발센터 확대 — 다중 프로젝트, Product/Domain 분류, 프로젝트 간 지식 연결(타입 관계의 교차 프로젝트 적용), Knowledge Lifecycle(supersedes 운영), 보안등급, 품질 KPI
  • Phase 4 · 전사 확장 — 사내 SSO, 전사 Search, 제품별 Knowledge Governance, AI Agent 연계(사내망 llms.txt·그래프 JSON 계약), 사내 개발 플랫폼 공식화

1차 PoC — OmniEsol ERP (SCM 도메인)

ERP는 업무 Rule의 밀도가 가장 높은 도메인이다. 영업·수주·구매·생산의 업무 Rule, 전표 상태 전이 체계(수주 → 출고 → 매출), 여신·가용재고(ATP) 체크 정책, 프로세스 간 연계, DB Table 구조와 Column 의미, 장애 사례, 정책 변경 이력 등 지식화 가치가 높은 요소가 이미 존재하며, 아래와 같은 identifier로 검색·축적 효과를 즉시 검증할 수 있다(엔트리 구조는 지식 관리 체계의 스키마 예시 참조).

SD_SO_HDR   SD_SO_ITEM   SO_STS_CD
CREDIT_CHK_YN   NR_SD_SO_COMPLETED   createSalesOrder

검증 KPI — 네 축, 게이트로 계측한다

KPI는 선언이 아니라 계측 방법이 붙어야 목표다. 네 축의 상당수는 Reference Wiki가 이미 CI 게이트로 재고 있는 값이어서, 회사 PoC는 측정 장치를 새로 발명할 필요가 없다.

  • 지식 생성 품질 — 자동 생성 정확도, 기존 문서 갱신 성공률, 중복 문서 생성률, 잘못된 추론 비율. 계측: 검증기 ERROR 0(끊어진 참조·중복 ID·미등재) + 인덱스 드리프트 0(--check) + 고아 문서 0(그래프 검증) — 전부 커밋마다 자동 판정. 추론 오류는 trust 등급별 표본 검수.
  • 검색 품질 — Identifier 검색 성공률(목표 방향: 소스에서 만난 식별자 1개로 정책 문서 도달 ≥90%), 연관 문서 추천 정확도, 원하는 정보 도달 시간.
  • 개발 생산성 — 반복 질문 감소, 과거 장애 재분석 감소, 신규 개발자 학습 시간 감소(왜 지금인가의 온보딩 3~9개월·주 8시간 손실 통계가 베이스라인), AI 도구 Context 설명량 감소.
  • 운영 품질 — Merge 대비 지식 반영률(목표 방향 ≥90%): "실질 변경이 있는 머지에는 지식 반영이 동반됐는가"를 diff 기반 동반 게이트의 통과율로 상시 계측(아키텍처의 무결성 게이트). 누락 변경 건수(sync-state 보정 Batch가 집계), superseded 처리율, 관계 타입 분포(선행지식 편중 여부 — 비차단 리뷰 신호가 새 문서마다 노출).
맺음 본 제안은 개발자의 업무 흐름을 바꾸지 않은 채 선순환(개요)을 만드는 것이며, 그 지식 엔진은 Reference Wiki로 이미 돌아가고 있다. 남은 일은 검증된 엔진에 GitLab이라는 Event Stream을 연결하는 것이다.
