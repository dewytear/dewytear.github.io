확장 — 스킬·플러그인·에이전트

스킬은 한 번 이상 반복할 작업을 저장해 두고 계속 재사용하는 기능 단위입니다. 앞에서 만든 디자인 시스템을 스킬로 만들면, 이후 여러 사이트를 같은 디자인으로 쉽게 찍어낼 수 있습니다.

@(골뱅이) — 파일·폴더 참조

기존 파일을 참고해 작업시키려면 @ 를 입력합니다. @ 를 치면 파일 선택 목록이 뜨고, 원하는 파일을 고른 뒤 Tab 으로 확정합니다.

# 디자인 시스템 파일을 참조해 스킬로 만들기
@design-system_new.html 이 디자인 시스템을 "my-design" 스킬로 만들어줘.

@ 뒤의 파일/폴더는 "이 내용을 참고해서 작업하겠다"는 의미입니다. 파일뿐 아니라 폴더도 지정할 수 있습니다.

권한 요청

작업 중 특정 폴더에 무언가를 하려 할 때 권한을 묻는 옵션이 나옵니다.

  • 1번 — 이번 한 번만 허용.
  • 2번 — 같은 작업은 더 이상 묻지 않기.

스킬이 저장되는 위치

  • 프로젝트 전용 — 프로젝트 하위 .claude/skills/ 에 생성(그 프로젝트에서만).
  • 전역 — 사용자 폴더 하위 ~/.claude/skills/ (Windows는 Users\사용자\.claude\skills). 어느 폴더에서 실행하든 사용 가능.

스킬이 만들어지면 ~/.claude/skills/my-design/ 아래에 그 내용(예: 애플 톤 화이트 디자인 시스템)이 기록됩니다.

스킬로 다시 사이트 만들기

@papers_new.md 이 논문 내용을 토대로 my-design 스킬을 사용해서
동일한 디자인으로 논문 소개 웹사이트를 만들어줘.

이렇게 하면 앞서 만든 미토스 사이트와 같은 디자인의 논문 소개 사이트가 만들어집니다.

더 많은 스킬 스킬 만드는 방식은 대부분 비슷합니다. 예를 들어 OpenAI GPT Image 2 의 개발자 문서 URL을 주고 "이 내용으로 GPT 이미지 스킬로 만들어줘" 라고 하면 인포그래픽 생성 스킬이 됩니다. HWP 처럼 공식에 없는 형식도 직접 스킬로 만들어 재사용할 수 있습니다.

플러그인 · 마켓플레이스

여러 스킬을 묶어 플러그인 형태로 배포할 수 있습니다. 논문은 대부분 PDF이므로, PDF를 잘 읽는 스킬이 든 공식 문서 스킬(document-skills) 플러그인을 설치해 봅니다.

1) 마켓플레이스 추가

Claude Code에서 /plugin 을 입력하고 Enter를 누르면 플러그인 화면이 나옵니다. 화살표 키로 마켓플레이스 를 선택 → Add Marketplace 로 Anthropic 공식 마켓플레이스를 추가합니다.

# GitHub 접속이 막히거나 UI가 어려우면, 명령으로 직접 실행
/plugin marketplace add anthropics/skills

2) document-skills 설치

추가된 마켓플레이스(anthropic 공식)에는 플러그인이 몇 개 있는데, 그중 document-skills 만 설치합니다. 목록에서 Space 로 선택하고 Enter 로 설치합니다. 명령으로도 됩니다.

/plugin install document-skills

이 스킬은 PDF · PPT(pptx) · 엑셀 같은 문서를 Claude Code에서 읽을 수 있게 해 줍니다.

3) 재시작 후 확인

설치 후 반영이 잘 안 되면, /exit 로 Claude Code를 나갔다가 다시 실행합니다. 그런 다음 /pdf 또는 /pptx 를 입력했을 때 명령이 뜨면 설치 성공입니다. 안 뜨면 마켓플레이스 추가·설치를 다시 시도합니다.

설치가 막힐 때 (GitHub 오류 등) 구글에서 "anthropic skills github" 를 검색해 공식 저장소로 들어가면, README 중간에 설치 명령이 있습니다. plugin marketplace add ... 한 줄과 plugin install document-skills 한 줄을 각각 복사해 Claude Code에 붙여 넣어 실행하면 됩니다.

에이전트(Agent) 만들기

에이전트는 특정 역할을 맡은 전문 작업자입니다. 스킬 만들기만큼 쉽습니다 — 아이디어만 있으면 나머지는 AI가 작성해 줍니다. 여기서는 논문 분석 에이전트를 만들어 다운로드한 PDF를 분석합니다.

1) PDF 준비

# 논문 상세 페이지 URL을 주고
https://arxiv.org/abs/....  이 논문의 PDF 파일을 다운로드해줘.

Claude Code가 arXiv에서 PDF 링크를 찾아 현재 폴더에 내려받습니다. (PDF 읽기는 앞서 설치한 document-skills 가 담당합니다.)

2) 에이전트 생성

이 프로젝트 한정으로 만들려면 .claude/ 하위에 만들도록 지정합니다.

.claude 하위에 논문을 분석하는 에이전트를 추가해줘.

생성된 에이전트에는 다음과 같은 메타 정보가 들어갑니다.

  • 이름 · 설명(description) — 이 에이전트가 어떤 일을 하는지.
  • 사용 도구 권한 — 파일 읽기, Bash 명령 실행 등.
  • 모델 지정 — 에이전트별로 사용할 모델 선택(예: 가장 좋은 opus).
  • 페르소나 · 원칙 — 예: "학술 논문 분석 전문가", "5분 안에 핵심을 파악하는 리포트 생성".

분석 방식(초록 중심 / 한계점 중심 / 검증 강화 등)은 추가 요청으로 고도화할 수 있습니다.

3) 목록 확인 · 실행

에이전트는 만든 직후 바로 로딩되지 않을 수 있습니다. /agents 로 현재 폴더에서 쓸 수 있는 에이전트를 확인하고, 안 보이면 /exit 후 재시작합니다.

# PDF를 참조로 걸고, 만든 에이전트로 분석
@paper.pdf  paper-analyzer 에이전트를 이용해서 이 논문을 분석해줘.

4) 병렬 분석 — Claude Code의 진가

하나의 오케스트레이터가 에이전트 여러 개를 병렬로 띄워 동시에 분석한 뒤 취합합니다.

링크를 알고 있는 나머지 논문들도 한꺼번에 분석할 수 있습니다.

나머지 논문들도 분석해서 파일로 저장해줘.

Claude Code는 에이전트를 여러 개 병렬로 스폰해(예: 12개 논문을 5~6개 에이전트로) 동시에 분석합니다. 이것은 웹 채팅에서는 안 되는 일입니다. 분석 결과는 앞서 만든 논문 소개 사이트의 상세 페이지로 만들어 연결할 수도 있습니다.

에이전트를 쓰는 또 다른 이유 — 컨텍스트 절약 에이전트는 메인 세션과 별도의 컨텍스트 윈도우를 씁니다. 무거운 분석은 에이전트에게 맡기고 결과만 받으면, 메인 세션의 컨텍스트를 거의 쓰지 않아 품질을 오래 유지할 수 있습니다. (다음 문서 참고)

만들 수 있는 건 다 만들어 봤으니, 남은 것은 오래 쓰는 법입니다 — 운영 편에서 사용량·컨텍스트·세션 관리와 마무리 팁을 정리합니다.
