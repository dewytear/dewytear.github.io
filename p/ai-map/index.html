Knowledge Map — AI

이 페이지는 AI World 아래의 강의·학습 문서 전체를 AI가 읽어 만든 구조적 지식 인덱스(knowledge-index.json)를 종합한 지식 지도입니다. 문서별 요약 · 핵심 개념 · 연관 문서를 모아, 무엇이 어디에 있고 서로 어떻게 이어지는지를 보여 줍니다. 각 문서 하단의 “연관 문서” 추천도 같은 인덱스에서 나오며, 이 연관 관계는 Knowledge Graph에서 3가지 3D 표현과 6가지 2D 표현으로 살펴볼 수 있습니다.

위키의 지식은 World → Domain → System → Document의 4계층으로 구성됩니다 — World는 최상위 지식 세계(AI · DOUZONE), Domain은 지식 영역, System은 구체적 체계·주제(아래 표의 그룹들), Document는 개별 문서입니다. 이 지도는 그중 AI World를 다루고, 업무 지식은 Douzone Knowledge Map이 같은 구조로 집계합니다.

두 World — 학습 지식(AI)과 업무 지식(DOUZONE)이 같은 인덱스 위에서 이어집니다.
세 갈래로 나뉘지만, 위 공유 개념들이 갈래를 가로질러 문서를 촘촘히 연결합니다.

System 한눈에

문서는 아래 System으로 묶입니다. “허브 문서”는 다른 문서에서 가장 많이 연관으로 지목된, 그 갈래의 관문 문서입니다. 표의 수치는 knowledge-index.json에서 실시간 집계됩니다. 편수는 하위 폴더의 문서까지 포함한 수라, 사이드바에서 접혀 있는 폴더가 있으면 눈에 보이는 항목 수보다 많을 수 있습니다.

System 상세 — 무엇이 들어 있고, 어떤 순서로 읽는가

지식 체계 — 이 위키 자체의 설명서 (6편)

이 위키의 지식이 어떻게 쌓이고, 이어지고, 읽히는지를 실제 데이터로 해설하는 자기기술 System입니다. 지식은 어떻게 쌓이는가(4계층·등재 파이프라인·세 가지 표식) → 문서는 어떻게 이어지는가(개념 큐레이션·idf 엣지·방향 있는 타입 관계) → 그래프를 읽는 9가지 눈(뷰별 질문·허브·브리지) → AI가 이 위키를 읽는 법(기계판독 계층) → 위키 엔진의 플러그인화(wiki-plugin) → 위키는 어떻게 스스로를 지키는가(게이트·자동화) 순서로 읽으면, 이 지도 페이지의 모든 수치가 어디서 오는지 알 수 있습니다.

고찰 — 이 위키를 밖에서 보는 자리 (1편)

지식 체계가 이 위키의 작동을 설명한다면, 고찰은 다른 방식과 견줘 보며 이 위키가 어디에 서 있는지를 묻습니다. 다 기록하는 사람, 발행하는 위키는 목걸이 녹음기와 화면 녹화로 삶 전체를 사적으로 담는 라이프로거의 시스템을 이 위키와 나란히 놓고, 수집·공개성·규율·정서적 보상의 축에서 둘이 대각선의 양 끝에 있음을 보입니다. 결론은 "더 많이 기록하자"가 아니라, 담는 이유를 데이터로 남기고 회고를 주기로 돌리는 두 가지를 가져오자는 쪽입니다.

CLAUDE.md — AI에게 주는 행동 지침 (1편)

CLAUDE.md의 10계명 한 편으로, AI 페어 프로그래머와 일할 때 저장소 규칙 파일에 무엇을 적어야 하는지를 다룹니다. 이 위키 자신의 CLAUDE.md가 그 실례라서, 여기 적힌 약속들은 지식 체계의 게이트 문서(위키는 어떻게 스스로를 지키는가)와 짝으로 읽으면 규칙과 기계 강제가 어떻게 맞물리는지 보입니다.

Introduction — Claude Code 첫걸음 (2편)

Claude Code가 무엇이고 어떻게 시작하는지를 다루는 입구 System입니다. 시작하기가 도구의 정체부터 설치·인증, 슬래시 명령어·CLAUDE.md·플랜 모드까지 기본기를 한 편에 담고, 확장 편이 Skills·MCP Servers·Hooks 세 갈래를 소개합니다. 이 System의 개념(설치·슬래시명령어·CLAUDE.md)은 Tutorial·OMC System으로 그대로 이어집니다.

Tutorial(입문) — 기초 강의 실습 (4편)

Claude Code 기초 강의를 문서화한 System입니다. 기초가 개요·터미널·CLAUDE.md로 관문을 넘게 하고, 실습이 조사·디자인 시스템 추출·논문 정리를 한 흐름으로 돌리며, 확장이 스킬·플러그인·에이전트를, 운영이 사용량·컨텍스트·세션 관리와 마무리를 담습니다.

Skill — 스킬 심화 (3편)

“스킬이 왜, 어떻게 동작하는가”를 원리부터 파는 System입니다. 스킬이란이 코딩 에이전트라는 배경과 특장점을, 구조와 동작이 컨텍스트 윈도우·점진적 로딩·SKILL.md와 예제를, 설치·보안·제작이 실습부터 skill-creator까지 실무를 다룹니다 — 마지막 장의 엔지니어링 계층 정리가 MCP·하네스와의 관계를 짚으며 자동화 갈래로 다리를 놓습니다.

Second Brain — 지식 관리 5단계 (4편)

개인·조직의 지식 관리를 레벨 1(정확히 찾기)부터 레벨 5(자율 브레인 OS)까지 단계 모델로 설명하는 System입니다. 세컨드 브레인이란이 개념과 5단계 지형을 한눈에 잡고, 레벨 1·2와 레벨 3~5가 층을 오르며, 적용이 무엇을 넣을지·내 레벨 고르기·팀 확장을 돕습니다. LLM Wiki System이 이 모델의 레벨 2를 구현하는 실체입니다.

LLM Wiki — 옵시디언 기반 지식 볼트 (3편)

Obsidian 볼트로 LLM 친화적 위키를 운영하는 방법론 System입니다. 체계와 캡처가 2-볼트 구조와 캡처 습관을 세우고, 노트의 구조가 메타데이터·연결·위키 카드·rules를 해부하며, 실습과 철학이 온보딩·Ingest·Query·Lint·웹 클리퍼와 두 볼트 운영 철학으로 마무리합니다.

Harness 엔지니어링 — 에이전트 팀 방법론 (4편)

에이전트 팀 방법론 System입니다. 하네스란이 정의·구성·효과로 개념을 잡고, 실행하기가 설치·실행·리뷰 실습을, 동작 원리가 주방 비유·에이전트 팀·핵심 3요소를, 활용과 확장이 사례·하네스 100·도구 조합을 다룹니다.

Harness 플러그인 — ERP 실전 하네스 (4편)

하네스 방법론을 ERP 커스터마이징 실무에 적용한 플러그인 System입니다. 소개·개념·설치 후 첫 실행과 동작 구조로 바로 실습하고, 설계와 검증이 에이전트·스킬 설계와 _workspace 품질 관리를, 시나리오·하네스100·명령어가 활용을 다룹니다. Harness 엔지니어링 System의 이론이 여기서 업무 도메인과 만납니다.

OMC 플러그인 — 실행 모드와 자율 실행 (5편)

oh-my-claudecode 플러그인의 사용법 System입니다. 소개와 설치가 용어·설치·진단으로 환경을 만들고, 실행 모드(autopilot·ralph·ultrawork·team)가 핵심 기능을, 에이전트·스킬과 Hook·메모리가 구성 요소를 다룹니다. 고급 활용(도구·워크플로우·Windows)과 비용·성능과 명령어 참조가 운영 편입니다.

Skills — 스킬 한 편씩 뜯어보기 (1편)

위의 Skill이 스킬의 원리와 구조를 가르치는 강의 System이라면, 여기는 개별 스킬을 하나씩 소개하는 자리입니다. 지금은 im-not-ai(Humanize KR) 한 편으로, AI가 쓴 티가 나는 33가지 문체 패턴을 잡아내는 편집 스킬을 다룹니다. 이 위키의 문서 121편을 그 스킬로 소급 점검한 기록도 함께 있어, 스킬이 실제로 무엇을 걸러 내는지 결과로 볼 수 있습니다.

Tip — Claude Code 활용 팁 (3편)

Claude Code 활용 팁 28가지를 공식 문서에 근거해 초급·중급·고급 세 편으로 정리한 실용 모음입니다. 초급은 컨텍스트를 아끼는 습관 9가지(/init·/context·/compact vs /clear·플랜 모드), 중급은 세션을 시스템으로 만드는 11가지(서브에이전트 병렬·스킬·CLAUDE.md 라우터·/rewind·훅), 고급은 병렬·자율·예약의 8가지(워크트리·권한 편집·에이전트 팀)를 다룹니다. 강의 System들과 달리 사전처럼 필요한 팁만 골라 읽어도 됩니다.

GraphDB — 관계를 저장하는 데이터베이스 (4편)

표의 행과 열 대신 개체와 개체 사이의 관계를 일급으로 저장하는 데이터베이스를 다룹니다. 사이드바 순서는 등재순이지만, 처음이라면 그래프 데이터베이스와 GraphRAG(벡터로 건지고 그래프로 걷는 검색)로 개념을 잡고 첫 벡터 리트리버에서 Neo4j 샌드박스로 직접 만들어 보는 순서가 편합니다. 그다음이 모델 선택의 논점입니다 — RDF냐 프로퍼티 그래프냐가 두 계보를 비교하고, 오라클 온톨로지와 프로퍼티 그래프가 기존 관계형 DB 위에서 같은 일을 하는 벤더 구현을 보여 줍니다.

Ontology — 의미를 정의하는 층 (2편)

GraphDB가 저장 기술이라면 온톨로지는 그 위에서 무엇이 무엇을 뜻하고 어떤 규칙을 따르는지를 정의하는 층입니다. 온톨로지란 무엇인가가 창고와 지도의 비유로 개념·시맨틱 레이어·환각 감소를 정리하고, 기업은 온톨로지를 어떻게 도입하는가가 산업 사례·ROI·구축 4단계·거버넌스로 실무를 이어받습니다. 두 편 모두 벤더 자체 수치는 그렇다고 밝혀 두었으니 사실검증 노트를 함께 읽는 편이 좋습니다.

News & Articles — 그때그때 읽은 것 (11편)

모델 출시·논문·강연을 읽고 정리한 기사들로, 강의 System과 달리 순서 없이 관심 가는 것부터 읽어도 됩니다. 모델 쪽으로는 Claude Opus 5·Kimi K3·OpenAI Astra가 있고, 일하는 방식 쪽으로는 하네스로는 부족하다·지운 사람과 띄운 사람·묻지 않는 기본값·손으로 코딩하는 시대의 끝?이 서로 다른 각도에서 같은 질문을 답합니다. AI 2040: 플랜 A는 원래 4부작 하위 폴더였지만 지금은 한 편으로 합본돼 다른 기사들과 나란히 놓입니다.

추천 학습 경로

  • 처음이라면 — 시작하기 → 확장 기능 → 기초 강의(Tutorial 순서대로). Claude Code를 설치하고 일상 도구로 만드는 최단 경로입니다.
  • 지식 관리가 목적이라면 — 세컨드 브레인이란 — 5단계 한눈에로 자기 레벨을 찾고, 레벨 2가 필요하면 LLM Wiki 체계와 캡처로 내려가 실제 볼트를 만듭니다.
  • 자동화·멀티에이전트가 목적이라면 — 스킬 심화로 원리를 다진 뒤 하네스란 → 실행하기, 이어서 실무 적용은 Harness 플러그인 또는 OMC로 갈라집니다.
