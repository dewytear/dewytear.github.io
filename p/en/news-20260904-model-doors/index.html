Doors on the Model — Who May Use It, and How You May Call It

Three-line summary

  • Fable 5.1 and Mythos 5.1 are one model with the same capabilities. Anyone can call Fable 5.1 through the API; Mythos 5.1 opens only to Project Glasswing participants.
  • The price dropped on a single line — cache reads, from $1 to $0.25 per million tokens. Base input and output rates are unchanged from Fable 5.
  • The same release changed three things about how you call it. You cannot force a tool call, earlier models cannot read its reasoning, and editing the conversation history invalidates the reasoning that came after.
  • Three weeks later the same rules arrived on Opus 5.5 (22 September). What had been the terms of a specialty model became the terms of the model you get by default, and this time the price fell on the base rate rather than on cache reads.

One model, two names

Fable 5.1 and Mythos 5.1, both out on September 1, have identical capabilities, specs and pricing. The only difference is who may call them. Fable 5.1 is open to every customer on the Claude API and through AWS, Google Cloud and Microsoft Foundry. Mythos 5.1 goes only to approved customers in Project Glasswing, Anthropic's program for securing software in fields where the stakes run high, such as cybersecurity and the life sciences. The same capability ships under two names, with a door on one of them.

The specs are a 1M token context window and up to 128k output tokens, with the same per-token price across the whole window. Adaptive thinking is always on and cannot be turned off; effort controls its depth. Both models carry 30-day data retention, so neither is available under zero data retention without express authorization.

One more thing splits them. Mythos 5.1 does not run the history-editing check described below. The same model can therefore be subject to different conditions, which is worth remembering if your code moves between the two names.

The price dropped on the cache line

Only one cell in the table changed. Base input stays at $10 per million tokens, output at $50, five-minute cache writes at $12.50 and one-hour cache writes at $20, exactly as on Fable 5. Cache reads went from $1 to $0.25. As a ratio, what used to be 0.1 times the base input price is now 0.025 times, against 0.1 on every other Claude model. The 512-token minimum cacheable length is unchanged.

One cell moves the whole bill because of how agents work. A long session re-reads its opening every turn: the system prompt, the tool definitions, the conversation so far. When that opening sits in the cache, most of what gets billed is cache reads, so cutting that line to a quarter pulls the total down noticeably. The "25% on typical workloads, up to 45% on highly agentic work" figures from launch coverage all come out of this one line.

The model itself is better than Fable 5 at agentic coding over long sessions, at documents, spreadsheets and slides, at multistep research, at reading charts and tables buried in dense PDFs, at reasoning across the full 1M context, and at operating a browser or desktop. The gap widens at higher effort. But as the price table shows, the improvement arrived as a discount on the cache rather than a markup on the model. Anthropic's own guidance is to start most workloads on Opus 5 and move to Fable 5.1 when Opus 5 at higher effort still falls short.

Three changes in how you call it

Swap the model ID on the strength of the price alone and you snag in three places.

First, you cannot force a tool call. Putting any or a specific tool name in tool_choice to pin the turn to that tool now returns a 400 error. The documentation gives the reason: thinking is always on for this model, and forcing a tool call skips it, so the model ends up writing its working-out into the tool arguments instead. Argument quality drops. Leave tool_choice at auto and set strict: true on the tool to enforce the schema, or say in the prompt when the tool applies.

Second, thinking blocks — the fragments that carry the reasoning a model ran before answering and stay in the history — now have a direction. Fable 5.1 reads blocks from Opus 5, Fable 5 and earlier models, but none of those can read its own. When a router switches models or a refusal fallback drops to an older one, the API strips the blocks that model cannot read and lets the request through. The stripped tokens are not billed, but that model re-plans from nothing. Without the beta header, the strip happens silently.

The third change touches the most code. A Fable 5.1 thinking block is valid only against the system prompt, tool list and conversation history that preceded it. Editing, reordering or removing an earlier turn, injecting a reminder line into an earlier turn and taking it out on the next request, rebuilding system or tools mid-conversation — each invalidates every thinking block after it. What does not invalidate them: removing a leading run of thinking blocks oldest first, server-side compaction and context editing, moving cache_control markers, and changing effort between requests.

The check is enforced by default only for API accounts created on or after August 31, 2026. Older accounts record the mismatch and move on. And if a tool manages the history for you — Claude Code, claude.ai, Managed Agents, the Agent SDK — the prefix is already kept intact. Code that assembles the messages array itself is what breaks, especially an agent framework that folds history behind a summary on the client. Anyone shipping such a tool for others to run should be more careful still: a developer's account is usually an older one with the check off, so users on new accounts hit it first.

How to check

Rather than guessing whether your code edits history, measure it. Send the thinking-binding-controls-2026-08-01 beta header with prefix_mismatch_behavior set to "drop_block": that turns the check on even for an account where it is off, and responses come back carrying an input_transformations array. Run one multi-turn session and log it. Empty on every turn means the history is intact. A prefix_binding_mismatch entry means something before that block changed. A model_binding_mismatch entry after a model switch is expected behavior, not a bug.

What to run in production depends on the design. If a changed history can only mean a bug, leave the default "error" and let it fail. If you compact history on purpose, set "drop_block" so only the affected blocks fall away. Either way, watch the 400s or the input_transformations entries.

A few other things are worth picking up while you are in there. The same release added betas for changing effort mid-conversation, for system messages scoped to a single turn, and for receiving inter-tool progress updates as text via display: "updates". Default behavior shifted slightly too: where Fable 5 batched several tool calls, Fable 5.1 more often issues one per turn. Answer quality holds, but the extra round trips cost tokens and time.

22 September — the exception became the default

Three weeks after this was written, Opus 5.5 arrived (22 September). The specs match Fable 5.1 at 1M context and 128k output, and adaptive thinking is always on there too. The pricing is what differs. Fable 5.1 left the base rate alone and cut a single cache line; Opus 5.5 cut the base rate itself.

Four things now return an error, and three of them are the ones above: thinking cannot be disabled, tool calls cannot be forced, and thinking blocks are bound to the model and the history. Only the fourth is new. On the Claude API and Google Cloud the older computer use tool (computer_20251124) returns a 400, so integrations move to the computer_toolset_20260801 toolset. On Amazon Bedrock the older tool keeps working, so the answer differs by platform.

Two changes that fail nothing may be the more dangerous pair. The first is that the default effort dropped from high to medium. Swap the model ID without setting effort and you get a model that thinks less than before, with no error and no warning. Carrying the old value over is not right either, since at the same effort setting this model tends to think more per turn; the official guidance is to measure again rather than reuse the setting.

The second is that the short notes written between tool calls now arrive as thinking blocks rather than text. At the default setting those blocks come back with empty text, so an interface that streamed them to users as progress goes quiet between tool calls. Nothing errors, which makes it easy to miss, and the text returns only once display is set.

The direction of thinking blocks now needs a map. Opus 5.5 reads blocks from Opus 5 and earlier Opus, Sonnet and Haiku models, but not from Fable or Mythos models. Going the other way, Fable 5.1 and Mythos 5.1 do read Opus 5.5 blocks (on the Claude API). So reasoning survives on the way up — Opus 5 to Opus 5.5 to Fable 5.1 — and is dropped on other moves. The history check applies identically, on by default for accounts created on or after 31 August 2026.

What makes this matter is not that the rules changed but that the place they sit changed. In early September these conditions were attached to an expensive specialty model and to one behind a door, which made them a question of whether to migrate. Claude Code 2.1.280, released the same day, made Opus 5.5 the default Opus model and switched the default on Pro and Team Standard plans from Sonnet to Opus. The model you get without choosing now carries these conditions.

Why these belong together

The cheaper-model story and the breaking-change story circulated separately, yet both sentences ask for the same thing — leave the opening alone and only append to the end. The conditions that keep the cache warm and the conditions that keep thinking blocks valid are the same conditions. The documentation says as much: describing the append-only patterns, it adds that they also keep the prompt cache warm. The cache discount is the reward for that discipline; the history check is the penalty for breaking it. Migrate for the reward alone and you meet the penalty.

Opus 5.5 pushed both a step further. The reward widened from one cache line to the base rate, and the penalty now reaches people who took the default rather than people who picked a specialty model. The stretch where following the discipline was optional has ended.

Who Gets to Make the Call traced a movement that pushes judgment toward the machine. How Mythos 5.1 ships is a case from the other side: given the same capability, a person verifies the organization before the door opens. How far automation goes there is set not by capability but by the size of the damage.

The stateless turn covered in Defaults That Stop Asking comes back here too. Remove the session as a container and the question of where state lives is still open. Stamping each thinking block with which model produced it and over which history is one answer: instead of holding a connection open, each fragment carries where it came from.

Fact-check note

The price table ($10 base input, $50 output, $0.25 cache reads, a 0.025 cache multiplier), the specs (1M context, 128k output, 30-day retention), the three breaking changes and their stated reasons, prefix_mismatch_behavior, input_transformations, the August 31 account condition, and the facts that Mythos 5.1 skips the history check and ships only to Project Glasswing all follow the official release documentation and the migration guide. Multipliers reported at launch, such as "double the Terminal-Bench-Science score" and "over 30% better agentic coding," do not appear in the official capability write-up and are not used here; that evaluation carries a reported standard error of 3.5 to 4.5 points per model, which makes a single comparison a weak basis for a multiplier. The 25% and 45% savings figures are Anthropic's own, and a workload where cache reads are a small share of spend will not fall by that much. The Opus 5.5 material (release date, $4/$20 pricing, $0.20 cache reads at a 5% multiplier, the medium default effort, the 1M and 128k specs, the four breaking changes, the thinking-block direction, and the platform split on the computer use toolset) follows the official release documentation and the model page; the default-model change was confirmed in the Claude Code 2.1.280 changelog. The "40% cheaper to run" figure some coverage carried is not used here — the official rates move from $5 to $4 and $25 to $20, a 20% cut per token, and 40% appears to be a per-task estimate that folds in the lower default effort spending fewer tokens, a multiplier the official documentation does not give.
