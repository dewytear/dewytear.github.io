Doors on the Model — Who May Use It, and How You May Call It

Three-line summary

  • Google shipped one model behind two doors. Gemini 3.8 Flash is open to everyone; 3.8 Flash Cyber, tuned for finding and patching vulnerabilities, opens only to vetted defenders.
  • Anthropic put conditions on the call in Fable 5.1. You can no longer force a tool call, and rewinding the conversation to edit it invalidates the reasoning that came after.
  • One vets people, the other vets requests, but both block the same thing — a capability being separated from the conditions that produced it.

One model, two doors

Google released Gemini 3.8 Flash on September 2. It sits in the cheap tier yet moved sharply on coding and tool use, scoring 90.8% on Terminal-Bench 2.1 against 81.6% for 3.7 Flash. Pricing stays at $0.75 per million input tokens and $3.75 per million output.

The variant released alongside it is the real story. 3.8 Flash Cyber is tuned for security work and scored 86.2% on CyberGym, a widely used evaluation for finding vulnerabilities in C and C++ code. On the patching side, CWE-Bench, it scored 47.2%, effectively tying a much larger rival at a much lower price. In Google's own testing it cleared a 70% discovery rate across 20 programming languages, and the Chrome security team reported 2.6 times more correct patches than the best commercial models, all of them far larger.

This variant never reaches the API. It opens only through a separate program called Fairwind, where applicants explain what their organization is, what defensive purpose they serve, and what safeguards they operate. Government authorities, critical-infrastructure operators and software maintainers qualify, and acceptance is not guaranteed. Finding a vulnerability well and breaking one well are the same skill, so shipping it openly would arm attackers and defenders in the same motion. Google broke that symmetry not with price or capability but with an identity check.

Conditions on the call

Fable 5.1, out a day earlier on September 1, is the other side. Anyone can call it, and the price and tokenizer are unchanged, but three things about how you call it are different.

First, you cannot force a tool call. Until now you could put any or a specific tool name in tool_choice and pin the turn to that tool. Fable 5.1 returns a 400 error for those requests. Instead you append a role: "system" message mid-conversation naming the tool, and set strict: true on the tool so the arguments match your schema. Compulsion became instruction.

Second, thinking blocks — the fragments that carry the reasoning a model ran before answering and stay in the history — now have a direction. Fable 5.1 reads blocks from Opus 5, Fable 5 and earlier models, but none of those can read its own. When a router switches models or a fallback drops to an older one, the API strips the blocks that model cannot read and lets the request through. You are not billed for the stripped tokens, but that model re-plans from nothing, which raises cost and latency for the first turn after the switch.

The third change touches the most code. A Fable 5.1 thinking block is valid only against the system prompt, tool list and conversation history that preceded it. Edit an earlier turn, rebuild the tools array, or compact the history on the client and then send the old blocks back, and the request fails with a 400. The check is on by default only for API accounts created on or after August 31, 2026. Older accounts record the mismatch without acting on it, though Anthropic says it plans to enforce the check for every account on future models.

It is clear enough who this lands on. If a tool manages the conversation history for you — Claude Code, claude.ai, the Agent SDK — the prefix is already kept intact. Code that assembles the messages array itself is what breaks, especially an agent framework that folds history behind a summary. Anyone shipping such a tool for others to run should be more careful still: a developer's API account is usually an older one with the check off, so users on new accounts hit it first.

How to check

Rather than guessing whether your code edits history, measure it. Send the thinking-binding-controls-2026-08-01 beta header with prefix_mismatch_behavior set to "drop_block": that turns the check on even for an account where it is off, and responses come back carrying an input_transformations array. Run one multi-turn session and log it. Empty on every turn means the history is intact. A prefix_binding_mismatch entry means something before that block changed. A model_binding_mismatch entry after a model switch is expected behavior, not a bug.

What to run in production depends on the design. If a changed history can only mean a bug, leave the default "error" and let it fail. If you compact history on purpose, set "drop_block" so only the affected blocks fall away. Either way, watch the 400s or the input_transformations entries.

Why these belong together

The two items look nothing alike. One is a deployment policy for a security model, the other a change to an API specification. Yet both tie a capability to the conditions that produced it. Fairwind keeps the ability to find vulnerabilities from coming apart from the standing to use it; block binding keeps reasoning from coming apart from the context that produced it. Swapping the context and laying old reasoning on top no longer passes quietly.

Who Gets to Make the Call traced a movement that pushes judgment toward the machine. Fairwind is a case from the other side, where a person reads the paperwork and verifies the organization before the door opens. How far automation goes there is set not by capability but by the size of the damage.

The stateless turn covered in Defaults That Stop Asking comes back here too. Remove the session as a container and the question of where state lives is still open. Signing a thinking block and binding it to the history before it is one answer to that question: instead of holding a connection open, each fragment carries where it came from.

Fact-check note

The three Fable 5.1 changes, along with prefix_mismatch_behavior, input_transformations and the August 31 account condition, follow the official migration guide. For Gemini 3.8 Flash Cyber, the 86.2% CyberGym figure is a public evaluation over C and C++ while "over 70% across 20 languages" comes from Google's own testing, so they are two different measurements; some summaries merged them into one, and they are kept apart here (SC Media, VentureBeat). Fairwind's eligibility and vetting criteria were cross-checked against TechTimes and CybersecurityNews. The CWE-Bench and CyberGym scores are all as announced by Google, not independently reproduced.
