How It Works and the 6 Stages

We look at what happens inside the harness after I hit go ahead. Broadly, it forms a team in 6 stages and then turns an operating loop.

The plugin's 6 stages — the process of making a team

This much is "forming the team". Once ⑥ verification passes, the actual work (the operating loop) begins.

The operating loop — how the team works

Once the team is made, the orchestrator turns the loop below. The core is "split it up and go in parallel, verify with tests, and if it is wrong do it again".

  1. Decompose — split the goal into work units. e.g. impact analysis · hold logic · notification · regression tests
  2. Assign & run in parallel — each agent handles its assigned task at the same time.
  3. Verify — QA cross-checks the results (standard feature regression, numerical consistency).
  4. Feedback loop — if there is a problem, it goes back to the agent in charge to be redone. Repeat until it passes.

Agent teams vs isolated subagents

Claude Code's default subagents are isolated from each other and cannot talk. An agent team does communicate — for example, if the development agent finds that "the standard source information is insufficient", it can wake the analysis agent back up and have it investigate further.

Experimental feature — how to turn it on Agent teams are an experimental feature. You turn them on with an environment variable in ~/.claude/settings.json: 
"env": {
  "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
}
There is a bug where they come up as isolated subagents if dynamic loading fails, so if you do not see the agents, /exit and come back in, then check with /agents.
Where do the files appear The generated agent and skill definitions are left under the project's .claude, so you can share them with the team via Git. However, the plugin itself has to be installed on each machine separately. The history of configuration changes is recorded in CLAUDE.md.
