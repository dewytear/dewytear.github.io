dews-sourcegraph — A Skill That Hands Internal Code Search to Claude

Any organization running SourceGraph in-house keeps meeting the same moment. Something of the same kind as the feature you are building almost certainly exists somewhere in the company, but that repository is not on your machine. So you open the web UI, run a search, skim the results with your eyes, and then explain them back to Claude — a round trip. dews-sourcegraph removes that round trip — Claude queries the internal instance itself, gets back repo │ file:line │ snippet, and carries the implementation forward citing that evidence as it stands.

The obstacle is authentication. A private instance blocks anonymous access with a 401, so an ordinary web-fetch tool reads nothing at all. This skill therefore performs a browser form login once, by itself, and caches the session it gets for reuse. There is no step where a person opens devtools and copies a cookie out.

Download dews-sourcegraph-skill.zip (15KB) — the skill body · the runner · a credentials template · an install README. The instance address and the account are not in it. You fill in the values for your own environment.

How the authentication flows

Figure 1. A live session skips ② — the browser comes up only on the very first run and when the session has lapsed

For the browser automation, playwright-core drives a properly installed Edge or Chrome directly. The reason it does not use the downloaded cache browser is what real corporate machines are like — on some company PCs a security agent blocks the executables under the ms-playwright cache, and there the cache browser hangs without bringing up even a blank page. The system browser works fine under the same conditions. The lookup order is the SG_CHROMIUM_PATH environment variable → the system Edge/Chrome → the cache browser.

Installing it

The tool paths are relative to the project root, so unpack it at the project root you open Claude Code in.

my-project/
├── .claude/
│   ├── skills/dews-sourcegraph/SKILL.md      # the skill body
│   └── tools/sourcegraph-search.mjs …        # the runner + package.json
└── SourceGraph.md                            # credentials (you write this)

Merge the zip's .claude folder into your project root, then copy SourceGraph.md.example to SourceGraph.md and fill in three lines.

URL:https://<sourcegraph-host>/
ID:(account ID)
PW:(password)

To keep it elsewhere, point the SG_CRED_FILE environment variable at that path. Then install the dependencies and restart Claude Code, and the skill turns up in the skill list.

cd .claude/tools
npm install
Two things you must not skip ① Never commit SourceGraph.md or .claude/tmp/ — the account and the session cookie leak into the repository. Add the two lines to .gitignore.
② When a login fails, do not retry — consecutive password failures lock the account for a while. Read the server message the tool prints (User or password was incorrect / locked out), fix the cause, and try again exactly once.

How to use it

Tell Claude "find ○○ on SourceGraph", or call it directly with /dews-sourcegraph. You can also run it straight from the terminal.

node --no-warnings .claude/tools/sourcegraph-search.mjs --query "myFunction file:\.java$ count:30" --max 20

Queries use Sourcegraph's standard syntax as it is.

FilterExampleMeaning
(bare term)myFunctionsearch the code contents
repo:repo:my-servicelimit to a repository-name pattern
file:file:\.java$file-path regex
type:type:pathmatch filenames only, ignore contents
count:count:allserver-side result cap
- exclude-file:bin/drop build-artifact noise

Add --pattern regexp when you need a regular expression. Zero results usually means the vocabulary is off, so it is faster to strip the filters, throw one wide query, correct your wording from what comes back, and narrow again.

Why it digs through the local code first

Local first is nailed into the skill document as a rule, because a company-wide search does not always give the better answer. Conventions differ from team to team even for the same feature, and a pattern that clashes with the existing code in your own repository comes back at review. So the trigger is narrowed to three cases — when no precedent of the same kind exists locally, when you have only a derived copy and need to confirm which repository the original lives in, and when you need to see the internals of a shared library or the places that call it.

The citation format is settled too. Evidence obtained by search is left as [SG {repo}/{file}:{line} → pattern to reproduce] and treated at the same grade as the file:line evidence of a local precedent. If the whole original is needed, the skill first checks whether that repository is present locally and, if it is not, asks the user whether to clone it. Search and excerpt is where this skill's boundary lies.

What the release covers The published zip is a generalized build that holds no organization-specific information — the instance address, the account, and any organization-specific search examples are filled in per environment. Because search results are that organization's code, the skill document also carries a clause against sending them out to any external service.
