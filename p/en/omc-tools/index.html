Advanced Use — Tools, Workflows, Windows

OMC provides a family of tools for handling code more precisely. They are useful when you need analysis more precise than a text search.

Tool familyRepresentative featuresWhat it is used forCautions
LSPlsp_hover, lsp_goto_definition, lsp_find_references, lsp_diagnosticsAccurate symbol navigation, checking type errors, searching referencesRequires a per-language server such as typescript-language-server, pyright, or rust-analyzer
AST Grepast_grep_search, ast_grep_replaceSearch · replace based on syntactic structureMore precise than a text grep, but you need the skill to write the patterns
Python REPLAnalysis based on pandas, numpy, matplotlibCSV · log · statistical analysisYou need to check access permissions for the data files and package availability
Ask / Team CLIomc ask, omc team, omc session searchExternal CLI workers and session searchYou need to distinguish the plugin installation flow from the CLI/runtime path
A note on LSP LSP (Language Server Protocol) is a standard that helps a code editor accurately work out "where is this variable defined?" and "is there a type error here?". Note, though, that the language server for the language in question must be installed for it to work properly.

Workflows by Real-World Scenario

We have organized how modes, agents, and tools are woven together in real situations into eight scenarios. Use the number buttons or the previous/next buttons below to look through the scenarios one at a time.

Scenario 1 — kicking off a new project

When you start an empty project for the first time — proceed in the order documentation → design consensus → requirement clarification → team implementation.

# 1. Document the project structure
/oh-my-claudecode:deepinit
# 2. Architecture consensus (based on expert consensus)
ralplan: design the overall system architecture (Next.js, PostgreSQL, Redis)
# 3. Clarify the core requirements
/deep-interview "a SaaS app with social login"
# 4. Implement the basic features with a team
team ralph: implement all of the basic CRUD features

Scenario 2 — adding a feature

If the requirements are clear, go straight to autopilot; if they are vague, refine them with deep-interview first and then implement.

# When the requirements are clear
autopilot: add email notification features (signup welcome, password reset, order confirmation)
# When the requirements are vague — clarify first
/deep-interview "add a notification feature"
# → implement with the clarified requirements
autopilot: implement with [the clarified requirements]

Scenario 3 — refactoring legacy code

Proceed safely in four steps: grasp the current state → plan → parallel conversion → verification.

# 1. Grasp the current state (technical debt analysis)
deep-analyze: identify the technical debt in this codebase
# 2. Migration plan
/oh-my-claudecode:plan JavaScript → TypeScript migration
# 3. Convert several files in parallel
ulw: convert all 15 of these files to TypeScript
# 4. Verification
review code
fix build

Scenario 4 — tracking down and fixing a bug

If you paste the error message as-is, the debugger analyzes the stack and finds the root cause.

# Paste the error message as-is
deep-analyze:
  Error: Cannot read property 'user' of undefined
  at AuthMiddleware (middleware.ts:45)
# → the debugger analyzes the stack → identifies the root cause → proposes a fix
# Apply the fix
fix build

Scenario 5 — code review before deployment

Run the quality and security reviews in turn, then fix the problems found all at once with ralph.

# 1. Comprehensive code review (logic · anti-patterns · performance)
review code
# 2. Check for security vulnerabilities
security review
# 3. Fix every problem found in one batch
ralph: fix every problem found in the code review

Scenario 6 — TDD development

It automatically repeats the flow of writing tests first and implementing afterwards (Red → Green → Refactor).

# Tests first, implementation later
tdd: develop the user authentication service
# → 1) write test cases  2) failing tests (Red)
# → 3) delegate implementation  4) confirm they pass (Green)  5) refactor

Scenario 7 — data analysis work

Several analysis agents run Python (pandas · matplotlib) in parallel to produce a comprehensive report.

# Analyzing log and CSV data
/sciomc analyze this CSV file:
  - user behavior patterns
  - churn cause analysis
  - features with a high contribution to revenue

Scenario 8 — automating Git work

You can delegate commit tidying, writing the PR description, and even branch strategy to git-master.

# Tidy the changed files into commits by meaningful unit
delegate to git-master: tidy the changed files into commits by meaningful unit
# Write the PR description (in Korean, including why · what · tests)
git-master: write the PR description for these changes
# Branch strategy
git-master: work on the feature/auth branch, then prepare a squash merge into main

Windows Cautions

The Windows PowerShell environment needs some separate attention. The key point is that tmux-dependent features are solved with psmux (no WSL needed), and WSL2 is an alternative path.

  • v4.14.4 included a fix related to the Native Windows Hook manifest (removing the sh invocation), and since then the Native Windows Hook can be used as is. The "WSL2 recommended" guidance in older documents is outdated — the current official README presents WSL2 only as an alternative path.
  • Features that need tmux (the omc team CLI, parallel execution of some external AI workers) may have limitations with Native Windows PowerShell alone. The official README presents psmux (winget install psmux), a native tmux-compatible tool for Windows, and when you use psmux, WSL is not needed.
  • Plugin installation · setup · doctor · using skills inside a session all work as is on Native Windows. If problems keep recurring in your environment, there is also the alternative path of switching to WSL2.
  • Even if npm view · npm ping work fine in PowerShell, the Claude Code plugin installation flow and the npm CLI installation flow are separate things.
Things to check beforehand 1. Whether your actual environment is Windows Native PowerShell or WSL2
2. Whether you will use OMC as a Claude Code plugin or as the npm CLI/runtime
3. Whether you plan to also use multi-AI features that need tmux, such as /omc-teams
