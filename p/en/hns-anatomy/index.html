Harness Composition and Effects

Many elements are needed to build a harness, but the core ones are as follows. Some people call everything surrounding the model, excluding the LLM model itself, the harness.

Core components

  • Agent — an AI worker with a defined role.
  • Skills · tools — the capabilities and connecting tools an agent uses while working.
  • Orchestrator — the PM role that coordinates the agents so they work well.
  • Evaluation · tests — verify the output and keep the quality up.
  • Artifacts · memory — continuously manage the deliverables and the context.

How productivity goes up

If there is an issue it goes back to parallel execution, and if it passes it is done.

The operating structure flows roughly like this.

  1. Decompose the goal and divide it up among the agents.
  2. Run the divided tasks in parallel.
  3. Verify the results with tests, and feed back what is wrong.
  4. Repeat the verification loop.

Thanks to this operating structure, human intervention is minimized, the AI works autonomously for longer and quickly in parallel, and quality is secured by test-based verification.

Big-tech cases and surging interest

  • Starting with Anthropic last November, cases began pouring out.
  • In January OpenAI published on its blog that "agents alone developed 5 million lines of code over six months without human intervention" → a big talking point.
  • Research and attempts around "how should we compose a harness" exploded, led by Silicon Valley developers. It was also found that multi-agent setups do better than one.
The bottleneck is not the model but the structure Model performance has already risen high enough (Gemini 3.5 Flash, GPT 5.5/5.6, Opus 4.8, and Claude Mythos, whose release is limited over security concerns, among others). The current bottleneck is the structure that wraps the model (the harness). People can now focus on design · verification · decision-making.
