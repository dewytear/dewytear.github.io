Wrap-up — Engineering Layers and Q&A

The layers of engineering

Sort what we have learned so far by purpose and, instead of "it's all engineering," the distinct grain of each becomes visible.

EngineeringPurpose
Prompt engineeringMaking the LLM smart
Context engineeringRaising the odds that the context is right
Agentic engineeringMaking the AI do the work well
Harness engineeringMaking it something you can trust and delegate to

A harness can be seen as a meta skill loaded with skills + subagents. With the concept of skills in hand, you can look at a harness understanding that it is complex inside even though it looks easy on the surface.

MCP vs skills

MCP is a protocol — a convention for connecting external tools with agents, so its loading and usage differ from skills. They are not competitors: if a skill needs an external connection it can use MCP, so MCP can live inside a skill. That said, skills are so powerful that cases of replacing MCP with skills are increasing too.

Q&A takeaways · Downloading open skills carelessly is not safe — only vetted ones.
· When there is an MCP function and a skill with the same name, which one wins depends on the situation, so be explicit ("use this skill") or separate them with namespaces.
· Evaluating skill performance — decide metrics first, such as whether it triggers well and whether the result is useful, then check with an LLM judge and by eye.
· Tokens — Claude Code uses more than regular Claude, but it can be more useful if it gets you the result you want in one go. Do not look at tokens alone; choose holistically.
