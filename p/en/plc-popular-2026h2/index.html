Popular Plugins of H2 2026 — The Top of the Official Directory, and How to Use Them

In three lines

  • As of October 23, 2026, the two most-installed plugins in the official Claude plugin directory (271 plugins) are Frontend Design (about 1.13 million) and Superpowers (about 1.01 million). Next come Code Review, Context7, Code Simplifier, Playwright and GitHub.
  • Ten of the top fifteen were made by Anthropic. The other five are Superpowers and MCP plugins that connect outside services (Context7, Playwright, GitHub, Vercel).
  • A plugin is a bundle that installs skills, commands, agents, hooks and MCP servers in one go. How you use a top plugin depends heavily on which of those parts it uses.

A plugin is the unit that installs a bundle of features into Claude Code at once. One plugin can mix skills (instructions read when needed), slash commands, subagents, hooks (scripts that run automatically at set moments) and MCP servers (connections that add outside services as tools). What each part is, is covered in Extending — Skills · MCP · Hooks, and the install screens in Extending — Skills · Plugins · Agents. This article picks the most-installed plugins in the official directory, reads each plugin's original files directly, and sets out how to use them.

What a plugin contains

The same word "plugin" hides different insides. Checking the top plugins against the file layout of their source repositories gives the picture below. Which column has a dot decides how you use it: with a command you call it yourself, with only skills or hooks it runs on its own, and with only MCP you get new tools.

3. Code Review — four agents look separately, only confidence 80+ survives

What it does. Call /code-review on a pull request (PR) branch and it first checks whether a review is needed, skipping PRs that are closed, drafts, trivial or already reviewed. It then gathers the repository's CLAUDE.md guidelines, summarizes the change, and launches four agents at once. Two check CLAUDE.md compliance, one looks for bugs in the changed code, and one uses git history (blame) for context-based issues. Every issue found gets a confidence score from 0 to 100, and anything below 80 is dropped.

/plugin install code-review@claude-plugins-official

# on a PR branch
/code-review
## Code review
Found 3 issues:
1. Missing error handling for OAuth callback (CLAUDE.md says "Always handle OAuth errors")
   https://github.com/owner/repo/blob/abc123…/src/auth.ts#L67-L72

Where it pays off. Review bots are usually annoying because of false positives. This plugin deliberately searches wide from several angles, then drops low-confidence findings so only comments worth reading remain. It uses the team's CLAUDE.md as its standard, so the better the rules are written, the sharper the review gets.

4. Context7 — pulls current docs into context

What it does. It connects a remote MCP server run by Upstash. The plugin holds just the server address (https://mcp.context7.com/mcp), so no local Node.js is needed. There are two tools: resolve-library-id turns a name like "next.js" into a Context7 library ID, and query-docs pulls that library's version-specific docs and code examples from the source repository.

/plugin install context7@claude-plugins-official

"How do I set up a Next.js 16 proxy? use context7"
→ resolve-library-id("next.js") → query-docs(…, "proxy")
→ answers from the current version's docs

Where it pays off. A model does not know APIs that changed after its training. With fast-moving frameworks, this stops it from writing code in old syntax. Adding use context7 to the end of a question is the usage the original docs recommend.

5. Code Simplifier — an agent that tidies freshly changed code

What it does. A plugin made of one subagent (code-simplifier, set to Opus). Unless told otherwise, it looks only at recently changed code. Its first principle is not to change behavior; within that, it reduces nesting, removes duplicate code and needless abstractions, and makes names clear. It is told to prefer readable code over short code, and nested ternary operators are banned. Its standard is the project's CLAUDE.md.

/plugin install code-simplifier@claude-plugins-official

"Clean up the files I just worked on"   ← delegated to the code-simplifier agent

Where it pays off. After an agent bolts on a feature quickly, the code tends to get cluttered. Run it once before committing. Scoping it to recent changes keeps it from overturning old code at random.

6. Playwright — Microsoft's browser automation MCP

What it does. It starts a local MCP server with npx @playwright/mcp@latest so Claude can open web pages, click, type and take screenshots. It reads pages through the accessibility tree rather than pixels, so it works without a vision model.

/plugin install playwright@claude-plugins-official

"Check what error the login page shows for a wrong password"

Where it pays off. End-to-end (E2E) testing and checking screens. It overlaps with agent-browser from the skills ranking. Microsoft's own docs say that for coding agents, CLI plus skills uses fewer tokens than MCP, which loads large tool schemas and long accessibility trees, and they point to a separate Playwright CLI. MCP suits exploring a page interactively; the CLI suits long coding sessions.

7. GitHub — handle repositories in conversation

What it does. It connects GitHub's remote MCP server (api.githubcopilot.com/mcp/), exposing what the GitHub API does as tools: creating issues, managing PRs, reviewing code, searching repositories. Authentication uses a personal access token in the GITHUB_PERSONAL_ACCESS_TOKEN environment variable.

export GITHUB_PERSONAL_ACCESS_TOKEN=…   # a token with only the scopes you need
/plugin install github@claude-plugins-official

"Summarize last week's closed issues labeled bug"

Where it pays off. Handling issue and PR work without switching between terminal and browser. The token's permissions are the agent's permissions, so give write access only to the repositories that need it.

8. CLAUDE.md Management — keeping project memory current

What it does. Two tools. The skill claude-md-improver finds every CLAUDE.md in the repository and scores whether it matches the current code. As in the screen above, it rates commands and workflows, architecture clarity, non-obvious patterns, conciseness, currency and actionability separately, then proposes fixes. The command /revise-claude-md writes what this session taught into CLAUDE.md at the end of a session.

/plugin install claude-md-management@claude-plugins-official

"Check whether my CLAUDE.md is up to date"   ← claude-md-improver skill fires
/revise-claude-md                            ← record what this session learned

Where it pays off. A CLAUDE.md quietly goes stale as the code changes. This wiki handles the same problem with rules and validators (The Ten Commandments of CLAUDE.md). Splitting periodic checks into a skill and end-of-session notes into a command is a practical design.

9. Feature Dev — building a feature in seven phases

What it does. A single /feature-dev command leads seven phases, with three agents (code-explorer, code-architect, code-reviewer) splitting the work between phases.

PhaseWhat happens
1 DiscoveryConfirm what to build, why, and the constraints
2 Codebase Exploration2–3 code-explorer agents in parallel study similar features, architecture and UI patterns
3 Clarifying QuestionsAsk about whatever is still ambiguous after exploring
4 Architecture Designcode-architect proposes a design
5 ImplementationBuild to the approved design
6 Quality Reviewcode-reviewer checks quality
7 SummarySum up what was done and what remains
 
/plugin install feature-dev@claude-plugins-official
/feature-dev Add user authentication with OAuth

Where it pays off. It stops the mistake of writing code first when adding a feature to an unfamiliar codebase. The key is that the questions come after exploration. Having read the code first, it asks fewer needless questions.

10. Security Guidance — security checks in three layers

What it does. A security check that runs through hooks, screening Claude-generated code at three moments. Light checks run often, heavy checks rarely.

/plugin install security-guidance@claude-plugins-official
# needs Claude Code 2.1.144 or later and Python 3.8 or later
# all settings are optional environment variables; it works with the defaults

Where it pays off. It gets Claude to fix problems itself before a human reviews. The second layer reviews the diff when the turn ends and hands severe findings back to Claude, so the fix is done before the user sees the answer. There are no commands; installing it is enough.

13. Ralph Loop — the same prompt again until it is done

What it does. It implements, inside a Claude Code session, the technique developer Geoffrey Huntley summed up as "Ralph is a Bash loop". Instead of an outer shell loop, a Stop hook blocks Claude's attempt to finish and feeds the same prompt back in. The prompt never changes, but earlier work stays in files and git history, so each time Claude reads what it left and carries on.

/plugin install ralph-loop@claude-plugins-official

/ralph-loop "Build a REST API for todos. CRUD, input validation, tests.
Output <promise>COMPLETE</promise> when done." --completion-promise "COMPLETE" --max-iterations 50
/cancel-ralph   # stop midway

Where it pays off. Leaving work with a clear finish line, such as passing tests, to run overnight. Work with a fuzzy finish line only piles up iterations, so always set a ceiling with --max-iterations.

What to check when choosing

  • Look at the parts first. A plugin with hooks (Security Guidance, Ralph Loop) acts every turn as soon as it is installed. A plugin with only commands runs only when called.
  • MCP plugins extend permissions outward. For a plugin that uses a token, like GitHub, the token's permissions are the agent's permissions.
  • Compare with skills that do the same job. Browser automation overlaps between the Playwright plugin and the agent-browser skill. The top two plugins are in effect skills, and Microsoft's docs also say CLI plus skills uses fewer tokens for coding agents. For long work sessions, look at the lighter option first.

Fact-check notes

Install counts, makers and the number of plugins in the directory (271) were read directly from the data on the claude.com/plugins page on 2026-10-23 (KST). The numbers are cumulative and change daily. Each plugin's make-up (skills, commands, agents, hooks, MCP), behavior and commands were summarized after downloading Anthropic's official marketplace repository anthropics/claude-plugins-official and reading its plugin.json, README, command, agent and hook files directly; the READMEs of upstash/context7 and microsoft/playwright-mcp were read as well. Code Review's four agents and threshold of 80, Security Guidance's three layers and version requirements, Feature Dev's seven phases and Ralph Loop's Stop-hook structure are as described in each README.
