Cost, Performance, and the Command Reference

The core of OMC is splitting work across several agents and handling it at the same time. That is why total working time can go down, but when several workers run at once the AI usage (tokens) grows accordingly, so the cost can go up. It helps to understand that speed and cost move together.

Why the cost varies

OMC's cost is not a fixed number — it varies greatly depending on how you work. The factors below drive the cost.

  • Whether it can be parallelized — if the work can be split into several pieces it gets faster, but because several workers run at once the tokens spent in the same amount of time increase.
  • Number of retries — if verification fails, the agent tries again. The more retries, the more tokens are consumed on top.
  • Model unit price and context size — the bigger the model you use, or the longer the context (code · documents) handled at once, the higher the cost per call.
  • Build · test failures — if builds or tests fail often, rework to fix them repeats, and the more it repeats the more tokens are used.
  • Using external CLI workers — modes that also call external models such as Codex or Gemini (CCG and the like) increase the model calls themselves, adding cost.
  • Scale of the work — running a large task all the way through in autonomous mode makes cumulative usage large. The cost difference from a small fix job is big.
In one line Being fast does not always mean being cheap. If you handle small jobs lightly in an ordinary conversation and use parallel and autonomous modes only for large jobs that are worth it, you can strike a balance between speed and cost.

Command Collection

We have gathered the commands you use often at a glance, with a note on what each one actually does. Slash commands are written in the namespaced (/oh-my-claudecode:) form wherever possible.

CategoryCommandWhat it does
Install/plugin marketplace add <repo> → /plugin install oh-my-claudecodeRegisters the plugin repository, then installs OMC. Run the two lines in order.
Project setup/oh-my-claudecode:omc-setup --localCreates OMC settings that apply only to the current project. It does not touch the global settings.
Global setup/oh-my-claudecode:omc-setupCreates settings that apply commonly to every project. It may affect your existing global CLAUDE.md.
Diagnosis/oh-my-claudecode:omc-doctorChecks the install and configuration state and tells you if something is wrong. The first step in troubleshooting.
Project documentation/oh-my-claudecode:deepinit [path]Analyzes the project structure and organizes it into a document (AGENTS.md) that is easy for AI to understand.
Requirement clarification/deep-interview <idea>Throws questions at a vague idea to refine it into concrete requirements.
Autonomous implementation/oh-my-claudecode:autopilot <task>Takes the requirements and proceeds on its own from implementation through verification.
Carry through to the end/oh-my-claudecode:ralph <task>Repeats without stopping until the completion condition is satisfied.
Maximum parallelism/oh-my-claudecode:ultrawork <task> or ulwHandles several mutually independent tasks at the same time to increase speed.
Team execution/oh-my-claudecode:team <N>:<agent> <task>Assigns the role (agent) to the specified number (N) of agents and divides the work among them.
Update/plugin marketplace update omc → /oh-my-claudecode:omc-setupSyncs the marketplace to the latest, then applies the settings again.
Plan / consensus/oh-my-claudecode:plan · /oh-my-claudecode:ralplanLays out an execution plan before the work. ralplan reviews more carefully, on a consensus basis. (omc-plan is a compatibility alias for plan)
Cancel/oh-my-claudecode:cancel or stopomc / cancelomcStops the OMC work in progress.
Pattern extraction/oh-my-claudecode:skillifyExtracts a work pattern that was effective in a session into a reusable skill. (learner is a deprecated alias)
HUD setup/oh-my-claudecode:hud setupSets up the on-screen display (HUD) that shows the progress of the work.
How to read this The parts wrapped in angle brackets, like <task>, <idea>, and <N>, are slots you replace with actual values. For example, in the <task> slot you write the work to be done, such as "implement the login API". Parts wrapped in square brackets, like [path], are optional items you may omit.

Quick Reference Card

A cheat sheet that groups the commands you use often by situation. Handy for finding something quickly while working.

Getting started

  • /deepinit — document the project structure
  • /deep-interview — clarify requirements
  • /omc-doctor — diagnose the installation

Planning

  • /plan — draw up a plan, then approve it (omc-plan)
  • ralplan: — planning based on expert consensus

Execution (in order of intensity)

  • autopilot: — autonomous execution (planning to verification)
  • ralph: — repeat until done
  • ulw — maximum parallel execution
  • team N:agent — team collaboration with N agents

Analysis & review

  • deep-analyze — debugging · root-cause analysis
  • review code — comprehensive code review
  • security review — check for security vulnerabilities
  • fix build — fix build · type errors
  • tdd: — test-driven development

Multi-AI

  • /omc-teams N:ai — use Codex · Gemini in parallel
  • /ccg — analysis by 3 models at once

Utilities

  • /cancel — cancel the current mode
  • /cancel --force — reset everything
  • /trace — evidence-based root-cause tracking
  • skillify — extract · reuse patterns (formerly learner)
  • /hud setup — install the status line (HUD)
At a glance Mode intensity: conversation < plan < autopilot < ralph < team ralph · model cost: haiku < sonnet < opus
