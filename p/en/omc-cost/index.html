Cost · Performance

The core of OMC is splitting work across several agents and handling it at the same time. That is why total working time can go down, but when several workers run at once the AI usage (tokens) grows accordingly, so the cost can go up. It helps to understand that speed and cost move together.

Why the cost varies

OMC's cost is not a fixed number — it varies greatly depending on how you work. The factors below drive the cost.

  • Whether it can be parallelized — if the work can be split into several pieces it gets faster, but because several workers run at once the tokens spent in the same amount of time increase.
  • Number of retries — if verification fails, the agent tries again. The more retries, the more tokens are consumed on top.
  • Model unit price and context size — the bigger the model you use, or the longer the context (code · documents) handled at once, the higher the cost per call.
  • Build · test failures — if builds or tests fail often, rework to fix them repeats, and the more it repeats the more tokens are used.
  • Using external CLI workers — modes that also call external models such as Codex or Gemini (CCG and the like) increase the model calls themselves, adding cost.
  • Scale of the work — running a large task all the way through in autonomous mode makes cumulative usage large. The cost difference from a small fix job is big.
In one line Being fast does not always mean being cheap. If you handle small jobs lightly in an ordinary conversation and use parallel and autonomous modes only for large jobs that are worth it, you can strike a balance between speed and cost.
