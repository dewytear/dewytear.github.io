Uses and Extensions — Cases, Harness 100, Tools

The harness has such a wide range of uses that it would be a waste to use it only for development. These are cases the instructor built himself.

Novel — "The Age of Agents"

When he said "let's write an SF novel", the agents and skills for writing a novel got created.

  • Character design agent — creating and developing the characters.
  • Worldbuilding agent — building the technology system and social structure of the setting (e.g. 2028–2032).
  • Science advisor agent — identifying and strengthening scientific errors · unrealistic elements in the manuscript.
  • Brainstorming, science verification and the like were made into skills and injected into the agents.

Flow: a one-line logline → the whole plot outline (a plan for tension and paying off foreshadowing chapter by chapter) → pre-generating the character · worldbuilding material → since the content of each chapter is already fixed, writing in parallel → science verification (e.g. correcting a random string into a string that is actually interpretable by a real algorithm and reflecting it).

Webtoon

When a webtoon was made from that same novel, a webtoon artist agent appeared, and a quality verification agent (checking character consistency · speech bubbles · errors) that catches odd panels was added. A loop was created to draw again when verification fails, so it ran through with a single "draw chapters 2 through 12".

Other cases

  • Onboarding guide — researching and organizing what has happened since ChatGPT in December 2022.
  • Markdown viewer (mdview.kr) — first deployment in 40 minutes to an hour with a harness. Supports HWP import, and documents are stored only in the browser without being sent to a server.
  • Survey of the national AI data center — organizing the numbers and the timeline, plus critical/positive press analysis and the problems (business viability · GPU supply · power · data sovereignty). Because it is source-based, hallucination dropped sharply.
  • Organizing things in newspaper style, planning research for an exam question service, and generating several UI templates to compare (planning with visible deliverables).
What they have in common Rather than "just write it", the agents · skills · workflow for doing that work are created first, and the result comes out on top of pre-planned material and a verification loop.

Harness 100 · Practice Ideas · Performance

Harness 100

A published collection that composes 100 case harnesses in advance for the things you need in daily life and at work. (Search for "harness 100"; a Korean version is provided.) The fields are as follows.

  • Content production (YouTube planning · podcasts · newsletters · online courses)
  • Software development, data analysis
  • Business strategy (from validating a startup idea to pitching, government support program business plans)
  • Education · learning, law (risk assessment), health · lifestyle, communication, operating processes, specialized domains

For example, "writing a government support program business plan" already comes with agents like a public notice analysis expert · business viability section writer · budget planning helper and the related skills. Users make use of it by finding a similar composition and customizing it.

Measuring performance — putting numbers on it

These are trends, not actual measurements — the harness gap widens as the difficulty rises.

To check the felt effect in numbers, 15 development tasks by difficulty (basic · intermediate · advanced) were compared without a harness vs with one, and the final code was evaluated by an LLM judge.

Result On average about a 60% performance improvement, and a 100% win rate when a harness was composed. Especially the harder the task — using only a single tool made the score drop a lot, but the harness had the effect of keeping the quality.
About the numbers The numbers above are not a public benchmark but the speaker's own measurements. For reference, Anthropic has also announced that a multi-agent configuration showed a 90.2% performance improvement over a single agent in its internal evaluation (multi-agent research system).

Extending the Tools and Wrap-up

Claude Code vs Gemini (Antigravity)

AI tools advance by leapfrogging each other. Right now Claude Code is the best, but the instructor also uses Antigravity CLI (the agy command) alongside it.

ItemClaude CodeAntigravity (Gemini 3.5 Flash)
Generation speedAbout 50–60 tokens per secondAbout 4 times faster
Image generationNot possible with the model itself (possible via the codex-image skill)Possible (Nano Banana)
Output qualityComes out prettier in the instructor's impressionFast, but needs polishing

You can compare performance · speed · price by model on the Artificial Analysis site. (Opus and GPT 5.5 are on the expensive side.)

About the numbers The "about 4 times faster" in the table is not a public benchmark but the instructor's own experience. For reference, the speedup of a parallel agent configuration is reported as anywhere from about 2 times up to 10 times depending on how independent the tasks are (Anthropic reported a 90% cut in elapsed time on complex queries).

Second-pass verification with Codex CLI

Since verification by a single model can be biased, you can attach second-pass verification to the QA agent with a skill that connects Codex CLI (GPT 5.5).

# when the composition needs to change, instruct with /harness
/harness Modify the QA agent so that it verifies using Codex CLI
  • The QA agent is updated to a double verification protocol — a first pass with Claude, a second pass with Codex CLI, and the two opinions combined.
  • Since it has to know the workflow, the orchestrator is updated along with it.
  • This kind of harness composition change history is recorded in CLAUDE.md.

The execution layer moves inside the organization — self-hosted runners

Tools are not the only thing that extends. With self-hosted environments, opened as a public beta in August 2026, remote sessions run on your organization's own infrastructure rather than Anthropic's cloud — one command, claude self-hosted-runner, turns your machine into the execution layer, and the harness works right next to your internal services and security controls. It opens a path for organizations that data-residency rules had kept out (August's releases).

Agent 1:1 (one-on-one)

There is also a feature that lets you talk with a specific agent as if having a coffee chat and redesign it. When you pick a counterpart from the agent list, that agent explains its own role and principles and asks "which part shall we modify?".

Wrap-up — what people should focus on

At the entrance to an era where agents do much of the work for us, people should focus on the following: setting goals, contextual judgment, quality standards, responsibility · ethics, good questions, systems thinking, domain expertise, evaluation · feedback, and AI collaboration.

Q&A points · If an agent does not show up in /agents, only the list is missing; restarting loads it (when dynamic loading fails it sometimes shows up as an ordinary subagent).
· Auto mode — switch between auto/accept/plan modes with Shift+Tab. Auto mode does not ask for permission every time, so it operates more autonomously (you can switch at any point in the middle). If you do not see it, Claude Code needs to be updated (a native install updates automatically, an npm install manually).
· Since 2026-08-14 auto mode is the default (new sessions on Pro, Max, and Team). Instead of asking, hard deny rules and prompt-injection screening make the call, and only irreversible or destructive actions come back to you — details in Defaults That Stop Asking.
· Agents · skills are created in the per-project .claude, so share them with Git; plugins are installed separately on each environment (PC).
· In real work, unlike in a demo, giving detailed requirements and data together (in markdown if long) makes the intent land reliably.
