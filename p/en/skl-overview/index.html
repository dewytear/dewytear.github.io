The Background of Skills — the Birth of the Coding Agent

Skills are not a technique that appeared out of nowhere one day. They emerged naturally on top of a foundation called the coding agent. You need that context to understand why skills work the way they do.

Kinds of agents

The higher the stage, the wider the range of what it does on its own — skills become possible on top of the coding agent.
  • Chat agent — the conversational kind we use by default.
  • Tool-calling agent — connects MCP and APIs to do external work such as checking Gmail or adding a calendar entry.
  • Coding agent — one step above tool calling. Claude Code belongs here.

"Keep the tools simple, leave the rest to the LLM"

At first the expectation was that building many sophisticated tools would make the agent work well, but no matter how well they were built, we ran into the limit of not getting the form we wanted. So the thinking was flipped.

  • Give only the most basic tools — reading, writing, editing, and finding files, plus running commands (about six of them).
  • Let the LLM figure out the rest.
  • For that you need an execution environment and a file system → a sandbox plus simple tools.

What was born this way is the coding agent. Rather than loading up every tool imaginable for a camping trip, it is closer to taking only basic tools like a hammer and making what you need on site.

Why Claude Code starts by latching onto a folder This is exactly why Claude Code runs inside a specific folder. Reading and writing files and running your commands requires your OS and file system, so it operates on your own computer (locally). Skills are a feature that is only possible on top of this coding agent.

What Is a Skill

A Claude Skill is a reusable work package built to teach a particular way of working. The core is not growing an individual's ability but making sure that whoever uses it inside the organization gets results of the same quality — that is, turning a personal knack into organizational knowledge.

Why it matters to an organization

  • When one person builds a skill and distributes it to everyone, everyone produces results of consistent quality with the same skill.
  • It is closely tied to agent governance, organizational policy, and workflows.
  • You have to be able to build skills yourself. Internal work is only known internally, so it is hard to take something built outside and use it as is. Only when an ecosystem for building and refining them in-house is in place do you use a coding agent freely.

In substance it is just a folder

Inside a skill there is a folder holding instructions, scripts, and resources. In computing terms it is just files and folders, a single archive. There is no impressive executable, only scripts and resources — but the fact that these are loaded dynamically at the moment they are needed carries great significance.

A 'work onboarding document' you hand to Claude

A skill is like a work onboarding document you hand to the Claude you use.

  • When should this work be done
  • In what order should it be handled
  • By what criteria is the result judged
  • What are our quality standards

Telling it these things so it builds things to your own taste is where a skill begins. We are all using general-purpose agents, and turning one into a specialized agent that fits my work makes a skill essential.

The Strengths of Skills

Usually a product's characteristics are a list of several features built separately. Yet the strengths of skills all derive from the single idea of the "skill". So once you understand the concept, the characteristics connect naturally.

StrengthWhat it means
ReusabilityBuild it once and productivity rises a lot even if you never share it and just use it many times yourself.
Packaging repetitive workTurn work you always do the same way into a skill and handle it easily and consistently every time.
Progressive loadingLoads only when needed, reducing context waste (the core principle — next chapter).
Scripts and resources includedLayer in proven existing scripts as they are, making probabilistic results deterministic.
Composite workflowsSeveral skills can be loaded at once and combined (fused).
Platform compatibilityUsable in Claude AI, API, Code, and Cowork (environments and permissions differ a little). Partly usable in Codex and Antigravity as well.
Packaging expertise and organizational knowledgeStandardize by capturing tone and manner, review checklists, quality standards, and the like in a skill.

Proven scripts as they are

Skills turn complaints like "what the AI writes differs every time, so I can't use it" and "there are hallucinations" into deterministic results that run inside the script I provided. If you layer a proven script you have used for years (for example, a field's traditional analysis script) into a skill, you can put it to use reliably without hallucination.

The value it gives an organization It carries great significance that the outputs coming out of our institution can be produced to a set quality standard. Package domain expertise and organizational knowledge into a skill, and no matter who makes it, the result is consistent — "as if one person wrote it".

The next chapter, How Skills Are Built and How They Work, takes this idea apart — how it solves the context-window problem through progressive loading, and what a SKILL.md actually looks like.
