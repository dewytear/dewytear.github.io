Agent Teams and Context Management

How you make several agents collaborate, and how you manage context, decide the quality of a harness.

Isolated subagents → a team that communicates

Isolated subagents only return a result, but an agent team wakes each other back up and collaborates.
  • The existing way — subagents each work in an isolated environment and only return the result (in parallel). There was no way for them to talk to each other.
  • Agent team — the agents work while communicating, so they behave more smartly.

For example, suppose a research agent finished its investigation and terminated, then an analysis agent was spawned, and during the analysis it finds a part where the research is lacking — instead of doing the research itself, it wakes the research agent back up and asks for additional investigation.

Enabling agent teams

This feature is an experimental version, so it is disabled by default. Turn on the environment variable in ~/.claude/settings.json in your user folder.

# env in ~/.claude/settings.json
"CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  • Only when this value is on do the agents talk to each other and act as a team.
  • When an agent succeeds at dynamic loading, team mode turns on properly; when it fails, it often comes up as an isolated ordinary subagent. (A bug of the experimental version.)
  • For reference, agent-to-agent communication has also been added to Gemini's Antigravity CLI.

Context = the kitchen counter

Context is like the counter on which you make a dish. It is tidy when only things related to that dish are on it, but once unrelated things get mixed in, there is room for mistakes (like sugar being in the salt shaker). In practice, when a conversation gets long the thinking before and after can end up contradictory, and if you give it work in that state the AI gets confused about "is A right or is B right". That is why context management matters.
