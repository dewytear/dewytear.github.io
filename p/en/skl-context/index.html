How Skills Are Built and How They Work

To understand how skills work, you have to start with the context window.

The context window

The context window is the size of the input fed into an LLM. (Because the output goes back into the input as things continue, it includes the output too.) It holds not only the user's question but all of the following.

  • Basic information (who you are, what today's date is, what you should do and what you must not do)
  • Instructions · few-shot examples · output format · context · memory
  • Tool definitions · the chat history (which keeps getting added to as it grows longer)

Older LLMs had contexts of only 2K to 8K (GPT-3 about 2K, early GPT-4 8K), but the models used in Claude Code today take 200K by default, and some models (Sonnet 4.6, Opus 4.6 and later) take up to 1M (a million) tokens. Bigger is not simply better, though. Once the context starts filling up the LLM gets anxious, and it will refuse to do the work or wrap it up strangely.

clear · compact — clearing your desk Claude Code's /clear·/compact are commands that shrink or empty the current context to get ready for new work. Think of it as the difference between working at a desk that is a mess and tidying it up completely before you start.

Tools eat up the context

A skill is, in the end, a kind of tool. But open up a single tool and it is a complex JSON spec listing the function, its arguments, when to use it, units, and so on. Each one is fairly large, so the context is ready to burst once you get past just a few tools. This is why "you cannot connect any more" comes up when you hook up several MCP servers and connectors.

The trunk analogy Tools are like a car trunk. Its size is limited, so you cannot fit all of your camping gear in. There are two options — buy a bigger trunk, or cut the load down as much as you can. Coding agents took the latter route, solving the problem by cutting down to six tools and handing over an execution environment along with them, and skills emerged on top of that.

Progressive Loading (the Core Principle of Skills)

The most essential principle behind skills is progressive loading (progressive disclosure). Rather than putting the whole skill into the context, only the metadata is loaded up front and the rest is pulled out when it is needed.

The library book cover analogy

Only the metadata (name + description, 3 to 4 lines, about 100 tokens per skill) of a registered skill goes into the context. It is like a library where the books are lined up on the shelves and you only skim the covers (title and short description), pulling one out to read when you need it. The metadata is so small that even more than 100 of them barely take up any context. (In contrast to JSON tools, whose full schema occupies the context up front so that the burden grows as their number rises — which is why Claude Code lazy-loads MCP tool schemas too.)

Three-level loading

The higher up, the more it is always loaded; the lower down, the more it is only when needed — the moment of loading gets later at each level.
LevelContentWhen it loads
1Metadata (the name and description in SKILL.md)Always loaded (about 100 tokens per skill)
2Instructions (the SKILL.md body, usage in markdown)When that skill is invoked
3Resources · scripts · templates (bundled files)Only when needed (scripts are only executed, never loaded)

Bundled files are not mandatory. If words (markdown) alone are enough you can do without files, and if you need an executable script or a template you include one. The more files there are, the more deterministic the result you get. For reference, the official guide recommends keeping the SKILL.md body under 5K tokens and splitting long content out into bundled files.

The manual analogy (flat-pack products · the Matrix helicopter) When you buy a flat-pack product online you skip the manual and assemble it from the photo of the finished item, and only the moment a screw is left out do you pull the manual out. A skill's instructions are likewise pulled out exactly when it fires and left alone the rest of the time. It feels like the scene in the film The Matrix where they load a manual in an instant in front of a helicopter and fly it.
A tip for checking Typing /context in Claude Code shows what percentage the system prompt, custom tools, skills, and so on each take up. You can confirm that even a large number of installed skills uses barely any tokens.

SKILL.md Structure and the Description

The center of a skill folder is the SKILL.md file, and alongside it sit bundled files such as reference, examples, and scripts.

Front matter (metadata)

Within a single file the front matter is always loaded, while the body is loaded when the skill is invoked.

At the very top of SKILL.md there is YAML front matter. For a PDF skill, for example:

# SKILL.md front matter (the part that is always loaded)
name: pdf
description: Toolkit for extracting text/tables from PDFs, merging, splitting, and so on

On the first load only this front matter comes in, and the actual manual (the body) is loaded when the skill is invoked.

Writing the description matters

A skill can be invoked explicitly with /skill-name, and it can also fire automatically on the basis of its front matter when you say something like "extract the text from this PDF." That is why the description has to be written well.

  • When it does not get invoked — for example, if it has a PDF editing capability but the description only says "used for reading," it may not be invoked when you ask for an edit.
  • When it gets invoked unnecessarily — it suddenly fires on something that has nothing to do with PDFs.

So test whether it gets invoked when it should and whether it fires when it should not, and when you build one yourself write the description with care.

Referencing files from the instructions

Inside the body (markdown) instructions you can write references to other files, such as "in this case, look at this file." Unlike the JSON tool specs we saw earlier, this amounts to writing something like "how to run the command" in natural language, as if you were telling a person.

Why read/execute alone is enough Coding agents come with file read, write, edit, and search tools built in, so they handle the file system freely. That is why the agent loads a file on its own even when the instructions only say "read this file." It is easier to grasp if you picture how a skill's content and the coding agent's tools interact as it reads.

A Tour of Example Skills

Now that the concepts are in place, let us look at real skill collections. When you are just getting started, opening up a few examples like these is recommended.

Anthropic's built-in skills

The built-in skills Anthropic made officially are published on GitHub. Copy a whole folder into Claude Code on your laptop and, on load, it reads only the YAML front matter of each SKILL.md first, loading the body when it is needed.

A science agent skill collection (about 140 of them)

There is also a collection that gathers skills for scientific research. It holds about 140 science-related skills, enough for researchers in a field to say "the scripts we use a lot in our field are right here."

  • Bio-related skills such as Biopython, and a dataset download skill (down to where and how to get them).
  • Scientific Writing — it covers paper formats by conference and the rules for figures and tables (minimum resolution, no JPG but PNG, and so on), producing clean papers and PDFs.

Thanks to the metadata you can load several skills at once and do interdisciplinary research. For example: "process this bio dataset with machine learning" → load bio → load data → train → on through writing and submitting the paper. Quantum and deep-learning hybrid processing is also possible to a degree.

A Korea-focused skill collection

There are also skill collections that are "by Koreans, for Koreans." They handle, right inside Claude Code (and the app), the things that used to be a nuisance every time in daily life.

  • SRT and KTX ticket booking, checking vacancies at recreational forests, KakaoMap
  • Seoul subway arrival information, lost-and-found lookup, news and weather, Han River water levels
  • Korean statute search, property registry extracts, HWP document viewing, parcel tracking, restaurants, and more
The gap in between The wide gap between the very scientific skills and the very everyday ones is one you can readily fill with skills for your own work.

With the principles in place, what remains is hands-on work — the installing, securing, and creating chapter installs and uses skills, covers the security caveats, and goes all the way to building your own.
