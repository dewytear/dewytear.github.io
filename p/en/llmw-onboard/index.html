Practice and Philosophy — from Onboarding to Operation

The starter kit contains an onboarding skill, so a single /onboard (or "onboard me") kicks off a personalized setup.

From getting the release to the moment you open the vault in graph view — a personalized setup with one /onboard.

Preparation — getting the release

  • Download the latest release file (1.7.0, for example) from the LLM Wiki page (GitHub repository) given in the course.
  • Unzipping it produces a single folder (= the wiki vault, soon to be an Obsidian vault).
  • Place this folder first at the path you will actually use (My Documents, Desktop, and so on).

Running onboarding

# Copy the folder path — Windows: Ctrl+Shift+C / Mac: Cmd+Option+C
# Then run Claude Code in that folder
/onboard        # or "onboard me"

A set of questions follows — what purpose are you using it for, what should it call you, whether to connect it to your main vault, and so on. The more context you give, the smarter it gets, so answer sincerely. (Takes about 5 minutes.)

  • Connect it if you have a main vault — the AI then references the notes I have written when it builds the wiki.
  • If you do not have one, starting standalone is fine.

Opening the vault in Obsidian

  1. Bottom left of Obsidian → Manage vaults → Open folder as vault, and open that folder.
  2. Check that your folder name is correct at the bottom left.
  3. Press Ctrl/Cmd + G to open the graph view and you can see the embedded relationships between notes.
To start clean If you want to start without the sample data, just delete the sample files in the concept, entity, and article folders. Files for Codex are prepared too, but using it in Claude Code is more advantageous.

Three Core Actions — Ingest · Query · Lint

These are the three important actions of the LLM wiki. (A concept put forward by Karpathy.)

The three actions loop, and queries grow stronger step by step from BM25 → vector → hypothesis check.

1) Ingest — digest and absorb

This is the work of splitting a single article or concept into chunks and turning it into cards that both AI and people find easy to read. Hand over raw material and source-based wiki cards are generated.

/ingest        # raw sources into wiki cards

2) Query — retrieving and using

Merely piling things up is useless, so you retrieve them with queries. An ordinary agent searches only with regular expressions (word frequency and matching), but here three kinds of search are used in stages through the QMD (markdown query) MCP.

MethodWhen
BM25 (lexicon)When the user states an explicit word — searching by high-frequency words.
Vector searchWhen it is vague — it brings in similar concepts too ("I want to drink water" → water glass).
Hypothesis check (hypothetical)When the user's level is below the level of the knowledge — the LLM reinterprets the question, makes keywords, and searches again.

Each step further along takes more time. If you know the file exactly, giving its address directly is fastest. Results are organized in the query folder, and they are kept source-based so you can pull them out again knowing what purpose the document was made for.

3) Lint — maintenance

This is maintenance work. On a new ingest, if an existing note (concept A, say) is related to a new note (A′) and has gone stale, it gets updated along with it. Run overall maintenance with /lint to keep things current enough to cite at any time. (The audit audit and verify verify skills come along too.)

Summary Ingest (raw material → cards) · Query (retrieving with BM25, vectors, and hypothesis checking) · Lint (staying current) — these three axes keep a living knowledge base running.

Web Clipper, the Inbox, and Query in Practice

Collect web articles into the inbox with the clipper, sort them with /inbox, ingest them, then retrieve them with /query.

Obsidian Web Clipper

Clip web articles with the Chrome extension Obsidian Web Clipper and put them into the vault's inbox. The instructor has placed the capture rules (a JSON template) in the wiki vault.

  • Register your vault names under vault storage in Settings → General options, and you can specify which vault to send to.
  • Import the template (JSON) and move the Web Article template to the very top (it fires first). There are also templates triggered by address, such as x.com or youtube.
  • When you capture, it is saved to a folder you designated in advance, such as 0.2 inbox/article.

The inbox skill — collect, then analyze

/inbox        # analyzes the material collected in the inbox and proposes topic-wise bundles

Collect several items in advance and run /inbox, and it proposes them split up by topic, like "3 of the 5 have the same grain, shall we ingest them together?"

Token tip — scrape the original

If you only give a link when ingesting, the AI has to scrape the original before it can start, which costs more tokens. Scraping in advance with the Web Clipper to secure the original before you start saves tokens.

Query in practice

/query Summarize the academic value of the LLM wiki vault.
I am going to cite the bibliographic information with a reference manager later.

If the wiki vault is not enough, it is set up to search all the way into the main vault and bring things back, and how I asked the question is recorded along with it. The result includes not just the answer but even recommendations on how best to design Obsidian metadata (author, created, source, category, and so on).

Do not put a whole paper in Rather than ingesting the entire full text of a paper, it is better to let it learn just the basic concepts from something like the abstract and to leave behind the location of the full text. Have it read only the important key papers in full, and it is more useful if you put your own commentary and experimental context in alongside.

Use and Philosophy — Reading Ability and Running Two Vaults

The wiki is a storage space for ingredients

The LLM wiki is a storage space for ingredients. The dishes cooked from them (the outputs) — curricula, lecture plans, and so on — move over to the main vault. If an output is too large to serve comfortably, it is managed in a separate dev (development) folder. (Heavy files such as HTML and node_modules are managed outside the vault, to prevent rendering slowdowns.)

The most important ability — reading

In the age of AI, the most important ability is the ability to read. It is easy to set an agent to work and then not read, but you can only direct it properly if you read it yourself. The instructor places the very purpose of setting up AI in "securing time for me to read". The wiki's concept, entity, guide, and query cards are all composed to be easy for people to read too.

Why split into two vaults

Stating the author and the .claude rules differ between the main vault (which I manage) and the LLM vault (which the AI handles on its own). Merging them into one brings more errors and contaminated information, so keeping them separate is better. If you want to move part of an existing vault into the wiki, you can migrate by starting the agent in the starter kit vault, giving it the address of the existing vault, and saying "move over what is worth making into a wiki".

Wrapping up — stay attached to AI knowledge directly

Leaders divide into two kinds — "tell me more" and "a member can just do it, why should I learn?". But the knowledge ceiling of my member (partner) becomes my own ceiling. That is why we have to attach ourselves directly to AI knowledge, and for that we need our own knowledge repository. The lecturer picks Obsidian as the best tool for it.

Q&A highlights · Shared vaults — official Sync, or self-hosting with osync (NAS, cloud, Docker). Even simultaneous editing is generally safe within 1 to 2 seconds.
· Scraping PDFs — convert if consistency matters; if you only need the context, turning them into markdown with Python saves tokens.
· Metadata fields are decided by the person who will retrieve the knowledge — design the key-values to match the classification you will retrieve by.
· Vault scale — filter by metadata (type and the like) and even ten thousand notes can be indexed and accessed without trouble.
