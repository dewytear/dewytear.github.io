Who Is Spending My Limit — Three Scenes from Claude Usage

Three-line summary

  • Malware has been stealing login sessions off people's computers and using them to run Claude on someone else's account until the usage limit runs dry. Anthropic signed the affected accounts out, deleted saved payment methods, and refunded the charges it identified as unauthorized.
  • On September 14 the weekly limit for Claude Code changes: a temporary 50% boost gives way to a permanent 25% increase, which is a net cut against what people hold today.
  • The harness moved the other way in the same stretch. /usage gained a spend-limit bar and a per-session prompt-cache line, and hooks now fire around the moment the model switches.

Someone else's session, your account

Once a login checks out, the site hands the browser a session cookie, a small token that keeps proving you are signed in. From then on that token is the identity. An infostealer, malware that scrapes saved credentials and cookies off an infected machine, copies exactly that token. Replay it and the server treats the attacker as someone who already finished logging in.

Two-factor authentication does not close this path. It guards the moment of logging in, and what was taken is the token issued after that moment had already passed. The symptom is quiet: if your usage limit looks like it refilled and then drained while you were not using Claude, this is worth suspecting.

Anthropic's response had three parts. It signed affected accounts out, which invalidates the stolen sessions; it removed saved payment methods so the accounts could not be charged further; and it refunded charges it identified as unauthorized. Because the payment method is gone, renewing or buying anything means adding one again. The named malware families are Vidar, LummaC2, StealC, RedLine and Acreed on Windows, plus Atomic Stealer on a small number of Macs.

One part is easy to miss. Signing out cuts the stolen session; it does not remove the malware. If the infection is still there, the next login leaks a fresh token. Add a payment method back only after the machine is clean.

September 14, and the weekly limit comes down

The temporary 50% boost on Claude Code's weekly usage limit becomes a permanent 25% increase on September 14. Read against the original limit, that is more. Read against what people actually hold this week, it is less: roughly 17% less.

That is why accounts of the same change disagree. Take the original limit as the baseline and it reads +25%; take today's temporary limit and it reads -17%. Neither is wrong, but the second number is the one that describes what changes next week.

The harness starts showing what it spent

Claude Code 2.1.251, on August 28, widened the surface where usage is visible. /usage gained a spend-limit bar, so the remaining headroom reads as a gauge, and a per-session prompt-cache line, so cache hits show up session by session. Tool calls from a foreground subagent now stream live to Remote Control clients.

The same release added PreModelSwitch and PostModelSwitch hooks, extension points that let you insert your own command at a chosen moment. They fire on either side of a model switch. Since models are priced differently, that moment is also where the bill forks.

Why this is one current

The three touch the same meter from different sides: who is spending it, how much is left, and what shows it. Treat usage as an incidental number attached to an account and the three look unrelated. For anyone who keeps a harness running all day, they are one problem.

The credential delegation in Who Gets to Make the Call was a problem you could see at the approval prompt. This session theft is the same delegation collapsing one layer below that prompt. Nobody clicked to allow anything, yet the request was handled as already allowed, which means the thing to design was never the approval button but the token underneath it that proves identity.

Fact-check notes

The session theft (sign-outs, deleted payment methods, refunds, the malware list, and the caveat that signing out does not remove the infection) is cross-checked against BleepingComputer, SecurityWeek, Help Net Security and Security Affairs. The September 14 weekly-limit change (temporary 50% to permanent 25%, a net drop of about 17%) follows a dated timeline of usage-limit changes, and the same change is described both as +25% and as -17%; the difference is whether the baseline is the original limit or today's temporary one, so the body states both. The Claude Code 2.1.251 items (model-switch hooks, spend-limit bar, per-session prompt-cache line, subagent tool-call streaming) follow the official changelog. Separately, summaries circulated that Claude Sonnet 5 would be repriced on September 1; the official pricing documentation states that the introductory rate is now standard and the scheduled increase will not occur, and this article follows the official documentation.
