Installing and Using Skills (Hands-on)

Practicing with skills is almost disappointingly simple — "install this skill" is all it takes. That said, it is far more interesting when you keep the mechanics you learned earlier in mind as you use them.

Installing

  • Pressing the "Get this skill" button on a skill's distribution page copies its git address.
  • Paste that address into Claude Code and say "install this skill" and it gets installed. (For a manual install, copy it into the corresponding folder.)
  • By default it is installed in the global folder. (You can also choose project or global, but you need not worry about it at first.)
  • If it does not show up after installing, run /reload (reload plugins) or quit and restart Claude Code and it will pick the skill up. (/clear is different — it only empties the context.)

On a smartphone you can also try skills out with the Claude app (which runs in a sandbox).

Using

# Check the list of skills available to you
What skills do I have available?
# Explicit invocation
/skill-name <command>

Hands-on — an organization brand skill

Install a brand guideline skill built from the style of an institution's website, then make a request like this.

Using the <brand> brand guideline skill,
make a summer workshop page

The page then comes out in the organization's brand style rather than any old way. The point is not prettiness — it is that everyone using the same skill gets a similar style, producing consistent, reusable deliverables across the organization. In the same way you use a PPT template skill (presentation decks), a Finder skill (finding experts in the organization), and so on.

Triggering recap The reason a skill fires even when you just say "make it in the organization's style" is that the metadata description states "when using this style, use this skill." Still, to be certain it is better to name the skill explicitly.
