Running It — Install, Run, Review

Composing a harness by hand every time (preparing each agent · skill one by one) is a hassle. So the instructor developed a "meta-harness" skill that composes the harness for you when you only give it a goal, released it on GitHub, and got a lot of user reviews and stars. Today's hands-on session starts with installing this skill.

Method 1 — two lines of commands

# 1) Add the harness marketplace
/plugin marketplace add lev-factory/harness
# 2) Install the harness plugin
/plugin install harness

Method 2 — the /plugin UI

  1. Enter /plugin → move right with the arrow keys and select the Marketplace tab.
  2. In Add Marketplace, enter lev-factory/harness → Enter (it downloads from GitHub).
  3. Enter on the plugin install screen → if you install it at User scope, you can use it in any project.

After installing — reload and check

When the install finishes, a notice tells you to "reload". After /reload (reload plugins), if /harness shows up, it was installed correctly.

/reload
# If the following autocompletes/runs, the install succeeded
/harness
Check the marketplace path The marketplace handle (lev-factory/harness) is carried over from the value mentioned in the talk, so when you actually install it, check the exact repository path on the instructor's GitHub (for example, search for "Harness 100"). If the plugin install does not go well, try the UI way and the command way alternately.

Running the Harness (Hands-on)

Convey just the intent and a team gets put together; once a human reviews and approves, execution leaves your hands.

Let's give the /harness you installed some real work. The key difference is that you "convey only the intent".

Not "write it for me" but "I would like to write it"

Normally you instruct an AI, "write me a report". But to the harness you state only the intent. Then it composes an agent team that will resolve that intent.

/harness I would like to research the 2026 strategic technology budget allocation
across all national science and technology fields and the post-PBS response strategy, and write a report.
  • Enter /harness, autocomplete it with Tab, then append your request.
  • When you run it, it proceeds with domain analysis → team composition.
  • Along the way it asks you to choose between things like "build the full harness / build only the harness".
  • If you have data of your own you can hand it over along with the question. (For example, it handles analyzing a PDF of more than 1,000 pages well.)

Composition done → review → run

When the harness composition is finished, it pauses for a moment. Review the agents that were created, and if there is no problem, run it.

# After the review, just tell it to proceed
Go ahead

At that moment the work leaves human hands, and the agent team carries research → report writing → QA all the way through in the order the orchestrator planned.

Several tasks in parallel

  • You can leave one task running, bring up another terminal window, and give it yet another job. (For example, researching "can the KOSPI go up to 10,000?")
  • At a working developer's desk, several terminals are up like this, doing different jobs at the same time.
  • With Shift + arrow keys you can look at what the currently spawned agents are doing. (An agent with color on it is working.)
What is it used for Data analysis, research, report writing, simulation, and so on — whatever it is, give it the intent and it composes an agent team to do that job.

Reviewing the Generated Result — Agents · Skills · Orchestrator

The orchestrator coordinates the agents, skills get injected, and the outputs collect in _workspace.

Let's look at what gets created once the harness is composed. Claude Code creates the agents, skills, and so on under the .claude folder.

The agents that were created (example)

For the "national R&D budget · post-PBS" task, this was the team that got composed.

  • Quantitative R&D budget analyst — breaks the budget allocation · adjustment plan down by ministry · program · year, and tracks changes in the government/government-funded ratio.
  • Governance · finance expert for government-funded institutions — derives the strategy for the transition from PBS to a mission-oriented system.
  • National R&D policy researcher — researches budget · policy documents · press releases · NIS/NSTC agenda items and the like from primary sources.
  • Report writing agent — gathers the preceding outputs and writes them up as a report.
  • QA reviewer — cross-checks not simple typos but claim–source consistency, numerical consistency, and the logical connection of the recommendations.

The skills that get injected

Agents alone are not enough, so specialized skills are created and injected. For example: a quantitative budget analysis method (standard forms · calculation rules · checklist), citation verification for policy reports (verification axes · priorities), and a government policy report writing format (table of contents).

Orchestrator (always one)

It is the PM role that coordinates the agents so they do not wander off. It does not look into the detailed work; it only watches "are the agents doing their jobs well". From Phase 0 on, the workflow is planned in advance as to which agent each stage needs. (It feels similar to Claude Code's plan mode.)

Review and getting ready to run

  • The review step is mandatory. If you give feedback like "add more agents", "this does not match the intent, fix it", or "revise the harness", agents/skills are newly created or reinforced.
  • There is an issue where agents are not loaded dynamically. If you do not see them in /agents, they load once you /exit and come back in.
The _workspace folder When you run with the harness, a _workspace folder appears where the intermediate outputs the agents produced collect — the first-pass research, the budget analysis, the QA report (critical · major · minor issues) and its fixes, the limitations, and even the supporting sources. Because it is source-based, hallucination is greatly reduced.
