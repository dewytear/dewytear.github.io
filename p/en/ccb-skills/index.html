Extending — Skills, Plugins, Agents

A Skill is a unit of functionality that stores a task you will repeat at least once so you can keep reusing it. Turn the design system you built earlier into a Skill and you can easily stamp out many sites with the same design later on.

@ (the at sign) — referencing files and folders

To have it work from an existing file, type @. Typing @ brings up a file picker; choose the file you want and confirm it with Tab.

# Turn the design system file into a Skill
@design-system_new.html Turn this design system into a "my-design" skill.

A file or folder after @ means "work from this content." You can point to folders as well as files.

Permission requests

When it is about to do something to a particular folder mid-task, options asking for permission appear.

  • Option 1 — allow just this once.
  • Option 2 — stop asking for the same kind of task.

Where Skills are stored

  • Project-only — created under the project in .claude/skills/ (available only in that project).
  • Global — under your user folder at ~/.claude/skills/ (on Windows, Users\<user>\.claude\skills). Usable no matter which folder you run from.

Once the Skill is created, its content (for example, the Apple-toned white design system) is recorded under ~/.claude/skills/my-design/.

Building another site with the Skill

@papers_new.md Based on this paper content, use the my-design skill
to build a paper showcase website with the same design.

This gives you a paper showcase site with the same design as the Mythos site you built earlier.

More Skills Creating Skills works much the same way every time. For example, give it the developer documentation URL for OpenAI's GPT Image 2 and say "turn this into a GPT image skill," and you get an infographic generation skill. Formats that are not officially supported, such as HWP, can also be turned into a Skill yourself and reused.

Plugins · the marketplace

You can bundle several Skills together and distribute them as a Plugin. Since papers are mostly PDFs, let's install the official document Skills (document-skills) plugin, which contains a Skill that reads PDFs well.

1) Adding the marketplace

Type /plugin in Claude Code and press Enter to bring up the plugin screen. Use the arrow keys to select marketplace → then Add Marketplace to add Anthropic's official marketplace.

# If GitHub access is blocked or the UI is awkward, run it directly as a command
/plugin marketplace add anthropics/skills

2) Installing document-skills

The marketplace you added (Anthropic's official one) has several plugins; install only document-skills among them. Select it in the list with Space and install with Enter. A command works too.

/plugin install document-skills

This Skill lets Claude Code read documents such as PDF, PPT (pptx), and Excel.

3) Restart and verify

If it does not take effect after installing, leave Claude Code with /exit and run it again. Then type /pdf or /pptx; if the command shows up, the install succeeded. If it does not, try adding the marketplace and installing again.

When the install gets stuck (GitHub errors, etc.) Search Google for "anthropic skills github" and go to the official repository — the install commands are partway through the README. Copy the plugin marketplace add ... line and the plugin install document-skills line separately, paste each into Claude Code, and run them.

Building an Agent

An agent is a specialist worker assigned to a specific role. Creating one is as easy as creating a skill — all you need is the idea, and the AI writes the rest. Here we build a paper analysis agent and use it to analyze a downloaded PDF.

1) Prepare the PDF

# Give it the URL of the paper's detail page
https://arxiv.org/abs/....  Download the PDF file of this paper.

Claude Code finds the PDF link on arXiv and downloads it into the current folder. (Reading the PDF is handled by the document-skills we installed earlier.)

2) Create the agent

To scope it to this project only, tell Claude Code to create it under .claude/.

Add an agent that analyzes papers under .claude.

The generated agent carries metadata like the following.

  • Name · description — what this agent does.
  • Tool permissions — reading files, running Bash commands, and so on.
  • Model selection — choose the model each agent uses (for example the best one, opus).
  • Persona · principles — e.g. "an expert in academic paper analysis", "produce a report that conveys the core in five minutes".

The analysis style (abstract-focused / limitation-focused / verification-heavy, and so on) can be refined further with follow-up requests.

3) Check the list · run it

An agent may not be loaded right after you create it. Use /agents to check which agents are available in the current folder, and if it does not show up, /exit and restart.

# Attach the PDF as a reference and analyze it with the agent you made
@paper.pdf  Analyze this paper using the paper-analyzer agent.

4) Parallel analysis — where Claude Code shines

A single orchestrator spawns several agents in parallel, analyzes concurrently, then aggregates the results.

You can analyze all the remaining papers at once as long as you know their links.

Analyze the remaining papers too and save them to files.

Claude Code spawns several agents in parallel (for example 12 papers across 5–6 agents) and analyzes them at the same time. This is something a web chat cannot do. You can also turn the analysis results into detail pages for the paper showcase site you built earlier and link them up.

Another reason to use agents — saving context An agent uses a separate context window from the main session. If you hand heavy analysis to an agent and take back only the result, you barely consume the main session's context, so quality holds up far longer. (See the next document.)

Having built everything there is to build, what remains is using it sustainably — the Operations chapter covers usage, context, session management, and closing tips.
