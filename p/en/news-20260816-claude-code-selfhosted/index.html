Claude Code on Your Own Servers — the Self-Hosting Public Beta and August's Releases

Three-line summary

  • Claude Code's self-hosted environments — running agent sessions on your organization's own infrastructure instead of Anthropic's cloud — opened as a public beta on 6 August 2026. Team and Enterprise plans, one command (claude self-hosted-runner), and your machine becomes the execution layer.
  • The same week brought GitLab merge request support (--worktree now accepts MR URLs) and auto-continue (a session stopped by a usage limit resumes by itself when the window resets, 14 August).
  • The three point the same way — control over where sessions run, which platforms they target, and when they work all moves to the organization. It is the next step after the auto-mode default moved approval decisions into written rules.

Sessions crossed into the organization's boundary

Until now, a remote Claude Code session ran in an isolated container managed by Anthropic. The code is cloned fresh when the session starts and the container is reclaimed when it ends — convenient, but the plain fact that data passes through computers outside the organization made it a non-starter for organizations bound by data residency (a requirement that data never leave a specified location) or network-separation rules, as in finance, healthcare, and defense.

The self-hosted environments beta, opened on 6 August, moves that boundary. With the claude self-hosted-runner command that landed in Claude Code v2.1.224 (7 August), your machine or container becomes the session's execution layer, and the agent works next to your internal services, toolchains, and security controls. Runners operate in two modes.

  • Fixed — keep a set number of runners up at all times and distribute sessions across them.
  • On-demand — watch for waiting sessions, spin a runner up when work arrives, and shut it down when it finishes.

It ships disabled by default and an organization administrator has to turn it on in settings; organizations on ZDR (Zero Data Retention — a contract option under which no data is stored at all) cannot use it yet. In short, this is not a feature everyone flips on — it is a path for organizations whose compliance requirements had blocked adoption.

The rest of the week — GitLab MRs, auto-continue, Compliance API

GitLab merge request support. claude --worktree now takes GitLab MR URLs alongside GitHub PRs, and the agent list shows MRs as !N. Platform detection works from git remotes and API probing, so it catches self-hosted GitLab instances, not just GitLab.com — a change that lands directly on organizations running internal GitLab, the very environment this wiki's AI development knowledge platform proposal assumes.

Auto-continue. A single checkbox that arrived in the desktop app on 14 August. A session stopped by a usage limit resumes automatically the moment the limit window resets. The limits themselves (the 5-hour window and the weekly cap) are unchanged — what changed is only that the restart a person used to come back for now happens on its own. For long autonomous jobs left running overnight, the difference is tangible.

Compliance API expansion. The API that lets security teams query session content and metadata in one place for audits and eDiscovery (electronic evidence disclosure) now covers Cowork and every Claude Code surface — desktop, web, mobile, and CLI (Enterprise beta).

Why this is one current

This week's releases look miscellaneous but move in one direction. Where the auto-mode default moved the question of what to allow from a prompt asked every time into rules written in advance, this week moved where sessions run (self-hosting), what they target (self-hosted GitLab), and how long they work (limit windows with automatic resumption) into values the organization sets. As agents grow stronger, the point of control shifts from the conversation to the environment and the rules — the same thread that runs through the permission editing and verification-splitting advice in this wiki's advanced tips.
