Hook · Memory

OMC makes use of Claude Code's Hook events to handle keyword detection, skill injection, state recovery, and completion verification. As of the latest Reference, the Hook events are broken down more finely.

Things to know

  • autopilot · ralph · ultrawork · ultraqa are skills, not Hooks. keyword-detector activates them, and the persistent-mode Hook assists with keeping them running.
  • To turn off all Hooks use DISABLE_OMC; to exclude only specific Hooks use OMC_SKIP_HOOKS.
  • Windows Native Hooks were improved after v4.14.4 and can be used as they are. Some features that require tmux also work without WSL if you use psmux (a tmux-compatible tool for native Windows), per the current official README, and WSL2 is the alternative path.
# Disable all of OMC's Hooks at once
export DISABLE_OMC=1
# Exclude only the specified Hooks (the rest work normally)
export OMC_SKIP_HOOKS=PreToolUse,PostToolUse

When Hooks run

A Hook is an action that automatically steps in and runs at each specific event in Claude Code. OMC uses this to inject context and turn skills on automatically. There are four main timings.

When a session starts and when you send a prompt, and just before and just after every tool, a Hook automatically steps in.
  • SessionStart — when a session starts. OMC initialization, loading notepad · project-memory, recovering the state of the mode that ran just before.
  • UserPromptSubmit — when you send a prompt. Magic keyword detection, automatically wiring up the right skill, context injection.
  • PreToolUse — just before using a tool. Hints recommending parallel reads, suggestions to preload related files.
  • PostToolUse — just after using a tool. Result verification, suggestions for follow-up action, suggestions for automatic fixes when an error is detected.

Reading the messages you see mid-conversation

While working you may see messages in the form of system-reminder. Don't be alarmed — just understand them as below.

MessageMeaning
hook success: SuccessA sign that it is working normally. You can just go on.
hook additional context: ...A useful hint. It is good to take it into account and apply it.
[MAGIC KEYWORD: ralph detected]A notice that the corresponding mode (here, ralph) has been turned on automatically.
The boulder never stops rollingA sign that ralph · ultrawork is still running.

Memory and project documentation

OMC provides three mechanisms for keeping the work context even across sessions. Each differs in where it is stored and what it does.

  • deepinit — skims the whole codebase and creates an AGENTS.md document in each directory. It lays out what each folder holds, the relationships between files, things to watch out for while working, and dependencies, so the AI does not have to explore the structure from scratch every time. It is useful as preparatory groundwork on large projects.
  • notepad — a work memo stored in .omc/notepad.md. It survives even when the conversation gets long and the context is compacted. It is divided into three tiers — information you must never lose (priority), the state of the work currently in progress (working), and memos you record manually (manual) — and cleaning up old items is handled with the notepad_prune tool.
  • project memory — stored in .omc/project-memory.json, it remembers the project's tech stack, coding conventions, and architecture guidelines. The defaults are set with omc-setup.
# Analyze the codebase and generate a per-directory AGENTS.md document (current path if [path] is omitted)
/oh-my-claudecode:deepinit [path]
