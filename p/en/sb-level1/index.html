Levels 1–2 — Find Precisely, Group by Topic

Every Second Brain starts here. You need exactly two things — a single CLAUDE.md and a few folders and files. The question at this level is simple. "That word or file I wrote — where is it?"

What CLAUDE.md is It is a file that is read automatically when you open the project folder. It works like the system prompt for that session (see the Basics chapter, CLAUDE.md section for details). The key point here is using this file as a "router (a signpost)".

CLAUDE.md = role introduction + routing rules

In CLAUDE.md you write not only "who you are and what matters" but also "which information lives in which folder". These are the routing rules.

# CLAUDE.md — example routing rules (signposts)
- If you need personal info about me  → read context/about-me.md
- If you wonder about the stack/env   → read context/stack.md
- Q1 priorities for this year         → they are in projects/2026-q1.md
- Big decisions and their reasons     → context/decisions.md (decision log)
With routing in place, the AI does not ask back "I don't know what you mean" — it goes straight to that folder.

Why routing is needed — AI cannot find what it does not know the location of

You have surely had the experience of the AI asking back "please give me more information" even though the file is clearly in the project. That is usually because you never told it the file was there.

The misconception — "it will dig through everything on its own" AI does not automatically dig through the whole codebase (doing that would only waste time and tokens). If it does not know something is somewhere, it cannot find it. With routing done right, you no longer need to repeat the same explanation — you just speak, and it knows where to look.

Folders the way you understand them

There is still no settled standard for the correct folder structure. The way someone else does it is not the only right answer. There is one criterion — does it make sense to you, and does it make sense to your AI too.

# Folder example (can also be organized by date)
context/
  about-me.md          # Me and how I work (background that is always true)
  stack.md
  decisions.md         # Decision log — add an entry with the date on big changes
projects/
  youtube/2026-05-30-top50.md
  clients/acme.md

Limits and the next step Level 1 is generally based on exact words and names. As files pile up it gets messy and things are easily missed. That is when you move on to Level 2 — the LLM wiki and memory, which groups by topic. (Note: copying CLAUDE.md into an AGENTS.md for Codex lets you keep using it even when you switch tools, and this tool independence is covered at level 2.)

Level 2 · Grouping by topic (LLM wiki + memory)

Once files pile up, you start wanting to weave them together by topic. That is where the LLM wiki comes in. The question at this level is "gather everything about this topic." Think of it as laying an index and links on top of Level 1.

Ties to a topic already covered This wiki already has an LLM Wiki set that covers the Karpathy-style LLM wiki in detail. Level 2 is exactly that world — here we only touch on the key points from a Second Brain perspective.

A wiki is "reading your way down the index"

A wiki's strength is its index. When AI enters the wiki, it goes "they asked about agentic workflows, so start here → drill down into the related WAT framework → and if needed go all the way to the CLAUDE.md system prompt," reading whole pages as it follows the trail.

Tell the AI to "put this in the wiki" with YouTube subtitles or meeting notes and it sorts them automatically into concepts, comparisons, sources, and techniques to build a structure like this.

Memory — a file the AI writes on its own

The new axis Level 2 adds is memory. Turn on Claude Code's auto memory and the AI keeps memory.md updated by itself. Context accumulates without you paying attention.

# Check whether auto memory is on or off
/memory
# If you see an auto-memory on / off state, just turn it on when it is off

Tool independence — Claude Code or Codex

A Second Brain is just files and folders, so it is not tied to one tool. The file-naming conventions do differ per tool, though.

ToolInstruction fileMemory
Claude CodeCLAUDE.mdmemory.md updated automatically
Codex, etc.AGENTS.md (copy the same content into it)Route it with "for memory, look at memory.md"

※ Copy CLAUDE.md over as AGENTS.md and both tools share the same brain. In the end it comes down to where you tell them to look (routing).

Wiki links = knowledge graph? No Links in a wiki are closer to "see also" and backlinks. They do not carry the meaning of a relationship, as in "this endorses that / this is a competitor of that." The effect is similar, but truly relationship-based is Level 4 — the knowledge graph.
Obsidian is not a requirement Obsidian, famous for its flashy graph view, is in the end just a layer that visualizes markdown. Use it if seeing things visually helps, and skip it if not — what matters is whether your system finds and pulls things out for you. Next comes Level 3 — searching by meaning.

That is as far as files and folders take you. From the next chapter, Levels 3–5, the tools change character — semantic search, knowledge graphs, and a brain OS.
