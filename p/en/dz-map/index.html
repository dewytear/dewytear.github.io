Knowledge Map — Douzone

This page is a knowledge map that consolidates the DOUZONE World (work and organizational knowledge). Knowledge in this wiki is organized in four levels, World → Domain → System → Document, and this map covers the DOUZONE World among them. It shows which System each company knowledge document belongs to and how they connect to one another. Each document's summary, key concepts, and related documents come from the structural knowledge index an AI built (knowledge-index.json), and you can explore these relations in three 3D and six 2D views in the Knowledge Graph. Course and learning knowledge is aggregated with the same structure by the AI Knowledge Map.

Two Worlds — learning knowledge (AI) and work knowledge (DOUZONE) connect on the same index.

System details — what's inside, and in what order to read

AI Dev Knowledge Platform — a GitLab-based automatic knowledge proposal (4 docs)

A proposal series for a Read-Only Engineering Knowledge Platform in which an AI analyses the development output accumulating in GitLab and automatically converts and accumulates it as organizational knowledge. Read in the order below and it runs as one flow from problem definition to execution plan.

  • Proposal Overview — Why Now, What — the one-sentence summary, the virtuous cycle, and the problem statement grounded in industry statistics. The series gateway.
  • The Core and the Architecture — the dev flow stays, AI does the knowledge-making; the Event Stream (GitLab) / Knowledge State (Wiki) split, the seven layers, triggers, SHA incremental analysis, and integrity gates.
  • The knowledge management system — value judgment · the atomic structure of knowledge · two layers of links (related · relations) · identifier search · provenance · FACT/INFERRED/DECISION trust tiers · the supersedes lifecycle.
  • Security, Added Value, and the Roadmap — reusing the Reference Wiki engine, PUBLIC–RESTRICTED tiers, per-audience value scenarios like auto-updated API specs, and the four-phase roadmap with the first PoC and KPIs.

AI Notification Send Engine — a Kafka-based send engine implementation request (1 doc)

A proposal series asking the Platform team to implement, as a Kafka-based shared send engine, the actual sending, timing, reprocessing, and status that follow once AI Notification has finished creating the send request. It is organized conceptually; the concrete design is settled through discussion.

  • The Send-Engine Request — Overview, Scope, Interface — the responsibility boundary (AI Notification ends at creating the send request), the requested scope (channel sends, idempotency, delivery guarantees, DLQ), and interface pre-agreement with expected benefits — in one piece.

Planned Systems — places where only the slot is ready

The three Systems below have only a folder prepared in the navigation. Once documents are added to those folders and registered in the knowledge index, they appear automatically in the table above and in the Knowledge Graph.

  • Architecture — where architecture knowledge will accumulate: the system structure, layer design, and inter-module integration of the OmniEsol ERP·SCM area.
  • Development Guide — where the development guides a team shares will gather: development standards, common patterns, code review criteria.
  • Project — where project-level knowledge will be recorded: the business Rules, decisions, and incident experience of individual projects.

Recommended reading paths

  • Reading the proposal for the first time? — Proposal Overview — Why Now, What → The Core and the Architecture. That much is the "what and why".
  • Here for a technical review? — The Core and the Architecture → Knowledge management system → Security, Added Value, and the Roadmap. These cover the "how".
  • Deciding whether to go ahead? — check the phases, PoC, and KPIs in the Security, Added Value, and the Roadmap, and go back to the overview if you need the background.

Bridges that link knowledge — bridge concepts

Concepts that appear in several Systems at once become “bridges” across branches. The two Systems of the DOUZONE World (the proposal series) share no key concept yet, so no bridge is aggregated — once a concept spans three or more Systems it appears here automatically. For now, concepts such as Knowledge platform · AI curator · Knowledge management connect by topic to the AI World (the Second Brain and LLM Wiki Systems), which makes them candidate bridges across Worlds.
