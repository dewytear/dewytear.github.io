Harness Plugin — Introduction

The Harness plugin is a Claude Code plugin that "lays out the setup so that, once you give it only a goal (an intent), several AIs form a team and work on their own for a long time." Instead of throwing prompts one at a time, if I just say "what I want", the plugin composes and runs the agent team · skills · orchestrator on my behalf.

The big picture on one page

What the Harness plugin does comes down to the flow below. People step in only at the very front (the intent) and the very back (review and decision-making), and the AI team takes on the repetitive work in the middle.

People handle only the front (intent) and the back (review); the AI team takes the repetitive work in the middle.

Why "harness" — from prompts to the harness

The way we handle AI has evolved as below. The harness is the stage of designing not one model but "the whole environment surrounding the model." Even with the same model, the quality of the output differs greatly depending on which setup (harness) you put it on.

StageCoreAnalogy
Prompt engineeringAsking questions wellPhrasing a single remark well
Context engineeringFeeding in the needed materials and context wellPutting the materials into their hands
Harness engineeringDesigning the whole system in which the AI worksFitting a horse with a harness so it runs well for a long time

Why it fits ERP customization well

Customization work for a client usually chains several stages in order — requirement (CR) analysis → grasping the standard source and impact → design → development → regression verification. This is a prime example of work that takes a long time if you do it alone in sequence, but is far faster if you split the roles and go in parallel. The harness hands each of these stages to a responsible agent and lets the orchestrator coordinate them.

  • Minimizing damage to the standard — the analysis agent first points out "where this customization affects the standard package."
  • Automated regression verification — after development, the QA agent cross-checks that the standard features have not broken.
  • Standardized deliverables — the specification, impact analysis, tests, and migration guide are all left together in _workspace.

※ A concrete example (a sales/order credit-limit customization) is followed step by step in First harness run.
