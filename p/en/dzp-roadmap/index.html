Rollout Roadmap — 4 Phases and the First PoC

Nothing unvalidated is introduced to the organization. Starting from pre-validation, the steps proceed in the order of team PoC, center-wide expansion, and company-wide rollout.

Four-phase rollout

  • Phase 1 · Porting the Reference Wiki engine — we do not start from a blank page: install wiki-plugin (v0.7.0) in the company repository to bootstrap the registration, index, and validation system as it is (the wiki-init → add-doc → validate skills of the plugin packaging), manually curate SCM domain knowledge through Claude Code integration, and validate Knowledge Index search, HTML accumulation, and the AI Curator Prototype. First target: OmniEsol ERP · SCM domain
  • Phase 2 · Company PoC (SCM구축개발1Unit) — company Wiki Repository, GitLab Project Registry, Change Collector, SHA incremental processing, AI Knowledge Curator, introduction of extension fields (identifiers · sources · trust), Read-Only Portal. First source: the OmniEsol ERP SCM GitLab Repository
  • Phase 3 · Expansion to the SCM Development Center — multiple projects, Product/Domain classification, knowledge links across projects (applying typed relations across projects), Knowledge Lifecycle (operating supersedes), security grades, quality KPIs
  • Phase 4 · Company-wide expansion — in-house SSO, company-wide search, per-product Knowledge Governance, AI Agent integration (intranet llms.txt and graph JSON contracts), formalization as the in-house development platform

First PoC — OmniEsol ERP (SCM domain)

ERP is the domain with the highest density of business rules. The business rules of sales, sales orders, purchasing, and production; the document status transition system (sales order → shipment → revenue); credit and available-to-promise (ATP) check policies; inter-process integration; DB table structures and column semantics; incident cases; policy change history — elements with high value for turning into knowledge already exist, and the search and accumulation effects can be validated immediately with identifiers such as those below (for the entry structure, see the schema example in Knowledge Management).

Validation KPIs — four axes, measured by gates

A KPI is not a declaration; it becomes a target only when a measurement method is attached. A good part of the four axes are values the Reference Wiki is already measuring with CI gates, so the company PoC does not need to invent the measuring instruments anew.

  • Knowledge generation quality — accuracy of automatic generation, success rate of updating existing documents, duplicate document creation rate, rate of wrong inferences. Measurement: validator ERROR 0 (broken references, duplicate IDs, unregistered documents) + index drift 0 (--check) + orphan documents 0 (graph validation) — all judged automatically on every commit. Inference errors are sample-inspected per trust grade.
  • Search quality — identifier search success rate (target direction: reaching the policy document from a single identifier met in the source ≥90%), accuracy of related document recommendations, time to reach the desired information.
  • Development productivity — fewer repeated questions, less re-analysis of past incidents, reduced learning time for new developers (the 3–9 month onboarding and 8 hours per week loss statistics of Why Now are the baseline), less context explanation for AI tools.
  • Operational quality — knowledge reflection rate against merges (target direction ≥90%): "was knowledge reflection accompanied in merges with substantive changes" is measured continuously as the pass rate of the diff-based accompaniment gate (the integrity gate of the architecture). Number of missed changes (aggregated by the sync-state correction batch), superseded processing rate, distribution of relation types (whether it is skewed toward prerequisites — a non-blocking review signal is surfaced for every new document).
Closing This proposal is about creating a virtuous cycle (overview) without changing developers' workflow, and that knowledge engine is already running as the Reference Wiki. What remains is to connect the event stream called GitLab to the validated engine.
