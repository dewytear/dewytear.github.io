Windows Cautions

The Windows PowerShell environment needs some separate attention. The key point is that tmux-dependent features are solved with psmux (no WSL needed), and WSL2 is an alternative path.

  • v4.14.4 included a fix related to the Native Windows Hook manifest (removing the sh invocation), and since then the Native Windows Hook can be used as is. The "WSL2 recommended" guidance in older documents is outdated — the current official README presents WSL2 only as an alternative path.
  • Features that need tmux (the omc team CLI, parallel execution of some external AI workers) may have limitations with Native Windows PowerShell alone. The official README presents psmux (winget install psmux), a native tmux-compatible tool for Windows, and when you use psmux, WSL is not needed.
  • Plugin installation · setup · doctor · using skills inside a session all work as is on Native Windows. If problems keep recurring in your environment, there is also the alternative path of switching to WSL2.
  • Even if npm view · npm ping work fine in PowerShell, the Claude Code plugin installation flow and the npm CLI installation flow are separate things.
Things to check beforehand 1. Whether your actual environment is Windows Native PowerShell or WSL2
2. Whether you will use OMC as a Claude Code plugin or as the npm CLI/runtime
3. Whether you plan to also use multi-AI features that need tmux, such as /omc-teams
