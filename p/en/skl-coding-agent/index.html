The Background of Skills — the Birth of the Coding Agent

Skills are not a technique that appeared out of nowhere one day. They emerged naturally on top of a foundation called the coding agent. You need that context to understand why skills work the way they do.

Kinds of agents

The higher the stage, the wider the range of what it does on its own — skills become possible on top of the coding agent.
  • Chat agent — the conversational kind we use by default.
  • Tool-calling agent — connects MCP and APIs to do external work such as checking Gmail or adding a calendar entry.
  • Coding agent — one step above tool calling. Claude Code belongs here.

"Keep the tools simple, leave the rest to the LLM"

At first the expectation was that building many sophisticated tools would make the agent work well, but no matter how well they were built, we ran into the limit of not getting the form we wanted. So the thinking was flipped.

  • Give only the most basic tools — reading, writing, editing, and finding files, plus running commands (about six of them).
  • Let the LLM figure out the rest.
  • For that you need an execution environment and a file system → a sandbox plus simple tools.

What was born this way is the coding agent. Rather than loading up every tool imaginable for a camping trip, it is closer to taking only basic tools like a hammer and making what you need on site.

Why Claude Code starts by latching onto a folder This is exactly why Claude Code runs inside a specific folder. Reading and writing files and running your commands requires your OS and file system, so it operates on your own computer (locally). Skills are a feature that is only possible on top of this coding agent.
