Operations — Usage, Sessions & Wrap-up

To use Claude Code well, you need to know how to manage usage (tokens), context, and sessions (conversational state). Tokens have become extremely important.

Usage — /usage

  • /usage — shows your current session and this week's usage.
  • Session limit: budgeted in 5-hour blocks counted from when you first started. If you burn through 100% within those 5 hours, you have to wait until the block ends.
  • There is also a weekly limit. It is the limit developers find most painful, so spending frugally is the key.

Context — /context

/context visualizes what is currently loaded into Claude Code. The size of the context window depends on the model — most default to 200,000 (200K) tokens, while the latest models (Fable 5 · Sonnet 5 · Sonnet 4.6, and Opus 4.6 onward) support 1,000,000 (1M) tokens. On the Max · Team · Enterprise plans Opus is automatically upgraded to the 1M context, and you can also pick it yourself by adding the [1m] suffix, as in /model opus[1m].

  • The system prompt, tool definitions, and the like take up part of it, and it fills up a little more with every task you assign.
  • Once it is fairly full, a compact kicks in and the contents are compressed and shrunk.
  • When a compact happens, some data is lost, so performance can drop slightly.
  • So rather than waiting until it is completely full, it is recommended to compact manually with /compact at a sensible point.

Making use of agents lets you conserve the main context while keeping quality up.

Managing sessions (conversational state)

Unlike a web chat, Claude Code loses its context once you leave with /exit. Use the following commands to pick it back up.

CommandWhat it does
claude --continueResumes the most recent session exactly where it left off
claude --resumePick from a list of past sessions and return to that context
/clearClears the context without exiting and starts a new session

Session records are saved per project and per session under your user folder in ~/.claude/projects/. That means even work from long ago can be revived with --resume. Note, however, that these records are stored locally only, so they do not exist on another PC.

Watch out for caching AI has caching, so when you continue a request you are billed only for the new portion. But caching has a time to live, so if you come back later and request again with --resume, everything accumulated is sent over again and you get no caching benefit. In that case, opening a new session may work out better.

Useful Features and Wrap-up

Finally, here are a few commands and skills for getting more out of Claude Code, plus where to go next.

Analyzing your own habits — /insight

/insight analyzes how you normally use Claude Code and produces a report on how to use it more efficiently.

Useful skills shared in the course

  • worklog — organizes your recent work like a weekly report. For example, ask "summarize the work I did over the past week" and it analyzes the logs and neatly lays out which projects you worked on.
  • manpower — analyzes how well you are using AI and visualizes it as an octagon (radar) chart. It shows where you fall short and your weekly growth trend. It is also useful for measuring employees' AI adoption (AX).
  • GPT Image 2 / HWP and others — custom-built skills for image generation and Hangul document handling.

Documents in other formats

PDF, PPT, and Excel are covered by the document-skills plugin. HWP, which is not officially supported, can be used by registering a separately built skill. Other formats can also be handled by building a skill around a conversion library where one exists, though pure binary formats can be difficult.

Cowork

Cowork, offered in the app, came out later than Claude Code and is still somewhat unstable and short on features, but 1.0 launched recently. If the terminal feels intimidating, starting with Cowork is one way to go.
