A list you can call — taking apart a ranked catalog of 167 agent harnesses

Three-line summary

  • The public repository best-of-Agent-Harnesses re-scores 167 agent harnesses across 12 categories every week. It does not stop at a ranked table for people: it ships an MCP server so agents can call the list as a tool.
  • Cloned and run directly, the counts, the categories, the weekly cadence and the 8 MCP tools all hold up. The recommendation logic, though, is not semantic search but word overlap plus the log of the star count.
  • The headline number the list leads with (“the same weights go from 30% to 95.5%”) is the weakest link in its own evidence table. It subtracts a self-reported run from an official leaderboard entry, and the configuration needed to reproduce it is not published.

A harness is the runtime that closes the loop between a stateless model and the outside world: the tool list, the approval rules, what the model sees each turn, and what survives a crash. This wiki covered that anatomy in what a harness is. Since then a separate problem has appeared, which is how to choose one. A catalog that lines up 167 of them and re-ranks weekly is the answer somebody built.

What the clone actually shows

Rather than repeat the claims, I pulled the whole repository. harnesses.json is a single 421KB file holding 167 entries across 12 categories. All 21 fields are filled on all 167 entries, so nothing has to handle a missing key.

The weekly re-scoring shows up in the commit history. Filtering commits that touch harnesses.json gives one line per Sunday: weekly rescore 2026-09-20, 2026-09-13, 2026-09-06. Star counts are labeled as captured on 20 September 2026.

The MCP server runs. MCP (Model Context Protocol) is the standard by which an agent calls outside tools, and this repository packs 8 tools into a single mcp/server.py, published to PyPI and the official MCP registry. Stubbing out the dependency and calling the functions directly gives real answers.

  • Ask for an unattended coding agent that survives a crash and it picks entries rated headless on autonomy and resumable on recovery, with alternatives.
  • Ask it to compare two entries and each axis rating comes back with an evidence URL and the date it was researched. 87 of the 167 entries carry that deeper research.
  • Ask for categories and it returns all 12 with a count for each.

How a recommendation is scored is right there in the code. Hand-picked use-case entries win first; otherwise the score is the number of shared words times three, plus the base-ten log of the star count. No embeddings, no semantic matching. The reason string that came back on one query was matches: coding, mid-run, survives, that, and the fact that that earned points tells you what kind of matching this is. Rephrase the question and the answer can move; entries with more stars are structurally favored.

One dataset, two doors

The part worth taking from this catalog is not the ranking. It is that the same data is given two different doors, one for people and one for agents.

The upper door needs the agent to arrive and parse. The lower one lets it call with tools it already has. The source is the same.

The difference is who does the work. Through the pull door the agent has to know the address, fetch, parse, and load the result into context. Through the call door it asks a question and gets a chosen answer. The catalog frames the second door as a way to skip reading a hundred table rows, and the context cost really does split between 421KB and a paragraph.

The overlap is large. Neither side hand-edits its output files; both generate them and run a gate before committing. Their gate checks that no category is empty and that each comparison page carries real prose, and it also fails the build if the entry count drops sharply against the previous commit. That guard aims at a generator going wrong and wiping the data, which is a cousin of this wiki's --check drift block but points at a different accident.

Two things genuinely differ. This wiki has directed, typed relations between documents (prerequisite, implements, example-of, evidence-for, supersedes) and the catalog has none. The catalog has a call door and this wiki has none. A rich graph is rich only to an agent that arrived; to one that never came, it may as well not exist.

The headline number is the weakest link in its own table

The catalog opens by claiming the harness matters more than the model, and cites the same weights scoring about 30% bare on ARC-AGI-3 and 95.5% inside a good harness. ARC-AGI-3 is a public test of abstract reasoning. I followed the number.

On the official leaderboard, 30.2% is Claude Opus 5's own listed entry. The 95.5% is what Prime Intellect reported for its Prime Agent harness, self-reported, and the public repository does not include the adapter, prompt, run logs or pinned configuration needed to regenerate it. No independent reproduction is on record. Meanwhile the official board has since moved: GPT-6 Astra sits at 62.7%, so “about 30% bare” is no longer even the ceiling. Subtracting the two numbers gives 65 points of two differently configured runs, not 65 points of harness.

Writing off the whole catalog over this would be the opposite error. The other measurements in the same table are far sturdier. Holding the model fixed and swapping only the harness on SWE-bench Pro moved GLM-5.2 from 23% to 52% pass@1 (the share solved on the first attempt) and Gemma 4 26B from 15% to 36%. Cursor's own benchmark had one model passing 46% under one harness and 80% under another. Harness-Bench reported that harness rankings barely transfer between models, at a rank correlation near -0.05. That is the real claim; the headline is its most dramatic and least solid line.

So what this catalog teaches is not the ranking but the habit sitting next to it. Each row of the evidence table is tagged as a measurement, a practitioner's statement or commentary, and the date every link was last checked is written down. That is precisely why an outsider could pull the headline number out and test it alone. Attaching an evidence URL to each rating is the same instinct: make it possible to point at what is wrong when something is.

What this wiki should take

Three candidates come out of the comparison, and they are not worth the same.

The largest is a call door. Every part of this wiki's machine layer is pull-shaped, so nothing starts until an agent knows about llms.txt and comes looking. Wrapping the knowledge graph in an MCP server would turn “documents covering this concept”, “prerequisites for this document” and “a path between these two” into single tool calls. The typed relations are already there, which leaves more to expose as tools here than the catalog has. It lands next to the skills already packaged in turning the wiki engine into a plugin.

Second is schema.org JSON-LD, a second copy of the same data in the vocabulary search and answer engines read. This wiki fixed its contract in its own schema and traversal guide, which works only for an agent that read the guide. This overlaps with what the sign-post file already does, so it ranks lower.

Third is keeping dead things in a graveyard instead of deleting them. The catalog leaves 3 dropped entries and 24 undecided candidates in the data. Delete them and the question “why is this missing?” gets asked fresh every time; keep them and a judgment made once gets reused. This wiki's Backlog sits in a similar spot, but it is a list of work to do, not a record of rejections.

Only the first is different in kind. The other two publish what already exists one more time; the first opens a door this wiki has not opened.

Fact-check note

The 167 entries, 12 categories, 21 fields filled on every entry, 87 deep-dive records, the weekly rescore commits, the 8 MCP tools and the scoring formula were all counted and executed directly from the repository on 21 September 2026. File sizes and graph figures were measured the same day from this wiki's own build outputs. Star counts are the values the catalog states it captured on 20 September 2026; the GitHub API was blocked in the environment this was written in, so no third-party comparison was possible. The official ARC-AGI-3 scores (Opus 5 at 30.2%, GPT-6 Astra at 62.7%) and the fact that the 95.5% is self-reported without published reproduction material were cross-checked against the ARC Prize leaderboard and several verification write-ups. The SWE-bench Pro figures (23→52, 15→36), Cursor's 46→80 and Harness-Bench's -0.05 rank correlation follow the primary sources the catalog's evidence table links, but arXiv would not open in this environment, so only figures on which the repository's citation and secondary summaries agree are carried over.
