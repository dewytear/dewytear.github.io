Note Structure — Metadata and Progressive Disclosure

Open a wiki note and it is laid out as title → metadata → body. If the body starts on line 38, for instance, then the 37 lines before it are all metadata.

YAML front matter is the heart of it

The point where Obsidian is most valuable as a markdown editor is exactly this YAML front matter metadata field. It works on the same principle as the progressive disclosure we learned about in Claude Code.

The agent reads the metadata (front matter) first, and opens the body only when it needs to.
  • The context window is limited (at most a million tokens), so it cannot open everything.
  • That is why only the important content is put at the very top (the metadata), stated concisely.
  • Agents like Claude Code read this metadata first. Compared with the whole, it is the tip of the iceberg, but by skimming just these tips they quickly grasp what the content relates to.

Writing good titles and descriptions (in English)

Just like a skill's description, it matters to write a note's title and description fields well. We are Korean, but artificial intelligence reads English faster and better, so it pays to write the metadata in English.

Context optimization A big advantage of Obsidian is that instead of packing everything into one file, you can point to the address of another file — "for tastes, see tastes.md," "for the expert persona, look here." That way only the files needed for the work at hand get opened, which optimizes context. Borrowing Karpathy's idea, the speaker built a set of commands and skills that automate writing this metadata.
