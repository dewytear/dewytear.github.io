The Vault System — Main Vault and Wiki Vault

Obsidian is fundamentally built on the vault system. A vault is a collection of markdown files bundled under a single name, and it is read as one set. It is the same structure as Claude Code opening a particular folder, reading the CLAUDE.md inside it, and taking on a distinct identity.

Separate knowledge written by AI from knowledge written by you

Wherever possible, it is best to separate knowledge written by AI from knowledge written by you into different vaults. It is easy to mistake what AI produced for something you fully understand yourself, so it matters to draw a strict line around how far your own study has actually gone.

Several wiki vaults (satellites) connect to the central main vault (mothership) through two-way sync and references.
VaultMetaphorWhat it holds
Main vaultmothershipConcepts you know well and can explain to others. Finished deliverables.
LLM wiki vaultsatellite (several of them)What you want to learn, what you do not know well yet, technical concepts. A storage space for raw material.

The speaker actually uses about 8 vaults, dividing them by purpose and by who they are shared with.

Local files and syncing

  • Obsidian works with local files, which is an advantage for work where security matters. File paths are exposed as-is, so computers handle them easily and quickly.
  • Avoid putting in files other than markdown (HTML, PDF, images, Hangul documents, and so on) — Obsidian's rendering slows down.
  • For syncing you can use the official Sync, or build a shared vault within an organization using a plugin such as osync, which mimics it and can be self-hosted.
