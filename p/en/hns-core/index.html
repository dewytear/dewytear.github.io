The Three Core Elements and How They Work

There are many harness components, but the instructor takes the view that multi-agent collaboration happens well with just these three and focuses on them — agent · skill · orchestrator.

1) Agent — a natural-language document

An agent is not code but a document written in natural language. It holds the following.

  • The role and the principles
  • Input protocol · output protocol (in what format to produce the result)
  • Collaboration — what to exchange with other agents
  • Behavior on re-invocation and when an error occurs

2) Skill — standardizing repeated work

A skill is a name + description that freely holds a defined process, knowledge and checklist.

  • Because the process is defined, consistency is maintained.
  • You can combine small skills to compose a bigger system.
  • Thanks to the standardization, repeated work gets faster.

A knack for designing skills: find the repeated work → separate it by single responsibility → define input/output → handle exceptions → connect it to an agent.

3) Orchestrator — a PM that does not micromanage

It is the PM responsible for whether the whole workflow is carried out well. Unlike a failing PM it does not interfere in the details; it only checks something like "is the workflow being carried out well".

The plugin's six steps

Once ⑥ verification is finished the team composition is done, and the operating loop runs next.

/harness handles a request in six steps in total.

  1. Analyze the request
  2. Design the agent team
  3. Create the agents
  4. Create the skills
  5. Create the orchestrator · establish the workflow
  6. Verify the harness setup
Six team behavior patterns Six collaboration patterns for an agent team are specified — sequential execution, parallel then integrate, a review process, and so on. These patterns are combined as hybrids to act as the situation requires.
