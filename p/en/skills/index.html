Extending Claude Code — Skills · MCP · Hooks

Claude Code does plenty of work out of the box, but it really earns its keep once you shape it around your team and your project. There are three ways in: skills package know-how you keep reusing, MCP servers reach systems beyond your local files, and hooks run at fixed points without fail. They play different roles, so none of them replaces another — they work best combined.

Skills — reusable capabilities

Skills are reusable, packaged capabilities that give Claude Code specialized knowledge and workflows for a specific task. A skill bundles instructions (and optionally scripts and resources) that Claude loads on demand when your request matches what the skill is for. You invoke a skill the same way you run any slash command — by typing / followed by the skill name — or Claude Code can trigger a relevant skill automatically when it recognizes the task. Examples of what skills can do:

  • Run a structured code review of the current diff.
  • Perform deep, multi-source research and produce a cited report.
  • Design and configure hooks, keybindings, or settings.
  • Build data visualizations that follow a consistent design system.
Skills keep your prompts short and your results consistent, because the detailed know-how lives in the skill rather than in every message you type. You can use the skills that ship with Claude Code, install skills from plugins, or author your own.

MCP servers — reaching the outside world

MCP (Model Context Protocol) is an open standard for connecting AI assistants to external tools and data sources. By adding MCP servers to Claude Code, you extend what it can reach beyond your local files — databases, issue trackers, cloud services, browsers, and more. Once an MCP server is connected, its tools become available to Claude Code just like the built-in ones. For example, with the right servers configured Claude can:

  • Read and create GitHub issues and pull requests.
  • Query a database or an internal API.
  • Search email, calendars, or documents.
  • Drive a headless browser to test a web page.
You manage servers with the claude mcp commands (add, list, remove) or through your configuration files. Each server declares which tools it exposes, and Claude Code stops only on the actions your rules catch — since 14 August 2026, auto mode is the default, so deny rules you write ahead of time and a set of safety checks make the call instead of a prompt on every step (Defaults That Stop Asking). Those rules and settings are how you control what external systems it can touch.

Hooks — automation that runs every time

Hooks are user-defined shell commands that Claude Code runs automatically at specific points in its lifecycle. They let you enforce rules and automate behavior deterministically — the harness executes them, so they happen every time, not just when Claude remembers to. Hooks are configured in your settings.json and are attached to events such as:

  • PreToolUse — before Claude runs a tool (e.g. block edits to protected files).
  • PostToolUse — after a tool runs (e.g. auto-format or lint a file that was just edited).
  • SessionStart — when a session begins (e.g. install dependencies so tests can run).
  • Stop — when Claude finishes responding (e.g. send a notification).
Typical uses include running a formatter after every edit, running the test suite before a commit, protecting sensitive paths, or sending a desktop notification when a long task completes. Because hooks are just shell commands, you can wire Claude Code into whatever tooling your project already uses. Skills grow what Claude Code knows how to do, MCP grows what it can reach, and hooks make rules actually hold. To see the three working together on real tasks, continue with the Claude Code tutorial.
