Practice — Research, Design, Papers

Save what you researched on the web to a file, then build and polish a site from that file.

Claude Code ships with several built-in tools. Among them, the web search (WebSearch) and web fetch (WebFetch) tools let it research the task you give it on the web and bring the results back. Let's run research → save to a file → build a website as a single flow.

1) Research and save to a file

Research the Mythos model and save the related content to a file.

Claude Code gathers material with web search and organizes it into a file, including source links. (If there is a CLAUDE.md instruction, it is written in Korean and _new is appended to the file name.)

2) Build a website from the research

Based on the research you just did, build a sleek, modern website.
Add a background with heavy animation effects and interactive elements.

Give it a single text file and Claude Code figures out the intent and finishes the site. Once it is done, say "open it in the browser" and it brings it right up.

3) Editing the design · branding

You can keep changing the site after it is built.

# Change the theme
Switch it to a white theme.
# Naming a brand yields a better design
Rework it in the style of Apple's site, in white.

When you mention a familiar brand, as in "the style of Apple's site," it tends to produce a more polished design.

Handy controls while it works

  • ESC — cancel the task in progress at any time.
  • If you type something while it is working, it is queued as the next task and carried out when the AI can get to it.
  • Even when an error occurs, saying "keep going" — or simply waiting — often lets Claude Code resolve it on its own.
Watch your tokens Big jobs like generating a website can burn through tokens (usage) quickly. You may hit your plan's limit partway through the exercises, so run heavy jobs only when you need them. (For managing usage, see "Usage, context, and session management" later on.)

Extracting a design system

When building a web service, developers usually receive a design system made by a designer and build screens on top of it. With Claude Code you can run this process in reverse — pull just the design elements out of a site that already exists and turn them into a design system.

Requesting the extraction

Extract the design elements of this finished site
and build a separate design system from them.

What gets captured

It pulls only the design elements of the current site and defines them in a single document.

  • Color palette
  • Text (typography) styles
  • Components — button styles, layout styles
  • Animation effects

Why build one

Once you have a design system, you can keep stamping out future sites with the same design. It keeps the tone consistent when you develop an internal system or build a second or third site, and it is easy to hand over and share with colleagues.

Next step You can reuse a design system built this way as it is, but if you plan to "keep using it from now on," it is more convenient to turn it into a Skill. (Covered in the next document.)

Organizing web material — Hugging Face papers

Give it a single URL and Claude Code fetches that page's contents and organizes them for you. In this exercise we organize the Hugging Face Daily Papers (the list of papers that got the most upvotes that day).

How to ask

# Paste the Daily Papers URL from huggingface.co
https://huggingface.co/papers
# then follow with
Organize today's papers.

It doesn't stop at the list page

It opens each paper's page from the list, collects the abstracts, and organizes them by category into one file.

The Daily Papers list page does not carry the details of each paper. So Claude Code

  • visits each paper's individual page (WebFetch) from the list,
  • pulls the abstract from each page,
  • and organizes everything by category into a file.

At the time of the exercise, a total of 16 papers were organized by category, each with its content, into a single file.

Putting it to use Instead of opening papers one by one, it is far faster to pull the relevant papers in wholesale, have the AI do a first-pass analysis, and skim the result. This organized file feeds into the "paper showcase site" and the "paper analysis agent" later on.

The design system and paper digest you just built become the raw material for the next chapter, Extending — harden them into skills, attach plugins, and hand them to agents.
