System Files and rules

The vault holds not only notes but also system files that govern how the AI behaves. These files, carefully carved out by the instructor, are worth reading through once.

Stating the author and the model

  • The main author of the main vault is a human (me).
  • In the LLM wiki, which model wrote it is stated alongside my name. For example: "Opus 4.8 · effort X-high", "Fable", "Codex Fugu · Ultra", and so on.
  • Recording which model made a wiki lets you compare and optimize quality. Ingesting uses a lot of tokens and time, so it is best to collect only the material that really matters.

System files in the main vault

These include documents for Claude to read, documents for other agents to read, CMDS (context) related material, vault rules, writing and formatting rules, research topics, personas (brain dump), and more.

core-context in the LLM wiki

The LLM wiki uses a context file that holds what purpose you intend to use the wiki for. When you start onboarding, you edit core-context.md and fill in your name, affiliation, department, hobbies, tastes, and so on. Here too, instead of writing everything in one file, you optimize context by stating addresses like "tastes go in 취향.md, the specialist persona goes here".

.claude/rules — rules read like a constitution Markdown files in the rules folder inside the .claude folder are read first, the moment a session starts (and obeyed strictly, like a constitution). CLAUDE.md, by contrast, is consulted like a guide. So it is good to put editing rules, preferences, and important mandatory rules into rules.
