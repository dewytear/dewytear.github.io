Level 3 · Searching by meaning (semantic search, vector DB)

Levels 1 and 2 mostly need the words to match. But we often search with words different from the ones we remember. So Level 3 searches by meaning. That is semantic search, and its engine is the vector database.

Keyword search vs semantic search

The biggest difference is "is it the same word (=)" versus "is the meaning close (≈)".

Keyword search finds only the X that equals X; semantic search also finds the Y and Z close in meaning to X.

How does it search by "meaning" — embeddings and chunking

The principle goes like this. A document is split into small pieces (chunks), and each piece goes into an embedding model. The embedding model turns that piece into a coordinate (vector) in "meaning space." Pieces close in meaning gather near each other.

Pieces about the company sit over here, pieces about finance over there — meaning decides the spot. The cluster view in a tool like Qdrant is a visualization of that mass of coordinates.
Term note — Qdrant A leading vector DB that stores and searches vectors is Qdrant. It groups images and text by semantic similarity and shows them as clusters (that demo where "similar pictures bunch together"). Beyond it, Pinecone and Supabase are also used to implement semantic search.

The decisive limit — a chunk cannot see the "whole context"

People mistake a vector DB for "magic that pulls out anything exactly." That is not true. Search only pulls in a few similar chunks, so it is weak on questions that require seeing everything.

SituationWhat vector search doesWhy it is wrong
"Summarize the March 5 meeting"Retrieves only 5 chunks similar to "March 5 meeting summary"If the meeting was split into 20 chunks, it never sees the other 15, so key points go missing
"Which was the highest-revenue week?"Looks at only some chunks (say week 6) and answers "week 6 was the best"In reality weeks 14 and 19 were higher, but it never looked at those chunks
For questions that need the whole thing, it is more accurate to read that markdown in full and answer from it.
So when do vectors shine When you pull a very specific snippet out of a huge body of text. Example: there are 1,000 rules and you ask "what was rule 17 again?" — no need to read everything, just hand over the chunks around number 17. To push accuracy higher, attach metadata or use the hybrid search below.

Raising accuracy — hybrid search and reranking (one step further)

  • Hybrid search — combines semantic (meaning) and BM25 (keyword) scores so each covers the other's weakness. (BM25 also comes up in the LLM Wiki practice chapter's Query.)
  • Reranking — after candidates are picked, a more precise model reorders them.
  • Chunking strategy — how finely you split and how much you overlap drives the quality of the results.
Not everything has to be vectors You do not need to turn the whole Second Brain into vectors. For instance you can keep only the YouTube subtitle folder in a vector DB and leave context/, projects/, and decisions.md as plain markdown. Pick a different approach per folder depending on the kind of data and how it is used. Next comes Level 4 — linking by relationship.
