AI Traversal Guide — how to read this wiki by machine

This page is the contract for an external AI to consult this wiki first when given a task and analyze information by its relations. It uses the same data as the human-facing Knowledge Map / Knowledge Graph (9 views) / Graph Studio, but specifies which files to fetch, in what order, and how to traverse and analyze.

Read this first — a single file

The root llms.txt is the sign-post; actual traversal needs only one self-contained file:

  • data/knowledge-graph.json — every node (document) plus edges (related), concepts, raw URL, and stats in one file. No joining required to traverse the whole graph.

Optional: knowledge-index.ko.json (source index) · list (nav tree / paths) · doc-dates.json (dates).

If you need the full text in one go, fetch llms-full.txt — a whole-corpus dump of every document as plain text (for loading everything into context instead of traversing). To subscribe to new documents, use feed.xml (Atom, latest 30 — English at feed.en.xml, Japanese at feed.ja.xml). Crawler policy lives in robots.txt (an AI-crawler allowlist), and the full URL inventory in sitemap.xml. Content is licensed CC BY 4.0 — quote and reuse freely with attribution.

Node schema

Each element of nodes[] in knowledge-graph.json (the file's top-level schemaVersion is currently 2 — pin your consumer to it):

{
  "name": "welcome",                     // immutable logical id (node key)
  "title": "Welcome",
  "summary": "...",
  "section": "AI · Claude · Code · Introduction",   // World · Domain · System · …
  "concepts": ["Claude Code","CLI", "..."],          // join keys (human-curated)
  "url":   "https://dewytear.github.io/docs/ko/ai/claude/code/introduction/welcome",
  "route": "https://dewytear.github.io/#!welcome",   // human-facing SPA view
  "page":  "https://dewytear.github.io/p/welcome/",  // static snapshot (readable without JS)
  "related": [
    { "name":"ccb-what", "title":"...", "shared":["Claude Code"], "via":"concept" },
    { "name":"install",  "title":"...", "shared":[],              "via":"folder" }
  ],
  "relations": [                          // (optional) curated, directed semantic relations — separate from computed related
    { "target":"kgs-edges", "type":"prerequisite", "evidenceRef":"...", "source":"human" }
  ],
  "citedBy": ["skills", "tip-beginner"]   // (optional) documents whose body links here — citation backlinks
}

Traversal & analysis rules

  • Nodes = documents (keyed by name), edges = related. via:"concept" is a semantic link via rarity-weighted shared concepts (shared is the evidence); via:"folder" is same-System adjacency (so every doc has 2–4 edges).
  • Typed relations = relations (optional). Where related is a symmetric, computed edge, relations is a human-curated directed semantic relation — type is one of prerequisite, implements, example-of, evidence-for, supersedes, with evidenceRef as the justification. Direction is this node → target; derive reverse relations by scanning all nodes (only the forward direction is stored). It is a separate signal that does not overlap related — use both.
  • Citation backlinks = citedBy (optional). The documents that actually link this one from their body — a third connection layer, independent of related (computed from concepts) and relations (curated). Read this layer to see which documents are cited most and which piece leans on which.
  • Concepts are the join keys. Docs sharing a concept are related; rarer concepts are stronger (idf). Reverse-index concepts to gather a topic.
  • Fetch raw content via url — a static HTML fragment, no JS rendering needed. If you want a complete page with metadata (title, description, dates, license), use page instead (/p/<name>/, English at /p/en/<name>/, Japanese at /p/ja/<name>/): the same body plus <title>, description, canonical, hreflang and Article JSON-LD, with in-body links rewired to sibling snapshots so you can traverse without JS.
  • Hierarchy comes from section (the top 3 tiers of "World · Domain · System · Document") and stats.clusters (per-System counts / hubs). The first segment is the World (e.g. AI, Douzone), and per-World summaries live in stats.galaxies (the key name is a legacy of the early schema, kept because data keys are stable). Global most-frequent concepts are in stats.topConcepts.
  • Entry points: start from stats.hubs (most-referenced) and expand along related; stats.bridges are concepts spanning multiple Systems.
  • Field differences in the auxiliary indexes: knowledge-index.*.json is the same graph's source index but carries no url/route/page (those exist only in the graph file). The English and Japanese indexes may add sectionL, a localized display path — the join key is always the canonical section.
  • Downloadable assets: some documents ship a distribution file (e.g. a zip) under assets/<doc path>/<name>/<file> (first case: the skill zip of sks-dews-sourcegraph). Resolve relative assets/… links in body fragments against the site root.

Traversal example (2 hops)

1) fetch https://dewytear.github.io/data/knowledge-graph.json
2) pick nodes whose concepts overlap the query (or start from stats.hubs)
3) related[].name gives the 1-hop neighbors; their related gives the 2-hop set
4) fetch the url of interesting nodes and read the raw HTML fragments
5) use shared[] as the evidence for *why* two documents are connected

Honesty principle

Concepts and summaries are human/AI-curated, not scraped — so edges are few but trustworthy. A sparse link is not a defect, and different Worlds (e.g. AI ↔ DOUZONE) are meant to be loosely coupled. Analyze using only the relations that exist, citing via and shared.

The data files above (graph, indexes, llms, feeds, sitemap) regenerate whenever a document is added, so they always match the current graph (tools/build_ai_export.py). The prose of this guide itself is maintained by hand — when the schema changes, this page changes with it.
