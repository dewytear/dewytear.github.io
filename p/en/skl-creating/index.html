Creating Skills (Skill Engineering)

Once you have used them well, the thought "I want to make one myself" comes naturally. Making skills is called skill engineering, and a skill-making skill (skill-creator) that helps with it comes built in.

skill-creator — the meta skill

It is refined by running an A/B test loop, and is finished once it passes the benchmark.

As a skill for making skills, it comes with the following flow and subagents.

  • A create → evaluate → improve → benchmark loop.
  • evaluator, grader, comparison, and analysis subagents built in.
  • Drop in a script and say "turn this into a skill," and it builds a solid one through its own loop and testing (A/B).

Two categories

TypeWhat it coversAs models advance
Capability-boosting skillsPDF manipulation, document generation, complex file conversion, and the like. Built as scripts so they run deterministically and reliably.Once the model gets good at it, they may become unnecessary
Organization-internalizing skillsThe organization's responsibilities, workflows, owners, and so on. Our internal knowledge, which the agent does not know.Irreplaceable no matter how much models advance — keep building them
Emphasis — keep building organization-internalizing skills Make good use of capability-boosting skills now, but do not assume they will "last forever" — view them as something you can retire as models advance. Organization-internalizing skills, on the other hand, cannot be replaced no matter how far LLMs advance, because they cannot stand in for our organization's responsibilities, flows, and owners, so building them continuously is the heart of agent governance.
Distribution is easy One of the biggest advantages of skills is distribution. Register one in a shared repository, server, or community and version management and sharing become easy: copy "Get this skill" → say "install it" once, and it spreads across the whole organization. Editing the file on the spot and redistributing it is possible immediately too.
