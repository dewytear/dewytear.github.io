중급 — 세션을 시스템으로 만드는 11가지

초급 편이 세션 하나를 깨끗하게 굴리는 습관이었다면, 중급은 반복되는 것을 시스템에 옮기는 이야기입니다. 병렬로 조사시키고, 잘 나온 프롬프트를 스킬로 굳히고, CLAUDE.md를 라우터로 쓰는 법 — 공개 강좌의 팁 10~20번을 공식 문서와 대조해 정리했습니다.

문서 정보 (출처) · 뼈대: 공개 강좌 영상 — Claude Code 꿀팁 28가지의 중급 편(10~20)
· 검증·보강: Claude Code 공식 문서 대조 (2026-08-14 기준)

10. 서브에이전트를 병렬로 굴린다

서브에이전트란 메인 세션이 부하처럼 띄우는 별도의 에이전트입니다. 각자 자기만의 컨텍스트 윈도우를 쓰고 결과 요약만 메인에 보고하므로, 조사·검증처럼 읽을 것이 많은 일에 특히 좋습니다 — 읽은 분량이 메인 컨텍스트를 태우지 않습니다. "레퍼런스 10개 이상을 병렬 서브에이전트로 조사해 줘"라고 하면 여러 에이전트가 동시에 각자 다른 각도로 조사하고, 메인이 종합합니다. 병렬이라 시간도 절약됩니다.

각 서브에이전트가 태운 컨텍스트는 자기 것 — 메인 세션은 요약만 받아 가볍게 유지된다.

공식 문서: Run agents in parallel · Create custom subagents. 서브에이전트끼리는 대화하지 않습니다 — 서로 대화가 필요하면 고급 편의 에이전트 팀입니다.

11. 나만의 스킬을 만든다

스킬은 .claude/skills/ 폴더에 두는 재사용 프롬프트 파일입니다. 매번 복사해 붙이던 긴 지시를 한 번 정의해 두면, 설명(description)에 맞는 요청이 올 때 Claude가 알아서 꺼내 쓰거나 슬래시로 직접 부를 수 있습니다. 반복해서 시키는 일이 있다면 그게 스킬을 만들 신호입니다. 만드는 법은 간단합니다 — "방금 한 거 스킬로 만들어 줘"라고 하면 Claude가 만들어 줍니다. 예측 가능한 결과를 얻으려는 이런 장치를 통틀어 하네스(harness)라고 부르는데, 스킬이 그 대표적인 예입니다.

이 위키의 스킬 강의가 원리부터 보안까지 12편으로 다룹니다. 공식 문서: Skills

12. 서브에이전트에는 싼 모델을 쓴다

검색해서 텍스트를 읽어 오는 일에 최상위 모델은 낭비입니다. 서브에이전트를 시킬 때 "서브에이전트는 Haiku로 돌려 줘"라고 명시하면 됩니다 — 커스텀 서브에이전트 정의라면 model: haiku 필드로 고정할 수도 있습니다. 조사·수집은 빠르고 싼 모델에, 종합·설계 판단은 비싼 모델에 맡기는 분업이 토큰을 크게 아낍니다.

모델별 단가: 공식 Pricing 문서 — 집필 시점 기준 Haiku 4.5는 입력 $1/출력 $5(백만 토큰당)로 최상위 모델의 몇 분의 일입니다.

13. 세션이 끝나면 CLAUDE.md를 갱신한다 — 단 150~200줄 상한

이번 세션에서 새 관례가 생겼거나 방식이 바뀌었다면 CLAUDE.md에 반영해 두세요. 안 하면 다음 세션의 Claude는 그 변화를 모릅니다. 다만 CLAUDE.md는 매 세션 무조건 읽히는 파일이라 길어질수록 시작 컨텍스트를 태웁니다 — 갱신을 시킬 때 "150~200줄 상한으로"를 함께 말하면 Claude가 알아서 압축합니다. 공식 문서도 "회의 사이에 훑을 수 없으면 너무 긴 것"이라고 권합니다.

공식 문서: Memory — CLAUDE.md

14. CLAUDE.md를 라우터로 쓴다

13번의 상한과 "많은 정보를 주고 싶다"는 욕심을 동시에 만족시키는 방법입니다. 내용 전체를 CLAUDE.md에 넣는 대신, "이런 니즈가 있으면 이 파일을 봐라"라는 안내만 넣으세요. 예: "코드 구조가 궁금하면 docs/architecture.md를 읽어라." 필요할 때만 그 파일을 읽으러 가니, 맥락은 전달하면서 상시 컨텍스트는 아끼는 영리한 구조가 됩니다. 이것도 Claude에게 "이 안내를 CLAUDE.md에 라우터로 추가해 줘"라고 시키면 됩니다.

15. 이상하면 끝나기를 기다리지 말고 끊는다

진행 중에 방향이 틀렸다는 게 보이면 즉시 멈추세요(Esc). 그리고 "지금 의도는 이거였는데 왜 그렇게 했어?"라고 물으면 Claude가 자기 의도를 설명합니다. 거기서 방향을 고쳐 다시 진행시키면 됩니다. 끝날 때까지 기다렸다 고치는 것은 시간·토큰 낭비일 뿐 아니라, 잘못된 결과가 컨텍스트에 남아 이후 판단까지 오염시킵니다. 멈춤 버튼을 두려워할 이유가 없습니다.

16. 닦달한다 — 그리고 잘 나오면 기록한다

첫 결과물이 마음에 안 드는데 어떻게 고칠지 모르겠다면, 추상적으로라도 다시 시키세요 — "더 고급스럽게", "완성도를 높여 줘", "아예 다른 관점으로 새로 해 봐". 첫 시도가 아니라는 맥락이 있는 상태라 두 번째는 적중률이 훨씬 오릅니다. 대부분 한 번 해 보고 포기하는데, 두세 번 닦달해 보면 놀랄 때가 많습니다. 그리고 원하는 결과가 나온 순간이 기록할 순간입니다 — "이 결과물 좋아, 스킬로 만들어 줘" 또는 "CLAUDE.md에 반영해 줘". 기록하지 않으면 다음에 같은 과정을 다시 밟습니다.

17. /rewind로 시간을 되돌린다

중간 결과가 잘못됐을 때 "다시 되돌려 줘"라고 말로 시키면 되돌리는 과정에서 또 오류가 날 수 있습니다. 대신 /rewind를 쓰세요 — 체크포인트 목록에서 시점을 고르면 그 이후의 파일 수정이 통째로 되돌아갑니다. 코드와 대화를 각각 되돌릴지도 고를 수 있습니다.

공식 문서: Checkpointing — 세션 중 수정이 자동으로 체크포인트로 쌓입니다.

18. 훅으로 알림을 받는다

훅(hook)은 Claude Code의 특정 시점 — 작업 완료, 승인 대기 등 — 에 자동 실행되는 명령입니다. "세션 작업이 끝날 때마다 소리로 알림 받게 훅 세팅해 줘"라고 하면 Claude가 설정 파일에 만들어 줍니다. 세션을 하나만 돌릴 땐 필요 없지만, 여러 프로젝트·여러 세션을 병렬로 굴리기 시작하면 어디서 뭐가 끝났는지를 알려 주는 이 장치가 필수가 됩니다. 간단하게는 preferredNotifChannel을 terminal_bell로 두는 방법도 있습니다.

공식 문서: Automate actions with hooks — 이 위키의 Hooks 소개도 참고.

19. Claude에게는 눈이 있다 — 이미지를 준다

에러 메시지, 마음에 드는 웹사이트, UI 화면 — 말로 설명하기 어려운 것은 스크린샷을 찍어 그대로 붙이세요. 터미널·데스크톱 앱 모두 이미지를 끌어다 놓거나 붙여넣을 수 있고, Claude가 이미지를 읽고 이해합니다. 에러 화면을 캡처해 던지는 것이 에러 문구를 손으로 옮겨 적는 것보다 빠르고 정확합니다.

20. 스크린샷으로 템플릿을 만든다

19번의 응용입니다. 레퍼런스 삼고 싶은 디자인 — 카드 뉴스 레이아웃, 색감이 좋은 페이지 — 을 캡처해 주고 "이 이미지를 참고해서 템플릿을 만들어 줘"라고 명시하세요. 핵심은 그대로 베끼는 게 아니라 색감·레이아웃의 구조를 뽑아 재사용 가능한 템플릿으로 만드는 것입니다.
