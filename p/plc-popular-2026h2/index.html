2026년 하반기 인기 플러그인 — 공식 디렉터리 상위권과 쓰는 법

세 줄 요약

  • 2026년 10월 23일 기준 공식 Claude 플러그인 디렉터리(271개)의 설치 1·2위는 Frontend Design(약 113만)과 Superpowers(약 101만)다. 3위 이하는 Code Review·Context7·Code Simplifier·Playwright·GitHub 순이다.
  • 상위 15개 중 10개는 Anthropic이 만들었다. 나머지 다섯은 Superpowers와 외부 서비스를 붙이는 MCP 플러그인(Context7·Playwright·GitHub·Vercel)이다.
  • 플러그인은 스킬·명령·에이전트·훅·MCP 서버를 한 번에 설치하는 묶음이다. 상위권은 어느 부품을 쓰느냐에 따라 쓰는 법이 크게 다르다.

플러그인은 Claude Code에 기능 묶음을 한 번에 설치하는 단위다. 한 플러그인에 스킬(필요할 때 읽는 지침), 슬래시 명령, 서브에이전트, 훅(정해진 시점에 자동으로 도는 스크립트), MCP 서버(외부 서비스를 도구로 붙이는 연결)가 섞여 들어간다. 각 부품이 무엇인지는 확장 기능 — Skills · MCP · Hooks에, 설치 화면은 확장 — 스킬·플러그인·에이전트에 정리했다. 이 글은 공식 디렉터리의 설치 수 상위 플러그인을 골라, 각 플러그인의 원본 파일을 직접 읽고 쓰는 법을 정리한다.

플러그인은 무엇을 담나

같은 "플러그인"이라도 속은 다르다. 상위권의 구성을 원본 저장소의 파일 구조로 확인하면 아래와 같다. 어느 칸에 점이 찍혔는지가 쓰는 법을 정한다. 명령이 있으면 직접 부르고, 스킬이나 훅만 있으면 알아서 돌며, MCP만 있으면 새 도구가 생긴다.

3. Code Review — 네 에이전트가 따로 보고, 확신 80 이상만 남긴다

무엇을 하나. 풀 리퀘스트(PR) 브랜치에서 /code-review를 부르면, 먼저 리뷰할 필요가 있는지 본다. 닫혔거나 초안이거나 사소하거나 이미 리뷰한 PR은 건너뛴다. 그다음 저장소의 CLAUDE.md 지침을 모으고 변경을 요약한 뒤, 에이전트 넷을 동시에 띄운다. 둘은 CLAUDE.md 준수를, 하나는 바뀐 코드 속 버그를, 하나는 git 이력(blame)으로 맥락상 문제를 본다. 찾은 문제마다 0~100의 신뢰도를 매기고 80 미만은 버린다.

/plugin install code-review@claude-plugins-official

# PR 브랜치에서
/code-review
## Code review
Found 3 issues:
1. Missing error handling for OAuth callback (CLAUDE.md says "Always handle OAuth errors")
   https://github.com/owner/repo/blob/abc123…/src/auth.ts#L67-L72

어디서 쓸모 있나. 리뷰 봇이 귀찮은 이유는 대개 오탐이다. 이 플러그인은 일부러 여러 시각으로 넓게 찾은 뒤, 확신이 낮은 것을 버려서 사람이 읽을 코멘트만 남긴다. 팀의 CLAUDE.md를 기준으로 삼으므로, 규칙을 잘 적어 둔 저장소일수록 리뷰가 날카로워진다.

4. Context7 — 최신 문서를 컨텍스트에 끌어온다

무엇을 하나. Upstash가 운영하는 원격 MCP 서버를 붙인다. 플러그인 안에는 서버 주소(https://mcp.context7.com/mcp) 한 줄만 있어 로컬에 Node.js를 깔 필요가 없다. 도구는 둘이다. resolve-library-id가 "next.js" 같은 이름을 Context7의 라이브러리 ID로 바꾸고, query-docs가 그 라이브러리의 해당 버전 문서와 코드 예시를 원본 저장소에서 가져온다.

/plugin install context7@claude-plugins-official

"Next.js 16에서 proxy 설정은 어떻게 해? use context7"
→ resolve-library-id("next.js") → query-docs(…, "proxy")
→ 지금 버전 문서를 읽고 답함

어디서 쓸모 있나. 모델은 학습 시점 이후 바뀐 API를 모른다. 빠르게 바뀌는 프레임워크를 쓸 때 옛 문법으로 코드를 짜는 일을 막는다. 질문 끝에 use context7을 붙이는 것이 원본 문서가 권하는 사용법이다.

5. Code Simplifier — 방금 고친 코드를 다듬는 에이전트

무엇을 하나. 서브에이전트 하나(code-simplifier, Opus 지정)로 된 플러그인이다. 따로 지시하지 않으면 최근에 바뀐 코드만 본다. 첫 원칙은 동작을 바꾸지 않는 것이고, 그 안에서 중첩을 줄이고, 겹치는 코드와 쓸데없는 추상화를 걷어 내고, 이름을 분명히 한다. 짧은 코드보다 읽히는 코드를 고르라고 적혀 있고, 중첩 삼항 연산자는 금지한다. 기준은 프로젝트의 CLAUDE.md다.

/plugin install code-simplifier@claude-plugins-official

"방금 작업한 파일들 정리해 줘"   ← code-simplifier 에이전트에 위임

어디서 쓸모 있나. 에이전트가 기능을 빨리 붙이고 나면 코드가 덕지덕지해지기 쉽다. 커밋 전에 한 번 돌려 정리하는 용도다. 범위를 최근 변경으로 묶어 두어서 오래된 코드를 함부로 뒤집지 않는다.

6. Playwright — Microsoft의 브라우저 자동화 MCP

무엇을 하나. npx @playwright/mcp@latest로 로컬 MCP 서버를 띄워 Claude가 웹페이지를 열고, 누르고, 입력하고, 화면을 찍게 한다. 픽셀이 아니라 접근성 트리로 페이지를 읽어서, 화면을 보는 모델이 없어도 움직인다.

/plugin install playwright@claude-plugins-official

"로그인 페이지에서 잘못된 비밀번호를 넣으면 어떤 오류가 뜨는지 확인해 줘"

어디서 쓸모 있나. 끝에서 끝까지(E2E) 테스트와 화면 확인이다. 스킬 순위의 agent-browser와 하는 일이 겹친다. Microsoft 문서도 코딩 에이전트에게는 큰 도구 스키마와 긴 접근성 트리를 싣는 MCP보다 CLI와 스킬 조합이 토큰을 덜 쓴다고 적고, 별도의 Playwright CLI를 안내한다. 대화형으로 페이지를 살펴볼 때는 MCP가, 긴 코딩 세션 안에서는 CLI 쪽이 맞다.

7. GitHub — 저장소를 대화로 다룬다

무엇을 하나. GitHub이 운영하는 원격 MCP 서버(api.githubcopilot.com/mcp/)를 붙인다. 이슈 만들기, PR 관리, 코드 리뷰, 저장소 검색처럼 GitHub API가 하는 일을 도구로 쓴다. 인증은 환경 변수 GITHUB_PERSONAL_ACCESS_TOKEN의 개인 접근 토큰으로 한다.

export GITHUB_PERSONAL_ACCESS_TOKEN=…   # 필요한 권한만 준 토큰
/plugin install github@claude-plugins-official

"지난주에 닫힌 이슈 중 버그 라벨 붙은 것만 정리해 줘"

어디서 쓸모 있나. 터미널과 브라우저를 오가지 않고 이슈·PR 작업을 처리한다. 토큰의 권한이 곧 에이전트의 권한이므로, 쓰기 권한은 필요한 저장소에만 준다.

8. CLAUDE.md Management — 프로젝트 기억을 최신으로

무엇을 하나. 두 도구가 들어 있다. 스킬 claude-md-improver는 저장소의 모든 CLAUDE.md를 찾아 지금 코드와 맞는지 채점한다. 위 화면처럼 명령·워크플로, 구조 설명, 비자명한 패턴, 간결성, 최신성, 실행 가능성을 따로 매기고 고칠 곳을 제안한다. 명령 /revise-claude-md는 세션을 마칠 때 이번 작업에서 배운 것을 CLAUDE.md에 적는다.

/plugin install claude-md-management@claude-plugins-official

"내 CLAUDE.md가 최신인지 점검해 줘"   ← claude-md-improver 스킬 발동
/revise-claude-md                     ← 세션에서 배운 것 기록

어디서 쓸모 있나. CLAUDE.md는 코드가 바뀌면 조용히 낡는다. 이 위키도 같은 문제를 규칙과 검증기로 다룬다(CLAUDE.md의 10계명). 정기 점검은 스킬로, 세션 끝의 기록은 명령으로 나눈 설계가 실용적이다.

9. Feature Dev — 7단계로 기능을 만든다

무엇을 하나. /feature-dev 명령 하나가 일곱 단계를 이끈다. 에이전트 셋(code-explorer·code-architect·code-reviewer)이 단계마다 나뉘어 일한다.

단계하는 일
1 Discovery무엇을 왜 만드는지, 제약은 무엇인지 확인
2 Codebase Explorationcode-explorer 2~3개를 동시에 띄워 비슷한 기능·구조·UI 패턴 조사
3 Clarifying Questions조사 뒤에 남은 모호한 점을 질문
4 Architecture Designcode-architect가 설계안 제시
5 Implementation승인된 설계대로 구현
6 Quality Reviewcode-reviewer가 품질 검토
7 Summary한 일과 남은 일 정리
 
/plugin install feature-dev@claude-plugins-official
/feature-dev OAuth로 사용자 인증 추가

어디서 쓸모 있나. 낯선 코드베이스에 기능을 붙일 때 바로 코드부터 쓰는 실수를 막는다. 질문 단계가 탐색 뒤에 있다는 점이 핵심이다. 코드를 먼저 읽었기 때문에 쓸데없는 질문이 줄어든다.

10. Security Guidance — 세 번 거르는 보안 검사

무엇을 하나. 훅으로 도는 보안 검사다. Claude가 만든 코드를 세 시점에서 거른다. 가벼운 검사는 자주, 무거운 검사는 드물게 도는 구조다.

/plugin install security-guidance@claude-plugins-official
# 필요: Claude Code 2.1.144 이상, Python 3.8 이상
# 설정은 모두 환경 변수(선택). 기본값으로 바로 동작

어디서 쓸모 있나. 사람이 리뷰하기 전에 Claude가 스스로 고치게 만드는 데 있다. 두 번째 층은 턴이 끝날 때 diff를 검토해 심각한 문제를 Claude에게 돌려주므로, 사용자가 답을 보기 전에 수정이 끝난다. 명령이 없으니 설치만 해 두면 된다.

13. Ralph Loop — 끝날 때까지 같은 프롬프트를 다시

무엇을 하나. 개발자 Geoffrey Huntley가 “Ralph는 Bash 루프다”라고 설명한 기법을 Claude Code 세션 안에서 구현했다. 바깥에 셸 루프를 두는 대신 Stop 훅이 Claude의 종료 시도를 막고 같은 프롬프트를 다시 넣는다. 프롬프트는 그대로지만 이전 작업은 파일과 git 이력에 남으므로, Claude는 매번 자기가 남긴 결과를 읽고 이어 간다.

/plugin install ralph-loop@claude-plugins-official

/ralph-loop "할 일 REST API를 만들어라. CRUD·입력 검증·테스트 포함.
끝나면 <promise>COMPLETE</promise>를 출력" --completion-promise "COMPLETE" --max-iterations 50
/cancel-ralph   # 중간에 멈추기

어디서 쓸모 있나. 테스트 통과처럼 끝이 분명한 일을 밤새 맡길 때다. 반대로 끝 조건이 흐린 일은 반복만 늘린다. --max-iterations로 상한을 꼭 둔다.

고를 때 볼 것

  • 부품을 먼저 본다. 훅이 든 플러그인(Security Guidance·Ralph Loop)은 설치만 해도 매 턴 동작한다. 명령만 든 플러그인은 부를 때만 돈다.
  • MCP 플러그인은 권한이 바깥으로 이어진다. GitHub처럼 토큰을 쓰는 플러그인은 토큰의 권한이 곧 에이전트의 권한이다.
  • 같은 일을 하는 스킬과 비교한다. 브라우저 자동화는 Playwright 플러그인과 agent-browser 스킬이 겹친다. 1·2위가 사실상 스킬이고, Microsoft 문서도 코딩 에이전트에게는 CLI와 스킬이 토큰을 덜 쓴다고 적었다. 긴 작업 세션이라면 가벼운 쪽부터 본다.

사실검증 노트

설치 수와 만든 곳, 디렉터리의 플러그인 수(271개)는 2026-10-23(KST) claude.com/plugins 페이지에 실린 데이터를 직접 읽었다. 숫자는 매일 바뀌는 누적값이다. 각 플러그인의 구성(스킬·명령·에이전트·훅·MCP)과 동작·명령은 Anthropic의 공식 마켓플레이스 저장소 anthropics/claude-plugins-official을 내려받아 plugin.json·README·명령·에이전트·훅 파일을 직접 읽어 정리했고, Context7은 upstash/context7, Playwright는 microsoft/playwright-mcp의 README를 함께 읽었다. Code Review의 에이전트 넷과 신뢰도 80 기준, Security Guidance의 세 층과 요구 버전, Feature Dev의 일곱 단계, Ralph Loop의 Stop 훅 구조는 해당 README의 설명이다. 카드 이미지는 원본 plugin.json의 이름과 설명을 바꾸지 않고 이 위키가 렌더한 것이며(긴 설명은 …로 줄임), Context7 표지와 CLAUDE.md Improver 실행 화면은 각 저장소에 커밋된 파일을 라이선스에 따라 실었다. Ralph 기법의 이름을 붙인 개발자는 플러그인 README가 인용한 개념 제안자라 이름을 적었고, 그 밖의 저장소 작성자 개인의 이름은 적지 않았다.
