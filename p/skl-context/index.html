컨텍스트 윈도우와 도구의 문제

스킬의 원리를 이해하려면 컨텍스트 윈도우부터 알아야 합니다.

컨텍스트 윈도우

컨텍스트 윈도우는 LLM에 입력되는 입력의 크기입니다. (출력이 다시 입력에 들어가며 이어지는 구조라 출력도 포함됩니다.) 여기에는 사용자 질문뿐 아니라 다음이 모두 담깁니다.

  • 기본 정보(너는 누구고, 오늘 며칠이고, 무엇을 하고 무엇은 하면 안 되는지)
  • 지시문 · 퓨샷 예시 · 출력 형식 · 맥락 · 메모리
  • 도구 정의 · 채팅 기록(길어질수록 계속 추가)

예전 LLM은 컨텍스트가 2K~8K(GPT-3 약 2K, GPT-4 초기 8K)에 불과했지만, 지금 Claude Code에서 쓰는 모델은 기본 200K, 일부 모델(Sonnet 4.6·Opus 4.6 이후 등)은 1M(백만) 토큰까지 받습니다. 하지만 크다고 마냥 좋은 게 아닙니다. 컨텍스트가 차기 시작하면 LLM이 불안해져, 일을 안 하려 하거나 이상하게 끝내 버립니다.

clear · compact — 책상 정리 Claude Code의 /clear·/compact 는 지금의 컨텍스트를 줄이거나 비워 새 작업을 준비하는 명령입니다. 책상이 어질러진 채 일하는 것과 싹 정리하고 시작하는 것의 차이라고 보면 됩니다.

도구가 컨텍스트를 잡아먹는다

스킬도 결국 도구의 일종입니다. 그런데 도구 하나를 열어 보면 함수·인자·사용 시점·단위 등이 적힌 복잡한 JSON 스펙입니다. 이게 하나하나 꽤 커서, 도구가 몇 개만 넘어가도 컨텍스트가 터지려 합니다. MCP·커넥터를 여러 개 연결하다 보면 "더 이상 연결할 수 없습니다"가 뜨는 이유가 이것입니다.

트렁크 비유 도구는 자동차 트렁크와 같습니다. 크기가 제한적이라 캠핑 도구를 다 넣을 수 없습니다. 선택지는 둘 — 더 큰 트렁크를 사거나, 짐을 최대한 줄이거나. 코딩 에이전트는 후자를 택해 도구를 여섯 개로 줄이고 실행 환경을 함께 주는 방식으로 문제를 풀었고, 그 위에서 스킬이 등장했습니다.
