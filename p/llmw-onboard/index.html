실습과 철학 — 온보딩부터 운영까지

스타터 킷에는 온보딩 스킬이 들어 있어, /onboard(또는 "온보딩 해줘") 한마디로 개인 맞춤 세팅이 시작됩니다.

릴리스 받기부터 그래프 뷰로 볼트를 여는 순간까지 — /onboard 한 번으로 개인 맞춤 세팅.

준비 — 릴리스 받기

  • 강의에서 안내한 LLM Wiki 페이지(GitHub 레포지토리) 에서 최신 릴리스(예: 1.7.0) 파일을 다운로드합니다.
  • zip을 풀면 폴더 하나(= 위키 볼트, 곧 Obsidian 볼트) 가 생깁니다.
  • 실제로 쓸 경로(내 문서·바탕화면 등)에 이 폴더를 먼저 위치시킵니다.

온보딩 실행

# 폴더 경로 복사 — Windows: Ctrl+Shift+C / Mac: Cmd+Option+C
# 그 폴더에서 Claude Code 실행 후
/onboard        # 또는 "온보딩 해줘"

정해진 질문들이 이어집니다 — 어떤 목적으로 쓰는가, 뭐라고 불러야 하는가, 메인 볼트와 연결할 것인가 등. 컨텍스트를 많이 줄수록 더 똑똑해지므로 성의껏 답합니다. (약 5분 소요)

  • 메인 볼트가 있으면 연결 — 인공지능이 위키를 만들 때 내가 썼던 노트들을 참조합니다.
  • 없으면 단독으로 시작해도 됩니다.

Obsidian에서 볼트 열기

  1. Obsidian 왼쪽 아래 → 볼트 관리 → Open folder as vault 로 그 폴더를 엽니다.
  2. 왼쪽 아래에 내 폴더명이 맞는지 확인합니다.
  3. Ctrl/Cmd + G 로 그래프 뷰를 열면 임베딩된 노트 관계가 보입니다.
깔끔하게 시작하려면 예시 데이터 없이 시작하고 싶으면 concept·entity·article 폴더의 예시 파일만 지우면 됩니다. 코덱스용 파일도 준비돼 있지만, Claude Code에서 쓰는 편이 더 유리합니다.

세 가지 핵심 동작 — Ingest · Query · Lint

LLM 위키의 중요한 세 가지 동작입니다. (Karpathy가 제시한 개념)

세 동작이 순환하고, 쿼리는 BM25 → 벡터 → 가설 검증으로 단계적으로 강해집니다.

1) Ingest — 소화·흡수

하나의 아티클/개념을 청크로 나눠, 인공지능도 사람도 읽기 좋은 카드로 만드는 작업입니다. 로우 자료를 넘기면 출처 기반의 위키 카드가 생성됩니다.

/ingest        # 로우 소스를 위키 카드로

2) Query — 꺼내 쓰기

모아 놓기만 하면 소용없으니, 쿼리로 꺼내 씁니다. 일반 에이전트는 정규표현식(단어 빈도·매칭) 으로만 검색하지만, 여기서는 QMD(마크다운 쿼리) MCP 로 세 가지 검색을 단계적으로 씁니다.

방식언제
BM25 (렉시콘)사용자가 명확한 단어를 명시할 때 — 빈도 높은 단어로 검색.
벡터 서치애매할 때 — 유사 개념까지 가져옴("물 마시고 싶어" → 물컵).
가설 검증(hypothetical)사용자 수준이 지식 수준보다 낮을 때 — LLM이 질문을 재해석해 키워드를 만들어 재검색.

뒤로 갈수록 시간이 더 걸립니다. 파일을 정확히 아는 상황이면 그 주소를 직접 주는 것이 가장 빠릅니다. 결과는 query 폴더에 정리되며, 어떤 목적으로 만든 문서인지 다시 꺼내 쓸 수 있게 출처 기반으로 남습니다.

3) Lint — 유지보수

메인터넌스 작업입니다. 새 인제스트 때 기존 노트(예: A 개념)가 새 노트(A′)와 연관돼 낡았으면 함께 업데이트합니다. /lint 로 전반적인 유지보수를 돌려, 언제든 인용 가능한 최신성을 유지합니다. (감사 audit·검증 verify 스킬도 함께)

요약 Ingest(로우 자료 → 카드) · Query(BM25·벡터·가설검증으로 꺼내 쓰기) · Lint(최신성 유지) — 이 세 축으로 살아 있는 지식 베이스를 굴립니다.

웹 클리퍼와 인박스, Query 실전

웹 기사를 클리퍼로 인박스에 모아 /inbox로 분류하고, 인제스트한 뒤 /query로 꺼내 씁니다.

Obsidian 웹 클리퍼

크롬 확장 Obsidian Web Clipper 로 웹 아티클을 클리핑해 볼트의 인박스에 넣습니다. 강사는 캡처 규칙(JSON 템플릿)을 위키 볼트에 넣어 두었습니다.

  • 설정 → 일반 옵션의 볼트 저장소에 볼트명들을 등록하면 어느 볼트로 보낼지 지정할 수 있습니다.
  • 템플릿(JSON)을 임포트하고, Web Article 템플릿을 맨 위로 올립니다(먼저 발동). x.com·youtube 등 주소에 따라 트리거되는 템플릿도 있습니다.
  • 캡처하면 미리 지정한 0.2 inbox/article 같은 폴더에 저장됩니다.

인박스 스킬 — 모아서 분석

/inbox        # 인박스에 모아둔 자료를 분석·주제별로 묶어 제안

여러 개를 미리 모아 두고 /inbox 를 돌리면, "5개 중 3개는 같은 결이니 같이 인제스트할까?" 처럼 주제별로 나눠 제안합니다.

토큰 팁 — 원본 스크래핑

인제스트할 때 링크만 주면 AI가 원본을 긁어서 시작해야 해 토큰이 더 듭니다. 웹 클리퍼로 미리 스크래핑해 원본을 확보한 뒤 시작하면 토큰을 아낍니다.

Query 실전

/query LLM 위키 볼트의 학술적 가치를 정리해줘.
나중에 레퍼런스 매니저로 서지정보를 인용할 거야.

위키 볼트에서 부족하면 메인 볼트까지 검색해 가져오게 되어 있고, 내가 어떻게 질문했는지도 함께 기록됩니다. 결과에는 답변뿐 아니라 Obsidian 메타데이터를 어떻게 설계하면 좋은지(author·created·source·category 등) 까지 추천해 줍니다.

논문은 통째로 넣지 말 것 논문 원문을 전부 인제스트하기보다, 초록(abstract) 정도로 기본 개념만 알게 하고 원문의 위치를 남기는 것이 좋습니다. 중요 키페이퍼만 풀로 읽히고, 내 코멘터리·실험 맥락을 함께 넣으면 더 유용합니다.

활용과 철학 — 읽는 능력과 두 볼트 운영

위키는 재료 저장 공간

LLM 위키는 재료 저장 공간입니다. 여기서 만들어진 요리(산출물) — 커리큘럼·강의안 등 — 은 메인 볼트로 넘어옵니다. 산출물이 너무 커서 서빙이 힘들면 별도의 dev(개발) 폴더에서 관리합니다. (HTML·node_modules 등 무거운 파일은 볼트 밖에서 관리 — 렌더링 저하 방지)

가장 중요한 역량 — 읽는 능력

AI 시대에 가장 중요한 역량은 읽는 능력입니다. 에이전트에게 시켜 놓고 안 읽기 쉽지만, 내가 읽어야 제대로 시킬 수 있습니다. 강사는 인공지능을 세팅하는 목적 자체를 "내가 읽을 시간을 확보" 하는 데 둡니다. 위키의 concept·entity·guide·query 카드는 모두 사람도 읽기 좋게 구성됩니다.

왜 두 볼트를 나누나

저자 명시·.claude 규칙이 메인 볼트(내가 관리)와 LLM 볼트(AI가 알아서)에서 서로 다릅니다. 하나로 합치면 에러와 오염된 정보가 많아져, 나누는 편이 낫습니다. 기존 볼트의 일부를 위키로 옮기고 싶다면, 스타터 킷 볼트에서 에이전트를 켜고 기존 볼트 주소를 준 뒤 "위키로 만들 만한 것 옮겨줘" 로 마이그레이션할 수 있습니다.

마무리 — AI 지식에 직접 붙어 있어라

리더는 두 부류로 나뉩니다 — "더 알려줘"와 "멤버 시키면 되지, 내가 왜 배워?". 그런데 내 멤버(파트너)의 지식 상한선이 곧 나의 상한선이 됩니다. 그래서 우리는 AI 지식에 직접 붙어(attach) 있어야 하고, 이를 위한 나의 지식 저장소가 필요합니다. 강사는 그중 Obsidian을 가장 좋은 도구로 꼽습니다.

Q&A 요점 · 공동 볼트 — 공식 Sync / osync 로 셀프 호스팅(나스·클라우드·도커). 동시 편집도 1~2초 내면 대체로 안전.
· PDF 스크랩 — 정합성이 중요하면 변환, 컨텍스트만 필요하면 파이썬으로 마크다운화가 토큰 절약.
· 메타데이터 필드 는 지식을 꺼내 쓸 사람이 정한다 — 어떤 분류로 꺼낼지에 맞춰 키-값을 설계.
· 볼트 규모 — 메타데이터(type 등)로 필터하면 만 개 노트도 문제없이 인덱싱·접근 가능.
