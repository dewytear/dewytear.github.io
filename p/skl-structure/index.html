SKILL.md 구조와 디스크립션

스킬 폴더의 중심은 SKILL.md 파일이고, 그 밖에 reference·examples·scripts 같은 번들 파일이 함께 있습니다.

프론트매터 (메타데이터)

한 파일 안에서 프론트매터는 항상, 본문은 호출될 때 로드됩니다.

SKILL.md 맨 위에는 YAML 프론트매터가 있습니다. 예를 들어 PDF 스킬이라면:

# SKILL.md 프론트매터 (항상 로딩되는 부분)
name: pdf
description: PDF 텍스트/테이블 추출, 병합, 분할 등에 사용하는 툴킷

처음 로딩될 때는 이 프론트매터만 올라오고, 실제 설명서(본문)는 호출될 때 로딩됩니다.

디스크립션 작성이 중요하다

스킬은 /스킬명 으로 명시적 호출할 수도 있고, "PDF에서 텍스트 추출해봐" 처럼 말하면 프론트매터를 근거로 자동 발동하기도 합니다. 그래서 description 을 잘 써야 합니다.

  • 호출이 안 되는 경우 — 예: PDF 편집 기능이 있는데 description에 "읽는 데 사용"이라고만 적혀 있으면, 편집 요청 시 호출되지 않을 수 있음.
  • 불필요하게 호출되는 경우 — PDF와 무관한데 갑자기 발동.

그래서 호출이 잘 되는지, 쓸데없이 발동하지 않는지 테스트해 보고, 직접 만들 때는 description을 공들여 작성해야 합니다.

지침 안에서 파일 참조

본문(마크다운) 지침 안에는 "이럴 때는 이 파일을 봐라" 처럼 다른 파일을 참조하도록 적어 둘 수 있습니다. 이는 앞서 본 JSON 툴 스펙과 다르게, 사람에게 알려주듯 자연어로 "명령 실행하는 방법" 정도를 적는 것입니다.

왜 read/실행만으로 동작하나 코딩 에이전트는 파일 읽기·쓰기·편집·찾기 도구가 기본 탑재되어 파일 시스템을 자유롭게 다룹니다. 그래서 지침에 "이 파일을 읽어라"만 있어도 에이전트가 알아서 로딩합니다. 스킬 내용과 코딩 에이전트의 도구가 어떻게 상호작용하며 읽는지를 상상하며 보면 이해가 쉽습니다.
