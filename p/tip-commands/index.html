명령어 20선 — 시작·작업·리뷰·실행 순서로 익히는 슬래시 명령어

Claude Code가 요즘 답답하게 느껴진다면 모델을 탓하기 전에 확인할 게 있어요. 입력창에 /를 치면 나오는 슬래시 명령어입니다. 같은 모델이라도 이 명령어를 아느냐 모르느냐에 따라 일하는 방식이 꽤 달라져요. 예를 들어 Opus 5.5의 기본 노력 수준은 다섯 단계 중 가운데인 medium인데, 공식 문서는 버그 수정처럼 검증이 중요한 일에는 high를 권합니다. 이걸 모르면 어려운 일을 계속 medium에 맡기게 돼요.

막히는 지점은 대개 비슷합니다. 대화가 길어지면 답이 흐려지고, 창 하나에서 한 가지 일만 기다리고, 다 됐다는데 막상 돌려 보면 안 돌아가요. 이 문서는 그 세 가지를 푸는 명령어 20개를 쓰는 순서대로 네 묶음으로 나눠, 각각 무엇을 하는지와 바로 따라 칠 수 있는 예제를 붙였습니다.

문서 정보 (출처) · 근거: Claude Code 공식 문서 (2026-11-24 기준) — 명령어는 버전·요금제·환경에 따라 목록에 안 보일 수 있습니다

먼저, 명령어를 치는 법

  • 입력창에 /를 치면 쓸 수 있는 명령어 목록이 뜨고, 글자를 더 치면 목록이 좁혀져요.
  • 명령어는 메시지 맨 앞에 있어야 인식됩니다. 뒤에 쓴 글은 그 명령어의 인수로 그대로 넘어가요.
  • Claude가 답하는 중에 명령어를 보내면 대기열에 들어갔다가 그 턴이 끝난 뒤 실행돼요. /tasks처럼 기다리지 않고 바로 열리는 것도 있습니다.
묶음은 외우기 쉽게 나눈 것이고 순서를 꼭 지킬 필요는 없어요. 처음이라면 문서 끝의 네 개(/init·/run·/code-review·/verify)부터 써 보세요.

① 시작 — 안내서, 모델, 노력 수준, 조언자, 공간

1. /init — 프로젝트 안내서 만들기

새 폴더에서 치면 Claude가 코드를 훑어보고 CLAUDE.md를 만들어요. 무슨 프로젝트인지, 어떻게 실행하는지, 지킬 규칙이 무엇인지가 담깁니다. Claude Code는 대화를 시작할 때마다 이 파일을 읽기 때문에 "이건 Next.js 프로젝트야"를 매번 설명할 필요가 없어져요.

/init          # CLAUDE.md 초안 생성
/memory        # 만들어진 CLAUDE.md를 열어 다듬기

공식 문서는 CLAUDE.md를 파일당 200줄 아래로 짧게 유지하라고 권해요. 길수록 컨텍스트를 더 쓰고 지시도 덜 지켜집니다. 자세한 작성법은 CLAUDE.md 십계명에 있어요.

2. /model — 모델 바꾸기

혼자 치면 선택 메뉴가 열리고, 이름을 붙이면 바로 바뀝니다. 고른 모델은 이후 새 대화의 기본값으로 저장돼요. 이번 대화에서만 바꾸고 싶으면 목록에서 s를 누릅니다.

/model             # 선택 메뉴 열기 (좌우 화살표로 노력 수준도 조절)
/model opus        # Opus로 즉시 전환
/model opusplan    # 계획은 Opus, 실제 수정은 Sonnet
줄임 이름어울리는 일
fable가장 어렵고 오래 걸리는 작업 (접근 권한 필요)
opus복잡한 추론이 필요한 작업
sonnet일상적인 코딩
haiku빠르고 단순한 작업
opusplan플랜 모드에서는 Opus, 실행으로 넘어가면 Sonnet

3. /effort — 얼마나 깊이 생각할지

노력 수준(effort)은 모델이 답하기 전에 추론에 토큰을 얼마나 쓸지 정하는 값이에요. low·medium·high·xhigh·max 다섯 단계이고, Fable 5.2·Opus 5.5·Sonnet 5.5·Haiku 5.5의 기본값은 medium입니다.

/effort high       # 버그 수정처럼 검증이 중요한 일
/effort max        # 보안 취약점 찾기 같은 정말 어려운 문제 (이번 대화에만 적용)
/effort status     # 지금 수준 확인
수준공식 문서가 권하는 쓰임
low결과를 하나씩 확인하는 빠른 주고받기. 브레인스토밍, 이름 바꾸기 같은 작은 수정
medium범위가 분명한 일상 개발. 새 기능 구현
high검증이 중요하거나 예외 상황이 많은 일. 기존 코드의 버그 수정
xhigh토큰을 더 쓰는 깊은 추론
max혼자 끝까지 풀게 맡기는 어려운 문제. 효과가 줄어들거나 지나치게 오래 생각할 수 있으니 넓게 쓰기 전에 시험해 볼 것

4. /advisor — 두 번째 모델에게 조언 받기

평소 작업은 지금 모델이 하고, 방향을 정할 때나 같은 오류가 반복될 때, 마무리 직전처럼 중요한 순간에만 더 강한 모델이 대화 전체를 읽고 조언하는 기능이에요. 언제 물어볼지는 Claude가 정합니다.

/advisor opus      # Opus를 조언자로 켜기 (예: Sonnet으로 일하고 Opus에게 조언)
/advisor           # 조언자 고르는 메뉴
/advisor off       # 끄기

조언 모델은 지금 모델과 같거나 더 높은 등급이어야 해요. Opus 5.5로 일한다면 조언자는 Opus나 Fable만 됩니다. 아직 실험 기능이고, 조언 모델이 대화를 통째로 읽으니 사용량이 더 듭니다. 대부분의 턴은 평범하지만 계획의 질이 결과를 가르는 긴 작업(큰 리팩터링, 오류가 되풀이되는 디버깅)에 어울리고, 짧은 작업에는 얻는 게 적어요.

5. /context — 공간 확인

컨텍스트는 Claude가 한 번에 들고 있는 대화와 파일 전부를 말해요. /context를 치면 무엇이 공간을 차지하는지 색 블록으로 보여 주고 줄이는 방법도 제안합니다. 대화가 길어져 답이 흐려지기 시작했다면 여기부터 보세요.

/context                               # 무엇이 공간을 먹는지 확인
/compact 인증 모듈 수정 내용 위주로 요약    # 대화를 요약해 공간 확보 (요약 초점 지정 가능)
/clear                                 # 완전히 새 대화로 시작

같은 일을 이어 갈 거면 /compact, 다른 일로 넘어갈 거면 /clear예요. 컨텍스트를 아끼는 습관은 초급 팁에서 더 다룹니다.

② 작업 중 — 곁가지 질문과 병렬 작업

6. /btw — 멈추지 않고 물어보기

"그런데(by the way)"의 줄임이에요. Claude가 한창 일하는 중에 문득 궁금한 게 생기면 작업을 끊지 않고 물을 수 있습니다. 지금까지의 대화를 보고 바로 답하고, 그 질문과 답은 대화 이력에 남지 않아요.

/btw 아까 그 설정 파일 이름이 뭐였지?

다만 도구를 쓰지 못해요. 새 파일을 읽거나 명령을 실행할 수 없고, 이미 대화에 있는 내용으로만 답합니다. 답은 한 번으로 끝나니 이어서 묻고 싶으면 /btw를 다시 치면 돼요.

7. /background (/bg) — 지금 대화를 뒤로 보내기

현재 대화를 백그라운드로 옮기고 터미널을 비워 줘요. 뒤에 마지막 지시를 붙일 수 있습니다. 백그라운드로 간 작업은 터미널을 닫아도 계속 돌아가요.

/bg 테스트 돌리고 실패하는 것 고쳐 줘

상태는 터미널에서 claude agents로 확인합니다. 내 답을 기다리는 것, 진행 중인 것, 끝난 것으로 나뉘어 한 화면에 모여요.

8. /fork — 대화를 복사해 따로 돌리기

지금 대화를 복사해 새 백그라운드 세션을 엽니다. 원래 대화는 여기서 계속하고 복사본은 뒤에서 따로 일해요. 복사본은 모델, 권한, 노력 수준을 그대로 이어받습니다.

/fork 같은 방식으로 결제 모듈도 리팩터링해 줘

Git으로 관리하는 프로젝트라면 복사본은 코드를 고치기 전에 워크트리(같은 저장소를 별도 폴더에 펼친 작업 공간)를 따로 만들어서, 원래 폴더의 파일과 섞이지 않아요. /background가 지금 대화를 뒤로 보내는 것이라면 /fork는 새 대화를 하나 더 만드는 겁니다.

9. /tasks — 백그라운드 작업 목록

Claude는 큰 일을 쪼개 서브에이전트(일을 나눠 맡는 또 다른 Claude)에게 넘기곤 해요. /tasks는 이 대화에서 넘긴 작업과 백그라운드 명령을 끝난 것까지 포함해 보여 줍니다. Claude가 답을 쓰는 중에도 바로 열려요.

/tasks                    # 목록 열기. 돌고 있는 작업을 고르면 그 작업으로 들어감
/rename 결제-리팩터링       # 세션에 이름을 붙여 두면 나중에 찾기 쉬움

10. /resume — 예전 대화로 돌아가기

닫았던 대화를 이름이나 ID로 다시 열어요. 인수 없이 치면 세션 목록이 뜹니다. 백그라운드 세션은 목록에 bg 표시가 붙고, 아직 돌고 있는 세션을 고르면 지금 대화가 뒤로 가고 터미널이 그 세션에 붙어요.

/resume                   # 세션 목록에서 고르기
/resume 결제-리팩터링       # 이름으로 바로 열기

/clear로 새 대화를 시작했어도 이전 대화는 사라지지 않고 /resume으로 돌아갈 수 있어요.

③ 리뷰 — 바뀐 것, 버그, 보안, PR, 습관

11. /diff — 바뀐 내용 보기

Claude가 고친 것과 아직 커밋하지 않은 내 수정을 합쳐서 파일별로 보여 줘요. 추가·삭제된 줄 수와 실제 바뀐 줄이 나옵니다. Claude가 파일을 고친 뒤에는 턴마다 무엇을 바꿨는지 따로 볼 수도 있어요.

/diff

12. /code-review (/review) — 버그 찾기

바뀐 코드에서 정확성 버그를 찾아요. 혼자 치면 현재 변경분을, PR 번호를 붙이면 그 PR을 봅니다. PR(풀 리퀘스트)은 GitHub에서 내 변경을 합쳐 달라고 올리는 요청이에요.

/code-review                # 현재 변경분 리뷰
/code-review high 1234      # 1234번 PR을 high 깊이로 리뷰
/code-review --fix          # 찾은 문제를 바로 고치기
/code-review --comment      # 찾은 내용을 PR에 댓글로 달기
/code-review ultra          # 클라우드에서 여러 에이전트가 깊이 리뷰

깊이는 low부터 max까지 고를 수 있고, 깊이를 안 적으면 마지막에 쓴 깊이를 다시 써요. PR이 열린 뒤의 리뷰·수정·승인을 통째로 맡기는 흐름은 Claude Ship에서 다룹니다.

13. /security-review — 보안만 보기

현재 브랜치를 원격 기본 브랜치와 비교해 인젝션(입력값에 명령을 끼워 넣는 공격), 인증·권한 문제, 데이터 노출 같은 위험을 찾아요. 원격 저장소가 origin이라는 이름으로 연결돼 있어야 합니다.

/security-review

14. /autofix-pr — PR 지켜보다 고치기

현재 브랜치의 PR을 찾아 클라우드 세션을 띄웁니다. 자동 검사(CI)가 실패하거나 리뷰 댓글이 달리면 고쳐서 다시 푸시해요. 기본은 모든 실패와 댓글을 고치는 것이고, 지시를 붙여 범위를 좁힐 수 있습니다.

/autofix-pr
/autofix-pr 린트와 타입 오류만 고쳐 줘

GitHub 명령줄 도구 gh와 클라우드 세션 사용 권한이 필요해요. 다른 PR을 지켜보게 하려면 먼저 그 브랜치로 체크아웃합니다.

15. /insights — 내 작업 습관 돌아보기

이번에는 코드가 아니라 사람을 리뷰해요. 이 컴퓨터의 최근 대화를 분석해 HTML 보고서를 만듭니다. 어떤 프로젝트에서 일하는지, Claude Code를 어떻게 쓰는지, 요청이 잘못 이해됐거나 버그가 난 지점이 어디인지, 써 볼 만한 기능이 무엇인지가 담겨요.

/insights      # 보고서는 ~/.claude/usage-data/report.html 에 저장

한 번에 아직 분석하지 않은 대화 200개까지 보고, 분석에 쓰인 토큰은 평소 사용량에 포함됩니다. 다른 기기나 claude.ai의 대화는 들어가지 않고 클라우드 세션에서는 쓸 수 없어요. 코드 리뷰보다 뜨끔할 때가 있습니다.

④ 실행·검증 — 띄우고, 확인하고, 진단하기

16. /run — 앱을 실제로 띄워 보기

"테스트가 통과했다"에서 멈추지 않고 앱을 실제로 실행해 바뀐 부분이 동작하는 모습을 보여 줘요. 따로 설정하지 않아도 README, package.json, Makefile 같은 파일을 보고 실행 방법을 알아냅니다.

/run

17. /verify — 의도대로 고쳐졌는지 확인

앱을 빌드하고 실행한 뒤 결과를 직접 보고 판단해요. 테스트나 타입 검사가 통과했다는 것만으로 끝내지 않습니다.

/verify
/run-skill-generator      # 실행 절차가 복잡한 프로젝트라면 한 번 실행해 절차를 기록

데이터베이스나 환경 변수 파일이 필요한 프로젝트는 실행 방법을 추측하기 어려워요. /run-skill-generator를 프로젝트당 한 번 돌리면 성공한 설치 명령·환경 변수·실행 스크립트가 .claude/skills/ 아래 스킬로 기록되고, 이후 /run과 /verify가 그 절차를 따릅니다. 스킬이 무엇인지는 스킬이란을 보세요.

18. /claude-in-chrome — 실제 브라우저에서 일하기

내 Chrome에서 페이지를 테스트하고, 입력란을 채우고, 콘솔 로그를 읽어요. 시작할 때 Chrome 연동을 켰거나(claude --chrome) 확장 프로그램 설치가 허용된 환경에서 쓸 수 있습니다.

/claude-in-chrome 로그인 페이지에서 잘못된 비밀번호를 넣었을 때 오류 문구가 뜨는지 확인해 줘
/chrome        # Chrome 연동 설정

19. /debug — 세션 문제 진단

디버그 로그는 평소 꺼져 있다가 /debug를 치는 순간부터 기록되고, Claude가 그 로그를 읽어 원인을 찾아요. 증상을 뒤에 적으면 그 문제에 집중합니다.

/debug MCP 서버가 연결됐다가 바로 끊겨
/doctor        # 설치·설정·확장·CLAUDE.md 문제는 이쪽

20. /claude-api — 앱에 Claude 붙이기

내 앱에서 Claude API를 호출하는 코드를 쓸 때 쓰는 명령이에요. 프로젝트 언어에 맞는 Claude API와 Managed Agents 안내서를 불러옵니다. 코드에서 anthropic이나 @anthropic-ai/sdk를 import하면 자동으로 켜지기도 해요.

/claude-api migrate          # 기존 코드를 새 모델로 옮기기
/claude-api cost-optimize    # API 비용이 어디서 나가는지 보고 줄일 방법 제안
/claude-api build-eval       # 평가 세트 만들기

처음이라면 이 네 개부터

스무 개가 많다면 네 개만 순서대로 써 보세요.

/init            # 1. 안내서를 만든다
/run             # 2. 고친 뒤 실제로 띄워 본다
/code-review     # 3. 버그를 잡는다
/verify          # 4. 의도대로 동작하는지 확인한다

여기에 익숙해지면 어려운 작업 앞에서 /effort high를, 답이 흐려질 때 /context를 더하면 됩니다.

병렬로 돌리기 전에 알아 둘 것

/background와 /fork로 여러 작업을 동시에 돌리면 편하지만 한도도 그만큼 빨리 닳아요. 공식 문서는 백그라운드 세션이 일반 세션과 같은 구독 사용량을 쓰기 때문에 열 개를 동시에 돌리면 한도가 약 열 배 빨리 줄어든다고 적고 있습니다. 백그라운드 세션은 내 컴퓨터에서 돌기 때문에 절전은 견디지만 컴퓨터를 끄면 멈춘다는 점도 기억해 두세요.
