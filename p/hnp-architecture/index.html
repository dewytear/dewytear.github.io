동작 구조와 6단계

내가 진행시켜 를 누른 뒤, 하네스 내부에서 벌어지는 일을 들여다봅니다. 크게 6단계로 팀을 짜고, 그다음 운영 루프를 돌립니다.

플러그인의 6단계 — 팀을 만드는 과정

여기까지가 "팀 짜기". ⑥ 검증을 통과하면 실제 작업(운영 루프)이 시작됩니다.

운영 루프 — 팀이 일하는 방식

팀이 만들어지면 오케스트레이터가 아래 루프를 돌립니다. 핵심은 "나눠서 병렬로 하고, 테스트로 검증하고, 틀리면 다시"입니다.

  1. 분해 — 목표를 작업 단위로 쪼갭니다. 예: 영향도 분석 · 보류 로직 · 알림 · 회귀 테스트
  2. 분담 & 병렬 실행 — 각 에이전트가 동시에 담당 작업을 처리.
  3. 검증 — QA가 결과를 교차 확인(표준 기능 회귀, 수치 정합성).
  4. 피드백 루프 — 문제가 있으면 담당 에이전트에게 되돌려 다시. 통과할 때까지 반복.

에이전트 팀 vs 격리 서브에이전트

Claude Code의 기본 서브에이전트는 서로 격리되어 대화하지 못합니다. 에이전트 팀은 서로 통신합니다 — 예를 들어 개발 에이전트가 "표준소스 정보가 부족하다"는 걸 발견하면 분석 에이전트를 다시 깨워 추가 조사를 시킬 수 있습니다.

실험 기능 — 켜는 법 에이전트 팀은 실험 기능입니다. ~/.claude/settings.json 의 환경변수로 켭니다: 
"env": {
  "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
}
동적 로딩에 실패하면 격리 서브에이전트로 뜨는 버그가 있으니, 에이전트가 안 보이면 /exit 후 다시 들어와 /agents 로 확인하세요.
파일은 어디에 생기나 생성된 에이전트·스킬 정의는 프로젝트의 .claude 아래에 남아 Git으로 팀과 공유할 수 있습니다. 단, 플러그인 자체는 머신마다 각각 설치해야 합니다. 구성 변경 이력은 CLAUDE.md 에 기록됩니다. 팀 설계 자체를 더 깊이 다루는 에이전트·스킬 설계로 이어집니다.
